# P-003 开发拍：检索窗 500→1024（= 票册 P1F-04，票序 2/7）

任务：消除「cited 却不可见」——生成模型只能看到检索片段前 500 字。`app/domains/kb/service.py` 两处构造 `IndexHit` 时写死 `text=text[:500]`（L1182 单路搜索读面、L1211 双路召回读面 `_hit()` 内），而入库切段上限是 1024 字（`app/domains/kb/domain.py` SMART_MAX_CHARS）——每个 smart 片段后半截系统性丢失，模型手里没有自己被要求引用的内容（实锤：B-反1 的 W-45 行在片段第 691/854 字，模型 citation 引了该片段却看不见那行，只能诚实说"未检索到"）。

施工方案：两处 `text=text[:500]` → `text=text[:d.SMART_MAX_CHARS]`（从 domain 导入常量，同源引用不造新魔数）；两处所在函数（单路 `index_search` 与双路 `index_search_dual` 的 `_hit` 闭包）的 docstring 若提及截断长度随票更新。除这两处外不动任何检索/排序/打分逻辑。

先读：票册 `tickets/phase1-fix/README.md` P1F-04 节；`eval/results/评测报告.md` §4 B-反1 段、§6 建议 4；`app/domains/kb/service.py` ~L1170-1235；`app/domains/kb/domain.py` ~L83-90（SMART_MAX_CHARS=1024）。

框架红线：无点名框架。

边界红线：只许改 `app/domains/kb/service.py` 与 `tests/domains/`（或 `tests/infra/`）下对应测试文件；不碰 chunk 逻辑/检索排序/embedding/chat 域；禁止 `git add -A`，工作区 Owner 私产（eval/README.md 修改、eval/answers/D-诱导题集.md）不碰不提交。

验收：以下全达才算过。
1. 新单测 ≥2 全绿：(a) 构造 1024 字片段走读面，断言 `IndexHit.text` 全文不截（len=1024）；(b) B-反1 形态回归——片段内含关键行于第 691~854 字区间，读面后 `text` 含该行（用合成 fragment 落 sqlite 测试底座即可，照仓内既有 kb 测试惯例）。
2. 存量测试无回归：`uv run pytest tests/domains/kb -q` 通过数附回报。
3. 四门禁＋两闸绿（全量命令照 PROTOCOL）；commit 前快扫（ruff＋两闸）输出附回报。
