施工方案：

**① 低分带常量（`app/domains/chat/domain.py`）**：`RESCORE_BAND` 语义常量（0.30 ≤ score < refuse_threshold——下沿用 0.30 固定、上沿随 D2 现值，常量＋注释）。

**② 第一道：放宽窗口重评（`chains.py` S6 后，`~L233-249` 一带）**：best 落低分带 → 纯代码重评一次（topK 放宽＋父块回捞重算 best 分，照链内既有权威源回读/父块机制的现成读面）→ 过闸照常生成（不弹帧）；帧注记记录两值（原分/重评分）。

**③ 第二道：LLM 改写＋双句评分（仍低才触发，仅此刻一次 LLM 调用）**：走 `gateway.complete`（caller 新增 `chat.query.rewrite`，按仓内 caller 自由字符串惯例，费用统计可溯源——施工先核对 gateway 现惯例）。改写提示词（措辞可微调、语义须覆盖）：去修饰保语义、输出检索优化问法、只回问法本身。用**同一把尺**（与 S4 相同的余弦算法）给原句/优化句各算一次 → 分支：
- 优化句 ≥ refuse_threshold 且原句仍低 → **澄清额度在**（clarify_count=0）→ 弹 rewrite 澄清帧（复用 `_suspend_clarify`/`resume`；新 subtype「rewrite」，选项＝「按优化问法『…』作答」/「坚持原问法」）→ resume 选是：用优化句上下文走生成（引用照常）；选否/不选：诚实兜底。
- **额度已用完**（N5 已弹过一次）→ 不弹第二帧：自动按优化句作答＋答案标注「已按优化问法检索」（写死路径）。
- 优化句也低 / 改写调用失败/解析坏 → 诚实兜底；S6 帧注记记三个分值（原句/放宽/优化句）。
