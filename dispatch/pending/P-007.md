# P-007 开发拍：入库结构图 LLM 化＋代码守门（= 票册 P1F-05 方案 A，票序 6/7，kb 域大票）

任务：根治入库 section 元数据污染（f26 整句正文被当标题吞进章节名、f42 表格行误判——引用抽屉标签不可读、章号错）＋把标题判定从规则穷举升级为 LLM 理解＋代码守门。Owner 拍板方案 A 混合架构：LLM 出结构图、逐字校验防幻觉、复合规则复检、规则独立回退、机械切块不动、版本级缓存保重入一致性。

施工方案（主体 `app/domains/kb/`，一步一验）：

1. **结构图 schema（`domain.py`）**：`StructureMap` 数据类（标题行号/标题文本/层级），LLM 输出 JSON 的解析与宽容处理（剥围栏/容错，参照 chat 域 `_parse_intent_json` 先例）。复合规则四条件落成可独立调用的纯函数（`_HEADING_RE` 分支命中＋行长 ≤40＋行尾无句读。；！？＋无表格特征〔全角空格连续格/多空格数字格〕）——规则面单独有测、不依赖 LLM。
2. **LLM 结构提取（`service.py` 入库管线 chunk 步前）**：`gateway.complete` 单点调用，caller 新增 `kb.ingest.structure`（先核对仓内 caller 惯例与计费留痕形态——chat.query.rewrite 先例）。提示词语义：只输出文档中真实存在的标题行、JSON 结构图、不过度发挥。
3. **逐字校验（防幻觉硬闸）**：结构图每张标题必须逐字命中文档真实行（行内容精确匹配），任一 miss → 整张作废。
4. **复合规则复检**：校验过的图再过四条件，双重保障；通不过的行从图中剔除（降级为正文）而非整图作废——注意区分两种处置：逐字校验失败＝整图作废（幻觉信号），规则复检失败＝单行剔除（保守）。
5. **回退路径**：LLM 不可用/超时/JSON 坏/整图作废 → 回退纯规则（复合规则独立可用），warning 留痕，入库不阻塞（F32 子任务失败不阻塞整卷同款语义）。
6. **版本级缓存（写死）**：结构图随报告版本落库（任务快照字段）；同版本重入直接复用、零 LLM 调用、片段集字节级一致。
7. **chunk 消费结构图**：`chunk_text` 的 smart/mixed 支路改为消费结构图边界（`_section_of` 扫描由图替代或增强——实现细节你定，约束：尺寸带 256–1024/重叠 10–20%/片段 ID/父子块打包全不动）；**回归语料库**进测试目录：三篇评测报告＋teach 原型样例的标题/正文/表格行三族，每条新误判模式补料。
