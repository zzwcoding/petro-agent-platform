## 偏差

1. **`pg_store.py` 改动超出票面范围清单字面（lake_store/ingest/迁移文件/midplatform SQL/对应测试）**：现象→票面第 1 条要求数据面自有 schema 收纳 freshness_registry/audit_record，而该两表建表 DDL 恰在 pg_store（未点名文件）。原因→同一表族两处定义不归位＝第二真源。处置→DDL 与查询 schema 限定 `data_plane`（构造幂等 ensure 同形兜底，迁移 001 互为镜像）；tests/pg 的 DROP 语句随改（对应测试）。红线零触碰（serve/deploy/主仓/DP-01·02 资产原样）。
2. **仓内新建 `.venv`＋`.gitignore` 一行（票面未点名）**：现象→湖真身/迁移/e2e 需要 psycopg＋boto3，主 python3.14 未装且 `ensurepip` 损坏（`platform.mac_ver()` 返回空——本机环境事实，uv/python3.14 -m venv 双路复现）。原因→实跑验收必须有驱动。处置→`.venv`（uv 管理，.gitignore 排除不入仓）作实跑环境；hermetic ci.sh 跑法不受影响（缺包自动 skip 同 tests/pg 先例）。是否把 psycopg/boto3 列入部署清单依赖，归 DP-04 部署批。
3. **specs/s1_tracer_bullet.md、specs/modules.md、.scratch 票 06、docs/prd.md §6 四处替身名改写**：现象→验收 2 要求 `grep InMemoryLake` **零命中**（字面全仓），而上述四处为历史文档中的类名提及。原因→字面零命中与历史文档留名互斥。处置→原地最小改写并带〔DP-03 注记〕（非静默：s1 范围行同时补拍板 3 湖形态变更注记）；docs/prd.md 惯例上归对齐拍（DP-02 疑点 4），本次仅替身名单一处名词级同步，§12 叙事债维持挂 L0。
4. **`SnapshotInfo.provenance` 语义收紧＋`schema()` 业务列视图**：现象→原替身 append 把整个 commit_meta 回塞 provenance（`{"provenance": {...}}` 双层包裹），schema() 返回构造入参列。原因→真身下 commit_meta 的 source/batch_id/manifest 在快照账各有专列/专段，整包回塞冗余；湖技术列（`_` 前缀）属管道件非问数信源。处置→provenance=质检/操作者出处本体、schema() 过滤 `_` 前缀列；差异已在 lake_store 文件头注记。如 L0 判为契约漂移，修复拍一行可回。
5. **well_overhaul 技术列让位 `_src_batch_id`＋equip_status 不落时间戳列**：现象→8 表通用技术列 `_batch_id` 与 well_overhaul 业务列 `batch_id`（设定书 §A.4 补录批次）撞名；§A.7 字典粒度"设备号+时间戳"但字典与 fieldforge 供给均无该列名。原因→业务列名是合同/供给事实，技术列让位；时间戳列名无真源（业务事实零发明）。处置→well_overhaul 技术列=`_src_batch_id`（表 COMMENT 注记）；equip_status 列形照 fieldforge 供给 5 列，COMMENT 登记粒度缺口（疑点 2）。
6. **迁移工具取 SQL 文件＋`tools/migrate.py`，非 Alembic**：票面授权"随仓现状定"——仓内自 S1 起无 Alembic 依赖与迁移链；99 §4.4 的"alembic/versions 线性序列、禁手工改库"纪律以 `migrations/` 线性序＋up/down 成对＋账本表照守。Alembic 悬置声明不变；若 L0 要求 Alembic 化，本结构可平移。
7. **raw 表不设业务主键约束**：设定书 §A 的 PK（如 oil_production_daily 一井一日）为逻辑键——A/B 班重复行、配产双值行是原始层 as-is 合法内容（质检闸在进料前拦截、清洗层才去重），约束化会拒收真源数据。处置→逻辑键以表 COMMENT 登记不约束，事实表补非唯一索引；迁移测试对 COMMENT 机判。
