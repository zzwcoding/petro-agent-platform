   现象→复制层落位后 `lint-imports --config tools/importlinter_v2.toml` 判红：

   而禁止清单无豁免即与自身意图矛盾（V1 同位契约 pyproject「B6 供应商 SDK 唯一
   接触点」带同款 `ignore_imports: ["app.infra.llm_client -> litellm"]`）。
   处置→修复（补 `ignore_imports = ["appv2.infra.llm_client -> litellm"]`，实证红
   前后各留闸门输出）；此改动越出票面「只许新建 appv2/infra/**、
   tests/infra/test_v2_infra.py」的文件边界字面，如实登记**请 L0 追认或回退**
   （回退则该契约对任何含 litellm 的复制层恒红，需另行裁决闸配置归属）。
2. **复制清理取舍披露（票面「复制清理」「带纪律不带业务语义」授权内）**
   - `config.py`：剥 InfraSettings 三键 `plan_breaker_consecutive_failures`/
     `plan_breaker_failure_rate_threshold`/`plan_effective_enabled`（消费面＝V1
     chat 域 PlanBreaker/ChatService，不进复制层）；剥 `load_entity_type_names`/

     （minio/neo4j 消费 adapter 未随本票，注记「落位批启用」）。

     （V1 prototype roles.js 页面组业务）；保留 `resolve_actor`＋五角色注册表
