### Schema 定稿要点（票面点名「ToolDescriptor/ToolContext/ToolResult/AskFrame 四 schema 随本票定稿」）

- `ToolDescriptor = {name, description, args_schema(jsonschema 子集), readonly: True}`——渐进披露恰四字段（书 5.5 三层披露之发现层），registry 拒绝注册 readonly!=True。
- `ToolContext = {actor: str = "", budget: int = 4, metric_candidates: tuple[str, ...] | None = None}`——运行策略归调用方不进 args：actor＝行级身份（data_query→plan.actor，**身份只从 ctx 进、plan_draft schema 无 actor 键**——伪造面收口，测试钉死）；budget＝检索送窗预算 M；metric_candidates＝FX-13 候选集逐字转发 query.validate。
- `ToolResult = {status: ok|failed|ask, observations: tuple[Observation, ...], ask, error}`——三态构造即定型不变式（C1 slots domain 同款纪律）。
- `AskFrame = {kind: clarify|external_table_approval, prompt, options, detail}`——detail＝审批卡素材透传（A1 帧 15 形状：approval_id/scene/title/reason/impact/audit_hint，approval_id 供 resume 留痕必需；specs 注记三字段外的定稿补充，见偏差 1）。
- `Observation = {content, source, source_id, version, freshness, scope, locator}`——locator 恒机读且 kind 键分型：台账卡（kind=五类 kind＋element_id＋binding_state）、agg_row（table/well_id/prod_date）、lineage、fragment/graph（library/report/section/fragment_id 三级出处链）、notice（notice_type：freshness_block/unbound_degrade/rebind/window_note/no_hit）。knowledge Evidence 同形位映射＝content←value、source_id←element_id（V2-02 票面留位本票落定）。

## 偏差

有，逐条如下（均为实现裁量登记，不阻塞验收）：

1. **AskFrame 增设 detail 字段（specs 注记三字段 kind/prompt/options 之外）**：现象→specs/tools.md 接口定义注记 `AskFrame = {kind, prompt, options}`，但 external_table_approval 的 resume 续跑必须持 approval_id（A1 帧 15 审批卡素材）——三字段装不下，resume 票（V2-06）将无从留痕。原因→specs 注记为形状示意，四 schema 定稿权在本票（票面点名「随本票定稿」）。处置→增 `detail: Mapping | None = None`（默认 None 不破三字段形状，clarify 态不携）；审批卡六键逐字透传不重造。若 L0 判应裁剪，改动单点在 schema.AskFrame＋_outcome_to_result 一分支。
2. **freshness_block/unbound_degrade 映射的 status 落 ok**：现象→specs/tools.md 行为约定 4 只写「→observations(闸依据 Evidence/水位)+notice 素材」，未点名这两态的 status；三态枚举中 ask 已被 need_clarify/external_table_approval 占用、refused 错误分类已被 refuse 联合态占用。原因→行为约定 4 把这两态与 rows 并列为观察承载（区别于 refuse 的错误路径），且 V1 拦停/降级话术走答案面非错误面。处置→落 status=ok＋闸依据观察＋notice（locator.kind=notice/notice_type 机读分型，agent 可机判「拦停非数据」）；data_query descriptor description 载明；query_outcome_mapping 钉死。见「疑点 1」。
3. **graph_query 的 anchors 消费＝锚名并入实体匹配问针**：现象→对齐项②字面「并入关键词腿检索单元＋编号保送」是 retrieve 面语义（P-003 实现）；引擎 graph 面按 `need.question` 子串匹配实体、不消费 anchors——若工具层仅透传，graph_query 的 anchors 参数为零消费面的死参数。原因→引擎 face 合同已定（P-003），工具层是参数契约落点。处置→工具层组合 needle＝question＋anchors（锚定语义的图谱侧投影），RetrievalNeed.anchors 仍逐字透传；端到端测试钉死。若 L0 判应保持引擎侧原样，改动单点在 graph_query handler 一行。
