### 根因链（四工序①③实证）

1. **缺陷定位（工序①）**：`scripts/dev` 旧形态两个 run 目录——`cmd_seed` 灌 `/tmp/tpa-fieldforge-run`（fieldforge 真产物），而 `start_worker` 常驻 daemon 吃 `/tmp/tpa-demo-run`（v1 demo 残留 28 行拟造值，`oil_output=21.0/liquid_output=27.13/oil_pressure=7.5`，与 agg 脏格逐格同值）。daemon 每日 cron（05:30 北京时）把 v1 28 行当「新批次」追加：湖快照账 37 号（`b-8c8cd81fea34`，2026-10-06 21:30 UTC）与 39 号（`b-c3852fb36d75`，2026-10-07 21:30 UTC）各 28 行——湖 as-of 时点视图「同键最新批生效」令 v1 值覆写真值，agg 刷新 upsert 把 v1 值冲回 `agg.fct_daily_metering`。**「v1 行未清就插新行」的病灶＝v1 行活在常驻 worker 的 run 目录里反复重灌，不在湖里**（湖 append-only，无行可清）。
2. **双批次号同根（工序③）**：修复前 agg 批次分布 `b-670d3a6a0d59×31362（真批，10-06 seed）＋b-c3852fb36d75×28（脏批，10-07 cron）`——血缘④「两个批次号」即 fct 行批次列混源，与 28 脏格同根（同一 cron 污染链；MinIO 桶内还有更早一代 `b-4e6425a023fc`（10-05 21:30 UTC），证明污染自 10-05 起每日复发）。
3. **修复**：主仓半边＝run 目录单源＋seed 整目录重建（源头上 v1 残留零存活）；数据面半边＝进料幂等闸（内容未变零追加，杜绝「同内容每日重灌」的批次号漂移；视图被旧批覆写≠源＝整批重灌重建真值）。
4. **幂等重灌（工序②）**：seed 首跑进料两表（快照 31/32）→ agg 刷新 `{'dim_well': 120, 'dim_date': 365, 'fct_daily_metering': 31390}`；水位三 tier 全部 2026-08-31（Q11 基线口径）。
