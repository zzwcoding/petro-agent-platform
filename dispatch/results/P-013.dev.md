## 偏差

1. **api 组合根例外延伸（设计裁决点，非缺陷）**：`compose_production_registry` 在 `appv2/api/app.py` 局部 import 引擎（knowledge/query/retrieval）与 tools 包——modules.md 边界规则表「api 引用 runtime 以外模块→禁止」的字面被票面任务 4 明文覆盖（「组合根：create_app 装配真引擎（替换 fixture 组合）」）；importlinter 无「api 禁引引擎」契约（七契约全 KEPT，实测通过）。fixture 组合（全部既有测试）照旧经 registry 参数显式注入，零改动零回退。**文档回写（api 卡注记延伸）归属：L0 对齐拍**。
2. **同步缝→异步 DB 桥（量级裁决点）**：KnowledgeStore 四方法/QueryExecutor.execute/WaterlineLoader 均为 specs 接口定义节冻结的同步签名，而 B3 唯一 DB 出口（infra.db）是异步会话——两生产读面（knowledge/query＋水位缝）以「每次查询专用临时 ConnectionManager＋两态桥」实现（无运行环本线程 asyncio.run 直跑；运行环内专用单线程另起环；finally dispose）。理由：连接池绑定创建它的事件循环（asyncpg 连接不可跨环复用），专用随调用建/拆保证池与环同源；会话获取仍唯一经 infra.db（B3 不破）、readonly 守卫恒挂。演示库单查询毫秒级（冒烟实证 27.53s 两题全链含 6 次真计费）。**长期形态（引擎缝异步化或常驻桥环）挂账：L0/治理批裁决**。
3. **「直读 PG」口径**：specs「不做缓存层（本期直读 PG，量级允许）」按**每次查询直读现行行**实现（PgKnowledgeStore 每次证据查询重读 sem_* 四账；水位读缝每次重读 water_line；PgFragmentLibrary 每次 fragments() 重读 kb_*）——零跨调用缓存，语义最强口径。
4. **测试基建 sqlite ATTACH**：组合根两向测试以 sqlite `ATTACH '<file>' AS agg` 承载 schema 限定表（Engine 类级 connect 钩子随 fixture 挂/摘，测试侧机制，生产代码零涉及）；agg 真方言语义由 PG16 集成测试（TEST_DATABASE_URL 门控）与 RUNTIME_SMOKE 真库覆盖——门内门 外双层。
5. **分支基线**：按派工指示自 master（9a9e7e7）切、不含 P-012 未合并工作——importlinter_v2 本分支 7 契约（P-012 合并后为 9，其新增两向互禁契约本票无触碰面）；与 P-012 分支改动文件零重叠（其动 ci.yml/importlinter_v2.toml/modules.md/specs/tools 与部分测试，本票只在 appv2/{knowledge,query,retrieval,api}＋对应新测试），合并冲突风险低。若 P-012 先合，本分支重放无预期冲突。
