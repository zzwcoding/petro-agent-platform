### consider（7 条）

**C1 观察材料与指南全文随每个 decision/answer 轮重复入簿，token 放大 3-4 倍**
- 证据：appv2/runtime/context.py:154-156 材料段拼进当前轮，context.py:166-168
  当前轮整体进 turns；graph.py:867-871（decision）、graph.py:1523-1528（answer）
  以 `dict(context.messages[-1])` 把含全量材料（≤24 支）＋指南全文（guide.py
  REACT_DISCIPLINE 等，graph.py:852 每轮注入）的当前轮写入 history。3 轮 run
  材料被装载 3-4 次、指南 3 次。
- 实质：ADR-0006 字面是「调用与输出入簿」，此实现合规不算错；12000 预算的
  确定性截断（最旧中间轮先弃，context.py:81-101）恰好先弃最旧的材料副本，
  兜底在。但 token_count 与网关计费随之放大，且同一 [n] 材料块在多条历史轮
  重复出现（序号语义一致，无误导，纯冗余）。
- 建议：细化批评估「历史轮去材料化」（历史轮只留 instruction/决策 JSON/台账，
  材料只在当前轮渲染一次）——需 Owner 表态是否属细化批范围。

**C2 _ledger_turn 把 bad_args/retryable/refused 三态统一渲染为「闸拒（拒因）」，措辞不如实**
- 证据：appv2/runtime/graph.py:743-759——非 ok/ask 一律
  `→ 闸拒（拒因：…）`；bad_args（模型自身参数校验拒，如「不在指标台账」）与
  retryable（工具暂不可用）也标「闸拒」。
- 实质：票面台账形只定义两态（「参数 → 结果：N 行／闸拒（拒因）」），实现按
  票面字面合规；但 ADR-0006「负信息如实落」的精神下，「暂不可用」读成
  「闸拒」可能让模型把可恢复路径当永久数据闸放弃（retryable 引擎侧仍自动
  重试一次并再落一条台账，实际误导有限）。
- 建议：细化批按 status 分型措辞（校验拒／暂不可用／闸拒），一行改动量级。

**C3 chars/4 口径对中文低估约 3-4 倍，12000 名义 token 实为字符预算**
- 证据：appv2/runtime/context.py:77-78（`len(text)//4`）、context.py:50
  （DEFAULT_MAX_CONTEXT_TOKENS=12000）。中文分词下 48000 字符的真实 token
  远超 12000（约 3-4 倍量级）。
- 实质：作为确定性增长上限仍有效（字符面有界），且与网关记账兜底同口径
  （注释声明）；但若上游按真 token 限位，名义值挡不住。
- 建议：并入 dev 疑点 2 处置——Q13 复测用网关 prompt_tokens 实测校准定稿，
  校准时要按中文口径折算而非直接对照。

**C4 连续 user 轮依赖网关/供应商兼容，适配责任在 GatewayChatModel 单点**
- 证据：graph.py:743-759 台账轮与下一决策轮均为 user role，历史中连续两条
  user 消息；llm.py `_agenerate` 经 `_message_to_dict` 直传 gateway.complete，
  不做归并。MiniMax 线形冒烟实证通过（回报申报）。
- 实质：单点出口纪律下可接受；若后端切换为要求 user/assistant 严格交替的
  供应商，需在该单点加归并策略。
- 建议：在 llm.py 模块注记一句已知形态即可（骨架版不动）。

**C5 追问无属主校验——任意身份可追问任意 run 并把其全史装进新 run 的模型面**
- 证据：appv2/runtime/executor.py:191-223 `_seed_history` 只查存在性与
  status，不比对 prior.actor 与当前 actor。
- 实质：与全仓现状一致（GET runs/{id} 同样无属主闸），开发期身份桩
  （X-Dev-User）posture 下非本票引入的缺陷；但追问的暴露面（前轮问题、数据
  结果、决策全史进上下文）比读接口更直接。
- 建议：挂到 OAuth2.0 替换 `security.resolve_actor` 的生产化批，随身份落地
  补属主闸（一眼改动：prior.actor != actor.user_id → 404）。

**C6 RunState.history 簿记面无界——预算只截模型面，不截簿记面**
- 证据：context.py:81-101 `_fit_history` 只作用于编译产物 messages；
  executor.py:222 每次追问播种前轮全史＋本轮自增；checkpointer 每步全量存
  state。长追问链下 state.history 与检查点行随之线性膨胀。
- 实质：单 run 轮数有 3 轮上限闸，风险集中在追问链长度；骨架版可接受。
- 建议：Q13／长会话压测时观察检查点行大小，必要时给播种加轮数上限。

**C7 AskBody 允许 resume_run_id 与 followup_run_id 同时在场，followup 被静默忽略**
- 证据：appv2/api/chat.py:146-148 resume 分支先行返回，chat.py:180 的
  followup 解析不可达；无互斥校验。
- 实质：无错误后果（重连语义优先合理），但调用方拼错参数会拿到「像成功」的
  重连而非追问，排障成本高。
- 建议：细化批补一行互斥 400（两参同在＝chat_param_invalid）。
