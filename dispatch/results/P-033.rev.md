## 发现

### blocker

- **B1 四相位外表审批「批准恢复」路由缺边——批准即 run 崩溃（实测复现）**。`_handle_choice` 四相位批准分支设 `next_intent=INTENT_PRECONDITION`（appv2/runtime/graph.py:1179），但该更新从 clarify 节点返回，`routes[NODE_CLARIFY]` 映射无 `INTENT_PRECONDITION` 键（graph.py:2516-2522；对照 routes[NODE_PRECONDITION]:2526 有此键）——langgraph 条件边按 path_map 查表，缺键抛 KeyError。本拍临时脚本实证：clarify 分解带 external_tables 子问题→前置条件机 blocked_ask（external_table_approval 帧）→waiting_ask 挂起正常→resume 批准→事件流收尾 `run 执行失败：'precondition'`（KeyError）。波及两条链：前置条件机越集审批恢复、批量执行引擎侧审批恢复（graph.py:2537 同经 clarify→_handle_choice）。A2 裁决落点（放行态→回前置条件机重判）的最后一跳断裂；零钉测覆盖该恢复全链（见 S5）。骨架程序闸自评称「四相位路由真跑」，审批恢复链不在真跑范围内——程序闸字面未破，实质链路有洞。修复：routes[NODE_CLARIFY] 增 `INTENT_PRECONDITION: NODE_PRECONDITION`（一行）＋图级恢复钉测。

### should

- **S1 闸数字报告失真**：回报称 1419 passed（dev.md:90-93「1419＝master 1400＋20 新钉−1 改型」），本拍复跑实测 **1420 passed, 108 skipped**（工作区＝fcd1093 干净树）。测试函数对账 660→680 恰 +20，且回报自认「改型测试函数数不变」——「−1 改型」算术自相矛盾，正确口径即 1400+20=1420。数字方向有利（多过 1 个）但 L0 清单第三节明示「数字对不上要解释」；回报数字须更正，防后续拍以错误基线对账。
- **S2 clarify 预算拒例外＝无界自旋洞**：预算驱动的 discover 拒不占轮（graph.py:1564-1565 `rnd = state.rounds if budget_reject else state.rounds + 1`）且被拒发射不耗发现预算（subtask.py:224-228 拒在执行前）——顽投模型每次自环零代价，唯一收敛面是 300s 时长闸。这与 SK2 无界自旋（215 次/5.38 元）同形，只是位置从 toolmatch 换到 clarify；「已由修正根除该形态」（dev.md 偏差 1）的声明对此路径不成立。建议：连续预算拒计数（≥2 次转占轮或确定性收敛/强制 decompose），与轮语义追认同窗落闸。
- **S3 恒真断言（假绿钉）**：test_v2_four_phase.py:506 `assert (answer_calls and "台账" in ...) or True`——恒真，名义锁「消息历史簿记主干在场」实际零约束。应改为真断言或删除该行（端到端钉其余断言扎实，不涉假绿主体）。
- **S4 R1「双证」强度弱于红线措辞**：AST 钉只查 ast.Attribute 调用形（`x.complete()`），裸名调用 `complete(...)` 漏检；且只扫 precondition/ledger/subtask 三个直接文件，红线措辞「及其传递依赖」未机检（ledger.py→handlers→query/retrieval 引擎面靠人查，本拍 import 面核对确无 LLM 通道）。建议补 import 闭包契约（lint-imports 或 AST 递归扫描）把传递依赖锁进机器闸。
- **S5 审批恢复全链零图级钉测**：B1 得以漏网正在于此——现有外表钉全是单元钉（judge 纯函数 test:357-371、_ctx_of 接线 test:386-394），挂起恢复钉只覆盖 clarify 反问帧（test:511-598），「越集审批→批准→重判→批量续跑」无全链钉。续作必须补（连同 B1 修复），并顺带覆盖批量引擎审批帧恢复。
