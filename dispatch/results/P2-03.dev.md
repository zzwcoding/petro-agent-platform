## token 增量估算（票面要求随票评估，不阻塞）

- 机理：生成窗席位 4→6，**单条材料宽度不变**（P1F-04 已扩 1024 字符/条＝`kb/domain.py:85 SMART_MAX_CHARS`，本票不叠加变化）。材料表行形状 `cN：[kind] label——snippet`。
- 增量只发生在**满窗 query**（证据数触上限时）：多送 ≤2 行——
  - 报告类行（大头）：每行 ≤ ref/kind/label 开销 ~56 字符＋snippet ≤1024 字符 → 增量上限 2×~1080 ≈ **2160 字符/次**；
  - 台账类行（满分档短材料：FAQ answer[:80]／@ 锚定直取名，通常 ≤100 字符）——台账池超 2 支时才会多送，量级可忽略。
- 按 GLM 族中文分词 ~0.6–1 token/字符折算：**约 +1300~2200 token/次**（上限估计；典型片段不满 1024 字符，实际多在 +600~1500 区间）。相对满窗 prompt（4 行 ×1024 ≈ 4.3K 字符 ≈ 3~4K token）增幅约 **+30%~50%（上限口径）**；证据 ≤4 支的 query（不触截断）**零增量**。
- 兜底提示：S7 权威回读/fail-closed 等下游面按行遍历，行数 +2 无额外模型调用；模型调用次数不变（GEN 序号不增）。
