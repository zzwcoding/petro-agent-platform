# ADR-0003 · LLM 调用并发模型：单实例 asyncio＋全局闸，不上消息队列，预留 RunCommand seam

- 日期：2026-10-08
- 背景：V2 loop 为多步长过程，Owner 提出是否需要消息队列消费模型避免 LLM 调用并发问题。
- 拆问题结论：
  1. 多任务并发——V1 gateway `_DynamicGate` 全局并发闸＋预算熔断原样复制，无需队列；
  2. loop 内 LLM 调用天然串行（步间数据依赖），无任务内并发冲突；每步超时防挂死拖垮事件循环；
  3. 长过程——waiting_ask 事件流收束＋checkpointer 落库，不占连接/进程；断线凭 run 态随时回看；
  4. 崩溃恢复——LangGraph checkpointer 每步落 PG＋重启清扫器。
- 决策：**本期单实例 asyncio＋全局闸，不上 MQ**。理由：书"最低充分架构"——队列的真触发条件是
  跨进程水平扩展/升级不打断在跑任务；一上队列须连带执行租约/围栏/幂等等一整套复杂度，本期量级不值。
- 预留接缝：runtime 以 RunCommand（ask/resume）→执行器→RunEvent 流建模，命令入口与执行器之间
  为显式 seam；将来水平扩展时执行器换 Redis Stream 消费者，api/tools/事件契约零改动
  （书：编排层与 Runtime 解耦，接口是任务与状态）。
- 反转条件（出现任一即回审本决策）：① 双实例部署需求出现；② 单实例 LLM 并发排队 P99 > 60s；
  ③ 在跑任务要求跨升级存活。
