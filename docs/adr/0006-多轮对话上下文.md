# ADR-0006 · ReAct 循环真多轮对话化（消息历史簿记进上下文）

状态: accepted（Owner 2026-10-09 拍板）
关联: ADR-0004（ReAct 重构）/ADR-0005（子任务图）/V2-37/V2-38/V2-34

## 背景与证据（为什么伪多轮不行）

V2-31 ReAct 骨架的每步模型调用是**全新两条消息**（system＋user，
`appv2/runtime/context.py:114-117`）——run 状态被重新序列化进单条 user 消息，
模型看不到自己此前的决策与执行，只看得见"观察材料有没有变多"。两个实证病灶：

1. **执行历史不在上下文**：context 只有 问题/理解/观察材料/任务 四段
   （`context.py:108-113`），"已用哪些参数查过、结果如何"无簿记。
2. **被拒尝试彻底消失**：闸拒路径只发 notice（`graph.py:1034-1045`），notice 类
   又被过滤出模型面（`context.py:82-86`）——被拒因是决策必需的负信息，却被抹除。
3. 后果实证：P-026 复测 16 题中 9 题**同参重复执行**烧满 3 轮预算——上下文逐字节
   不变，模型理性地重发同参。指南两轮警告到模型自律边界仍残余，因为指南在让模型
   "别做它没有记忆做过的事"。

## 决策（Owner 拍板原文精化）

**所有循环都必须做多轮对话，历史信息必须放入上下文**——包括 10 次 discover 的
小循环、3 轮的大循环，以及**后续用户在对话框的追问**（追问同样是多轮对话的一部分）。

落字三层：

1. **run 内消息历史簿记**：understand/decision/answer 的模型调用与输出、工具执行
   的参数与结果（含闸拒拒因，负信息如实落）、拒因回喂，全部作为消息轮次进历史；
   后续每步在完整历史上续写，不再每次重序列化。
2. **执行台账段**：每次执行以「参数 → 结果：N 行／闸拒（拒因）」形落在历史中——
   同参重投由模型自己避免，V2-37 机器闸降格为兜底而非主力。
3. **追问续会话**：用户在对话框追问＝会话线程上新的一轮——历史消息（含此前问答）
   随追问进上下文；run 生命期延展或会话线程承接（实现形态归 V2-38 票面）。

## 影响

- 新建 **V2-38（多轮对话上下文）**，排序在 V2-34 之前（同面 context.py，先立结构
  再叠词典层注入/前置条件机）。
- **V2-37 重定位**：decision 出口同参重投闸保留，定位从"主力修复"降为"确定性兜底"。
- 工程约束：历史增长须带 token 预算/截断策略（截断显式进 Manifest）；[n] 引标体系
  与 verify（INV-1）语义不变；剧本 ScriptedCompleter 按消息历史形态重写。

## 被否方案

- 维持伪多轮＋加机器闸：闸拦得住同参拦不住"变参空转"，病灶在记忆不在纪律。
- 只加执行台账段不做追问线程：Owner 拍板明确追问同属多轮对话，一次做齐。
