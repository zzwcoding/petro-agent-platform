## ① 边界与用户

**做什么**：`appV2/` 新建 Data Agent 后端——一次提问进入一个**有界 agent loop**
（理解→规划→工具调用→观察→核验→阐述），LLM 是推理主控，执行全走确定性工具；
本体台账（指标/术语/对象/关系/族）以 Knowledge Evidence 形态被 agent 现场消费；
每次模型调用留 Context Manifest；答案 fail-closed 引用、矛盾分源列明。
**不做什么**（本期）：不动 `app/` 任何文件；不做自进化闭环（经验库/data loop）；
不做 Memory 体系；不改入库/切块/抽取链（复用 V1）；治理管控面沿用 V1。
**用户/调用方**：平台用户（X-Dev-User 身份桩），经 Web 问一问入口或 API。
**成功标准**：97 题回归集 V2 跑分不低于 V1（Q11 基线 52✅/35⚠️/10❌），且
病灶清单 TOP4（路由翻面/生成窗截断虚答/同型张冠李戴/本体低利用）逐条清零或登记。

## ② 业务对象与关系 `[AI自动补全]`（复用 V1 本体资产，V2 不重建模）

- 本体元素：指标/术语/对象/关系/族标注（sem_* 台账，ontology/ 真源）——身份＝元素 ID。
- 数据：agg 三表（dim_well/dim_date/fct_daily_metering）＋湖表——身份＝(well_id, prod_date)。
- 文档：库/报告/片段——身份＝fragment_id，出处链 fragment→report→library。
- 任务态：run（一次提问的执行）→ steps（loop 步）→ plan（计划）→ observations（工具结果）→ answer（带引用答案）。
- 关系：答案—引用→片段/台账行/表；计划—绑定→指标槽/时间窗；run—归属→用户。

## ③ 功能与规则

- **Agent loop**（核心）：一轮＝四相位——业务澄清（LLM＋只读钻取，发射带台账注释的
  问题组）→工具匹配（子问题→工具/链）→前置条件机（纯固定代码逐子问题判四态）→
  批量执行＋汇总核验；有界：每用户输入周期 ≤3 轮失败子集回炉、钻取全程 ≤10 次、
  总时长/单工具超时，收敛必达。
- **工具清单**（全只读）：`semantic_query`（查本体台账，返 Evidence）／`data_query`
  （V1 六站链降格，输入计划返权威表＋血缘）／`doc_retrieve`（V1 S4 双路召回，矛盾同窗供给）／
  `graph_query`（图谱）。工具结果统一 Observation schema（值/来源/版本/时效/适用范围）。
- **不变量**（INV）：INV-1 无引用不给数（fail-closed citation，确定性校验）；
  INV-2 只读（无任何写工具，SQL 只读账号）；INV-3 用户筛选顶不掉权限谓词；
  INV-4 多来源矛盾必须分源列明或显式声明歧义，禁止无出处调和；
  INV-5 审计留痕（谁/何时/何输入/何输出/依据哪条口径）。
- 异常分支：缺参→反问帧（ASK）；无据→如实拒答；工具失败→分类重试/降级/拒答；
  loop 超界→收敛兜底（交付已核实部分＋明示未完成项）。

## ⑨ 异常与边界
