## 五、跨票实施顺序与依赖

1. **波 0**：`V2-113`（先拿干净观察面——EB12 可比；帧扩键待 L0 裁）→ `V2-116`（非本组，前置）。
2. **波 1（硬依赖链）**：`V2-119` → `V2-120`。**必须先后**：V2-120 逐字稿「对照下方子问题覆盖表」以 V2-119 的段存在为前提；反序＝合同指代悬空。
3. **波 2（同段串行）**：`V2-101` → `V2-121` → `V2-124提示词侧`。三票同改 `ANSWER_DRAFT_CONTRACT`（族⑤）：101 收紧首句 → 121 追加术语级出口 → 124 追加段尾推断句；一票一提交，后票 diff 只许追加、不许改写前票字面。
4. **波 3（族②串行）**：`V2-110` → `V2-111`。两票同改 `CLARIFY_EMISSION_CONTRACT`（族②），且 110 的「选项值可原样消费」是 111「ledger_notes 注明」的措辞前提。
5. **可并行**：`V2-109`（族⑥）与波 2／3 不同常量，可任一位置并行，但**须在 V2-101 之后**（101 改 `ANSWER_DRAFT_CONTRACT`、109 改 `ANSWER_REQUIREMENTS`，同属答案规章段，段序断言同批回归）。
6. **`V2-102` 不施工**（吸收销项）；`V2-96` 已 done，只作回归面。

## 六、需 L0 裁（本设计不自行裁量）

1. **V2-111 窄口的可执行性**：「报告库确无该井」在澄清相位无检索动作、无程序事实可判——是「模型自述确无」还是需编排提供检索事实？前者＝语义自证（可能复发误判），后者＝新增程序面（越本组边界）。
2. **V2-119 记号化单点**：票面要求「复用 verification 的记号化单点」，但 R1 禁相位互 import、R2 禁深层 import ⇒ `answering` **不能** import `verification.rules.number_tokens`。本设计暂用 `answering._numeric_anchor_tokens`（`:266`，既有单点）；是否把 `number_tokens` 下沉共享层（跨块重构）**需 L0 裁**。
3. **V2-113 帧扩键**：step 帧加 `payload` 动 `specs/transport.md` 帧闭世界——裁「扩帧」还是「runner 读落盘/黑匣子面」。
4. **V2-121 待核前提的列举面**：逐字稿只给**静态规章句**（零语义、程序可挂）；若 L0 要「逐条列出题面引述」，须另立语义抽取器（新程序面）。

## 七、两个最大风险

1. **族⑤/族② 同常量多票并发改写 ⇒ 字面漂移与单点破裂**：101／121／124 共改 `ANSWER_DRAFT_CONTRACT`，110／111 共改 `CLARIFY_EMISSION_CONTRACT`。合同文本单点纪律下，任何并行施工都会把后票 diff 建立在陈旧字面上（V2-80 系列「同一答案规则三处并维护」病灶同型）。对策＝§五 的串行序＋每票 diff 只许追加、`::contract_constants_no_duplicate_literals` 逐票复跑。
2. **V2-119 依赖的记号化单点被边界规则切断**：R1/R2 使「复用 verification 记号化」不可直接落地；若强行复制一份 tokenizer，即造出第二真源（数值比对域从此两套，核验面与覆盖信号可能互不一致）。对策＝本设计暂用 answering 既有 `_numeric_anchor_tokens` 并在 `specs/answering.md` 明写「覆盖面与核验面记号化暂不同源」的登记，或按 §六·2 由 L0 裁下沉方案后再动。
