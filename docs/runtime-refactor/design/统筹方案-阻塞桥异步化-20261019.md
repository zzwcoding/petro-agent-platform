## 一、现象与根因（已复现）

**现象**：3 并发跑批时，点击对话的 `GET /runs/{id}` 被阻塞 **4–11s**（静态资源始终 40ms，容器 CPU 近 **0%**）；停批后回到 ~45ms。

**根因**：六处「同步签名面 → 异步出口」的桥在**事件循环线程里同步等待**：

```python
with ThreadPoolExecutor(max_workers=1) as pool:
    return pool.submit(lambda: asyncio.run(awaitable)).result()   # ← 阻塞的是服务器环线程
```

| # | 桥 | 阻塞行 | 同步签名面 | 过桥时机 |
|---|---|---|---|---|
| 1 | `bookkeeping/closing.py` | `:283` | `call_model(...) -> str` | **每个相位的每次模型调用**（最贵：秒级） |
| 2 | `execution/core.py` | `:474` | `execute(state) -> ExecutionOutcome` | 每次工具派遣（`data_query`／`doc_retrieve`／`semantic_query`） |
| 3 | `query/pg_executor.py` | `:63` | `PgQueryExecutor.execute(plan)` | 取数 |
| 4 | `query/pg_waterline.py` | `:68` | `loader() -> WatermarkFace\|None` | 台账装载／水位 |
| 5 | `knowledge/pg_store.py` | `:58` | `KnowledgeStore.evidence/...` | 台账装载／语义查询 |
| 6 | `knowledge/pg_faq.py` | `:75` | `PgFaqStore.similar(question, top)` | FAQ 命中 |

**过桥频次 ≈12–17 次/run**（`doc_retrieve` 零桥）。规格里**本就登记了这个缺陷**：`specs/gateway_adapter.md:83` 行为 4「`async` 是硬要求……不得在事件循环内同步阻塞调用」＋`:129` 风险 2「同步桥阻塞事件循环」＋`specs/modules.md:605` 卡级修正①。

## 二、两案对照（**结论：A 案不是安全快修**）

| | A 案：调用点 offload（`asyncio.to_thread`） | B 案：六处同步面改 async（本方案） |
|---|---|---|
| 改动面 | 小-中（graph 节点＋handlers＋app 装配点） | 大（6 桥＋2 ABC＋20+ 调用点＋4 份 spec 接口行＋大批测试转 async） |
| **致命副作用** | ① 把 `EventBus` 拖进工作线程（`bus.py:96-105` future 在主环、`_wake` `set_result`；`execute` 内 `bus.emit`）⇒ **SSE 帧延迟/丢失、消费方挂起**；② 放大 **`_DynamicGate` 跨环唤醒**（`service.py:101-141` 无锁＋环亲和，生产跨环共享；并发 ≥3 时主环 waiter 被工作环 `set_result` ⇒ **整 run 挂死**）；③ `SecurityAuditSink` 无运行环即 `RuntimeError`（`app.py:100-101`）＋ `RunState` 跨线程读写竞争 | 无——帧/状态/门/审计**全在主环**；mypy strict 对漏 await 必红兜底 |
| 环绑定 | 安全（工作线程内 `asyncio.run`＋各自新建 `ConnectionManager`，按环分桶） | 安全，且**首次真实复用连接池**（须核 `pool_size/max_overflow`） |
| 结论 | **仅在「不碰帧/状态/审计/门」的纯读桥上安全** | **正解**，但属签名级变更（须 ADR） |

## 三、实施方案（三票，按「单次阻塞时长 × 频次」排序）

| 票 | 内容 | 为什么先做 | 前置 |
|---|---|---|---|
| **V2-143** | `call_model` 异步化（桥 #1）＋五相位调用点 `await` 化 | **最高价值**：每次 LLM 调用几秒 × 每 run 5–8 次，是 4–11s 阻塞的主因 | ADR（签名级） |
| **V2-144** | `execution.execute` 异步化（桥 #2）＋ graph 两节点 `await` | 工具派遣（含取数）；异步化后帧/状态仍在主环 | V2-143（同形范式先落） |
| **V2-145** | 四处纯读桥异步化（#3–#6）＋ handlers/ledger/app 调用点 | 收尾清零；四处均为纯读、风险最低 | V2-144 |
| 登记 | ①`_DynamicGate` 跨环安全——三票完成后所有 LLM/DB 回主环，**跨环消失**（须加「单环」看守用例）；②`SecurityAuditSink` 的环依赖随之消解；③`specs/gateway_adapter.md:129` 风险 2 收口 | 收口验证 | 三票 |

**共同纪律**：不改对外 HTTP 面；不新增依赖（用 stdlib）；每票自带「心跳不阻塞」机检＋反向判据；`tests/infra/test_v2_db_loop_scope.py` 两例恒绿。

## 五、验收（可机检，含反向判据）

- **心跳不阻塞**（单元）：`tests/infra/test_v2_bridge_nonblocking.py::test_in_loop_call_yields_event_loop`——5ms 心跳协程 + 被调协程 `sleep 0.1`，断言 `ticks >= 10`；**反向判据**：回退成 `pool.submit(...).result()` ⇒ `ticks <= 1` ⇒ 红。

- **门单环看守**：`::test_gate_no_cross_loop_wakeup`（三票完成后应天然绿）。
