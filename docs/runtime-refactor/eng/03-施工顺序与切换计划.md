## 一、依赖归并（从 17 卡依赖列推出）

依赖只引「本 17 块内部 + 已建好的平台层（`infra`／`tools` 公开面）」。归并后的依赖图（A → B 表示 A 依赖 B）：

```
orchestration → 七个相位 + persistence + transport + bookkeeping
answering     → context + prompts + gateway_adapter + state
understanding → gate + prompts + parsing + gateway_adapter + state
clarification → prompts + parsing + gateway_adapter + state
execution     → transport + state
tool_matching → state
preconditions → state
verification  → state
gate          → state
bookkeeping   → gateway_adapter + state
context       → state
parsing       → state
prompts       → state
transport     → state
persistence   → state
gateway_adapter → infra
state         → infra
```

**两个结构事实**：① `state` 是唯一被全体依赖的块（R4 防环已入闸）；② 七个业务相位**互相零依赖**（R1 禁互引）——它们之间没有施工先后约束，先修谁纯粹是走查/测试网加厚顺序问题。

## 二、施工波序（五波，阶段 4 票序即此序）

| 波 | 块 | 为什么在这一波 | 本波出口判据 |
| --- | --- | --- | --- |
| **W1** | `state` | 全体地基；53 字段重划（S5 字段矩阵是现成测试蓝本） | 字段读写矩阵逐字段在场；限额机制单点、数值只引预算表；R4 绿 |
| **W2** | `parsing` `prompts` `transport` `persistence` `gateway_adapter` | 纯件层，只依赖 state/infra；其中 **gateway_adapter 的测试替身（fake）是后续所有相位测试的地基**，必须最先可用 | 解析异常分支不静默；帧/游标单调；只追加可重放；模型出口唯一＋**替身可注入** |
| **W3** | `context` `bookkeeping` `gate` | 组合件，依赖 W2 的 gateway_adapter；bookkeeping 单写口是相位开发的共同依赖 | 每模型调用有 Manifest；写口无旁路（AST＋import 双证）；两道闸机械分派 |
| **W4** | 七个业务相位（understanding → clarification → tool_matching → preconditions → execution → answering → verification） | 互零依赖，**建议按业务链序施工**（便于走查 narrative 与测试网逐块加厚），不禁止并行 | 每相位配属规格十节版式定稿＋新规格钉绿＋触及该相位的特征钉绿 |
| **W5** | `orchestration` | 依赖全部相位＋persistence/transport/bookkeeping，天然最后 | 有界终止；挂起恢复；相位顺序只由本块决定 |

**纪律**：每波开工前该波块的规格必须先定稿（W4 的 7 块里 4 块已有/在途规格，其余块的规格覆盖模型＝**待 Owner 裁决题一**，见 `规划.md` §八-A）；每波收口述职材料＝特征钉＋新规格钉全绿。
