# 公共簿记块讲释（人类阅读版）

> **本文是派生视图，不是真源。** 真源＝`specs/bookkeeping.md`（已定稿）。
> 规格改，本文即废；本文与规格冲突，以规格为准。
> 日期：2026-10-16。写给人看——没跟过工程的人也能读懂；给机检看的断言一条都不在这里。

## 一、这块是干嘛的

一条问答流水线有很多工位（读题、选工具、查数、核验、作答……），每个工位都要往同一份运行状态里写东西：记一条「我做过什么」、往对话里加一句、记一条通知、写「下一步该去哪」。

如果每个工位都伸手直接改这份状态，很快就会出现「谁在什么时候改了哪一格」没人说得清的局面。**公共簿记块就是那个唯一的前台窗口**：所有工位要写东西，都到这一个窗口来办，窗口负责按规矩写好、记好账。它管的事包括：步记录与编号、对话链与对话层的追加、过程档案（`process_notes`，放工位指令与过程记录的摘要）、通知、超限收敛的落地、完成收口旁路、调模型的单一发起点、工具上下文装配、工具结果归一投影。

一句话概括它的定位：**多节点写同一份状态，只有这一个门口。**

一句话记住它：**状态只有一个写入窗口：谁要写都来找它，越界就拒。**

## 二、它和邻居怎么打交道

一句话：它的**运行逻辑只依赖两块**（状态块的形状与限额判定、网关桥的模型出口），**另借三块的「类型与常量形状」**（工具、存储归档、事件通路），然后**向所有相位提供写口**。

- **谁给它料**：
  - **状态块**：字段形状、材料清单、「超没超限」的判定结果、三族常量。
  - **网关桥块**：模型出口——本块只**发起**调用，不做重试退避那些实作细节。
  - **工具块**：只借「工具上下文」的类型与送窗预算公式（**不走它的行为面**，也就是不真去调工具）。
  - **存储归档块**：只借「步记录」的形状（**本块只产形状、不写库**）。
  - **事件通路块**：只借通知类型的闭世界常量（**本块只按闭世界记账，发帧归它**）。
- **它给谁用**：**全部相位与编排层**——它们经由本块的写口改状态，不许自己直写。
- **它不碰谁**：不引框架；不直引模型出口；不直引检索引擎；不落盘（不写库、不写文件）；不替模型做语义判断。
- **它在图里的位置**：

```
state（形状 + check_limits 判定）      gateway_adapter（complete 模型出口）
tools / persistence / transport（只借类型与常量）
        │
   bookkeeping（本文这块：唯一写口 + 收敛落地 + 收口旁路 + 调模型/工具面）
        │  写口
   ├─→ 各相位（只能经写口改状态；禁直写）
   └─→ orchestration（读 next_intent 决定跳转；失败收口）
```

## 三、关键行为逐个讲

规格的「行为约定」共 18 条。逐条翻译。

**行为 1｜写口单点。** 规格：全节点共享的可变写面（步记录／对话链／对话层／过程档案／通知）只经本块函数；相位不得直写这些字段。人话：这几格只有前台能改，工位自己不许动笔。规格还点明这条要覆盖到 `state.messages`／`steps`／`process_notes`／`notices`／`dialogue`／`next_intent` 六个字段。

**行为 2｜序号单调且与步记录成对。** 规格：`next_seq`＝已有步记录数＋1；取号在 `record_step` 内部完成——**禁调用方手加偏移**。人话：序号由窗口自己数，不许外面的人「我觉得该从第几条开始」自己跳着编。为什么：现状的手工偏移导致序号与步数可以不等，重写收正。

**行为 3｜步记录形状＝全字段且状态如实。** 规格：产出**七个字段**——`run_id`（自状态取，**不由调用方传**）＋`seq`＋`step`＋`status`＋`title`＋`manifest`＋`payload`；`status` 表达真实态（`ok`｜`failed`｜`refused`，显式入参）——**不得恒 `ok`**。人话：一条「我做过什么」的记录固定七格，案号由窗口盖（不让调用方自己填）；这步是成是败，要如实说，不许一律写「成功」。为什么：现状没有失败态表达面（恒 `ok`），规格把这条列为风险。

**行为 4｜`payload` 原样保真。** 规格：`payload` 直写（空 `{}` 照写 `{}`、缺省写缺省，**两者读回可区分**）；**禁 `payload or {}` 式假值归一**。人话：装东西的盒子是空的、和根本没有这个盒子，是两件事，不许糊成一件事。

**行为 5｜材料清单随步投影。** 规格：材料清单非空 → 以全键形式投影进步记录；为空 → 写空（**不得省略键**）。人话：有没有内容都要留着格子。

**行为 6｜路由意图的唯一写口＝本块。** 规格：`next_intent` 的取值必须 ∈ 路由意图闭世界（十值），越界即拒；各相位经这个入口给出意图，收敛与直答旁路两处由本块内部写；**「去哪」的决策仍在编排块**（路由表读该字段决定跳转——写字段≠做路由决策）。人话：窗口只负责把「想往哪走」写对格式，真正决定路线的是编排块；这两件事不许混。

**行为 7｜对话链只追加（钉，最高优先级）。** 规格：`append_message` **只追加、不改写**（不替换、不重排、不删除既有条目）。人话：聊过的话只能往后接，前面的字一个都不许动。术语：**钉**＝测试网上的一根桩，一条「无论如何不能破」的行为断言。

**行为 8｜相位合同一次性（钉写入面）。** 规格：合同标记的唯一写函数＝本块 `append_contract(state, phase)`；已标记相位再标记＝**幂等无操作**；越界相位抛错（合法相位只有三个：`decision`｜`clarify`｜`toolmatch`）。人话：给工位立的规矩那段文本每个工位只追加一次；重跑时窗口看到「已标记」就直接跳过，不重复追加。术语：**幂等**＝同一件事重复做，结果和做一次一样。为什么：规格记明这一条写入面原先**悬空无人认领**，本批由主窗裁定「谁写口谁拥有」归本块。

**行为 9｜对话层纯度。** 规格：对话层追加的 `origin`（来源标签）越界即拒；**过程内容（任务书／指令／注记）不得经该入口**——要写过程内容走过程档案那个入口。人话：对话层只装人和助手真正说的话；工位指令、任务书这类内容走另一个抽屉。`origin` 三个合法值和它跟角色的对应关系，真源在状态块规格（用户原话、助手终稿、澄清与审批回收原文三值）。

**行为 10｜过程档案有界且只追加。** 规格：过程档案在**写入点**截断摘要，只追加、不改写既有条目。人话：过程记录一进来就被截短（不要太长），而且只许往后加，不许回头改。**注意：截断上限的具体数字不在本规格里**（真源在别处），规格只认领「写入点截断、只追加」这件事。

**行为 11｜通知恰三键＋分型闭世界。** 规格：通知落 `{type, gates, content}` 恰三键；`type` ∈ 通知类型闭世界（二十九值，真源在事件通路块）、`gates` ⊆ `LimitHit.limit` 七限额键名（`rounds`／`discovers_per_round`／`executes_per_round`／`seconds`／`tool_timeout`／`discovers_per_run`／`ask_cap`——流水 52-B），越界即拒；只追加。人话：通知单固定三个格子；「是哪道闸拦的」只许填这七道闸的名字；通知只增不减。（2026-10-16 随规格改批同步：条数由二十二值改二十九值（流水 53-C）；`gates` 由旧两限额世界措辞改为七限额键名（流水 52-B），旧「`max_rounds`／`total_seconds`」两名为旧世界取值，已废。）

**行为 12｜触界收敛落地（幂等）。** 规格：收敛时先调状态块的限额判定；**命中** → 落地六键（`budget_hit` 追加命中项／通知追加如实注记／答案正文＝已取得材料逐条如实交付／`draft_kind="direct"`／`status="completed"`／`next_intent=answer`）；**未命中** → **零副作用**；**幂等**：已收敛（`budget_hit` 非空）再调 → 无操作（不重复追加通知、不重复追加 gates、不覆盖答案与状态）。人话：超限了就把六件事一次性办完，其中最重要的是「已经拿到的材料照实交付、没做完的照实说明」；没超限就什么都别做；已经办过的再办一次等于没办。术语：**收敛**＝预算到顶后的有界收尾，把事情按现有材料老实收掉，不是降级。

**行为 13｜收敛答案与通知材料面同源。** 规格：交付的正文材料与通知里的未完成项清单**取自同一材料面**（不存在两处漂移：答案说交付了 X、通知说未完成 X）。人话：同一份材料，不许一边说交了、一边说没交。

**行为 14｜完成收口旁路单点。** 规格：`direct_answer(state, text)` 恒写三键（`draft=text`／`draft_kind="direct"`／`next_intent=answer`）——拒答、闸拒、收敛转答、直答共用**同一出口**（免起草免核验）。人话：凡是「不查数、直接给结论」的路径（拒答、被安全闸拦下、超限转答、纯概念直答）都从同一个门走出去，写法固定三格。

**行为 15｜调模型单点（桥接）。** 规格：从状态取 `run_id` → 调网关桥 → **向节点只回 `content`**；**回执的用量与归因面（token／`cached_tokens`／`alias`／时长／`caller`／`run_id`）由本块记进步记录与材料清单**——**禁裸文本吞掉记账面**。人话：同一个门铃只按一次：干活的节点只拿到模型说的那句话；花了多少、谁花的，由前台另外记账，绝不能让「只有一句文本」把账目吞掉。

**行为 16｜工具上下文装配。** 规格：**身份只从状态取**（不接调用方传身份）；**外表放行态随上下文走**（不进工具参数、不重排计划）；送窗预算按**子问题数**取值。人话：装配工具箱时，「你是谁」必须从状态里读，不许调用方自己说；「哪些外表被放行」跟着上下文走，不许塞进工具参数里；送多少材料进窗口按子问题个数算。**注意：预算数值与公式的真源在别处（本规格不复述数值）**。

**行为 17｜结果归一投影。** 规格：逐字段**原样投影**（无增删改名）；**空值语义统一**——「有该字段但为空」与「无该字段」**读回可区分**（禁真假值归一）。人话：工具结果往标准化形状上搬时，一格都不许动；「空的」和「没有」必须分得清。

**行为 18｜本块零判断。** 规格：除调模型的转发与两侧闭世界分派外，无词表／正则语义判定。人话：前台只照章办事，不猜用户的意思。

## 四、施工时要注意的坑

- **合法降级路径＝无**：闭世界越界即抛错；收敛只做「有界终止」的如实交付，不是降级。
- **触界不静默**：注记必落且正文如实交付已取得材料（依据＝红线「不许静默」）。
- **记账不丢**：用量与归因面**必须**落到步记录／材料清单——「裸文本吞掉记账面」视为缺陷。
- **不许自述完成**：完成由程序侧判定（限额判定与核验结论），本块只**落地**别人给的结论。
- **依赖面窄但没有专属机器闸**：只有「运行逻辑依赖状态块与网关桥块；另三块只许借类型与常量（不调工具、不落盘、不发帧）；不落盘；相位禁旁路直写」这几条——都靠静态断言＋人审，别指望闸拦。
- **框架类型零出现**：旧码里「角色→框架消息类」的映射含框架类型，只许活在编排块；本块只做文本层的消息追加。
- **几处旧码函数不承接**（规格的承接对照表）：入口闸判定（归状态块＋编排／相位）、单工具超时结果构造（归执行块）、截断话术（属文本面，归澄清／作答块）、工具台账条目的措辞五形（归执行块，它决定写什么、本块只收定型条目）。特别地，一个旧的「user 消息构造单点」在旧码里**已零调用点**，重写**不承接该函数**。
- **收敛措辞不许写死**：现状的收敛文案前缀恒称「已取得材料未及核验」，与实际阶段不符——重写后正文**由材料面决定**、措辞随实际态；**若仍要固定前缀，属规格变更**。
- **已知未定／登记项（照实说：还没定）**：过程档案摘要的截断上限数字不在本规格（真源在别处）；工具送窗预算的数值与公式真源在别处；本块依赖白名单这一面**只登记待补**（静态断言＋人审）。
