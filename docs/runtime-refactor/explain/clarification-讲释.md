# 澄清块讲释（人类阅读版）

> **本文是派生视图，不是真源。** 真源＝`specs/clarification.md`（已定稿）。
> 规格改，本文即废；本文与规格冲突，以规格为准。
> 日期：2026-10-16。写给人看——没跟过工程的人也能读懂；给机检看的断言一条都不在这里。

## 一、这块是干嘛的

读题块定完「走全程」之后，问题还不能直接拿去查：「近三天的产量是多少」得先弄清是哪个指标、哪些井、时间段算不算得出来。**澄清块就是把读题结论变成「可执行的子问题清单」的那一块**——中间该探的去探（到资料里钻取），该问的问（向用户反问），最后定案交出一组子问题。

它做事的方式是全仓的通用分工：**四个动作由模型定，程序只做闭世界对账**。

- 四动作（**闭世界**，即合法取值只有这四个）：`discover`（钻取：先去台账／资料里找候选条目）｜`decompose`（拆题：把原问题拆成子问题）｜`ask`（反问：向用户提一张澄清卡）｜`finalize`（定案：确认材料够了，交出子问题清单）。**越界值判失败**（不猜、不取默认）。
- 程序只做三件机械事：动作在不在闭世界里、子问题条数在不在上限内、注释能不能在台账注入块里逐字找到。

有一个分工必须先记清：**`discover` 不在本块里直调工具**。本块只以「下一步意向＝discover」这个信道把它交出去，由编排块路由到发现步去真执行，结果再回到本相位。所以本块自己返回的结论只有三种，**单出口互斥**（一次调用只返回其中之一）：

- `ClarifyAsk`——反问卡，进挂起；
- `ClarifyFinal`——定案，带子问题清单；
- `ClarifyRejection`——结构化拒因，回喂模型重决策（不是终局）。

`discover` 不占这三个返回位。

它不管的事：不拦安全问题（门卫块的事）、不判废弃口径（工具匹配块里模型产出的事）、不选工具、不查数、不发请求。它只做「拆题、探料、反问、定案」四件事。

一句话记住它：**模型出四动作、程序只对账；拆题必带逐字台账注释。**

## 二、它和邻居怎么打交道

一句话：它**接住读题结论**，**通过统一窗口叫模型做四动作**，然后**把三种互斥结论之一**交回编排块。

- **谁给它料**：
  - **读题块**：读题结论（原问题、时间窗等结论）随状态传进来。
  - **状态块**：状态形状——`pending_ask`（挂起时那条反问的存根，随检查点一起走）与子问题列。
  - **提示词块**：澄清轮的指令与「**台账注入块**」（把台账条目注入给模型的那段文本）——只出文本。
  - **解析块**：把模型交回来的发射解析成结构化对象，并做闭世界 schema 对账。
- **它给谁用**：**编排块**——把 `discover` 路由出去执行、把 `ClarifyRejection` 回喂模型、承接 `ClarifyAsk` 的挂起与 `resume` 入口。
- **它不碰谁**：不直引模型出口（模型调用发起走公共簿记块的统一窗口，即「单点发起」纪律）；不引框架；不直引检索引擎（知识库／查询／检索三块）；不碰存储归档块。
- **它在图里的位置**：

```
读题结论
   │
 clarification（本文这块：四动作 + 反问挂起 + 覆盖校验）
   │
   ├─ ClarifyAsk ──────→ 反问卡 → 挂起（等用户）
   ├─ ClarifyFinal ────→ 子问题清单 → 工具匹配块
   └─ ClarifyRejection → 回喂模型，回本相位重决策
```

## 三、关键行为逐个讲

规格的「行为约定」共 19 条。逐条翻译：规格在说什么 → 人话 → 为什么（有依据才写，找不到依据就只讲行为）。

**行为 1｜四动作由模型出结构化发射，程序只做闭世界对账。** 规格：对账面＝动作／条数／注释／路线。人话：模型交回一份「我要干什么」的结构化结论，程序只核对这四个字段在不在规矩内，不替模型决定干什么。

**行为 2｜时间能确定就不许反问。** 规格：时间范围能从问句确定 → 不许反问，直接定范围（含引擎缺参反问的兜底），判断在模型侧产出，程序只按结论分派；**这条属模型侧策略，不入程序验收面**。人话：能读懂的时间，直接定下来，别问用户；程序不自己判断「能不能确定」，只照模型的结论办事。

**行为 3｜没有时间词就默认「近 30 天」并注记。** 规格：无时间词 → 默认「近 30 天」并注记。人话：用户没说时间段，就按近 30 天去查，但要在过程里如实标注「这是默认来的」。

**行为 4｜口径不给默认。** 规格：口径有歧义 → 反问，不交模型猜。人话：同样的词可能指两种口径（比如问的是哪套统计标准），这种必须问用户，模型不许自行选一个。

**行为 5｜先探后问是首选策略（模型侧，不入程序验收面）。** 规格：模型先 `discover` 出候选，再带着候选去反问；程序侧只做闭世界 schema 对账，不验收该策略。人话：反问时最好手上已经有候选清单，让用户选比让用户空想好答；但程序不为「有没有先探」打分。

**行为 6｜台账全量每轮注入。** 规格：词典层小、利于前缀缓存；**词典层变大即转按需检索——阈值待定、暂以全量注入为唯一现行为**。人话：现在每轮都把整份台账塞给模型（台账不大，整份给反而让模型的前缀缓存命中得更好）；**将来台账长大了改「按需检索」的那个阈值，还没定**。

**行为 7｜封顶数值一律引限额真源，不写字面值。** 规格：子问题条数上限、连续反问次数上限、发现次数上限、返工轮次上限（回炉一次）——本规格不写字面值。人话：所有「最多几次」的数只有一处真源，本块只引用不复制；其中「子问题条数上限」在限额那两处真源里都没单列，数值真源另在「澄清-分解问题」那节。

**行为 8｜注释按三段槽位对账。** 规格：`ledger_notes` 必填非空，形＝`槽位｜绑定态｜窗`；段一（槽位）须**逐字** ∈ 台账名录（指标/对象/关系/术语名）**或**＝「无台账命中」（本子问题**无台账行可锚**——knowledge 链报告内容题常态，如「完井液密度」本无台账行；此形只免锚台账行，段二段三照验，**自造名不算**），段二（绑定态）∈ `已绑定`／`未绑定`，段三（窗）＝锚定窗或「窗未定」（同义形「无时间窗」同收）或双 null 发射形——任一段不过即判违约、拒因回喂且指明哪一段哪个值为什么（不做语义改写、不摘要、不自动修补）；该拒因载荷自带整套回喂壳体（头行「上次发射被拒：…」＋尾行），回喂条原样透传、不再套壳（壳恰一遍）。人话：每条子问题附的注释是「属于台账的名字｜绑定没绑定｜问的时间窗」三段；名字要一字不差地是台账里那个名字（不许自己改写或压缩）——**只有这个问题本来就不落在台账上（报告里的事实题）才写「无台账命中」**，自己编的名字不算；绑定态和时间窗也各按固定几种写法填——程序逐段对账，填得不对就退回来说清楚哪里不对，不替模型改。

**行为 9｜覆盖校验交模型。** 规格：拆完后由模型自证「子问题合起来覆盖原题」；程序只校格式，不拿词表猜覆盖。人话：拆得全不全，由模型自己负责声明；程序不去猜「有没有漏」。

**行为 10｜子问题之间无依赖。** 规格：`Subtask` 不含依赖字段，子问题独立并行。人话：拆出来的子问题地位平等，没有先后依赖，可以同时查。

**行为 11｜反问卡合并。** 规格：同一轮里多处歧义 → 合并成一张卡一次问清（反对逐条追问）。人话：一次能问清的都放进同一张卡，别一个问题一个弹窗。

**行为 12｜挂起语义。** 规格：等待**不计轮、不计时**；`resume` **重置轮预算**；用户所选的**原话进对话链**（去系统前缀）。人话：挂着等用户回答的时间不算进预算；用户回来继续时，轮预算从头算；用户点选的原文照实进对话记录。

**行为 13｜恢复时重取易变量。** 规格：恢复时对「等待期间可能变了的量」（数据水位／新鲜度／地基／落库新数据）重取一遍。人话：用户去喝杯咖啡回来，期间数据可能已经更新了——恢复时要重新核对这几个活的东西，不能拿挂起前的旧结论接着跑。

**行为 14｜挂起不设超时。** 规格：无限等，记录为已知选择。人话：用户不回答就一直等着，不设过期时间——这是有意识的取舍，不是漏做。

**行为 15｜到顶不环。** 规格：连续反问到上限 → 截断 ＋ 带已取得材料如实直答（不继续环）。人话：澄清问到上限就别再问了，把已经拿到的材料整理成答案给用户，并说明还有没问到的部分。

**行为 16｜发射判据。** 规格：`ask` 仅限**两种白场**（阈值判断形的口径反问／目标-对象-口径真歧义）——属模型侧策略，由 Skill 指南承载，程序不验收、不做语义判断；**台账命中且时间窗已定 → 禁再 `discover`**（机械半句，程序可验收）。人话：只有两种情形值得反问；另外「台账里已经有、时间窗也定了」时不许再去重复钻取——这条程序可以机械地验收。

**行为 17｜定案前的合法性闸。** 规格：判「材料足够」直答收口的前置＝**窗内非 notice 实质观察数 ≥1**（faq 命中卡／台账条目卡／检索片段；**空手探查**——未命中 notice／工具失败／零观察——不算数）；零则回喂拒因「零实质观察禁定稿」，**不得直答收口**。程序侧只数观察数（纯结构判定，零语义判断）。人话：模型说「材料够了，我直接答」之前，必须先真拿到过实质材料；什么都没捞到就想收口，程序直接驳回——这是纯数数的机械闸，不是猜意思。术语：「**notice**」＝一条系统通知（比如「没找到」这类说明），不算实质材料。

**行为 18｜定案被打回时，拒因必须带三段带路。** 规格：`finalize` 被拒时，拒因载荷必带**三段拼装文本**（机器已知事实说全、**零模型调用**），段缺则跳、「；」连接成单段文本：

- ①有绑定拒／台账外形的前置判定 →「该指标材料走报告检索：分解时 chain=knowledge、tool=doc_retrieve」；
- ②已空手探查清单 →「已空手探查：{tools}——禁再试同名同参」；
- ③兜底句**恒在**「先 discover 取得条目（精确名单词），或 decompose 分解走 doc_retrieve 检索执行。」

人话：模型定案被驳回时不能只甩一句「不行」，要把「为什么不行、已经试过什么、接下来走哪条路」三段话拼好交给它——这三段由机器已知的事实拼成，不额外叫一次模型。

**行为 19｜解析拒文变结构化拒因，归本块做。** 规格：解析块产出的拒文是纯字符串，把它转成 `ClarifyRejection` 归本块（消费方）：字符串逐字填进拒因字段、再映射成拒因枚举，纯机械适配、零语义判断；解析块不感知本块类型。人话：解析块只管说「这里不合格式」；把这句话翻译成本块的拒因结构这件事，由收这一头的本块来做。

## 四、施工时要注意的坑

（以下是规格红线、风险与登记项的口语版。数字、上限、闭世界取值逐字不动。）

- **合法降级路径：无**——本块不自降级。
- **截断、挂起、拒因回喂都必须产生机读信号**：反问帧／`pending_ask`／步载荷里的拒因字段／notice 各就各位。
- **到顶截断不得静默**：必须带已取得材料交付，并明示未完成项。
- **框架零接触**：本块不引入任何框架；`langgraph`／`langchain` 只许活在编排块（机器闸守）。
- **模型调用不许旁路**：发起只走公共簿记块的统一窗口（单点发起），不得自建模型客户端、不得绕过它直连上游；唯一出口仍是网关适配块，本块不直引它。
- **程序不判语义**：不许出现词表／正则式语义判断（机器扫源码）。**豁免面＝形态处理**——「逐字子串校」与「集合成员判定」不算语义词表／正则。
- **封顶数值不许复制进实现**：限额数值只从真源读；检测手段＝限额常量单点测试。
- **覆盖校验滑成程序判** → 违总纪律；判据只留在模型侧。
- **恢复重取漏项** → 会拿旧数据交付；重取清单（水位／新鲜度／地基／落库新数据）要照做。
- **还没定／登记在案的事**：
  - **词典层「全量注入」转「按需检索」的阈值：还没定**，暂以全量注入为唯一现行为。
  - **子问题条数上限**：限额那两处真源均未单列，数值真源在「澄清-分解问题」那节；本规格不复制字面值。
  - **挂起不设超时**：无限等是记录在案的已知选择，不是缺陷。
  - **收窄口径外的发射判据**（两种白场）与「先探后问」属模型侧策略，程序不验收——验收表里只落「分派形」，不落判断本身。
