# 批量执行块讲释（人类阅读版）

> **本文是派生视图，不是真源。** 真源＝`specs/execution.md`（已定稿）。
> 规格改，本文即废；本文与规格冲突，以规格为准。
> 日期：2026-10-16。写给人看——没跟过工程的人也能读懂；给机检看的断言一条都不在这里。

## 一、这块是干嘛的

过闸放行的子问题，终于可以真去查了。**批量执行块是「真干活」的那一块**：把一组子问题拿工具去查数／搜报告，把结果收成**带出处的观察**。

它的行为特征一句话：**只读并行、成功不重跑、失败只重做失败的**。

- **只读并行**：本平台全部工具只读、没有副作用，所以并行安全，一批子问题可以同时开工。
- **成功不重跑**：已经查成功的子问题（指纹命中，即「这个输入以前跑过」），不再发一次工具调用。
- **失败只重做失败的**：失败的按类别处理，只把**可重试**的那一档重跑，成功结果保留。

它产出的每条结果分两层记：

- `exec_status`——**执行状态**（`ok`｜`failed`｜`need_input`，闭世界三值），讲的是「这次调用跑成什么样」；
- `answered`——**是否真拿到答案**（这是业务面），判据是**可观察事实**：该子问题**是否拿到非空观察**（观察内容非空，或大结果引用存在）。

这两个**分开记**，`exec_status="ok"` 不等于 `answered=True`——跑成功了但什么都没捞到，是可能的。

一句话记住它：**要么拿到观察、要么如实记失败——只重跑可重试的。**

## 二、它和邻居怎么打交道

一句话：它**接一组过闸的子问题**，**只经工具公开面去调工具**，然后**交回带出处的观察与逐子问题执行结论**。

- **谁给它料**：
  - **前置检查块**：三态放行的子问题（`refuse` 的那档＝终局，不回炉）。
  - **状态块**：执行状态、观察序列、指纹簿记的状态形状。
  - **工具块**：统一的调用出口——本块只消费它的公开面。
  - **存储归档块**：大结果**原文落引用**的落盘面——本块只经它的公开面落引用，不自行写库。
- **它给谁用**：
  - **传输块**：本块发 `tool`／`observation` 事件，走传输块发帧。
  - **核验块／作答块**：观察是答案与核验的原料。
  - **编排块**：消费执行结论决定回炉与收口。
- **它不碰谁**：**不调模型**（本块属零 LLM 面）；不直引模型出口；不引框架；不直引任何引擎。

## 三、关键行为逐个讲

规格的「行为约定」共 14 条。

**行为 1｜只读子问题并行执行，观察编号与执行顺序解耦。** 规格：执行顺序不影响观察编号——编号按子问题定序分配（同一输入两次运行得同一编号）。人话：一批子问题同时跑，谁先跑完无所谓；但观察的序号按子问题本身的次序发，跑到第几遍都是同一套编号。

**行为 2｜成功不重跑。** 规格：已成功的子问题（指纹簿记命中）不重发工具调用。人话：查过且查成的，别再花一次时间和钱重查。

**行为 3｜失败分类写明文，只重跑可重试的。** 规格：`retryable`（超时／上游抖动／限流）｜`bad_args`（参数错，可回炉「修参」）｜`refused`（**前置闸拒**——拒＝终局、不回炉）；**只重跑 `retryable`**（附拒因），成功结果保留。人话：三类失败分开记——网络抖了可以重试，参数写错要改参，前置检查拒了就是真的不该查；注意这里有个容易混的地方：**前置闸拒是终局**，而编排主链里「绑定闸拒＝换链回炉」是**另一码事**（绑定闸拒**不落本档**）。

**行为 4｜大结果落引用（不是一刀切截断）。** 规格：超过阈值的原文**落存储归档块**——**替代**旧的「渲染帽裁剪」做法。行集题交付与落引用界线（与作答块行为 12 同一规则、逐字一致）：**行集题**（明细行集类：问句要求明细／排名／列举全行集）**全量交付为默认**——引擎返回的全部数据行逐行交付、**丢行＝0**；非行集大结果超阈才落引用（窗口只留摘要＋稳定引用＋行数），**截断与落引用必披露**。**阈值数值阶段 5 待定**（随真机数据定），但行为归属与披露义务现在就定死：**行集题不得因落引用而丢行**。人话：明细表这种全要的题，必须一行不落地交出去；只有那些又大又不是明细的结果，才只在窗口里留摘要和引用，而且必须明说「截了」。

**行为 5｜执行状态与是否真答上分开记。** 规格：`exec_status` 与 `answered` 分别落账；`answered` 的判据＝可观察事实（是否拿到非空观察），这是**结构判定**；「答案对不对／好不好」归核验块。人话：跑没跑成、有没有捞到东西，是两件事，各自记账；判断「这东西够不够用」不是本块的事。

**行为 6｜缺参就挂起等用户。** 规格：工具报缺参时该子问题 `exec_status="need_input"` 并挂起；恢复时**重取易变环境量**（等待期间可能变了的量必须重校验），**不重放已完成的部分**。人话：工具说「还差个参数」，就停下等用户；用户回来时把可能已经变了的环境量重新核对一遍，但已经查好的不要重复查。

**行为 7｜每次记账。** 规格：每次工具调用记参数／回来多少行／或被拒原因（可事后复算）。人话：每次调用都留一笔账，事后能重新算一遍。

**行为 8｜缺位回捞。** 规格：执行后如发现子问题有缺位，按「**模型给出的缺位结论**」驱动回捞——**程序不拿词面判「相不相关」**，不静默留空。人话：发现漏了什么要补捞，按模型说的补；程序不许自己拿关键词猜「这条相不相关」。
这条与早先设计里的口径**有偏离**：原口径含一个 `recall_relevant` 词面门，按总纪律改掉了——**词面判断不许出现在程序里**。

**行为 9｜观察必带出处。** 规格：每个观察带 `source`（台账行／片段→报告→库／表名）；**缺出处＝判失败**。人话：每条观察都要说清是从哪来的，没出处等于不可查，直接判错。

**行为 10｜失败不炸整批。** 规格：任一子问题失败不阻断其余子问题的执行与回流。人话：一条挂了不影响别的继续跑。

**行为 11｜发现步归本块。** 规格：本块职责含「发现」——发现步的只读工具调用与 `tool` 事件的发射同属本块；发现步同样只经工具公开面、同受零 LLM 约束。人话：澄清块交出来的「去钻取一下」这件事，真正执行和发事件都在本块。

**行为 12｜落引用的单一责任方。** 规格：大结果落引用**由本块落**、存储归档块为**引用载体**；作答块**只消费引用、不重复落**。人话：大结果该落谁落由本块一个人负责，作答块拿到引用直接用，不许再落一遍。

**行为 13｜第一道闸：空手探查记指纹＋同参空手重发整发射拒。** 规格：探查空手（工具失败／`refused`／重试耗尽，或成功但本次新增非 notice 观察为 0）→ 记**同参指纹**（判定键＝工具名＋参数逐字 JSON——**参数改了＝新尝试，门开着**）；**同参空手重发在发射级整发射拒**（不执行工具、不占探查预算）；**首拒免轮、第 2 次起占轮**。人话：一次探查什么都没捞到，就把「拿这套工具加这套参数、结果是空的」记下来；下次模型又拿**一模一样的输入**来试，直接在发射口拦住——工具根本不跑，也不算进探查预算。第一次拦不占轮，连着第二次起就开始占轮（逼它收敛）。只要参数改了一个字，就是新尝试，放行。术语：「**空手**」＝什么都没捞到；「**指纹**」＝把输入固定成一把可比的钥匙。

**行为 14｜第二道闸：同参重投闸。** 规格：dispatch 工具调用前查同参指纹簿（指纹器材归解析块、指纹簿记字段归状态块）；**全支皆在实录＝拦**（拒因回喂模型重决策，**首拦免轮、连续第 2 次起占轮**）；**任一支新参＝放行**。人话：真发工具调用之前先查一遍账本：如果这次要投的每一项参数以前全都投过，就拦住并把理由退回模型；只要有任何一项是新的，就放行。
**两道闸勿混**（规格特意互引提醒）：空手闸记的是「空手指纹」，拦的是**同参空手重发**；重投闸查的是「发射支载荷指纹」，拦的是**同参重投**。一个管「又是空的」，一个管「完全照抄再来一遍」。

## 四、施工时要注意的坑

（以下是规格红线、风险与登记项的口语版。数字、上限、闭世界取值逐字不动。）

- **合法降级路径：无**——本块不自降级。
- **大结果落引用、失败、缺参都必须产生机读信号**：`observation`／`tool` 事件 ＋ 步载荷里的 `row_count`／`ref.handle`／`error.reason` 字段。
- **被落引用的原文不得静默丢弃**：引用必须**可寻址**（`handle` 能读回原文）——写了找不回就等于静默丢材料。
- **零 LLM 面**：本块不调模型、不存在模型调用发起面；**不得引模型出口块**（机器闸守）。
- **只经工具块公开面接触世界**；**大结果落引用只经存储归档块公开面**（不自行写库、不直连对象存储）——这一面**没有对应的边界闸**，降维成一条机器扫源码的断言「**不许出现直连符号**」（对象存储客户端／裸数据库驱动）。
- **不许自建工具调用旁路**、不许绕过工具块直引引擎。
- **程序不判语义**：不许出现词表／正则式语义判断（机器扫源码）。**豁免面＝形态处理／集合成员判定**。
- **别把 `answered` 当 `exec_status` 用**：两者分列字段、分别落账，否则核验与回炉的输入会失真。
- **并行别弄乱编号**：观察编号按子问题定序分配、与完成顺序解耦。
- **还没定／登记在案的事**：
  - **大结果「超阈值」的阈值数值：阶段 5 待定**（随真机数据定）；但**行集题全量交付、丢行＝0**这条现在就定死。
  - **两道闸的归属**：闸件本体不归本块（指纹器材归解析块、指纹簿记字段归状态块），本块只在发射／dispatch 口**被拦**；触发／拦截／回喂的实现不在本块，也不在本块验收表里。
  - **绑定闸拒是「换链回炉」那一面**，不落本块的失败分类档——两处别混。

## 五、一句话记住它

**要么拿到观察、要么如实记失败——只重跑可重试的。**
