# 解析与发射块讲释（人类阅读版）

> **本文是派生视图，不是真源。** 真源＝`specs/parsing.md`（已定稿）。
> 规格改，本文即废；本文与规格冲突，以规格为准。
> 日期：2026-10-16。写给人看——没跟过工程的人也能读懂；给机检看的断言一条都不在这里。

## 一、这块是干嘛的

模型交回来的东西，本质是一段**自由文本**。系统要往下走，就得把这段文本变成**有固定字段的数据**——哪个是问题、哪个是链、哪个是工具，一格一格装好。**解析与发射块就是干这个转换的那一块**：理解面、澄清面、工具匹配面三处模型应答的解析、发射格式的结构校验、子任务与问题组的载荷定型，另外还提供「同一次工具调用是不是又重复发了」的指纹计算器材。

术语：**发射**＝让模型输出一份规定的结构化内容（比如「按这个格式给出你的分解结果」）；**拒因**＝解析不通过时回给模型的说明文字（下一次好让它改对）；**定型载荷**＝装好格子的数据对象。

它的定位是**纯结构判定**：只查「字段在不在、类型对不对、取值在不在清单上、条数超没超」，**绝不做语义判断**（不猜「用户是不是提到这个指标」「要不要反问」——那些是模型的活）。

一句话记住它：**把模型的自由文本装进定型格子：不合格式就退回，绝不猜。**

## 二、它和邻居怎么打交道

一句话：它**只依赖状态块**（只读限额常量与指纹簿记字段的形状），**被三个业务相位消费**（理解／澄清／工具匹配，经统一包根）。

- **谁给它料**：调用方传进来的**原始文本**，加上调用方注入的限额参数（单次发现上限、全 run 剩余发现预算、子任务条数上限）。**本块源码不写任何裸的数值上限。**
- **它给谁用**：
  - **理解相位**：解析读题结果（合格给载荷、不合格给 `None`）。
  - **澄清相位**：解析分解动作（四种动作）与发现支，不合格给拒因文字回喂。
  - **工具匹配相位**：解析匹配结果并与问题组做「一一对应」对账，不合格给拒因文字回喂。
  - **执行面**：用本块的指纹器材做「同参重投」判断（注意：谁是**唯一**闸，见下面「还没定」那条）。
- **它不碰谁**：不调模型（连模型出口都不引用）；不判语义（「提及 vs 执行」的语义词表判断归模型侧产出，结论分派归前置条件块）；不做直答结构核验（归理解块）；不做拒因回喂与轮次记账（归调用方相位＋簿记块）；不渲染台账、不装配提示词；不执行工具；不解析旧版决策发射（随旧决策节点整体废弃）。
- **它在图里的位置**：

```
模型应答（原始文本） ──┐
调用方注入的限额参数 ──┴─→ parsing（本文这块：三面解析 + 定型载荷 + 拒因/指纹器材）
                              │ 经统一包根（消费方只引用，不复刻字面）
                              ├─→ understanding（合格 → 载荷；不合格 None → 抛解析错）
                              ├─→ clarification（不合格 → 拒因文字回喂）
                              ├─→ tool_matching（不合格 → 拒因文字回喂）
                              └─→ execution（指纹器材；闸的触发与拦截在它那边）
```

## 三、关键行为逐个讲

规格的「行为约定」共 18 条。逐条翻译。

**行为 1｜理解面＝统一 JSON 严格解析（V2 定案，Owner 直令）。** 规格：合格 → `Understanding`（`route="full"`）或 `Direct`（`route="direct"`）两形互斥；路由越界／缺必填字段／类型不符 → `None`（**不猜、不取默认、不做降级提取**）；旧的两行式形（行首「理解：／指标候选：」）与「直接回答：」行通道**不再受理**。人话：读题结果只认一种格式——一个规矩的 JSON；格式不对就交回「不合格」，绝不去文本里抠出个大概凑着用。为什么：旧代码干过「从回答里抠第一个花括号凑活用」这类降级提取，那是静默降级的源头；V2 由 Owner 直接下令退场。

**行为 2｜澄清面＝四动作闭世界＋分派。** 规格：动作合法值恰四个——`discover`｜`decompose`｜`ask`｜`finalize`；越界或缺失 → 拒因正文（回喂）；四支各自校验见行为 3–5，`finalize` 支**零载荷直通**（不读载荷）；`thought`／`note` 经字符串归一随定形携带（四动作通吃）；**载荷无键白名单**——动作之外的未知键**静默忽略**。人话：澄清这一轮的应答只有四种动作，各走各的检查；`finalize` 只管「收尾」不看别的；顺便带的思考与备注四支都能带；多出来的不认识的键不算错、直接忽略（这是现状事实，V2 不改）。

**行为 3｜问题组载荷校验（`decompose` 支）。** 规格：问题组须是对象；子问题须是**非空数组**；条数超上限 → 拒（**上限数值真源在别处**：统一预算表口径「子问题 ≤4」；**状态块的承载键还没落定**）；逐支按序过闸：支须对象／`id` 归一后非空且组内唯一／`question` 归一后非空／`ledger_notes` 归一后非空（**台账注释必带——本块是它唯一的机检点**）／`chain` 归一后非空时必须落在闭世界 `data`｜`knowledge`；**`tool` 键＝未知键静默丢弃**（Owner 裁决已让该键退场）；未知键一律静默丢弃。**本层不做**链与工具的一致性、链与载荷的配套校验（那归下一层，行为 6）。人话：分解出来的子问题逐条过体检；台账注释（`ledger_notes`）是必填项，而且**只有这里会检查它**。

**行为 4｜发现支校验＋预算闸。** 规格：发现须非空数组；支数超单次上限 → 拒；剩余预算不为空且支数超剩余 → **预算拒**——拒文以机读前缀「发现预算」开头；支须对象且含 `tool`（`tool` 的值本层不校验闭世界）；通过 → 逐支归一为 `{"tool": …, "args": …}` 形（`args` 缺省／假值归一空对象；**`args` 非对象＝拒**——拒文逐字「发现工具 {tool} 的 args 须为对象」）。人话：让模型「去看看有什么工具」的那一支，条数要过两道闸（单次上限＋整条运行的剩余预算）；超预算的拒文前面固定带「发现预算」四个字，好让程序一眼认出来；每支工具的参数必须是对象，不是对象就照这句原文拒。

**行为 5｜`ask` 支校验。** 规格：`ask` 须对象；`prompt` 归一后非空；`options` 非 list（缺失／None／标量）→ **归一为空列表**（随后按个数越界拒）；list 逐项字符串化去空白、空白项丢弃（**不去重**）；个数不在「2~4」→ 拒——拒文逐字「ask 缺 options 或个数越界（2~4 个选项）」。人话：反问用户的选项必须是 2 到 4 个；重复的选项**照样放行**（这是现状事实）；不合法就回那一句固定原文。

**行为 6｜工具匹配面＝闭合世界对账（恰一一对应）。** 规格：匹配须非空数组；逐支按序 fail-fast（一错即停）：支须对象／`id` 归一后非空／`id` 须在问题组 id 集合内（不在＝拒且拒文列全组 id）／`id` 组内不重复／`chain` 归一后 ∈ `data`｜`knowledge`／`tool` 非空且等于该链唯一工具（`data`→`data_query`、`knowledge`→`doc_retrieve`）／`data` 链的 `plan` 须对象且 `metric_slot` 非空／`knowledge` 链的 `retrieval_need` 须对象且 `question` 非空／`caliber_key` 经归一后做零值域校验再装载（真值才出键）；组内存在没见过的 id → 覆盖缺口拒（拒文列缺失 id 全量）；返回顺序＝**发射顺序**（不回排成组序）。人话：模型给每个子问题配一条方案，必须**一条不多一条不少**、链和工具必须配套（`data` 链只能配 `data_query`、`knowledge` 链只能配 `doc_retrieve`），少配的要把缺的 id 全列出来。**注意**：计划类字段的深形白名单（`ranking` 等）到底由谁补检——**两说待对账，还没定**。

**行为 7｜拒因正文＝机器拒因原文（迁移照抄，零改动）。** 规格：全部分支的拒因文本**逐字迁移、承载位换文本不变**；**逐字稿载体＝迁移前的现行代码字面**；施工以该字面照抄，**偏离即停**；机读甄别面恰一值＝前缀「发现预算」。人话：所有回给模型的拒因说明，都是一个字不改地从旧代码搬过来的——施工时以旧代码为逐字稿，不许自己改写措辞。**例外**：预算拒文里嵌的数字（以及 `ask` 的边界「2~4」）是**待裁项**——「照抄字面」与「把数字做成插槽」两种做法还没定，裁定后随批同步。

**行为 8｜拒因带定位。** 规格：提取失败时拒因要**带定位**拼装——无左花括号形含逐字提示「输出中没有任何以左花括号起始的 JSON 对象（检查是否漏了 JSON 外壳、只输出了围栏或解释文字）」；语法坏点形含异常消息＋绝对坏点字符序（「（约第 {bad} 字符）」形）＋坏点前后窗原文＋逐字修复指令「只修正语法错误，结构与其余内容照旧，重新输出一个 JSON。」，另含「常见原因：少写右括号或方括号、尾逗号、引号未闭合。」句与坏点窗帧句——**按旧代码相应行逐字照抄，不另誊**；**括号始终不平衡就退裸 fallback（零定位）**（这是现状事实）；「括号失衡也给定位」要不要做**需另裁，本块不自行裁量**。人话：模型输出格式坏了的时候，回给它的说明要指出「坏在第几个字符附近、前后长什么样」，好让它自己修；但括号一直不闭合这种情况现在不给定位。「本块不自行裁量」＝这条边界不许施工者自己拍板。

**行为 9｜提取单点＝首个花括号平衡块。** 规格：只读第一个块、首块坏即 `None`（不续扫后面的块）；深度归零处切片交给 JSON 解析；成功且顶层是对象 → 返回对象；无左花括号／括号未平衡／顶层不是对象 → `None`。两处发射面共用同一件（单点）。人话：从文本里找第一个「括号配平的 JSON 块」作为唯一提取对象，它坏了就直接判不合格，不许去翻后面还有没有别的块。

**行为 10｜引号自修＝确定性纯字符处理。** 规格：逐字符在「串内／串外」两态扫描；串内的反斜杠连同后一个字符原样带过（转义序列不误伤）；串内遇到 `"` 且其后（跳过空白）首字符**不**属于 `,` `}` `]` `:` 这个结构集 → 认定是值里的裸引号，替换为「／」（该串内按出现次序开闭交替）、串态保持；属于结构集 → 结构引号原样；扫描完与原文相同（没病）→ `None`；有替换且**全文**可解析 → 返回修复文本；仍失败 → `None`（两种 `None` 不可区分——现状事实）。**受理编排**（解析被拒 → 自修一次 → 重解析 → 保留首次拒因＋受理标志）是本块单点（一个函数三处调用，不复制三份）；**理解面不受理自修**（现状事实：零调用点）；受理通知由调用方发。人话：模型偶尔会把引号写错（本该书里的引号写成了包装用的引号），程序用一套**纯字符规则**修一次——只修一次、修好就用、修不好就退回原来的拒因；读题结果不享受这个待遇（严格解析，直接判不合格）。

**行为 11｜载荷定型类＝旧字段表逐字迁移（一处 V2 定案退场）。** 规格：`Subtask{id, question, ledger_notes, chain=""}`（**`tool` 退场**）、`QuestionGroup{subtasks: 元组}`、`SubtaskMatch{id, chain, tool, plan=None, retrieval_need=None, caliber_key=""}`，另有旧版发射定形 `ClarifyEmission{kind, group=None, discovers=(), ask_prompt="", ask_options=(), thought="", note=""}`；全部 `frozen=True, slots=True`（即创建后不许再改的「读一次就锁死」对象）。投影规则逐字：`Subtask` 恒带三键、`chain` 是**真值**才出键；`QuestionGroup` 恒单键形（`subtasks` 数组）；`SubtaskMatch` 恒 `id`／`chain`／`tool`，`plan`／`retrieval_need` 非 None 才出键，`caliber_key` 真值才出；`ClarifyEmission` 恒 `action`，`thought`／`note` 真值才出，`group` 非 None 才出，`discovers` 非空才出，**`ask` 段以 `ask_prompt` 真假单点开闸**（只有 `ask_options` 有值时它静默消失——现状事实）。人话：这些数据对象的格子和「哪些格子空着就不写出来」的规则，全部一字不改照旧版搬过来。

**行为 12｜载荷类形状单点（消费面不重定义）。** 规格：五类（`Understanding`／`Direct`／`Subtask`／`QuestionGroup`／`SubtaskMatch`）的字段形状**物理定义点就是本块**（依据：函数签名里已经引用前两类，而本块又不许引用理解块）；`Understanding`／`Direct` 的字段集以理解块规格为准（`text`／`metric_candidates`／`route`），其余三类以本规格行为 11 字段表为准；三份消费方规格里**有两份**的「消费面视图」与本规格有差异，**登记待阶段 7 对账回改引用句**。人话：这几类数据的「形」只有一处定义（就在这里），消费方只能引用不能另立；有两份别的规格把它写得不一样，那两处还没改，等阶段 7 对账。

**行为 13｜指纹器材（同参重投闸的指纹面）。** 规格：载荷规范指纹＝键序归一（排序键）＋紧凑分隔符＋不转义非 ASCII 的 JSON 串；发现调用指纹＝`{"tool": 名, "args": 参}` 键序归一 JSON（**与前者归一规范不同**，两套各自保留、不跨面比较）；按支拆算＝单支单形（`plan` 支在前；两皆空 → 空元组；两支皆在 → 两值）；同参判定＝空元组 → 放行；全部支都在实录里 → 拦；任一支是新参 → 放行。**触发点与拦截／回喂归消费方**（本块只产纯函数）。人话：本块只负责算「这次调用跟以前那次是不是同一个指纹」；至于什么时候查、查到重复了怎么拦，是别的块的事。术语：**同参重投**＝用同样的参数又发一次同样的调用。

**行为 14｜纯结构判定。** 规格：本块全部判定＝存在性／类型／闭世界成员／计数／字符串归一／字符扫描——**零词表零正则语义判定**；豁免面＝形态处理（闭世界成员判定／字符串归一／字符扫描）。

**行为 15｜确定性纯函数。** 规格：同入参两次调用输出逐字相等；零 IO、零模型调用、零时钟、零随机、零事件发射、零状态写入。

**行为 16｜数字与上限单点（注入制）。** 规格：三个限额参数**由调用方注入、签名无缺省值**——单次发现上限与剩余发现预算取自状态块的限额键；子任务条数上限的**数值真源在别处**（统一预算表口径「子问题 ≤4」），但**状态块的承载键还没落定**；旧版签名里的裸默认值已随注入制消解；预算拒文里嵌的数值与 `ask` 边界「2~4」是否改成插槽＝**待裁**。人话：所有上限都由外面传进来，本块一个数字都不自己写——「不写裸数字」这条原来是旧代码的毛病。

**行为 17｜同类条目多次出现不静默覆盖。** 规格：重复 `id`（问题组支／匹配支）逐条拒；**JSON 里同一个键出现多次**（解析后取后者）这一形**真源未裁落点**——历史病灶（两行式同类行后覆盖前）已随行为 1 退场，退场后剩余的这个静默覆盖面**登记为疑点**，**本块不自行加严**。人话：同一个 id 出现两次要拒；但「同一个 JSON 键写了两遍」这种情况该怎么处理**还没定**，本块不许自己加码。

**行为 18｜共用件单点、消费方零副本。** 规格：两个发射面共用的提取件／拒因带定位件／引号自修件＋受理编排件，在运行期面内各恰一处定义；相位块里出现同形字面副本（自己写提取循环、自己写引号扫描）＝判失败。

## 四、施工时要注意的坑

- **合法降级路径＝无**：解析不降级——不合格就是三态返回（拒因正文／`None`），**不半成品、不静默丢格式内字段、不改写模型原文**（格式外的未知键按现状事实忽略）；固定 fallback 话**只作拒因前缀**，不作交付面的替代。
- **返回三态闭世界（全体解析成员统一口径）**：①定型载荷（合格）②拒因正文（`str`——机器拒因原文）③`None`（不合格的无回喂形）。**任何不在这三态内的返回形态（半成品载荷、部分字段、哨兵值、裸抛业务异常）＝判失败。**
- **错误契约**：本块不抛业务异常、不吞错——不合格一律走三态返回；**异常出口唯一**：理解相位把 `None` 转成解析错误。
- **机读信号（本块承诺面两处）**：①拒因正文恒非空（所有拒分支都返回字符串）；②预算拒前缀「发现预算」在场。**事件面信号**（比如引号自修受理的通知）＝调用方义务，本块零事件，**不冒充覆盖**。
- **本块零截断**：不改写／截断拒因与载荷内容；拒因里的坏点前后窗是设计内的明文摘录，不算静默截断。
- **只许引用状态块**：本块不感知运行状态机、不引其它运行期块、不直引旧码。**诚实声明覆盖面**：机器闸只拦了「禁引七个业务相位」这一半，**「禁引公共层其余块」那半面没有闸**——靠静态 import 扫描兜底，余下人审。**零模型调用**（连网关桥都不引用）也无专属闸，靠静态断言。
- **消费方向**：三个业务相位只许经统一包根引用本块，深层子模块算私有。
- **禁手写替代（解析单点）**：提取件／拒因带定位件／引号自修件在运行期面内各恰一处定义，禁在相位块另存副本（旧码曾把提取件搬家还留了个旧名字转发，这是病灶）。
- **卡与规格有一处分叉（L0 级、只登记不改）**：卡面给的返回形是初拟形（问题组容器单件），本块按旧版逐字迁移形（含四动作定形＋拒因）并把族成员展开成名单，且指纹器材四件＝卡面缺公开成员。**注意：规格头部写「已定稿」，而风险 1 又写「清零（卡面补录）前本规格不定稿」——两处口径需主窗对账**（见文末疑点登记）。
- **已知未定／登记项（照实说：还没定）**：
  - **预算拒文里的数值与 `ask` 边界「2~4」是否插槽化＝待裁**（现文取「保留旧版迁移字面」解，裁定后随批同步）。
  - **JSON 重复键那一形＝真源未裁落点**，本块不自行加严。
  - **子问题条数上限的承载键还没落定**（数值真源已定，状态块的键面待定）。
  - **计划类字段（`plan`）深形白名单与其余必填键（`ranking` 等）的补检归属待对账**（工具层参数校验 vs 匹配相位强校验，两说）。
  - 「括号失衡也给定位」要不要做**需另裁**。
  - 载荷类消费面**两份已定稿规格的类体与本规格差异待回改**（阶段 7 接口契约对账）。
  - 拒因从字符串转成消费方结构化拒因的**转换点已裁在消费方**；同参重投闸的**触发／拦截／回喂已裁归执行面**（本块只产指纹纯函数；注意执行面另有一个「空手探查闸」，两件闸勿混）。
  - 理解面的异常分工：本块只产 `None`，异常由理解块抛——理解块那边**待补一条输入半面**（登记）。
