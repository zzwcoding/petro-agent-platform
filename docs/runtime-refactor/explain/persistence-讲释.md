# 存储归档块讲释（人类阅读版）

> **本文是派生视图，不是真源。** 真源＝`specs/persistence.md`（已定稿）。
> 规格改，本文即废；本文与规格冲突，以规格为准。
> 日期：2026-10-16。写给人看——没跟过工程的人也能读懂；给机检看的断言一条都不在这里。

## 一、这块是干嘛的

系统回答一个问题的过程，如果只活在内存里，机器一重启、网一断，整件事就查不回来了。出了问题更没人知道「当时到底发生了什么」。

**存储归档块就是「记账、存档、留证据」的那一块。** 它负责五件事：①运行记录（这次问答的总体状态）②检查点（中途拍下的快照，断线重连靠它接着跑）③黑匣子（把运行经过的细节按顺序记下来，只能往后写）④审计留痕（谁、出于什么意图、干了什么、结果是什么）⑤大结果原文的存放凭据（查出来的一张大表放别处，这里只存一张「取件凭据」）。

有一条铁律：**业务数据（油田数据）零写入**——本块对业务数据表一个字都不写，所有写入都落在自己的簿记表里。术语：**簿记表**＝系统自己的记账表（前缀 `agent_v2_*`），跟用户的业务数据表是两码事；**只读边界**＝全部工具只读、数据库用只读账号＋白名单 Schema。

一句话记住它：**只记账不碰业务数据：黑匣子与审计只追加，出错就喊出来。**

## 二、它和邻居怎么打交道

一句话：它**向状态块问形状、向基础设施块要出入口**，然后**向下游交出存取入口**。

- **谁给它料**：①状态块——借「运行状态对象」的形状（读回时返回它）；②基础设施块——数据库会话、时钟、审计写口都只从它走。
- **它给谁用**：
  - **编排块**：用本块的框架无关入口做检查点存取，并且**不许直连表**——它把框架的检查点存取件「组合」在本块的五个行级读写口上。
  - **执行块**：大结果落引用时用本块的可寻址凭据；执行块产出的窗口侧材料条目里的 `handle` 与本块的凭据**同源同值**，直接喂进来就能取回原文。
  - **接口层（对外 API 块）**：长任务的分页／上限归它管，本块读口不改语义。
- **它不碰谁**：不引包里其它运行期块（只依赖状态块，引编排块就成环）；不碰框架（检查点存取件的框架类型只许活在编排块）；不碰模型出口；不碰检索引擎。
- **它在图里的位置**：

```
state（运行状态形状）
infra（数据库会话 / 时钟 / 审计出口）← 唯一出入口
   │
persistence（本文这块：落盘 + 读回 + 审计 + 引用载体）
   │
   ├─→ orchestration（组合检查点存取件，不直连表）
   ├─→ execution（大结果原文的取件凭据）
   └─→ api（分页 / 上限在此侧）
```

## 三、关键行为逐个讲

**行为 1｜三类落盘语义，逐类定死。** 规格：①运行记录＝按状态机**更新**（同一 run 一行）；②步记录＝**同键幂等**（`(run_id, seq)` 重复落盘不产生第二行，且内容等价才允许覆盖）；③黑匣子与审计＝**只追加**（既成行不得改写、不得删除）。人话：运行记录像档案卡（一人一张，随时更新）；步记录像考勤格（同一格重填要么不写、要么写一样的内容）；黑匣子和审计像账本（写过就是历史，不许涂改、不许撕页）。依据：这条挂在 Owner 裁决「只追加、不原地改」上。术语：**幂等**＝同一件事重复做，结果和做一次一样。

**行为 2｜状态机把守在本块。** 规格：运行记录的状态写入值必须 ∈ 运行状态四值闭世界；`waiting_ask → running` 是**唯一合法的「恢复」迁移方向**——这是结构约束，有现状先例；「该不该迁移」的决策仍在编排块。人话：本块只管「这个状态字合法吗、这个方向合法吗」，不管「现在到底该不该挪」。术语：`waiting_ask`＝在等用户答复的状态，`running`＝跑起来了。

**行为 3｜恢复可重放。** 规格：同一 run 两次读回得到等价的状态；读回不得产生副作用（不写盘）。人话：读档案不许把档案改动——只读就是只读。

**行为 4｜黑匣子只追加、首写为准。** 规格：每个 run 的归档**至多一次**；重复归档**不覆盖**并**如实记账**（幂等跳过＋机读信号）；跳过的落点＝该次调用的返回值／错误面——对已有归档的 run 再 `save` 就抛既定异常「已归档」，调用方据该异常记一条通知单，发帧由编排块协调。人话：黑匣子一次封存、不许重写；有人想再封一次，系统就明确报「已归档」，并且这次跳过要留下记录。

**行为 5｜审计四要素齐备。** 规格：每条审计记录必须给出**主体**（`who`；`scope` 是主体的范围细化——会话线程／子问题域，并入本项、不另立要素）／**意图**（`action`；`authorization` 是其授权依据——角色／审批单号，无则空串，并入本项、不另立要素）／**事实**（`facts`）／**结果**（`evidence`），缺项判失败。人话：审计四件事——谁、想干什么、干了什么、结果怎样；范围并进「谁」，授权并进「想干什么」，不许另立成第五、第六个要素。

**行为 6｜审计动作闭世界，计数只有一个口径。** 规格：`action` 取值 ∈ 七值闭世界，恒 `agent_v2.*` 前缀，越界抛错；**计数口径以「action 七值」为唯一真源**，分组说法不产生第二个数字，本规格不写类数。人话：动作清单只有七个，任何「分成几类」的说法都不许拿来当计数依据。规格还专门纠了一处旧账：编排规格原来写的「四事件」是现状陈旧口径（漏了「禁用词豁免留痕」），已就地改述；另一处的「六类」是方法粒度分组，同样不再当计数真源。

**行为 7｜业务数据零写入。** 规格：本块对业务表零写，所有写入落在 `agent_v2_*` 簿记表；测试用探针注入——任何对业务表的写入尝试判失败。

**行为 8｜步记录载荷原样保真。** 规格：`payload` 不做裁剪、不做假值归一（空 `{}` 与「无 payload」是两件事，读回必须可区分）；核验对账等机读字段必须能被读面机检；本块只负责原样落盘、原样读回。人话：当时是什么样，存进去就是什么样，读出来还得是什么样——「空的」和「没有」绝不许混成一回事。为什么：现状是把假值归一成「无」，语义就丢了，规格把这条列为风险。

**行为 9｜`run_id` 全盖章（落盘面）。** 规格：运行／步／黑匣子／审计四类记录都携 `run_id`，读回可按 `run_id` 聚合回同一 run；逐题账集合与落盘记录等值可对账（对账数据源＝逐题账的 run 号集合与跑批记录里的 run 号集合等值）。人话：四类账本每一条都盖同一个案号章，事后能按案号把散落的记录全拢到一起对账。

**行为 10｜引用载体可寻址。** 规格：`put_ref(blob)` 返回凭据；`read_ref(handle)` 返回**逐字节相同**的原文；凭据不可解析 → 抛错；载体实现（簿记表／对象存储）**阶段 5 定**，语义不随载体变。人话：存进去再取出来必须一个字节不差；凭据对不上就直接报错，不猜。

**行为 11｜黑匣子键白名单闭世界。** 规格：黑匣子记录的键必须落在白名单内；新增状态键必须同批入列，禁「白名单外偷偷进」。

**行为 12｜旧检查点／旧黑匣子如实读入（回放面）。** 规格：旧版本的黑匣子／检查点**回放**不抛错；旧 run 的对话通道**如实空显**，不得伪造补写。人话：翻旧档案不许崩，也不许替它补内容——没有就是没有。规格写明分工：状态字段的读入不炸与版本号如实归状态块；本块只断言**回放读口**这一面。

**行为 13｜截断必可见。** 规格与真源值逐字：审计 `facts` 摘要与黑匣子转写文本的截断必须留可见标记（不得静默截断）；审计 `facts` 摘要 **≤120 字符**（`SUMMARY_LIMIT=120`）；黑匣子单行摘要 **≤96 字符**、换行替换后按字符数计；分面截断 **title 30／60、digest 80、source 40**。人话：太长要截，但必须让读者看得见「这里被截过」，而且长度有硬上限，不许随便截。

**行为 14｜落盘失败 fail-closed。** 规格：写失败上抛、不吞错、不半写（同一记录要么落要么不落）；不留无声缺口；发帧的实施口是传输块、批次协调归编排块，本块只把错误如实抛出。术语：**fail-closed**＝出错就按失败处理并停住，绝不放行。为什么：依据是红线「不许静默」。

**行为 15｜本块零判断。** 规格：无词表／正则语义判定、无模型调用。

## 四、施工时要注意的坑

- **框架类型零出现**：检查点存取件需要框架类型，它归编排块（这是卡级澄清，已记施工流水）；本块只出框架无关的表与读写入口。
- **检查点三表的写操作必须全经本块五个行级口**：编排块的存取件**组合它、不直连表**（表主人是本块）；这条要 AST＋行为双证。
- **数据库／时间／审计的唯一出口**：DB 只经 `infra.db`、时间只经 `infra.clock`、审计只经 `security.audit`——规格明确说这三面**没有专属机器闸**，降维成静态断言＋人审；对应地，本块不许出现裸数据库会话构造、不许出现裸取当前时间、不许直连审计表写路径。
- **不引包内其它块**：只依赖状态块，引编排块即成环（这条也无专属闸，靠导入白名单＋人审）。
- **合法降级路径＝无**：存储不可用时 fail-closed 上抛，不产残缺记录、不静默丢弃；截断必留可见标记、归档跳过必留记账、写失败必上抛，三者都配机读信号。
- **审计不可改写**：既成审计行不得改、不得删（Owner 裁决「原始事实不可改写」），本块不提供任何改写入口。
- **不许自述完成**：完成判定（三态收口）由编排块决定，本块只如实落盘它给的终态。
- **已知未定／登记项（照实说：还没定）**：
  - `BlobRef` 的原文存放载体（簿记表／对象存储）**阶段 5 定**——本规格只写可寻址语义。
  - 步记录时间戳的语义在规格内定死为「**该记录末次落盘时间**」；**首次落库时间不可回溯**，若要首写时间须新增列（登记为阶段 5 可选项）。
  - 长 run 全量读**无分页**（现状无 limit）：本块读口不改语义，**分页／上限归接口层**——本条登记在接口块，本批不新增。
  - 建表双轨（幂等建表 vs 迁移脚本）靠人审，没有机器闸看守「两处同形」。
  - 现状遗留的疑点（黑匣子白名单两处不一致、指针对账缺口）按 Owner 令「不结旧账」**不逐条 triage**，重写只按白名单闭世界收口，历史疑点只作现状证据。

## 五、一句话记住它
