## 一、这块是干嘛的

工具和参数都配好之后，还不是马上就能去查。**前置检查块是「真去查之前的那一道固定检查站」**：每个子问题依次过一串**固定顺序**的检查，最后得出三种结论之一——

- `allow`（**放行**：可以去查了）；
- `refuse`（**拒答**：这个子问题如实告诉用户查不了／不能按这个口径查）；
- `ask`（**等用户**：需要用户先做一个选择，比如越集审批或口径反问）。

它的第一特征：**纯程序、零模型（零 LLM 铁律）**。判语义的那些事——「用户是提到旧名还是真要按旧口径出数」「口径对不对」「时间窗能不能确定」——**已经全部上移到工具匹配块，由模型产出结论**；本块只**接收结论、按固定规则机械分派**，自己不判语义。

第二特征：**判定序固定、命中即停**。一串检查按固定次序过，某一项命中就直接出结论，不再往下走。

一句话记住它：**查数前先过八道固定判定位：放行、拒答、或等用户。**

## 二、它和邻居怎么打交道

一句话：它**接一组配好工具的子问题**，**沿途要几样外部判定结果**，然后**交回每子问题一条三态结论**。

- **谁给它料**：
  - **工具匹配块**：语义类结论——归一后的指标名与口径、废弃词「提及 vs 执行」的结论、时间窗结论（都在上一步由模型产出）。
  - **状态块**：判定结果与注记的状态形状。
  - **工具块**：**闸件本体就在工具侧**（闸件的实现代码放在公共工具层，本块只经它的公开面调用）；外表实扫归引擎执行面。
  - **公共簿记块**：**写口面**——落步记录／notice 都经它的唯一写口，只引函数、不引其内部。
- **它给谁用**：
  - **编排块**：承接非放行的留痕与 `ask` 的挂起—恢复链。
  - **作答块**：「全拒 → 带拒因如实直答」由作答块承接（本块只保证拒因齐备）。
  - **执行块**：只让放行的子问题进入真执行。
- **它不碰谁**：**不调模型**（连模型出口都不引）；不引框架；不直引检索引擎；不产出子问题与路线。

## 三、关键行为逐个讲

规格的「行为约定」共 10 条，外加一张**判定序明文表**。

**行为 1｜逐子问题判定。** 规格：对每个子问题**恰好一条** `SubtaskVerdict`；`subtask_id` 必须对上某子问题（对不上＝判失败）。人话：几条子问题就出几条结论，编号必须一一对上。

**行为 2｜判定序固定＋命中即停。** 规格：不得乱序、不得并行判定同一子问题。人话：按下面那张表的次序一项一项过，某一项命中立刻出结论、不再往下。

**行为 3｜判定位的条数与次序以真源为准。** 规格：现为 **8 个判定位（6 主闸号 ＋ 2 子闸）**——本规格不复制该数字以外的新值、不新增判定位。人话：一共八道，主闸六道＋子闸两道，这个数是真源写定的，施工时不许增减。

**行为 4｜闸内只做结构校验与机械分派。** 规格：语义类结论——禁用词「提及 vs 执行」、口径归一、时间窗能否确定——**一律由工具匹配块的模型产出**；本块只接收结论并按其机械分派，不判语义。人话：本块不猜意思，只看「在不在台账、编号对不对、窗口够不够」这类硬事实。

**行为 5｜注记并入放行。** 规格：命中带注记的判定位时，`decision="allow"` 且把注记写进 `notes`；**不设第四态**。人话：有些检查过了但要留个提醒（比如「用了默认时间窗」），这种结论仍是「放行」，把提醒塞在注解里——**没有第五种、第四种状态**。

**行为 6｜外表审批只做申报面判定。** 规格：闸 2 **只做申报面判定**（计划里声明的外表 → `ask`／审批）；**「执行前再扫」归引擎执行面**（真扫描由引擎在 SQL 定稿后执行）；恢复后本块**消费 `approved_ids` 重判**。人话：本块只看「计划里自己说了要用平台外的表吗」，真执行时引擎还会再扫一遍；用户批准后，本块拿批准名单重新判定放行。术语：「外表」＝不在平台内的数据表。

**行为 7｜换链回炉一次为界。** 规格：同一子问题因换链回炉**只允许一次**；再触发同支 → 转 `refuse`（不给第三次）。人话：同一个子问题因为「该换条路查」被退回，只给一次机会；再犯就直接如实拒答，不许无限循环。术语：「**回炉**」＝把失败的部分退回上游相位重做。

**行为 8｜可解释性。** 规格：任一非 `allow` 的结论必须带 `hit_rule`（命中的判定位标识）＋ 人话原因（`human_text`）；口径类拒答还必须带**替代项**（`alternatives`）——缺项＝判失败。人话：拒答不能只说「不行」，要说清「撞了哪条规矩、用大白话是什么意思、还有什么替代口径」；缺一项就算错。

**行为 9｜全拒的处理不属本块。** 规格：本块只逐子问题出结论；「全拒 → 带拒因如实直答」由作答块承接（本块只保证拒因齐备）。人话：全都拒了之后怎么跟用户交代，是作答块的活。

**行为 10｜判定结果全部留痕。** 规格：每个 `SubtaskVerdict` 落步记录（含 `hit_rule`）；**静默放行是已知失败模式**，故 `allow` 且带 `notes` 时注记必须落在步载荷里。人话：放行、拒答、等用户，每一条都要留下可查的痕迹——「悄悄放过」是被点名的失败模式。

### 两种「等用户」的形状与对外的映射

`ask` 结论里的 `kind` 只有两值（闭世界）：`external_table_approval`（外表审批）｜`caliber_clarify`（口径反问）。它们要映射成对外的问询帧类型——**唯一映射表**是：`external_table_approval` → `external_table_approval`；`caliber_clarify` → `clarify`。**真正的发帧与映射由编排块／传输块承接**，两处取值**不得各说各话**（这张表就是对账依据）。

### 错误契约

判定器抛错（闸件不可用）→ **不着 `allow`**（fail-closed，即「拿不准就按最保守的处理」），**转为 `refuse` 并带拒因**，由编排块承接留痕。

## 四、施工时要注意的坑

（以下是规格红线、风险与登记项的口语版。数字、上限、闭世界取值逐字不动。）

- **合法降级路径：无**——本块不降级；闸件不可用时按 fail-closed 转 `refuse`，**不静默放行**。
- **任何非 `allow` 与任何带注记的 `allow` 都必须产生机读信号**：步载荷的 `hit_rule`／`decision`／`notes` 字段 ＋ notice。
- **零 LLM 铁律**：本块及其闸件**不得 import 任何模型客户端**，也不得引唯一的模型出口块（机器闸守）＋一条机器扫源码的测试兜底。
- **只经工具块公开面接触世界**（闸件本体也属于工具块公开面的一部分）；不得自建闸件旁路、不得绕过工具块直引引擎。
- **不许自建第二套判定位表**：判定位条数与次序以唯一真源为准，写成上文**一处明文表**；历史上有过 5／6／8 三种说法，检测手段＝判定序测试。
- **程序不判语义**：不许出现词表／正则式语义判断（机器扫源码）。**豁免面＝形态处理／集合成员判定**——不算语义词表／正则。
- **闸件被别处绕过直调**（跳过三态收口）是已知风险；闸件本体仍是工具块公开面的一部分。
- **「静默放行」被登记为已知失败模式三变体之一**：`allow` 带注记时必须强制落步载荷。
- **还没定／登记在案的事**：
  - **不设「确定性词面门」**：时间窗能否确定由模型给结论，本块不自己拿词面判；这是明确的「不设」，不是待补。
  - **外表「执行前再扫」归引擎执行面**（真扫描在 SQL 定稿之后）——本块只做申报面判定。
  - 三态与更早文档里「四态」说法的差异**已由裁决覆盖并同步修订完毕**（ADR 与那份单元矩阵的旧说法已改），本块以**三态**为准。
