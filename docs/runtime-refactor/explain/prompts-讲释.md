# 指令与提示词块讲释（人类阅读版）

> **本文是派生视图，不是真源。** 真源＝`specs/prompts.md`（已定稿）。
> 规格改，本文即废；本文与规格冲突，以规格为准。
> 日期：2026-10-16。写给人看——没跟过工程的人也能读懂；给机检看的断言一条都不在这里。

## 一、这块是干嘛的

每次叫模型干活，都得先给它一段话交代：「你是谁、这次要干什么、给你什么材料、答案要什么格式」。这段话长得又长又啰嗦，还要在不同工位之间保持一致——**指令与提示词块就是负责把这些话写成文本的那一块**。

它有两个产物：①**合同常量**——一段段固定的规矩话（不随数据变化）；②**装配函数**——把「固定的话」和「当前状态里的数据」按固定顺序拼成最终要发出去的文本。

它最硬的定位是：**只出文本、不做判断**。术语：**纯文本装配**＝只做字符串拼接，不含任何「要不要问」「是不是指这个」之类的意思判断。判断归模型，装配归程序，两边不越位。

一句话记住它：**只出文本不做判断：合同的唯一写处，装配是纯函数。**

## 二、它和邻居怎么打交道

一句话：它**只依赖状态块**（只读它的字段），**被四个业务相位消费**（经统一包根引用，不许自己抄一份合同字面）。

- **谁给它料**：状态块——只读它的投影字段（各相位需要的当前数据）、字段清单以字段矩阵为界；另有一些文本由调用方传进来（比如过程段的渲染产物、时间量）。**注意：时间量只经入参注入，本块不读时钟。**
- **它给谁用**：四个业务相位（理解／澄清／工具匹配／作答）——它们经统一包根引用合同常量与装配函数。
- **它不碰谁**：不解析模型输出（解析块的事）；不渲染材料段、不编译材料清单、不做配额与截断、不装载动态内容（上下文块的事）；不做模型调用（网关桥的事，本块连那个出口都不引用）；不管合同追加的记账与重发判定（状态块＋编排）；不做发射判据的语义判断（模型侧产出，分派归澄清／前置条件块）；不写状态（簿记块是唯一写口）；不引框架、不引检索引擎。
- **它在图里的位置**：

```
state（唯一模块依赖：只读投影，零写入）
   │
prompts（本文这块：合同常量族 + 各轮装配函数，纯文本进出）
   │ 经统一包根（消费方只引用，不复刻字面）
   └─→ 四个业务相位：理解 / 澄清 / 工具匹配 / 作答
```

## 三、关键行为逐个讲

规格的「行为约定」共 16 条。逐条翻译。

**行为 1｜合同常量名单闭世界＋文本单点。** 规格：全仓合同文本定义点唯一（六族见接口）；消费方只经包根引用常量，**任何相位块／编排块内不出现合同字面副本**。人话：规矩话只有一处写着，谁要用就来这里拿，不许自己抄一段存着——现状的毛病就是同一段答案规则在三个地方各写一份、还得三处同步维护。

**行为 2｜答案要求清单＝7 条逐字在场、顺序固定、以「；」分隔。** 规格：七条是**迁移照抄**（承载位换了、文本不变），**逐字稿以现行代码字面为准，照抄不改；偏离即停**。七条内容逐字如下：
①逐条事实断言带 [n] 引标（n＝观察材料序号）；
②材料未覆盖的部分不得断言、如实说明未覆盖；
③材料含多个来源（不同报告／油田／井）时逐个来源分别作答（不冲突也要分别列出，不以反问代替作答）；
④作答后仍有未覆盖的来源或指代不明处，如实点名未覆盖来源（含检索窗注记的未进窗来源）并请用户补充检索或指明对象，不静默略过；
⑤引擎的降级/未绑定/拦停注记必须如实转述进对应子问题条目（不得静默丢弃）；
⑥引用观察材料请摘录必要短语并带引标，禁整段照搬原文充当回答；
⑦「理解：／指标候选：」及任何动作 JSON 是过程产物，出现在答案中即废品。
术语：**引标 [n]**＝答案里标注「这句话来自第几份材料」。

**行为 3｜任务书段序固定、题干置末。** 规格：三区序＝**指令区→数据区→输出契约区**；题干段置末、紧邻生成点（题干非三区之一，段间以「\n\n」连接）。指令区构成＝场景／任务／样例／红线四个常量，相对序为**场景→任务→样例→红线**。两处与旧版的设计变更显式声明：红线由「环境段之后」移入指令区；输出契约区是 V2 新增（旧版没有）。人话：给模型的这份「考卷」三段排死：第一段讲你是谁干什么（里面固定四小件，顺序也定），第二段给参考材料，第三段在最后、很短，说答案要什么格式；题干挂在最后紧挨着回答的位置。

**行为 4｜任务书样例区＝固定示例集。** 规格：三则（多部分题／口语映射题／判断纠错题），**不加边界对照例**；样例区文本不随状态变化。人话：示例永远是这三道固定的例题，不跟数据走。

**行为 5｜数据区从活体投影现取且空投影走占位文案。** 规格：改投影 → 输出文本随之变；空投影走**逐字占位文案**——族「（暂无族标注）」、指标／术语／对象「（空）」、关系「关系：（空）」、水位「（水位未取得）」。人话：数据区永远现取最新，不放缓存；某一类没有内容时用一句固定的「空话」明说（不是删掉这一段、也不是悄悄跳过）。术语：**活体投影**＝从当前数据源现取的快照，区别于缓存。

**行为 6｜题意锚行两形、置于决策轮指令最前。** 规格：理解有真值 → 单行「用户原题：{question}｜题意：{understanding}」（前缀固定「用户原题：」、全角冒号、全角「｜」直连）；理解是假值 → 单段「用户原题：{question}」（**不输出空「题意：」段**）；插在澄清轮／工具匹配轮指令最前面。人话：决策轮的指令第一行永远先复述用户原题，能读出题意就一并写上，读不出来就只写原题——不许留一个空的「题意：」。

**行为 7｜决策轮首入包构成固定、逐件可溯。** 规格：澄清轮／工具匹配轮首次进入时的包＝①题意锚行＋②相位合同（合同头行＋正文；澄清轮另含收尾交付面边界句）＋③（澄清轮）分解发射样例／（工具匹配轮）样例嵌在合同内＋④指南段（文本经入参注入）＋⑤（工具匹配轮）问题组 JSON 渲染（顶层是单键 `subtasks` 形）＋⑥（投影非空时）台账常驻块包裹。人话：每个工位第一次开工时发给模型的那一包，件数与件序都是固定的、每件都能追到出处。规格还给了一条更好记的口径：**四要素按轮合看逐轮在场**——任务动词（合同头）、题意锚（锚行）、产出样例（澄清轮用分解样例／匹配轮用合同内嵌样例）、失败反馈（增量条里的拒因回喂）。

**行为 8｜台账常驻块逐字转抄、恰一份、三删不回流。** 规格：常驻块内的台词条目**逐字转抄**自状态投影（不改写、不摘要）；台账／名录信息在决策轮装配输出中**恰出现一次**（只经常驻块一份，装配不另拼名录段）；三处删掉的段（与相位合同逐字重复的段、名录重复份、收口硬规则旧句）**不回流**。人话：台账内容原样搬、只搬一次，被删掉的旧段落不许偷偷回来。

**行为 9｜消歧头统一措辞。** 规格：澄清／工具匹配两轮的装配用**同一句**消歧头，逐字为「……窗词锚定/单井红线/三链路由；动作类措辞以上方合同为准」，且**不点名已删段**（「发射判据」「指标名册」「收口硬规则」三个段名必须缺席）。人话：两个工位的开场提示用完全一样的一句话，而且不许再提那些已经删掉的段名。

**行为 10｜分解发射样例＝运行时动态渲染、不进合同常量。** 规格：样例里含台账真源词与当日日期，所以只能运行时现造（合同的命名闸要求合同里不许出现业务名词）。渲染规则：取**首条未绑定指标** → knowledge 链／doc_retrieve 形；无未绑定就取首条可出数 → data 链／data_query 形；台账空投影 → 返回**空串**（调用方跳过）；样例窗＝「today−近 30 天 ~ today」示意；载荷形＝`{"action": "decompose", "question_group": {"subtasks": [单条]}}`（两层嵌套），子问题条目**五键齐全**（id／question／ledger_notes／chain/tool），其中 `ledger_notes` 的绑定态段写**闭世界值**（`已绑定`／`未绑定`——样例教的即澄清对账闸收的）。人话：这道样例题是「按当前台账现编」的，因为里面要带真实指标名和今天日期；没有可编的内容就交空串让调用方跳过；产出必须是**合法 JSON**。为什么：旧码是字符串拼接、不转义，会拼出非法 JSON，规格把这条列为病灶。

**行为 11｜合同常量零业务名词。** 规格：合同常量文本不含台账真源指标名／别名／井号形／业务日期段字面（扫描交集为空集）。人话：合同里一个业务名词都不许有——那是运行时数据的事，写进合同就固定死了。

**行为 12｜答案轮段序固定、材料段零渗入。** 规格：答案轮装配输出段序＝三件套置顶（行 1「用户问题：{question}」→ 行 2 动词钉死句 → 行 3「【答案要求】」内嵌答案要求清单全文）→ 汇总合同 → 子问题结果清单 → 起草答案合同（收尾）；**材料段不在装配输出内**（由调用方按上下文块的渲染产物追加在尾部）。人话：答案轮的指令六段排死；真正的材料正文不在这里拼，是别人拼好了接在尾巴上。

**行为 13｜答案轮禁令件在场（钉的合同侧）。** 规格：装配输出必须含**动词钉死句**——「现在：写最终答案交付用户。本步是写答案步——不再做任何决策、不再发射任何动作指令（finalize/decompose 等动作出现即废品）。」——与答案要求第⑦条（「理解：／指标候选：」及任何动作 JSON 是过程产物，出现在答案中即废品）两处字面；**提示词侧不注入回声形指令**。人话：写答案那一轮，指令里必须有两句「禁令」原话，防止模型在该出答案的时候又跑去发动作指令。术语：**回声**＝模型把过程产物（理解、指标候选、动作 JSON）原样吐回答案里；观测面归作答块，本块只负责合同侧的禁令句在场。

**行为 14｜装配是确定性纯函数。** 规格：同入参两次装配输出逐字相等；调用前后状态深比较相等（零写入）；零 IO、零模型调用、零时钟读取、零随机。人话：同一个输入永远得到同一个字符串，而且装配过程不碰任何外部东西。

**行为 15｜不夹带程序判断。** 规格：装配输出＝合同常量与状态投影的确定性拼接，**不含任何程序判定的结论文本**（三选一结论／放行／拒答／覆盖自证／裁决结论等不作为装配产物产生）；静态扫描本块无语义词表／正则判定（**豁免面＝形态处理**：集合成员判定与逐字子串校不算语义词表／正则）。人话：这里只拼字，不产出「结论句」；「在不在清单上」「这段文字在不在里面」这种纯形态检查不算语义判断，允许。

**行为 16｜决策轮增量条构成固定、逐字稿如下。** 规格（逐字照抄，槽位用花括号标出）：
- ①探查预算条（**仅非首入轮**）「探查预算：全 run ≤{全 run 探查上限} 次，已用 {discover_used} 次。」
- ②回炉条（**仅当存在失败子问题时**）「回炉：只分解以下失败/缺失子问题（成功子问题结果已保留，禁止重复分解执行）：」＋逐行「- [id] question——拒因：reason」；拒因词面含「未绑定」或「不在台账」→ 行尾接「→改走 knowledge 链（tool=doc_retrieve）」（触发判据＝机器拒因原文的闭世界子串校，属行为 15 的豁免面）
- ③用户补充条（用户补充非空时）「用户已补充：{hint}——请把它落进本轮分解。」
- ④拒因回喂条（发射错误非空时）「上次发射被拒：{decision_error}——修正后重新输出 JSON。」
- ⑤已做段（调用方传入文本原样在场、零改写——渲染归上下文块）
工具匹配轮的增量条只有两件：拒因回喂条＋已做段。人话：重跑和返工时的追加提示条，件数与文案都是逐字钉死的，顺序也定；「什么时候追加」是调用方的义务，本块只提供条文本。术语：**回炉**＝上一轮有子问题失败，本轮只重做失败的那些。

## 四、施工时要注意的坑

- **合法降级路径＝无**：投影缺位走**占位文案**或**空串段**两形，不删段、不编造数据、不替换成通用措辞。**缺位的机读信号就是这两形**：空串段（调用方跳过）＋占位文案（「（空）」「（水位未取得）」「（暂无族标注）」「关系：（空）」逐字在场）。
- **本块零截断**：装配输出不做任何静默截断／省略（截断与配额归上下文块）；输出中不出现省略号形占位。红线原文（逐字）：「**不许静默**——若任何相位仍发生截断，模型面必须随材料段带明示……收口注记面同步披露」。
- **只许引用状态块**：本块不感知运行状态机、不引任何其他运行期块。**诚实声明覆盖面**：机器闸只拦了「禁引七个业务相位」这一半，**「禁引公共层其余块」那半面没有闸**——靠静态 import 扫描测试兜底，余下人审。
- **消费方向**：四个业务相位只许经包根引用本块，深层子模块算私有——这条有闸。
- **禁手写替代**：合同文本单点在本块，禁在相位块／编排块另存一份合同字面。验收写法＝「运行期面内唯一定义点」断言。
- **合同的加料只能一种方式**：六族之外新增合同文本，只许「新增常量入族＋同批改自己这份清单」；消费方私设第二合同源＝判失败。
- **装配函数族名单是闭世界**：增删成员必须同批对账四个消费方规格的触及面。**常量实名与函数签名阶段 5 施工时按卡定**（本规格锁的是名单闭世界与纯文本进出）。
- **已知未定／登记项（照实说：还没定）**：
  - **系统层提示词 `SYSTEM_PROMPT` 的全文本不归本块六族**，确切落块**待阶段 2 对账**（现只记「属某两个落点」）；其内旧版答案规则句残留副本随落块后的规格销项，**不在本块扫描范围**。
  - 一处**枚举缺口**待澄清：指令区的枚举没列「样例」（现按旧版相对序「任务→样例→红线」归位），以及题干段与输出契约区「末尾」的先后关系——**登记为跨规格债，交主窗统一回提，本块只登记不代办**。
  - 其他登记项（一律只登记）：作答块挂钩表补一条承接行；作答块「材料装配文本」措辞改述（材料段渲染归上下文块）；上下文卡与本块在「常驻块渲染」上的定界两说；本块卡注释补「族名单以本规格接口定义为准」（闭世界）；指南段的装载实现**已裁归上下文块**（与台账同形、装载一次进状态），本块只读渲染。
  - 台账常驻块的**交界两说**已由本规格定界：固定包裹文本＋逐字转抄渲染归本块；投影取得归上下文块；**材料清单记账与「不入史」归上下文／状态面**——靠人审做接口契约对账。
