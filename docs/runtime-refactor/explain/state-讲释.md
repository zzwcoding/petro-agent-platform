# 状态与限额块讲释（人类阅读版）

> **本文是派生视图，不是真源。** 真源＝`specs/state.md`（已定稿）。
> 规格改，本文即废；本文与规格冲突，以规格为准。
> 日期：2026-10-16。写给人看——没跟过工程的人也能读懂；给机检看的断言一条都不在这里。

## 一、这块是干嘛的

一次问答从开头到结束，系统心里要记很多事：用户问了什么、聊到第几步了、这一轮带了哪些参考材料、时间超了没有、下面该往哪走。这些「要记的事」如果谁想记就自己记一份格式，很快就会变成三处都记、三处都对不上。

**状态与限额块就是给全系统「定记录格式」的那一块。** 它规定：运行过程中的状态对象（记为 `RunState`，就是「这次运行的完整记事本」）有哪些字段；每次调模型时随行的那份材料清单（`Manifest`，「这次给模型看了什么」的存根）长什么样；受理一次用户请求的载荷（`AskRequest`）和用户选项（`AskChoice`）长什么样；有哪些合法取值；限额（`Budget`，防跑飞的预算）有哪几个参数；以及超限判定（`check_limits`，一个只算不改的纯函数）怎么算。

它只干两件事：**定形状**（数据长什么样）和**算数**（超没超限）。它不发请求、不落盘、不改状态、不做任何语义判断。真正的「谁来改状态、下一步走哪」是编排块的事；把「超限了」这件事写进状态是簿记块的事。

一句话记住它：**全系统状态的唯一形状真源——只定形状、只算限额，不办任何事。**

## 二、它和邻居怎么打交道

一句话：它**向上游要一个东西**（身份对象的类型），**向下游交出四种东西**（状态与载荷的形状、三族合法取值、限额参数、超限判定结果）。

- **谁给它料**：基础设施块（`infra`）——只借用「谁在操作」（身份对象）这一种类型，别的一律不要。
- **它给谁用**：
  - **簿记块**：用它的载荷形状与判定结果，负责把「超限了」如实写进状态、并落下机读信号。
  - **编排块**：用它定义的状态与载荷形状来读、来迁移状态、来消费受理请求。
  - **所有相位**：用它的合法取值（步类型六值、运行状态四值、路由意图十值）来对齐口径。
- **它不碰谁**：不碰任何别的运行期块（它是最底一层，防成环）；不碰模型出口；不碰检索引擎（知识库／查询／检索三块）；不碰框架（框架只许活在编排块里）。
- **它在图里的位置**：

```
infra（身份对象类型）
   │
 state（本文这块：形状 + 常量 + 限额参数 + 纯判定）
   │
   ├─→ bookkeeping（唯一写口：把判定结果写成状态与信号）
   ├─→ orchestration（读状态、迁移状态、消费受理载荷）
   └─→ 各相位（对齐合法取值）
```

## 三、关键行为逐个讲

规格的「行为约定」共 16 条。逐条翻译：规格在说什么 → 人话讲 → 为什么这么设计（能找到依据才写，找不到就只讲行为）。

**行为 1｜字段集单点。** 规格：状态对象的字段集＝字段矩阵全量；增删字段必须同批改矩阵和全部读写方。人话：字段清单只认一个总表，谁要加字段，得把总表和所有读它写它的地方一次性改齐。为什么：这个字段矩阵是现状实测出来的全量清单，只改一侧就会全链失配（规格自己把这条列为风险）。

**行为 2｜可变与不可变两类形态。** 规格：状态对象可变；其余七种（材料清单、受理载荷、用户选项、运行句柄、限额、超限结果、单条超限）全部 `frozen=True, slots=True`（即创建后不许再改的「读一次就锁死」对象）。人话：只有记事本本身能涂改，别的卡片一旦写好就焊死。为什么：卡片是要跨进程传递、要对比、要当证据的形状，能随手改就无法查账。

**行为 3｜状态可投影。** 规格：状态对象全部字段值都必须是 JSON 原语（即最基础的可序列化值：字符串、数字、布尔、列表、字典），`json.dumps` 能成功。人话：记事本必须能整本抄成标准文本——这是「进程重启还能接着跑」的结构前提。

**行为 4｜`messages` 只追加不改写（钉，最高优先级）。** 规格：`messages` 是整条对话链，每次调模型发送整链，任意相邻两次调用互为前缀延伸，任何替换／重排历史条＝判失败。人话：给模型看的对话历史只能往后接，绝不许改前面的字、不许重排。术语说明：「钉」＝测试网上的一根桩，一条「无论如何不能破」的行为断言。为什么：模型是靠前缀命中的——历史被改写（哪怕只是顺序变了），缓存和可复现性一起崩。

**行为 5｜相位合同一次性。** 规格：`contracts_appended` 记录已追加过合同文本的相位，**回炉轮不重发**。人话：「相位」＝问答流水线上的一个个工位（读题、选工具、查数、核验、作答等）；合同文本＝给该工位立规矩的那段话。这段话每个工位只发一次，回头重跑（回炉轮）不再发一遍。

**行为 6｜对话层纯度（钉）。** 规格：`dialogue` 只装自然对话，条目形态固定为 `{role, content, origin}`；`role` ∈ `user`｜`assistant`；`origin` 是来源闭世界，合法值仅三——`user_verbatim`（用户原话）｜`assistant_final`（assistant 终稿）｜`clarify_approval_replay`（澄清与审批回收原文）。任务书、相位指令、过程原话、注记前缀只入 `process_notes`（有界摘要）。写入口归簿记块。还要守一条一致性不变量：`user_verbatim ⇒ role=user`、`assistant_final ⇒ role=assistant`、`clarify_approval_replay ⇒ role=user`，张冠李戴同判失败。人话：对话层只许放「人和助手真正说的话」，工位指令和过程记录一律另存一处；每一条还要老实标出处，标错关系也算错。术语：「闭世界」＝合法取值只有清单上这几个，清单外一律算错。为什么：这是本次重写**自立的新结构**（现状的对话条目只有 `role`／`content`、没有来源标签），无现状真源可抄，**Owner 2026-10-15 已追认定型**（按最佳实践：单链＋闭世界标签，「隔离优于过滤」——写入点即拒）。所以规格明确：**新增第四个合法值必须走裁决／ADR，闭世界枚举不经裁决不许长胖**。

**行为 7｜追问播种＝前轮终链整链承接（钉，最高优先级）。** 规格：`followup_of` 非空的新 run，其 `messages` 以前一个 run 检查点终链整条为前缀，不裁剪、不摘要化，再接新问。人话：用户追问时，新一回合的对话链要把上一回合的完整历史原封不动接在前面。为什么：摘要化会丢细节——追问靠的是「上一轮原话」，不是别人的概括。

**行为 8｜旧检查点如实读入（钉的字段面）。** 规格：旧版本检查点读入不抛错；`dialogue` 是兼容字段、本块对它零业务写，不得伪造或补写历史；`schema_version`（数据版本号）如实照读。人话：翻旧账本时不许崩、不许替旧账本补写内容。规格还写明分工：同一个钉的「黑匣子回放」那一面由存储归档块负责，两处不各写一遍。

**行为 9｜三族常量为闭世界且单点消费。** 规格：步类型六值、运行状态四值、路由意图十值只在本块定义；任何写入口的取值必须落在对应族里，越界抛错；每族必须有真实消费点（禁「定义了没人用」），全仓不许出现第二处自建状态集合或裸状态字面量。人话：三份合法值清单只有一处真源，谁都别自己另抄一份。（规格同时说明：通知类型的闭世界**不属本块**，它是帧载荷面，归传输块——那份规格定稿时须立该闭世界并落定取值真源。）

**行为 10｜限额参数键集闭世界。** 规格：`Budget` 键＝轮数／轮内发现／轮内执行／段时长／单工具超时／全 run 发现／连续反问上限；数值与缺省值只引真源，常量定义与合同文本同源引用、不重复硬编码；缺键取缺省、禁散落的兜底字面量。人话：预算表只有这七把尺子，尺子的刻度只有一个地方写着，不许在别处再写一遍。规格另有一句重要分辨：循环上限五项里的「回炉一次／同参重投即拦」两项是**行为机制、不是 Budget 键**——它们说的是「怎么做」，不是「有多少」。

**行为 11｜触界判定确定、纯、不改入参。** 规格：`check_limits` 同输入两次结果相等；调用前后入参深比较相等；无 IO、无模型、无随机。人话：这个判定函数是一台**计算器**——只吃数、只吐结果，不写任何东西、不掷骰子。

**行为 12｜触界必带如实注记。** 规格：`hit` 非空 ⇔ `notice` 非 None；`notice` 恰三键 `type`／`gates`／`content`；未触界恒 `notice is None`，不得凭空产注记。人话：超限了就一定带一张「为什么停」的通知单，通知单固定三个格子（类型、闸门、内容）；没超限就一张都不许发。

**行为 13｜触界不静默。** 规格：触界时若未落 `budget_hit`（状态里的「预算已命中」字段）即判失败；「未完成项」明细由簿记块装配进注记。人话：超限必须留下机器能读到的痕迹（状态字段＋通知单两处同现），不许悄悄停下；没做完的事由簿记块如实列出来。依据：规格把这条挂在红线「不许静默」上。

**行为 14｜受理三形态互斥（钉的形状面）。** 规格：三种受理形态＝仅带 `question`（提问）｜带 `resume_run_id`（断线重连）｜`question`＋`followup_run_id`（追问续会话）；`resume_run_id` 与 `followup_run_id` 同在场＝判失败；`AskChoice.kind`／`decision` 越界＝抛错。人话：一次请求只能是三种身份之一，含混不清直接报错。

**行为 15｜材料清单全键恒出。** 规格：`as_dict()` 恒返回与字段同名的全部键；列表值返回**拷贝**（改返回值不改原对象）。人话：导出清单永远不缺点；交出去的是复印件，改复印件不影响原件。为什么：规格把这条列为「同一件事多处数字」的预防面——键少一个，下游就会自己编一个。

**行为 16｜本块零判断、零 IO。** 规格：无词表／正则语义判定、无模型调用、无落盘。人话：这块里不许有任何「猜意思」的代码，也不许碰硬盘。

## 四、施工时要注意的坑

（以下是规格红线、风险与钉节的口语版。数字、上限、闭世界取值逐字不动。）

- **三族常量的条数与取值不在本规格里**：本规格只给族名与条数（步类型**六值**、运行状态**四值**、路由意图**十值**），取值真源在别处；写码时不许在本块之外另立第二套集合，也不许出现裸状态字面量参与把守。
- **框架零接触**：本块不引入任何框架；`langgraph`／`langchain` 只许活在编排块。验收写法＝依赖锁文件不出现框架包、行为测试绿。
- **不许 import 运行期其它块**：本块是最底层数据形状，引任何兄弟块都可能成环。
- **模型出口零接触**：本块连模型出口类型都不引用，也不引网关适配块；并且整层的供应商库只许有一个接触点（本块不在其中）。
- **不直引引擎**（知识库／查询／检索）——这条会被机器闸拦。
- **正文引数值不许复述**：限额数值「只许引真源」，常量定义与合同文本同源引用，不许在调用点再兜底一个数字。
- **触界不是降级**：合法降级路径＝**无**；限额触界不是降级，是契约内的**有界终止**。唯一允许的「降级」是旧检查点读入——缺字段按 `schema_version` 补缺省并**如实标注，禁伪造历史**。
- **不许自述完成**：完成判定归核验／编排，本块只承载状态取值，不判断完成。
- **两个待补的机检钩子（人审兜底）**：「不出现自建帧类型符号」这一面目前只登记待补；「依赖白名单」也没有专属闸，降维后靠不引兄弟块／不引框架／不引引擎／不直引模型出口四条合起来覆盖。
- **已知未定项**：`RunState` 里 `dialogue` 条目的 `origin` 属新立结构，**新增第四个合法值必须走裁决／ADR**；钉的字段面分工里，有几条钉只在本块承载「字段／参数键面」，行为面在别的块（材料截断披露归作答块、连续反问到顶行为归澄清块、全盖章与计费对账面归编排块）——本块不重复挂行为测。
