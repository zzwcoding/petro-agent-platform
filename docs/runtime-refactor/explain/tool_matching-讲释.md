## 一、这块是干嘛的

澄清块交出一组子问题之后，每个子问题还得回答一个问题：「**这一条用哪个工具去查、参数怎么填**」。**工具匹配块就是干这个的**——给每个子问题配上**恰好一个**工具／路线，并把参数校验到**可执行**的程度。

它的分工同样是一句话：**模型提议，程序做闭世界对账**。模型负责「这条子问题该用哪个工具、参数是什么」；程序只核对提议在不在规矩里，**绝不替模型选工具**。

它配出的每条匹配（`SubtaskMatch`）包含这些格：

- `id`——必须对上某个子问题编号；
- `tool`——工具名，**闭世界**：必须在工具注册表名单内；
- `chain`——走数据链还是知识链，**闭世界**：只有 `data`｜`knowledge`；
- `plan`——数据链必填（查询计划，形状真源在查询那份规格里）；
- `retrieval_need`——知识链必填（检索参数，其中 `question` 必填，须逐字转抄子问题原文）；
- `caliber_key`——口径键，**由本块产出**；
- `mention_mode`——「提及 vs 执行」的结论，**闭世界两值**：`executed`｜`mentioned_only`。

最后那格要多说一句：用户问句里出现的旧口径名，可能是「只是提到」也可能是「真要按它出数」。这个判断由模型在配工具这一次调用里一并给出，落在 `mention_mode` 和 `caliber_key` 上，交给后面的前置检查块去做机械分派。

一句话记住它：**一个子问题恰配一条工具——模型提议，程序只做闭世界对账。**

## 二、它和邻居怎么打交道

一句话：它**接一组子问题**，**通过统一窗口叫模型提议**，然后**把「配好的计划」或「结构化拒因」之一**交给编排块。

- **谁给它料**：
  - **澄清块**：子问题清单（问题组）。
  - **状态块**：状态形状——匹配列等。
  - **提示词块**：工具匹配轮的指令与提示词合同——只出文本，本规格只消费。
  - **解析块**：工具匹配发射的解析。
  - **工具块**：只走它的**公开面**，其中「工具描述文本」是模型选工具时唯一看到的依据。
- **它给谁用**：**编排块**——把漏配／多配等的拒因回喂模型重配；配好的计划交下游执行。**下游消费方**：前置检查块（消费 `mention_mode`／`caliber_key` 做机械分派）、执行块（真去查数）。
- **它不碰谁**：不直引模型出口（发起走公共簿记块的统一窗口）；不引框架；不直引检索引擎；不真执行工具；不碰闸件本体。
- **它在图里的位置**：

```
澄清块（子问题组）
   │
 tool_matching（本文这块：模型提议 + 程序闭世界对账）
   │
   ├─ ToolPlan ──────────→ preconditions（消费 mention_mode／caliber_key）
   │                       └→ execution（真查数）
   └─ ToolMatchRejection → 回喂模型，回本相位重配
```

## 三、关键行为逐个讲

规格的「行为约定」共 11 条。逐条翻译。

**行为 1｜模型只提议，程序做闭世界对账。** 规格：模型负责「子问题 → 工具 ＋ 参数」，程序不替模型选工具。人话：选哪个工具是模型的活；程序只核对「这个工具名在册吗、参数全吗、编号对得上吗」这三类结构问题。

**行为 2｜恰配一条。** 规格：每个子问题**恰好一条**匹配；漏配／多配／编号对不上任一 → 判失败。人话：三条子问题就必须有三条匹配，数量、编号都要严丝合缝对上。

**行为 3｜拒因回喂、不自动修补。** 规格：失败一律带**结构化拒因**回喂模型重配；程序不补齐、不猜。人话：程序绝不替模型补一条缺的匹配，只把「哪里不合格」如实退回去。

**行为 4｜参数强校验。** 规格逐项：`chain="data"` → `plan` 必填；`chain="knowledge"` → `retrieval_need` 必填；`metric_slot` 必填非空且**不得为英文列名形**；`ranking` 必填布尔且与 `direction` 同现；`caliber_key` 由本块产出（模型用账本把旧名归一到现行名，前置检查块只做台账闭世界的结构校验）。人话：数据链必须带计划、知识链必须带检索参数；指标槽位必须填中文口径名，**不许填成 `oil_pressure`／`WELL_NAME` 这样的英文列名**；带排名要求时必须同时给方向。
「英文列名形」的判定要讲清：这是一条**形态判定**（**只判形状，不判语义**），判定形＝值整体呈 **ASCII 标识符形**——首字符是 `[A-Za-z]`、其余只许 `[A-Za-z0-9_]`，**大小写都咬**。这是 Owner 2026-10-15 拍板的 B 案，理由是 **fail-closed：宁可误拒让模型重新提议，也不可漏放一个列名形的值**。禁例逐字：`oil_pressure`／`WELL_NAME`。

**行为 5｜枚举闭世界。** 规格：`chain`（`data`｜`knowledge`）、`direction`（`asc`｜`desc`）、`tool`（注册表名单）、`mention_mode`（`executed`｜`mentioned_only`）——越界值判失败。人话：这四格只能取清单上的值；`mention_mode` 这一格是 2026-10-16 补进来的，越界或缺字段都判失败（不猜、不取默认）。

**行为 6｜工具描述写全。** 规格：每个工具的载体＝`ToolDescriptor.description`（模型选工具时看到的就是它），必须含**何时用／不能做什么／参数示例**三项；这是选得准的**第一因**——**不加额外选型规则**。人话：想让模型选得准，就靠每个工具把这三件事写清楚；不许在别处再加一套「选型规则」来打补丁。术语：「`ToolDescriptor.description`」＝工具说明书正文。

**行为 7｜出数只认现行口径。** 规格：`metric_slot` 到查询引擎前只认现行名；**模型产出归一后的名字**，本体账本只提供旧名↔现行名的**「结构映射」**（不替模型做语义判断）。人话：真正送到查询引擎的必须已经是现行口径名；账本只负责给出「旧名叫什么、现在叫什么」的对照表，怎么归一是模型判断。

**行为 8｜不做主动发现。** 规格：不引入检索式选工具／工具主动发现设施（工具集小）。人话：工具就那么几个，直接列出让模型选，不上「检索工具」这类重设施。

**行为 9｜熔断暂不加。** 规格：拒因回喂自环**靠轮数闸兜底**；轮数等限额引限额真源，**本规格不写字面值**。人话：模型反复配不对的死循环，暂不加专门的熔断器，靠总数上限兜住；上限值只在限额真源里，本块不复制。

**行为 10｜名归一闸保留。** 规格：精确键未命中时按名归一扫描。人话：查台账时先精确找；找不到再按名字做归一（去装饰、按 token 包含等）再找一次——这套归一行为保留不变。

**行为 11｜解析拒文变结构化拒因，归本块做。** 规格：解析块产出的 `str` 拒文转成 `ToolMatchRejection` 归本块（消费方）：逐字填进拒因字段＋映射拒因枚举，机械适配、零语义判断；解析块不感知本块类型。人话：解析块只报「不合格式」，翻译成本块拒因结构由收这头做。

### 六类拒因（`MatchReason.kind` 闭世界）与逐字拒文

规格把拒因枚举定为**六类闭世界**。前五类与「错误契约」的五类逐字同源；**第六类 `malformed_matches` ＝支形状失败**，成员名照码面（2026-10-16 归位）。下面拒文**逐字照抄**（`{…}` 处为原 f-string 占位）：

| 成员（`kind`） | 逐字拒文 |
|---|---|
| 缺配 | `缺 matches（非空数组——组内每个子问题恰一条）` ／ `matches 覆盖缺口（组内子问题缺匹配：{missing}）——每子问题恰一条` |
| 多配 | `matches id 重复：{match_id!r}（每子问题恰一条匹配）` |
| 编号不符 | `matches 支缺 id` ／ `matches id {match_id!r} 不在问题组内（闭合世界：{group_ids}）` |
| 必填缺 | `matches {match_id} 缺 tool` ／ `matches {match_id} data 链缺 plan（data_query 计划草案对象）` ／ `matches {match_id} plan 缺 metric_slot（必填非空）` ／ `matches {match_id} knowledge 链缺 retrieval_need（参数对象）` ／ `matches {match_id} retrieval_need 缺 question（必填非空）` |
| 枚举越界 | `matches {match_id} chain 越界（{'/'.join(sorted(CHAIN_KINDS))}）：{chain!r}` ／ `matches {match_id} chain/tool 不一致（{chain} 链须配 {_CHAIN_TOOL[chain]}）` |
| malformed_matches | `matches 支须为对象（{id/chain/tool/plan\|retrieval_need}）` |

三处照抄要点，施工时别自作聪明：

- **第六类拒文里的 `{id/chain/tool/plan|retrieval_need}` 不是占位符**——码面那一行没有 `f` 前缀，是整串字面，**不得当占位替换或改写**（上表里的 `\|` 是排版转义，逐字是 `plan|retrieval_need`）。
- 前五类拒文与「错误契约」的五类词逐字同源：**漏配／多配／编号对不上／必填缺／枚举越界**。
- 第六类系原「未归类一条」经主窗裁归入而增；**前五类成员名与逐字拒文一字未动**。闭世界以这**六类**为准。

## 四、施工时要注意的坑

（以下是规格红线、风险与登记项的口语版。数字、上限、闭世界取值逐字不动。）

- **合法降级路径：无**——本块不自降级。
- **失败与拒因必须产生机读信号**：步载荷的拒因字段 ＋ notice；`caliber_key` 归一的机读信号也落本块步载荷。
- **不得静默丢子问题**：漏配即判失败，**不许「当作已配」或跳过该子问题**。
- **框架零接触**；模型调用发起只经公共簿记块统一窗口，**不直引模型出口**；**只经工具块公开面接触世界**（机器闸守）。
- **同参重投闸不归本块实现**：闸件本体归解析块（指纹）＋状态块（限额计数），**拦截实现归执行块**（dispatch 统一出口）；本块只在它的发射点**被拦**——触发／拦截／回喂都不在本块。
- **工具描述写全落在工具块侧**，这是本块唯一涉及 runtimev2 之外文件的地方：改动限于描述文本，**不动工具块公开接口签名**；检测手段＝工具卡公开接口对账。
- **查询计划只引不复述**：`QueryPlan` 真源在查询那份规格里；**如果那里缺 `aggregate` 字段，就记「待回阶段 3 补」——也就是还没定，本块只引不复述字段**。
- **程序不判语义**：不许出现词表／正则式语义判断（机器扫源码）。**豁免面＝结构归一／形态处理**（如去装饰符号、token 包含匹配），**不算语义词表**。
- **「熔断暂不加」是登记在案的取舍**：靠轮数闸兜底，不是漏做。
- **解析拒文的转换在消费方**（本块），不是解析块做——这一条已裁定，两头不认的旧疑点已销。
