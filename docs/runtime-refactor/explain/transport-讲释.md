# 事件通路块讲释（人类阅读版）

> **本文是派生视图，不是真源。** 真源＝`specs/transport.md`（已定稿）。
> 规格改，本文即废；本文与规格冲突，以规格为准。
> 日期：2026-10-16。写给人看——没跟过工程的人也能读懂；给机检看的断言一条都不在这里。

## 一、这块是干嘛的

用户在页面上看到的一切——「正在查数」「查到了什么」「问你一句」「答完了」——都是系统**一帧一帧推给页面**的。**事件通路块就是负责这些帧的那一块**：一帧长什么形状、叫什么名字、怎么编号、断线了怎么接着推。

术语先解释三个：**事件**＝系统内部发生的一件事（比如「发了一次工具调用」）；**帧**＝要把这件事送到页面上时打包成的那一张纸；**wire**＝真正在网络上跑的那条线。事件的本体发生在各个业务相位里，本块**不管「什么时候该发哪种事件」**，只管**「出去的那一帧长什么样、怎么编号、怎么续」**。

一句话记住它：**只搬帧不定业务：一处编号、断线续推不重不漏、不给原始异常。**

## 二、它和邻居怎么打交道

一句话：它**只借状态块的类型名**，然后**把帧与游标语义交给接口层去渲染、把总线交给编排块持有**。

- **谁给它料**：状态块——只在「运行句柄里的流」这个字段上以**字符串前向引用**的方式点到本块的帧类型（这是为了让状态块不必反过来引用本块，避免成环）；真正的发帧内容来自各业务相位与编排层（它们是发射方）。
- **它给谁用**：
  - **编排块**：持有总线（一条运行一条总线），把它注入各相位；三态收口的发帧也由编排块调用。
  - **接口层**：把帧渲染成页面的流（SSE），并承接断线游标；开流前的鉴权／参数校验／错误码归接口层，不归本块。
  - **所有发射方**：用本块定义的事件名闭世界与帧信封格式。
- **它不碰谁**：不引包里其它运行期块；不碰框架；不碰模型出口；不碰检索引擎；不落盘（该落盘的东西由存储归档块负责，帧里只出**瘦指针**，术语：瘦指针＝只说「东西存在哪、多大、几条」，不含正文）。
- **它在图里的位置**：

```
各相位 / 编排层（决定「何时发哪类事件」＝业务语义）
   │ emit(名字, 载荷)
transport（本文这块：总线 + 帧对象 + 信封 + 游标 + 闭世界常量族）
   │ 帧
   ├─→ api（渲染成页面 SSE / 断线游标接缝）
   └─→ 页面
```

## 三、关键行为逐个讲

规格的「行为约定」共 15 条。逐条翻译。

**行为 1｜事件名闭世界十二值。** 规格：帧的事件名 ∈ 九个运行类事件 ∪ 三个 wire 帧，越界在**构造期**就抛错（fail-closed，不静默丢弃、不降级为默认类）。人话：帧的名字只有十二个合法值，十二个之外一律造不出来。术语：**fail-closed**＝出错就按失败处理并停住，绝不放行。

九个运行类事件的取值逐字为：`step`｜`text`｜`tool`｜`observation`｜`ask`｜`verdict`｜`citation`｜`notice`｜`blackbox`。
三个 wire 帧的取值逐字为：`session`｜`done`｜`error`。
规格特别点明两点：①**`blackbox` 必须与其他八类同列导出面**（现状有缺漏，本块收正）；②旧文案里的「八类」是陈旧注记，口径是**九类**。

**行为 2｜帧信封字节形恒定。** 规格：信封恒为「`id: <int>` ＋ 换行 ＋ `event: <str>` ＋ 换行 ＋ `data: <json>` ＋ 换行 ＋ 空行」三行＋空行；JSON 以 `ensure_ascii=False` 序列化（中文不转义）；非 JSON 原语值兜底为字符串而**不炸流**。人话：每张纸的排版一模一样：第一行编号、第二行名字、第三行内容，然后空一行；中文原样写，不要写成乱码转义；碰上不认识的复杂值就当成字符串写下去，绝不让整个流崩掉。

**行为 3｜游标＝全流单调编号（一处编号）。** 规格：编号由总线历史长度唯一决定、0 起、严格递增、无跳号；跨段（提问段→重连段）不重启、重放不位移；响应内不再另起计数器。人话：一条运行里所有帧共用**一个从头数到尾的编号**，中间换了段、重放过也不许重新从 0 数。为什么：规格写明这是治现状「首段／重连段／重放流三套编号互不同源」的历史缺陷。依据：Owner 裁决「游标全流单调——跨段不重启、重放不位移」。

**行为 4｜信封 `id:` 行＝「最后已消费事件编号」。** 规格：事件帧的 `id` 等于该帧自身编号（交付即消费）；**三个 wire 帧不推进事件游标**，其 `id` 写作**最后已消费事件编号**（尚未消费任何事件时＝**-1**），故 wire 帧的 `id` 可与前帧相同、且不改动续传位置；客户端拿任一帧的 `id` 回送就能**无位移续传**。人话：编号行回答的是「页面已经收到第几件事了」；纯通知类的三个帧（开场、收尾、报错）本身不算「事件」，所以它们不推高这个数——也因此开场帧在什么都还没发生时写 `-1`。

**行为 5｜断线续推不重不漏。** 规格：`cursor` 的语义＝**下一帧的编号**；`stream(cursor)` 给出编号 ≥ `cursor` 的全部帧（含历史里的与后续新到的），不重复、不遗漏；客户端把 `id` 回送时**换算＝`cursor = id + 1`**，且**该式对事件帧与 wire 帧两类 id 同式成立**。人话：续推的起点是「我收到的下一个」；客户端把收到的编号加一报回来即可，不管断在哪一类帧上，都从最后一条已消费事件之后接着推，不漏不重。（术语：`Last-Event-ID` 就是客户端报回来「我收到哪儿了」的那个头。）

**行为 6｜载荷透传，零裁剪零改名。** 规格：帧的载荷＝发射方传入的内容**原样**；**唯一改造＝`verdict` 帧注入 `subtype` 键**（判据单点：载荷含 `status` 键 → `final`，否则 → `verify`；键集越出契约时判 `verify` 且原键如实透传）。人话：搬帧的人不许动箱子里的东西，只有一个例外：裁决帧要额外贴一张「这属于哪种裁决」的标签，标签只有两种取值 `verify`｜`final`。

**行为 7｜通知恰三键且分型闭世界。** 规格：通知帧载荷**恰三键** `{type, gates, content}`；`type` ∈ 二十九值闭世界，越界即拒；**取消现状的隐式兜底**（旧码缺省填 `"notice"`）——**缺 `type` 即拒**（不猜不填）；新增类型必须同批入列。人话：通知单固定三个格子，多一个少一个都不行；通知类型只有二十九个合法值，缺一个类型宁可报错也不许自己填一个默认的。二十九个取值逐字为：`refused`｜`run_failed`｜`ban_exempt`｜`budget_converged`｜`clarify_capped`｜`emission_strip`｜`emission_quote_repair`｜`material_truncated`｜`unsupported_claim`｜`contradiction_split`｜`attribution_split`｜`decision_note`｜`decision_rejected`｜`chain_switch_reentry`｜`window_miss_reentry`｜`approval_gate_pending`｜`approval_recorded`｜`tool_unavailable`｜`subtask_failed`｜`subtask_refused`｜`audit_write_failed`｜`blackbox_write_failed`｜`window_note`｜`no_hit`｜`unbound_degrade`｜`freshness_block`｜`same_param_replay`｜`rebind`｜`schema_not_allowed`。（2026-10-16 随规格改批同步——流水 53-C：末七值由 B5 golden 回放 54444 帧实测补入；该族取值真源＝**现状码面实测＋回放实测**，由本规格自立为取值真源。）

**行为 8｜提问帧形状与挂起铁律。** 规格：`ask` 帧载荷＝`{frame: {kind, prompt, options, detail}, run_id}`；`kind` ∈ 二值 `clarify`｜`external_table_approval`；**`ask` 帧之后照发 `done`**——挂起看 `ask` 帧、不看 `done`，`done` 只代表本腿流结束。人话：系统要反问用户时会发一帧「问你」，接着照样发一帧「本条腿说完了」；判断「是不是在等人」看前者，不能看后者。

**行为 9｜流末恒发 `done`，帧通路自身异常才改发 `error`。** 规格：正常收束 → `done`（载荷 `{run_id}`）；**帧通路／流渲染自身异常** → `error`，载荷**定形＝恰二键 `{code, message}`**（`code`＝稳定错误码、`message`＝稳定话术），**不做 HTTP 状态**；**引擎／网关异常不发 `error` 帧**——它走通知 `run_failed`＋正常 `done`。人话：一切正常就发「完」；只有「搬帧本身」坏了才发「错」，而且「错」里只有两格：一个稳定编号、一句固定话术。为什么这么分：业务上的失败要如实告诉用户（走通知），搬帧坏了才是通道故障。依据：Owner 裁决「不还给用户原始异常文本」——原始异常文本只进内部留痕。

**行为 10｜黑匣子帧恒发一帧，且是业务帧意义上的流末帧。** 规格：收口段**恒发一帧**（写库成败都在，以 `stored` 布尔区分），随后才关闭；载荷为**瘦指针**（七个键：`run_id`／`question`／`status`／`error`／`stored`／`bytes`／`counts{…}`），**全文入库不入帧**。人话：每一条运行收尾都要发一帧「归档情况」——存成功了还是失败了都在这一帧里说；帧里只放目录信息，不放正文。

**行为 11｜多消费者各自独立游标与收束。** 规格：同一总线可被多个消费者（原响应／断线重连／后连观察者）按各自游标读取，互不抢占；**每个消费者的收束由「已关闭且无新帧」判定，不依赖一次性哨兵**。术语：**哨兵**＝只在结束时发一次的信号；一次性哨兵意味着第二个来的人永远等不到它。人话：谁来看都能从头或从中间看，各看各的、互不干扰，谁都能正常看到结束。为什么：治现状「哨兵单发→第二名消费者永久等待」的缺陷。

**行为 12｜关闭幂等＋关闭后拒发。** 规格：重复关闭不重复投递终止信号；关闭之后再发**抛错**（不静默丢弃）。人话：关门可以说很多次都没事，但门关了还想发东西就明确报错。

**行为 13｜无「截断重放」帧。** 规格：wire 面上没有 `replay_truncated` 这类帧；重连时缓冲内没有该 run → **由接口层在开流前拒绝**（诚实拒），帧面不带截断信号。人话：算不清就说算不清，不要造一个含糊的帧糊过去。

**行为 14｜帧内不出现原始异常与内部路径。** 规格：`error` 帧的 `message` 为稳定话术；**任何帧都不得携带内部堆栈、模块路径、SQL 文本**。人话：给页面看的话不许漏出代码里的内部信息。规格注明这条**无对应钉，登记为人审面**。

**行为 15｜本块零判断零模型。** 规格：无词表／正则语义判定、无模型调用、无落盘。

## 四、施工时要注意的坑

- **合法降级路径＝无**：帧通路不自降级——发射失败就是异常上抛，不吞、不改写成别的帧。
- **四条「不得静默」**：编号无跳号无重启、缺帧不吞、通知分型越界即拒、关闭后发射抛错——四条都要有断言。
- **失败披露一律走帧**：引擎／网关异常 → 通知 `run_failed`＋正常 `done`（**不触发 `error` 帧**）；只有帧通路自身异常才发 `error`。
- **脱敏是硬要求**：对外帧只带稳定话术；原始异常文本归内部留痕。
- **禁手写替代**：帧对象、信封、游标都只在本块实现，接口层只做渲染——不许自建第二套帧通路。
- **`SseEvent` 的类型表示**：状态块不能引用本块，故以字符串前向引用指过来；不许给帧类型安第二套含义。
- **已知未定／登记项（照实说：还没定）**：
  - 缓冲**无上限、无淘汰**（现状是每条运行的缓冲全量常驻、无过期机制）：本批**不新增淘汰机制**（Owner 已把该现状缺陷登记为现状证据、不设「收债」环节），**登记为阶段 5 可选项**，靠人审。
  - **背压**（生产端太快、消费端跟不上时怎么办）**没有承接方**：本批**不新增背压机制**，定性归接口层的流桥，须**呈主窗定性**，落地时在接口块规格里登记。
  - 有一条历史钉子写的是「帧里 `frozen_date` 全在场」，但经码面取证该字段只出现在评测跑批记录里、**SSE 帧里根本没有这个键**——该半面**不属本块**，建议改准原文措辞，**呈主窗**（本批不自行改）。
  - 「缓冲区里有这个 run 没有」的读口字段面归接口层，本批靠人审对账。
  - 三条「没有专属机器闸」的面（只依赖状态块、禁手写第二套帧通路、信封实现单点）目前只登记待补降维断言＋人审。
