## 一、这块在业务上干什么

用户在问一问页打了一句话，比如「近三天 A7 井的产量是多少」。这句话送进系统后，**第一个动脑的是读题块**。

它干两件事：

1. **读懂这句话**——让模型把大白话整理成一张结构化的「读题结论」：这句话想要哪个指标、涉不涉及具体数字、需不需要走完整流程。
2. **定路线**——读完马上分派：这个问题是**走全程**（查数、核验、正式作答），还是**可以直接答**（比如纯概念解释「什么是完井」）。

一句话记住它：**语义判断交模型，程序只按结论机械分派**。模型负责「这句话什么意思」，程序负责「按结论办事」，两边不许互相越界（这是设计总纲的总纪律，裁决表 #11 一脉）。

## 二、逐条讲「行为约定」——每条规则翻译成业务语言

规格的「行为约定」有 8 条。下面每条分三行：原文要点（锚在规格）、人话意思、为什么这么重要。

**行为 1｜任务书分三区且顺序固定：指令区→数据区→输出契约区。**
人话：每次叫模型读题前，系统要先组装一份「考卷」。考卷三段：第一段告诉模型你是谁、干什么的、红线是什么；第二段给参考资料（指标名录、术语表）；第三段在最后、很短，告诉模型答案必须是什么格式。
为什么：顺序固定是为了让模型的注意力落在最后的输出格式上——格式要求放中间会被海量资料淹没。

**行为 2｜数据区每轮现取活体投影，标来源、放末尾。**
人话：参考资料不许用缓存的旧名单。指标名录这种天天变的东西，每次读题都从活的数据源现取一份，并且注明「这份名单来自哪里」。
为什么：名录是活的（本体在持续扩充），用昨天的名单可能漏掉新指标。

**行为 3｜输出契约＝单个 JSON 对象。**
人话：模型必须交回一个规定格式的结构化答案，不许用旧的「两行式」自由文本。
为什么：下游全是程序在消费这个结论，格式自由就没有可靠接口。

**行为 4｜程序只按 route 分派，不触发任何词面/正则判断。**
人话：路线决定之后，程序只看「full」还是「direct」这一个字段办事。哪怕这句话里出现了敏感词，程序在读题块里也**不做任何自己的判断**——拦截是别的块（gate）的事。
为什么：判断只许有一处。如果读题块也偷偷做关键词判断，将来改口径要改两处，必漂移。

**行为 5｜直答结构核验：模型说「可以直接答」时，程序要复核三件事。**
人话：模型有时会自信过头，说「这题不用查库我直接答」。程序不信口号， mechanically 检查三个硬指标：
- 答案里有没有**数字**（哪怕一个）？有数字就不许直答——数字必须来自数据，不能来自模型的记忆；
- 有没有**指标名录里的指标名**？有就说明涉及具体口径，必须走全程去对账；
- 有没有**结构卡（数据库表）名**？有就说明要查数。
三个都没中，才放行直答。生僻词不算——这是机械核对，不做语义猜测。
为什么：这是防「模型幻觉数字直接答给用户」的第一道关。数字错一个，用户失去的信任比慢十秒贵得多。

**行为 6｜单出口互斥：一次调用只返回两种结论之一。**
人话：读题结果要么「走全程」要么「直接答」，不允许出现一个模棱两可、两头都沾的结果。

**行为 7｜解析严格：不合格式就报错，不静默降级。**
人话：模型交回来的东西格式不对，读题块必须**当场喊出来**（抛 UnderstandingParseError，留着原始片段备查），绝对不许「尽量猜着用」。
为什么：旧的代码干过「从回答里抠第一个花括号凑活用」这种事——表面看系统没崩，其实拿一个可能是残缺的结论喂给了全流程。这种「装作没事」比当场报错危险一个量级，全仓的总红线就是「不静默」。

**行为 8｜候选指标必须出自名录，出现名录外的名字判违约并上报。**
人话：读题结论里点名的指标，必须能在官方指标名录里查到。模型自造一个听起来很像的指标名（幻觉），程序要标记为违约事件上报，不许悄悄放行。

## 三、术语小词典（读其它块讲释前先扫这个）

- **闭世界**：「合法取值只有清单上这些，清单外的一律算错」。全仓最重要的口味。
- **机械分派 / 不做语义猜测**：程序只查「在不在清单上」，不猜「是不是这个意思」。猜意思永远是模型的事。
- **不静默降级**：出了错只能喊出来或按规定收敛，不许装作没事继续跑。
- **钉（pin）**：测试网上的一根桩——一条「无论如何不能破」的行为断言，每条 pin 有编号、有优先级。
- **闸（R1–R7 契约）**：import-linter 机检的依赖方向规则，机器守，不靠人记。
- **活体投影**：从当前数据源现取的快照，区别于缓存。
- **触及的模块**：本块要用谁家的东西——注意读题块自己**不直引模型出口**，发起模型调用要走 bookkeeping 的统一窗口（单点发起纪律）。

## 四、这块在全景里的位置

```
用户一句话
   │
  gate（先过安全闸：注入/外发/写意图——读题块不管这个）
   │
  understanding（本文这块：读懂 + 定路线）
   │
   ├─ direct ──→ 直接作答链路
   └─ full  ──→ tool_matching → execution（查数）→ verification → answering
```

它**不做**的事（规格「不做什么」表，人话版）：不拦截安全问题（gate 的事）、不判断废弃口径、不反问（clarification 的事）、不选工具、不查数、不发请求。它只做「读懂 + 分派」。

## 五、自检：我怎么知道读懂了

合上本文，能答出这三问即过关（答不出回规格行为节对号）：

1. 用户问「什么是压裂」，模型说 direct，程序凭什么放行？（行为 5：无数字、无名录指标、无表名）
2. 用户问「A7 井昨天产液量」，模型说 direct，程序怎么办？（行为 5：命中表名/数字 → 退回 full；行为 4：只按 route 分派，不自己加判断）
3. 模型交回来的 JSON 缺了 route 字段，旧代码会抠花括号凑活用，新代码怎么办？（行为 7：抛错留痕，不静默降级）
