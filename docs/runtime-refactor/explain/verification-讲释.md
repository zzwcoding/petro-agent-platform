## 一、这块是干嘛的

答案在交给用户之前，要过最后一道「有没有材料撑着」的检查。**核验块就是这道检查**，它的底色是：

- **纯程序、零模型（零模型铁律）**——这是防编造的**机器底线**。判「这句话意思上能不能被材料支持」这种语义活，本块**不做**；它只做**确定性的断言级核验**：数值有没有复述、引标能不能解析。
- **没支撑的话改写掉**——没有材料撑的句子，改写成「未找到／材料未披露」；
- **两个来源对不上就分开列**——不硬凑。

它交出的判定卡是 `Verdict`（对外判定，**不是答案侧的文本**）。这张卡必须**各字段齐备，缺键＝判失败**：五个计数 `supported`（有支撑的句数）／`rewritten`（被改写的句数）／`split`（因矛盾被分列的组数）／`cited`（被引用的观察序号）／`attribution`（归属审是否通过），加上 `ok`（是否仍有「无据断言」残留——`ok=False` 才需回炉）与 `gaps`（结构化缺口，复用作答块的缺口口径、核验侧只产出 `kind="unverified"`），再加上行集对账两字段 `delivered_rows`（答案交付行数）／`obs_rows`（在窗数据行数）。

一句话记住它：**交付前逐句对材料：没支撑就改写、对不上就分列。**

## 二、它和邻居怎么打交道

一句话：它**接答案草稿与观察材料**，**只做确定性比对**，然后**交回一张判定卡**。

- **谁给它料**：
  - **作答块**：答案草稿（本块据此逐行核验）。
  - **执行块**：观察材料（原料）。
  - **状态块**：判定结果、改写行、引用的状态形状。
  - **公共簿记块**：**写口面**——落步记录／notice 经它的唯一写口，只引函数、不引其内部。
- **它给谁用**：**传输块**——本块发 `verdict`／`notice` 帧；**编排块**——拿 `Verdict.ok` 决定是否回炉，并协调 `verdict` 帧的批次落定。
- **它不碰谁**：**不调模型**（零 LLM 面，不引模型出口块）；不引框架；不起草答案、不执行查询、不编译材料。
- **它跟既有测试的关系**：本块绑**新建**的测试文件；既有那个测「现状核验步」的老文件继续覆盖现状行为，**本批不改**。

## 三、关键行为逐个讲

规格的「行为约定」共 11 条。

**行为 1｜逐行断言级核验。** 规格：先把答案剥掉结构性残留（JSON／引标记号），再**逐行**判定；**不是整段判**。人话：按行来查，一句一句过；先把那些不是人话的结构性垃圾剥掉再判。

**行为 2｜数值须复述（带承载豁免）。** 规格：被引观察里的**数值须在断言文本里复述**才算有支撑——只凭「引用了一个数」不算；**但表格行／血缘卡／片段（`agg_row`／`lineage`／`fragment`）这几种承载形式下豁免「全数值复述」**——**任一数值重叠即支撑、零重叠照改**（零重叠不回退）。人话：光挂个引标还不够，引的那个数得在句子里真出现才算数；但表格行、血缘卡、片段这几种形态例外：只要有一个数对上就算撑住了，一个都对不上就照样改写。

**行为 3｜无据 → 改写。** 规格：没有支撑的句子**改写成「未找到／材料未披露」**（改写原因＝`no_material`），并发 notice。人话：没撑的句子改口说「没找到」，并留一条通知。

**行为 4｜矛盾 → 分列。** 规格：两个来源给的数对不上时**分开列、各带出处**（改写原因＝`conflict`），**不强调和**、不取其一。人话：两边打架就把两边都摆出来，各带出处，别擅自选一个。

**行为 5｜归属审。** 规格：引用的材料与问句点名的对象对不上号 → `attribution=False`，并把该情形写进缺口。人话：题干点名的是这个对象，引的材料却是别的对象的，就判归属不通过，并记进缺口。术语：「**归属审**」＝核对「引的材料」和「问句点名的对象」是不是同一个。

**行为 6｜给出核对结果卡。** 规格：`Verdict` 各字段齐备（五计数 ＋ `ok`／`gaps` ＋ 行集对账 `delivered_rows`／`obs_rows`）——**缺键＝判失败**。人话：这张判定卡不许少格子。

**行为 7｜判据加严（治已知假阳／假阴）。** 规格：数值比对**先做边界记号化**（`52` 不得命中 `1520`）；**全角与半角标点先归一**再切分。人话：比数字要先认准边界——查 `52` 时不许把 `1520` 里的 `52` 也算命中；标点有全角半角之分，先统一了再切句。
术语：「**边界记号化**」＝比对时要求数字是独立的记号，不许当子串乱蒙中；「**假阳／假阴**」＝误判成有据／误判成无据。

**行为 8｜零数值断言不恒过。** 规格：断言里**没有任何数值**时，**不得自动判过**——仍须有可解析引标支撑，否则计入无据。人话：一句话里没有数字，不代表就安全；还是得有能解析的引标撑着，否则照样算无据。

**行为 9｜`Verdict.ok=False` 才回炉。** 规格：只要仍存在无据断言残留，`ok=False`（供编排块决定回炉）；`ok=True` 时不得再改写。人话：核验卡自己说了算——还有没撑住的句子就是 `ok=False`，编排层据此回炉；已经全撑住就不许再动。

**行为 10｜`verdict` 帧的批次落定由编排块协调。** 规格：本块只保证自产部分（`Verdict`／`notice`）就位。人话：发帧的时点由编排层统一掌握，本块只把自己那份准备好。

**行为 11｜行集对账（记账面、非拦截阀门）。** 规格：verify 面确定性对账**在窗数据行数 vs 答案交付行数**——`Verdict` 产出 `obs_rows`（在窗数据行数）／`delivered_rows`（答案交付行数）两机读字段并随步载荷落账；**差额>0 且答案面无行集声明 → 补如实注记**；**不改写数值断言、不重试、不拦截**。人话：本块顺手核一下「窗口里有几行数据、答案交了几行」，差得多就补一条如实注记；但它只是记账，不拦、不改、不重跑。

## 四、施工时要注意的坑

（以下是规格红线、风险与登记项的口语版。数字、上限、闭世界取值逐字不动。）

- **合法降级路径：无**——本块不降级；**核验器不可用时按 fail-closed 取 `ok=False`**（拿不准就按「有残留」处理，不静默放行）。
- **错误契约**：核验器自身抛错 → **不判 `Verdict.ok=True`**（fail-closed），转 `ok=False` ＋ 缺口，由编排块承接。
- **改写、分列、归属失败都必须产生机读信号**：`verdict`／`notice` 事件 ＋ 步载荷里的 `supported`／`rewritten`／`split`／`cited`／`delivered_rows`／`obs_rows` 字段。
- **改写不得静默**：被改写的原句与原因必须留痕（`RewriteRecord`）——无据改写记 `no_material`，矛盾改写记 `conflict`（**闭世界两值**，越界判失败）。
- **两个维度不强行映射**：「为什么改写这句」（`no_material`｜`conflict`）和「哪个子问题有缺口」（`Gap`）是**不同维度**，不做一一映射。
- **零 LLM 铁律**：本块**不调模型**、不存在模型调用发起面；**不得引模型出口块**——真正覆盖本块的是「零 LLM 面」那条机器契约（只禁「直引底层模型客户端」的那条契约对本块只是天然满足）。验收写法＝机器扫源码 ＋ 「无旁路」断言。
- **框架零接触**；帧只经传输块公开面（**不自行拼 wire 帧**——这半面无专属闸 → **人审**，登记待补降维断言）。
- **程序不判语义**：不许词表／正则式语义判断（机器扫源码）。**豁免面＝形态处理／集合成员判定**。
- **确定性**：同一输入两次运行，`Verdict` 的五个计数与 `ok` **完全一致**（零随机、零模型）。
- **还没定／登记在案的事**：
  - **核验的召回率／误杀率从未与人工标注度量过**——这是本块最大空白（Owner 裁决「要补」）：对策是用人工标注样本算精确率／召回率（拦错的 vs 放过的）**进测试网**，**不是**本块实现的运行时能力。
  - **「第三档」语义蕴含判定：不做**——本块零模型是机器底线；将来若要引第三档（用更强模型提准确率），**须先裁「是否允许破零模型」并记 ADR**。
  - **溯源粒度**按 Owner 裁决**保持「行＋引标」**（只读问答、单租户够用）。
  - **核验对增量引标（承接真流式）尚未落点**：本块现状只覆盖「剥结构性残留 → 逐行判定」，对**增量里的引标对齐**还没定，**登记为跨块待办**，随作答块真流式协同定稿。
  - **答案是流式的，核验怎么跟上**：同为上一条的待办面，别当成已有能力写进说明。
