## 二、SSE 帧通路（规则条目）

### A. 事件类闭世界与信封（T-P9a1-01..06）

- **T-P9a1-01**：wire 面事件类型集＝runtime `EVENT_KINDS` ∪ wire 三帧＝`EVENT_KINDS \| {session, done, error}`（`wire.py:47`）。集合真源＝`appv2.runtime.events`（`events.py:23-44`，单源 re-export），wire 只消费不另立（`wire.py:1-19`）。
- **T-P9a1-02**：runtime `EVENT_KINDS` 为**九类**闭世界：`step/text/tool/observation/ask/verdict/citation/notice/blackbox`（`events.py:23-44`）；`RunEvent.__post_init__` 越界即 `ValueError`（`events.py:55-59`）。
- **T-P9a1-03**：帧信封字节形＝`id: <int>\nevent: <str>\ndata: <json>\n\n` 恒三行＋空行收束；`json.dumps(ensure_ascii=False, default=str)`（中文不转义；`Decimal/date` 兜底不炸流）（`wire.py:66-74`）。测试钉：每块恒三行、首帧字节形逐字（`tests/api/test_v2_asks.py:568-595`）。
- **T-P9a1-04**：载荷透传——帧 `data` ＝ runtime `RunEvent.data` 原样（api 层零裁剪、零改名、零白名单，`bridge.py:143-148`）；唯一改造＝verdict 注入 `subtype` 键。
- **T-P9a1-05**：verdict 拆形单点 `verdict_subtype`：判据＝「载荷含 `status` 键」→`final`，否则`verify`（`wire.py:56-63`）；`VERDICT_SUBTYPES` 二值闭世界（`wire.py:53`）；键集在契约外时判 `verify` 且原键如实透传（不吞不猜）。
- **T-P9a1-06**：verdict 两形载荷键集（消费面契约）：`verify`＝`{subtype, supported, rewritten, split, cited, attribution}`（`attribution` 为 V2-50 additive，`{anchors, cross}`）；`final`＝`{subtype, status, run_id, manifest_digest}`（发射点 `graph.py:3773-3780`；测试钉 `tests/api/test_v2_asks.py:512-541`）。

### B. 首帧 session 与帧号（T-P9a1-07..11）

- **T-P9a1-07**：三端点流首**恒发** session 帧，载荷 2 键 `{run_id:str, resume:bool}`：提问形态 `resume=false`（`chat.py:256`）；重连形态 `resume=true`＋`run_id`＝被重放 run（`chat.py:227`）；resume 段 `resume=true`（`chat.py:283`）。前端以 session 帧接线 run 上下文（`web/src/landing/A1V2.jsx:223-225`）。
- **T-P9a1-08**：session 帧占帧号 `first_frame_id`：新段（提问/resume 段）＝0；重放流＝断点+1（`bridge.py:138-142`；`chat.py:225`）。
- **T-P9a1-09**：帧号＝**响应内**自增计数器（每产一帧 +1），非全局计数、非 runtime seq（`bridge.py:138,148`）。
- **T-P9a1-10**：帧号 ≠ `RunEvent.seq`——runtime `seq` 只作为 `step`/`tool` 帧载荷内的一个键随行（`graph.py:2056-2057,3327-3328,3584`）；帧 `id` 是 SSE 信封层事实，`seq` 是 runtime 事件序事实，两者独立。
- **T-P9a1-11**：缓冲位↔帧号映射契约「缓冲位 p 的帧号＝p+1（session 首帧占 0）」（`bridge.py:11-14`）——**仅在首段流成立**（对照 T-P9a1-17、T-P9a1-21）。

### C. Last-Event-ID 与重连重放（T-P9a1-12..17）

- **T-P9a1-12**：`Last-Event-ID` 解析（`chat.py:48-61`）：缺头/空白＝`None`（非重连）；非整数＝400 `chat_last_event_id_invalid`，**开流前**拒绝（请求没进门，不开流）。
- **T-P9a1-13**：仅 `Last-Event-ID` 而无 `resume_run_id`＝400 `chat_param_invalid`（`chat.py:232-237`）——V2 无「缓冲窗口」语义：补不出不是诚实降级而是请求缺参。
- **T-P9a1-14**：重连定位＝`registry.get(resume_run_id)`；缓冲无该 run＝404 `chat_run_not_found`，message 明示「或不在本进程缓冲内」（`chat.py:213-220`）——与「run 在库但不在本进程」同码（D-P9a1-04）。
- **T-P9a1-15**：重放游标：`follow_cursor = breakpoint_id if not None else 0`（无头＝全量重放）；消费起点＝缓冲位 ≥ cursor（`bridge.py:73-77` `index=max(cursor,0)`）；帧号枚举起点＝`cursor+1`（`chat.py:221-231`）。
- **T-P9a1-16**：重放可**尾随在跑 run**：缓冲耗尽且段未收束（`_active>0`）时 `await condition`，新事件到达续产；段收束后重放该 run＝全缓冲重放＋收场帧（`bridge.py:73-89,82-88`）。测试钉：断点重放尾部逐帧同形同值、无头＝全量（`tests/api/test_v2_asks.py:372-407`）。
- **T-P9a1-17**：重放帧号与原流**不对齐**（如实登记，`bridge.py:11-14`）：因 session 帧占用了 `breakpoint+1` 号位，重放事件帧号＝原流帧号+1。例：断点 2 → session=3，缓冲位 2 的事件在原流为 3、在重放流为 4。

### D. 缓冲机制（T-P9a1-18..22）

- **T-P9a1-18**：缓冲结构＝`RunStream`（per-run：`list[RunEvent]`＋`asyncio.Condition`＋`_active` 在挂段数＋`_error` 排空异常，`bridge.py:39-104`）＋`RunStreamRegistry`（`dict[run_id → RunStream]`，`bridge.py:107-122`）。全量常驻进程内，**无淘汰、无上限、无 TTL**（D-P9a1-05）。
- **T-P9a1-19**：api 层是 `handle.stream` 的**唯一排空点**：`attach` 起后台 `_drain` 任务逐条 append＋`notify_all`（`bridge.py:63-71,93-104`）。多消费者（原响应／断线重放／后连观察者）各凭游标读同一缓冲，互不抢占；`AsyncIterator` 单消费者限制在桥内收口（`bridge.py:1-19`）。
- **T-P9a1-20**：`registry.register(handle)` → `attach` 返回 `mark`＝**挂接前**缓冲长度（本段起点游标）；同 run 二段（ask → resume）续拼**同一缓冲**（`bridge.py:113-119,63-71`）；段响应只出本段新增事件：提问/resume 段 `first_frame_id=0`＋`follow_cursor=mark`（`chat.py:250-260,277-287`）。
- **T-P9a1-21**：resume 段帧号**重新从 0 起**（session=0，本段首事件=1），与全局缓冲位无对应关系——该段最后收到的 `id` 不能当跨段/跨响应断点（D-P9a1-02）。
- **T-P9a1-22**：排空异常留痕：`_drain` 捕 `Exception`→`_error=str(exc)`；`finally` 段 `_active -= 1`＋notify；异常**不冒出流**（转为 error 帧，T-P9a1-24）；`closed`＝`_active==0`，`error` 属性供帧渲染面选 done/error（`bridge.py:53-61,93-104`）。

### E. 收场帧 done/error（T-P9a1-23..27）

- **T-P9a1-23**：流尾**恒发**保留帧：`stream.error is None` → `done`，载荷 `{run_id}`；否则 `error`（`bridge.py:149-156`）。
- **T-P9a1-24**：`error` 帧两处形态（同 code 不同措辞）：①排空异常→`{code:"chat_stream_failed", message:"流内异常——{stream.error}"}`；②帧渲染面自身异常→`{code:"chat_stream_failed", message:"流内异常——请重新提问：{exc}"}`（`bridge.py:149-162`）。
- **T-P9a1-25**：流内异常**不走 HTTP 错误包**（00 §6.1）；HTTP 状态码只在开流前同步段出现（400/401/404/409）（`chat.py:19-22`）。
- **T-P9a1-26**：挂起对外铁律：`ask` 帧之后**照发** `done`——挂起看 ask 帧、不看 done（done 只代表本腿流结束）（`web/src/api/chatV2.js:14-15`；测试钉 `tests/api/test_v2_asks.py:341`）。

## 三、关键保证与边界

### 每端点一句话不变式

- **E1**：任何身份可得全局最近 N 条 run 的 7 键摘要，`created_at` 降序、`limit` 静默夹取 1..100 不报错——重写后键集、排序、夹取语义三者须逐字不变。
- **E2**：一次请求恰为「提问（新建 run）／重连（重放缓冲不重跑）／追问（新 run 播种前轮历史）」三形态之一；对外区分手段只有 session 首帧的 `resume` 布尔与 `run_id`；互斥/缺参/前轮状态一律开流前 400/409/404 拒绝，绝不静默降级。
- **E3**：只对 `waiting_ask` run 生效，请求值映射到 `AskChoice` 闭世界后交给 runtime；404/409 在开流前出状态码，其后只出帧。
- **E4**：只读回放面——`status`＋`steps`（`seq` 升序 6 键）＋`manifest_digest`，`waiting_ask` 时随行 `pending_ask`（与流内 ask 帧同形）；run 不存在＝404 不带存在性差异信息。

### 已知边界（跨进程/容量/安全面）

- **缓冲在进程内**：`RunStreamRegistry` 与 `app.state` 均为进程内单例，跨进程重启后重放＝404（`chat.py:215-220`、`bridge.py:16-19` 自述归 ADR-0003 队列消费者形态）；缓冲无淘汰/无上限/无 TTL。
- **帧号只在单响应内有意义**：三种编号（首段、resume 段、重放流）互不同源（T-P9a1-09/17/21）。
- **流内两账不同源**：流内 `step` 帧 3 键 vs E4 `steps[]` 6 键；流内 `seq`（runtime）与帧 `id`（信封）独立。
- **run 读面全局**：E1/E4 均带身份依赖但**无身份过滤**（`store.py:156,152` 无 actor 谓词），任意身份可读任意 run 的 `question`/`answer` 全文。
- **标识与错误**：身份为开发期桩（`X-Dev-User`，缺头落默认角色）；错误码全集 7 值（`errors.py:26-32`），域前缀 `chat_*`／`request_invalid`／`security_*`；错误包不带 HTTP 语义字段。
- **合同登记面**：V2 三条（asks／resume／runs 详情）在 `config/contract_endpoints.json` 带 owner 挂账；E1 列表端点未见对应清单条目（D-P9a1-07）。

### 疑点（只列不判）

- **D-P9a1-01**：重放帧号位移（+1，T-P9a1-17）使「重放中收到的 id 当新断点」会跳过缓冲位事件——二次重连可能遗漏；现有测试 `_parse_frames` 丢 `id` 行故无断言（`tests/api/test_v2_asks.py:247-261` 解析器只取 event/data；重放测试 372-407 只比事件名与载荷）。
- **D-P9a1-02**：resume 段帧号从 0 重启（T-P9a1-21），该段 `id` 与全局缓冲位无对应；若将来按 `Last-Event-ID` 在 resume 段后重连，定位错误。V2 前端（`A1V2.jsx`）当前无重连实现，未暴露（V1 的 `A1.jsx:505` 有）。
- **D-P9a1-03**：`followup` 的 404/409 与 `resume` 同码同值（`chat_run_not_found`／`chat_run_state`），语义不同（被问 run 不存在 vs 前轮不存在 vs 前轮未收口）——客户端无法只凭 code 分型，须读 message。
- **D-P9a1-04**：重连 404 把「run 不存在」与「run 在库但缓冲不在本进程」并为同码（message 区分，T-P9a1-14）；多进程/重启后重连一律 404。
- **D-P9a1-05**：缓冲无淘汰、无上限（全量 `RunEvent` 常驻），长驻进程内存单调增长；无容量闸/无观测指标。
- **D-P9a1-06**：E1/E4 无身份过滤（actor 已解析未参与过滤）——是否需要按 actor 过滤属业务裁决，未判。
- **D-P9a1-07**：appv2 路由不在合同覆盖率闸扫描面（`tools/contract_coverage.py:67` 缺省扫 `app/api`；A13/清单双向对账对 appv2 失效），`GET /api/v2/chat/runs` 列表（V2-73）连清单条目也无——appv2 端点增删无机器闸对账。
- **D-P9a1-08**：文档口径漂移三处：`wire.py:7-8`／`bridge.py` 注释写「八类」而 `EVENT_KINDS` 为九类（含 `blackbox`，`events.py:31,42`）；`app.py:16,258` 写「agent_v2 五表」而 `store.py:267-274` 建六表；`tests/api/test_v2_runs_list.py:157` 注释「六键」而 161-165 断言为 7 键。
- **D-P9a1-09**：`EVENT_BLACKBOX` 未进 `runtime/__init__.py` 公开面 re-export（`__init__.py:63-75` 只导八类常量），`wire.py` 靠 `EVENT_KINDS` 集合间接覆盖——若重写把事件常量改为显式白名单，`blackbox` 帧会静默丢。
- **D-P9a1-10**：E4 在 `waiting_ask` 时触发 runtime 侧图重建读态（`executor.py:321-330+`：`build_graph`＋`aget_state`）——只读请求带运行时开销；重建异常不在 `errors.py` 映射表内（将成裸 HTTP 500）。
- **D-P9a1-11**：error 帧 message 直出 `str(exc)` 原始异常文本给浏览器（`bridge.py:153,161`）。
- **D-P9a1-12**：`ask` 帧与 `pending_ask` 的 `detail` 结构在 api 层无定型（`dict[str,Any]` 直出，`chat.py:112`；`graph.py` 各发射点各自构造 frame），字段面单方由 runtime/tools schema 决定，api 层零校验。
