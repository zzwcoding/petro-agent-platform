## 三、错误映射

接触点清单（C25–C28）：
- C25 `install_error_handlers` 五张 handler（errors.py:63-110）。
- C26 `error_payload`/`ApiError`/CODE_* 码值表（errors.py:26-60）。
- C27 映射源异常类定义：`RunNotFoundError`/`RunNotSuspendedError`（runtime/executor.py:78-83）、`UnauthenticatedError`（infra/security/domain.py:73）。
- C28 流内错误（非 HTTP）：`CODE_STREAM_FAILED` 于 SSE error 帧（bridge.py:27/153/161）；`ApiError` 自抛现场 chat.py:57-60/136-146/200-215/233-243/300-307。

| 异常类（来源模块） | HTTP 状态码 | 响应体形 |
|---|---|---|
| `UnauthenticatedError`（infra/security/domain.py:73；handler errors.py:73-78） | 401 | `{"code":"security_unauthenticated","message":str(exc)}`（str 含未登记键与五角色键清单，domain.py:93-96） |
| `RunNotFoundError`（runtime/executor.py:78；handler errors.py:80-85） | 404 | `{"code":"chat_run_not_found","message":str(exc)}` |
| `RunNotSuspendedError`（runtime/executor.py:82；handler errors.py:87-92） | 409 | `{"code":"chat_run_state","message":str(exc)}` |
| `RequestValidationError`（fastapi.exceptions；handler errors.py:94-110） | 400（收口 fastapi 缺省 422） | `{"code":"request_invalid","message":"入参形状非法","detail":{"errors":[{"loc":[...],"msg":"…"}]}}` |
| `ApiError`（appv2/api/errors.py:35-50；handler errors.py:66-71） | 构造传参 `status_code`（chat.py 现用 400/404/409） | `{"code","message"}`＋可选 `"detail"`（仅 detail 非 None 时占位，errors.py:56-60） |
| 流内异常（非异常映射——SSE 帧路径，bridge.py:153/161） | 无 HTTP 状态（帧） | SSE error 帧载荷 `{"code":"chat_stream_failed","message":…}` |

- T-P9a2-22 错误包形状单点：`error_payload(code, message, detail=None) -> {code, message[, detail]}`（errors.py:53-60）——重写后字段名与缺省省键行为等值。
- T-P9a2-23 码值闭世界七值（errors.py:26-32）：`security_unauthenticated / request_invalid / chat_param_invalid / chat_last_event_id_invalid / chat_run_not_found / chat_run_state / chat_stream_failed`；V2 不新立码值，新立须登记票面差异清单（errors.py:9-13）。
- T-P9a2-24 400 收口：入参形状非法统一 400（fastapi 缺省 422 与合同冲突——errors.py:96-97 注释）；detail.errors 逐条 `{loc(list), msg}`（errors.py:103-108）。
- T-P9a2-25 接口层自抛：`ApiError(status_code, code, message, detail)`（errors.py:35-50）；现用现场＝Last-Event-ID 非整数 400 chat_last_event_id_invalid（chat.py:57-60）、参数非法 400 chat_param_invalid（chat.py:136-146/233-243）、重连与追问互斥 409 chat_run_state＋detail（chat.py:200-215）、run 不存在 404 chat_run_not_found（chat.py:216-221/300-307）。
- T-P9a2-26 流内异常不走 HTTP 映射：SSE 真流内异常收敛为 chat_stream_failed 错误帧（bridge.py:153/161）；HTTP 错误包只保证「开流前」判据（chat.py:52 注释「开流前＝错误包；非整数＝400 错误包不开流」）。

## 四、关键保证

- 身份面对外行为锚点（重写必须逐字等值）：头名 `X-Dev-User`；缺头/空白→aqiang 不 401；五角色键与 display 全集；非登记键→401 `security_unauthenticated`；`resolve_actor(str | None) -> Actor` 签名与抛错行为（OAuth 只换实现体）。
- 注入面对外行为锚点：`create_app` 形参名与语义（`registry=None`＝生产组合）；app.state 四键名 `db/agent_runtime/stream_registry/run_store`；deps.py 三个 getter 名（`get_runtime/get_registry/get_run_store`）与 Annotated 别名（`CurrentActor/RuntimeDep/RegistryDep/StoreDep`）。
- 错误面对外行为锚点：六行映射表的状态码/码值/响应体字段形；错误包字段 `code/message/detail`；400 收口（含 422 改写）与 401/404/409 判例。
- 装配顺序锚点：先 registry（含生产补齐）→ guide → models → executor → app 建体 → handlers/router → app.state → lifespan（app.py:205-254）。

- 疑点（只列不判）：
  1. 409 双源：`ApiError` 自抛（resume/followup 互斥，chat.py:200-215，code=chat_run_state）与 `RunNotSuspendedError` handler（errors.py:87-92，同码同状态）——两种异常路径同对外形，重写归类时需注意保持两源都映射一致。
  2. 404 双源：resume 缓冲缺失（chat.py:216-221，消息「run 不存在（或不在本进程缓冲内）」）与 store.get_run None（chat.py:300-307，消息「run 不存在」）——同码 chat_run_not_found，消息措辞不同。
  3. 401 消息回显：`str(exc)` 含 `X-Dev-User={actor_id!r}` 原值回显与五角色键清单（domain.py:93-96）——是否合规待 Owner。
  4. domain.py:8-9 注记「V2 是否沿用 V1 五角色表待 Owner 裁决」——本次实读实现已沿用五角色表，裁决落点未在本文件闭合。
  5. 五角色 display 值标注照抄 prototype roles.js 冻结值（domain.py:37 注释），原型真源在 teach-petro-agent 仓——本次未出仓逐值比对。
  6. `app.state.production_composition`（app.py:253）本次未在 appv2/api 内 grep 到消费方——用途/消费方待确认。
  7. `who_of` 回退 `resolve_actor(actor.user_id)`（runtime/audit.py:59）在异常 user_id 下会抛 `UnauthenticatedError`，该异常在 runtime 审计路径的归宿（executor 转 notice 出流，audit.py:8-9 附近注记）与 HTTP 映射无关——重写时归属需保持。
  8. `load_object_digests` 无缓存、每次调用读 yaml 文件（ontology_guide.py:52-54）——调用频率与重写后是否保留逐调用语义待确认。
  9. `install_error_handlers` 只由 `create_app` 调起（app.py:247）——若重写后出现不经 create_app 的入口，错误包形状无守卫；装配面契约未机器化校验。
