## 四、关键保证与边界

- 引擎接触保证：唯一通道 ToolRegistry.call；引擎方法名/形参签名＝QueryFace/RetrievalFace Protocol（handlers.py:95-112）逐字；返回形＝ToolResult 四字段（status/observations/ask/error）。引擎零写路径（INV-2）。
- 引擎错误保证：引擎不抛业务异常（六态收口/空集回退），工具层统一三分类，runtime 只按 category 决策——三层职责不互串。
- 审批态保证：runtime 的 `approved_tables` 只经 ToolContext（graph.py:1146）进引擎，不进工具 args、不重排计划（graph.py:1143-1145 注记）。
- 模型缝保证：runtime 唯一触网点＝`Completer.complete`（自写 Protocol）；caller 归因前缀 `v2.runtime.`＋三桶；run_id 逐调用随行；alias 空串语义；Completion 八字段＋usage 三字段键名。
- 网关重试保证：runtime 只看 429 退避（≤3 次/5-20-60s/env 可覆写）；网关切换/记账/熔断/并发门对 runtime 不可见但不得改动可观察结果（NoAvailableRoute 形、served_alias/fallback 标记）。
- 基建保证：DB 只经 ConnectionManager（B3）；时间只经 infra.clock（B14）；审计只经 SecurityService.audit（B12）；身份只经 resolve_actor（硬纪律 4）——四红线在 runtime 侧的落点文件与行号如上，重写时替换物＝注入实现，调用面签名不变。
- 装配保证：引擎/网关生产实例在组合根一次构造（api/app.py:55-121 引擎；226-245 模型与执行器）；runtime 构造形参名（registry/models/db/saver/budget/builder/security/guide/today/four_phase/ledger_dump/watermark/data_wells/object_digests，executor.py:134-155）为注入契约。

- 疑点（只列不判）：
  1. **cached_tokens 断层**：LlmCompletion 有 `cached_tokens`（llm_client.py:87），网关投影 Completion 无此字段（gateway/domain.py:47-58）——runtime 经 GatewayChatModel 看不到 cache 命中数；重写是否在网关投影层补字段未决（牵动 _settle 与 SpendRecord 列）。
  2. **MODEL_KEYS 双定义**：runtime/graph.py:325 与 api/app.py:52 各写一份三桶元组（同值）——caller 桶契约的单一真源位置未在任一文件声明为权威。
  3. **Protocol 无运行期校验**：QueryFace/RetrievalFace 是 mypy 结构判据，registry 构造不 isinstance 检查（handlers.py:95-112；registry.py:115-127）——引擎方法重命名只在类型检查/首调用时暴露。
  4. **window_note 字符串解析面**：handlers.py:813-827/829-842 从人话串反解「缺位来源」——重写检索供给层文案会静默破坏这两个解析点（无机器闸覆盖声明）。
  5. **超时归属**：工具超时是 runtime 侧等待（graph.py:2142-2155），超时后 registry.call 的协程被取消——引擎侧半途状态（PG 查询取消语义）未在本次范围验证。
  6. **audit 写口空 actor 回退抛错**：`who_of` 回退 `resolve_actor(actor.user_id)`（audit.py:59）对异常 user_id 抛 UnauthenticatedError；runtime 审计路径的归宿（executor._audit 转 notice）与 HTTP 映射无涉——与 P9a2 疑点 9 同一处，重写需保持归属。
  7. **`_DOMAIN_ONLY_PARAMS` 是网关私有常量**（service.py:45-47）：runtime 的 run_id 盖章依赖它不转发上游；常量名/成员属网关内部细节，外部契约表述（run_id 落账、note 记备注）散在 docstring 与 SpendRecord 列定义处——重写对齐点需明确以哪处为准。
  8. **PgQueryExecutor 逐调用建 ConnectionManager**（pg_executor.py:9-20/127-133）：连接池与事件环生命周期随调用建拆；runtime 不可见，但属出向链性能/资源特性——重写审查接触点链时需保留或显式改判。
  9. **检索精排自带网关缝**（engine.py:66-68/110-116）：检索域独立持 completer＋caller `agent_v2.retrieval.*`——与 runtime 的 `v2.runtime.*` 归因并存；重写 runtime 不涉及，但若统一 caller 命名会撞检索域。
  10. **runtime 侧 `transaction()` 零消费**（本次全仓 grep 未见 runtime 调用）：run 创建与审计行非同一事务——审计行独立性是当前语义；重写若合并事务即行为变化，需 Owner 裁决。
  11. **`ensure_ready` 先置后建**（audit.py:76-81）：并发受理下 `_ready=True` 先于建表完成——checkfirst 幂等兜底；重写建表策略时该顺序语义需保持或重审。
