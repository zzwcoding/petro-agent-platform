## 三、新业务逻辑提案（重新表述）

### 3.0 总原则（继承 Owner 拍板，作为重写公理）

1. **三职分离**：身份、格式、路由**不许压进同一段提示词**（P6a A-P6a-01）；第二步三层重组（身份层/契约层/数据层，每层一文件单一职责）是本模块的**目标形态**（P6a A-P6a-06）。
2. **模型管判断，程序管格式**：判别面（路由）放宽交模型，机读合同面（格式）冻结交程序（P6a A-P6a-07）。
3. **语义问题归 LLM，程序只做两件事**：装配上下文（喂够信息）＋检查发射物格式与前置合规；**代码不做语义裁判**（V2-58 A-P4b-19/21）。
4. **提示词写「做什么」不写「不做什么」**；判断依据是原则不是例子集（P6a A-P6a-03）。

### 3.1 路由原则（推翻现状的「两出口并列猜测」）

新逻辑：**默认走重管线**——理解步只判一个问题「这句话是否**可能**与油田数据业务有关」（业务范围正面定义）。
- 「可能有关」（哪怕一点关联/含糊/拿不准）→ 两行式，进后续管线；
- 只有「确定无关」（寒暄/道谢/道别/无关闲聊）→ 直答；
- 直答行以「油田数据问答助手身份友好回应＋引导到油田数据话题」承载（**正向写法**，身份泄漏失去出口、编造无据可依）（P6a A-P6a-16/17/18）。

### 3.2 直答认领的确定性闸（新增，双保险）

模型认领直答后，**必须**过一道零模型程序闸：拿**用户原话**（不是模型输出）过业务词面闭世界，含任一实词＝拒认直答、程序确定性转两行式（理解行＝原话逐字、候选空）＋发机读 notice（可统计误判率）＋开关可整体回退（P6a A-P6a-25..32，即 V2-80c）。
- **效果**：把「模型猜错」的最坏后果从「编造直达用户」变成「多走一次管线」（P6a A-P6a-25 原文）。
- `【待裁-M1-1】` V2-80c 默认开关值：方案 §4 写「默认 off」、票面伪代码写「缺省 true」——两处冲突（P6a V2-80c 疑点），须定一个。

### 3.3 出口契约（待裁：是否统一 JSON）

现状两出口靠**格式分叉**（两行式 vs 直答行）区分。P6a A-P6a-09 建议③指出「分类靠枚举字段不该靠格式分叉」，方向是统一为一个 JSON（加 `can_answer_directly` 字段），但消费面（指标候选白名单闸/理解旁白灰条/直答通道）要同步迁移——已列为缓行项（无承接票）。
- **提案**：本模块重写时**一并迁移为统一 JSON**（一次到位，避免「新逻辑仍带旧格式分叉」），消费面同步改。`【待裁-M1-2】` 是否采纳（若否，维持两行式逐字契约，P6a A-P6a-09 不动）。

### 3.4 安全闸族重构（推翻「N0/N1 两族硬编码」）

现状 N0（词面族硬编码 + 无豁免）与 N1（台账禁用词 + 有豁免）是**两套平行实现**（P6）。新逻辑：

- **统一为一个「入口词面安全闸」单点**：一条判定流水线，族间共享匹配方式与豁免语义；**收口骨架单点化**（消除 P6 两处平行实现）。
- **匹配方式统一**（消除 P5）：英文/混合词面统一 casefold 折叠。
- **豁免对称**：N0 的注入族保留「无豁免」（注入无元问语义，V1 同）；但**外发/写意图族引入与 N1 同构的元问/引用豁免**（解 P4 误伤——「删除的数据还能查到吗」类元问应放行）。
- **分型键名改正**（解 P7）：机读分型键从 `n1_gate` 改为语义正确的 `gate`（或按族名）。
- **I/O 纪律显式化**（解 P13）：闸族若需读词典层，**声明为「一次取读、零额外副作用」**，与「零模型零执行」并列写进契约，不再自相矛盾。
- **缝取读次数统一**（解 P10）：闸族内**统一一次取读**，结果复用（含写回策略统一，解 P11）。
- **多命中处置明确**（解 P8）：多禁用词同句时**逐条判、全部非豁免项都拦**（不再是「首个豁免即整句放行」）——`【待裁-M1-3】` 是否改为全判（涉行为变化）。

### 3.5 解析与产物

- **解析器重写**（解 P15/P16）：以**显式契约解析**替换「冒号回退取整行」；同类行多次出现**报错或取最后一条并在产物中标注**，不再静默覆盖。
- **直答与理解产物互斥**（解 P12）：一次应答要么直答、要么理解，程序按契约强制二选一（新契约下由 JSON 字段天然互斥）。
- **产物落点**：理解文本与指标候选仍双出口（state 字段＋text 事件）；模型原话不入对话层（R-C-11 纪律保留）。
- `【待裁-M1-4】` 解析降级：新契约下是否保留 JSON 降级宽容（R-A1-16 现状），还是严格契约解析（拒因回喂）——涉容错度。

### 3.6 上下文与链（呼应 H6，本模块只声明接口）

- 任务书装配：静态骨架与动态活体数据**分节**（指令与数据不同段，P6a A-P6a-06）；动态数据程序渲染、永不与指令同段。
- 链纪律：**链尾追加、只追加不改写**（V2-80h）；任务书追加的**幂等性显式化**（解 P14，不再只靠拓扑）。
- 问句原文的链面处理（解 P17）：`【待裁-M1-5】` 追问/缓存面是否需要问句原话以类型正确的 user 消息进链。
