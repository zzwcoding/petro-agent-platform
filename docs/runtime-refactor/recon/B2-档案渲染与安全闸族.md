### `_render_process_notes`（L1278-L1302）｜process_notes→有界摘要段（头注＋逐条行；超预算截断必披露）

- 消费：`state.process_notes`（条目形 {phase,title,digest}，digest 由 `_note` 单点截 200 字 L1227-1229）；budget 参数缺省 `_PROCESS_NOTES_BUDGET`（三处调用点均用缺省，无覆盖）。
- 装配：调用方把返回段作独立 user 消息追加对话链链尾——decision L1718（每轮，有档案时）；clarify L2417／toolmatch L2717（先入 tail_parts，与回喂行并入同一条 user 消息）。understand 节点不消费本段。
- 分支表：
  1. `state.process_notes` 为空 → 返回空串 → 调用方 `if segment:` 跳过，不入链（首轮零噪声）。
  2. 行追加后 `total（头注长度起算）＋len(line)＋1 ≤ budget` → 追加 `- [{phase}] {title}｜{digest}`、total 累加 → 下一条。
  3. 行追加后超预算 → 追加截断披露行 `-（过程档案摘要有界截断——已渲染 {len(lines)}/{len(state.process_notes)} 条）` → break（后续条目不再检查；截断行自身不参与预算复检）。
  4. 全部条目入预算 → 无截断行，返回头注＋全部行。
  5. 首条即超预算 → 0 条渲染，仍返回头注＋截断行（披露 0/N）。
- 副作用：无（纯字符串；不发事件、不写库、不改 state）。
- 返回：str（`""` 或 `_PROCESS_NOTES_HEADER + "\n" + 行…`）。
- 规则条目：
  - R-B2-01 零档案零段：process_notes 为空 → 摘要段不渲染，不占链（首轮零噪声）。
  - R-B2-02 有界渲染：摘要段总长（含头注）受 budget=400 字约束，逐条追加、超即止。
  - R-B2-03 截断必披露：超预算时追加「已渲染 n/总数条」账目行，不静默丢失（截断行本身免预算复检）。
  - R-B2-04 摘要定位：段首头注逐字声明「防重参考，不是作答材料」——摘要段永不以对话轮出现（只作指令 material 拼进当前轮 user 消息）。
- 耦合：`RunState.process_notes`（appv2/runtime/state.py L192）；本段常量 L1274-1275。测试直调：tests/domains/test_v2_multi_turn_context.py L786-797（断零段与截断披露）。
- 疑点：
  - D-B2-07 截断行在预算判定之外直接 append（L1294-1299）——输出总长可略超 400 字预算，越界幅度无定义；首条即超预算时披露为 0/N。
  - D-B2-08 截断披露只有条数账（已渲染 n/总数），不含被截条目的 phase/title/digest 摘要——模型面不知道自己丢了哪类记录。
