### 1.2 ① 根因：交付字段是**对象**，`extract_finalize_answer` 只认字符串
- 模型原话（`logs/llm_calls/20261019.jsonl`，`caller=answer`）逐字：
  `{"action": "finalize", "answer": {"text": "W-32 井「检泵周期」栏的 215 天…", "citations": [{"source": "[1]", "loc": "指标台账·检泵周期"}]}}`
  ——整应答**恰一枚** finalize JSON，`action` 正确，但 `answer` 是 **dict**。
- `appv2/runtimev2/answering/emission.py:92-117` `extract_finalize_answer` 三条件齐才提取；条件③在 `:115`：
  `if not isinstance(answer, str) or not answer.strip(): return None` → **dict 判负 → 零提取**。
- 随即 `appv2/runtimev2/answering/core.py:611` `strip_emission_fences(source_text)`：
  - 无围栏 → 规则 1 零动作；
  - 规则 2（`_line_has_emission_token`，`emission.py:120-151`）对 `"finalize"` 命中后，尾段 `, "answer": {…}` 的 `{` 落在最近 `}` 之前 → **不咬**（嵌套花括号窄口径）；
  - 规则 3（`_line_is_bare_json`，`emission.py:154-159`）→ 整行可解为 JSON 对象 → **整行剥除**。
- **为何是「整篇」而不是逐行／逐块**：`emission.py:196-200` 的规则 2/3 是**行级**判据，而该应答**整篇 0 换行**（`content.count("\n")==0`）——「一行」＝「整篇」。剥除粒度不是缺陷本身，**粒度与「整篇包成一枚 JSON」的模型形错配**才是。
- 兜底「不推空答案」**生效了**，但只是「不编造」：`core.py:671-674` 零 text 帧、`state.draft` 保持空、`gaps` 落 `missing`；`gaps` 是**审计面**（`constants.py:128-137` 逐字：四个 `*_REASON` 只进 payload，`web/src/landing/*` 不渲染 `gaps`）⇒ 用户可见面仍为空。**「不推空答案」不是「不空交付」兜底**。
- 判分称「`emission_strip` 判定『混进程序格式内容』后把整篇正文去掉」——方向对，但**主因不是格式闸**：正文完整存在（就在 `answer.text` 里），是**提取器只认字符串**把可恢复的正文判成不可恢复（判分归 C6 评测口径／我核为 C6＋提取器缺陷）。

### 1.3 ② 根因：模型回**上一相位的发射形**（工具匹配），同样零提取
- 模型原话开头逐字：`{"matches": [{"id": "s1", "chain": "data", "tool": "data_query", "mention_mode": "executed", "plan": {…}, "result": {"rows": [{"日期": "2026-08-29", "区块": "渤南", "井号": "N-01", "日产油量（吨）": 18.65}, …`，尾段 `… "engine_notes": "窗口 2026-08-29~2026-08-31（近 3 天，按数据水位 2026-08-31 收口）…"}, "truncated": true, "total_rows": 50}]}`。
- `{"matches":[…]}` 是**工具匹配相位**的发射形（`appv2/runtimev2/tool_matching/matching.py:250`、`parsing/parsers.py:307`），**无 `action` 键** ⇒ `extract_finalize_answer` 条件②（`emission.py:112`）判负；`parse_explore` 亦不认 ⇒ 无回喂重读（该 run 仅 1 次 `caller=answer`）。
- 同 ① 的规则 3：整篇 0 换行 → **整行剥除** → 空稿。**与 ① 同一根因族**（`extract_finalize_answer` 覆盖面窄＋整行剥除粒度），**不同触发形**（① 交付字段非串；② 相位形错位）。
- 判分称「resume 后 `emission_strip` 抹空正文」（判分 B §四-5 归「答案收口」）——我核为：剥除在**起草步**，且抹空的是**回声 JSON**（模型未作答），非「已写好的正文被抹」；判分 B 归因「答案收口环节掉链」不确。

### 1.4 ③ 根因（**与 ①② 不同**）：澄清槽位对账四连拒 → 轮预算耗尽 → 零材料收敛

### 1.5 R4 判定汇总
- **①② 同因**（`extract_finalize_answer` 只认 `{"action":"finalize","answer":<非空串>}` ＋ 行级剥除遇「整篇单行 JSON」＝全删）；**③ 异因**（澄清槽位对账闸教具／判据不自洽 → 四连拒 → 轮预算耗尽 → 零材料收敛占位串）。**三例并非同一根因**。
- 判分口径差异：跑批行 `status=waiting_ask` 是 runner 派生值（`eval/suite-147/runner.py:273-276`：帧列含 ask 帧即标 `waiting_ask`），与帧末 `verdict=completed`／`server_status=completed` 不矛盾；`数-反1` 不应按「挂起未答」读。
- **修法落点**：
  1. **收口空答兜底**（①②）：`emission.py:100-117` 条件③放宽为「`answer` 为串**或** mapping 且其 `text` 为非空串」时取 `text`（与 V2-82g 同精神：程序接管输入侧、合同零新增）；② 可另加「整枚 `{"matches":…}` 形＝相位形错位」的回喂重读一次（复用 `core.py:570-591` 的 explore 回喂机制），或至少把「零草稿」路径降级为**非空**的程序化如实收口正文（复用 `MISSING_DRAFT_REASON`／收敛正文装配）。
  2. **剥除粒度**：`emission.py:192-201` 行级规则加「整篇恰一枚 JSON 对象且含可交付字段时先取字段」的前置提取（即 1 的同一处），避免「一行＝一篇」的全删。
  3. **收口闸降级**：`core.py:671-674` 与 `:711-722` 的空稿路径应产出**用户可见**的如实短句（当前只有机读 `gaps`，`constants.py:128-137` 明写不上屏）——即判分 A §六-1「正文全删时降级为告警而非清空」的正解。
  4. **审批帧保留**（③）：审批面本身无需改；修 `clarification/core.py:619` 段一判据与 `prompts/decision_round.py:223` 渲染面的**同一性**——二选一：名录增补 `value` 行首名形，或渲染面首名改用 `slot`；同时把 `constants.py:238` 【期望形】与判据对齐（否则教具继续把模型引向必拒形）。
