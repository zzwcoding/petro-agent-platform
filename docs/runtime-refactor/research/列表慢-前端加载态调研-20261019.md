## 一、现象复现（file:line 链）

1. **「暂无历史对话」全程冒充加载态**：`ThreadList.jsx:81` `loadState` 初值 `'ok'`（非 `'loading'`）→ 首帧即走空态；`:91` `load` 才置 `'loading'`；`:154` `emptyText` 三态只判 `error`／`searching`／其它，**`loading` 落回「暂无历史对话」**。故 mount→响应落地全程出空库文案。
2. **触底＝重拉全量**：`:124-130` `limit+pageStep` → `load(next)` → `:93` `fetchRuns(limitValue)`；后端 `appv2/api/chat.py:189-221` **无 offset**、`limit` 夹 1..100；每行含 `answer`（`:214`）与 `supplements`（`:218`）。步进 20→100 共重拉 20+40+60+80+100＝**300 行**换 100 行视图。
3. **分组每次渲染重算**：`ThreadList.jsx:117` `groupRunsIntoChains(window)` 未 memo；`:76` `maxRows=100`。
4. **选中链＝N 次串行 HTTP**：`A1V2R.jsx:368-390` `onSelect`，`:376` `for (const r of chainRows)`＋`:378` `await getRunV2(r.run_id)`；期间中栏无加载态（`:448-457` 仅在 `viewTurns.length===0` 出 `flow-empty`，`chain` 未 set 时中栏停在旧内容）。

## 二、规格约束逐条原文（specs/frontend-redesign.md）

**L1（:119）逐字**：「初始 `GET /runs?limit=20`；加载更多＝**滚到列表底部**（离底 ≤40px）触发、limit 步进 +20 重拉全量替换（最新在上、更早在下）。**零按钮零提示**（Owner 2026-10-17 打磨批⑦：原「加载更早」按钮与「已到最早」小字退场；窗口数>库数时的「已载入 N / M」旧计数行随按钮消失）；**exhausted 判据**（拿到响应后）＝新 runs 行数＝旧行数（没有新内容）**或** 行数 < limit（库比窗口小）→ 此后不再 fetch（静默）；limit ≥ maxRows 亦不再 fetch。」

**验收表 #14（:156）逐字**：「ThreadList 真接：初始 limit=20、步进至 100 封顶（零按钮零提示，到头静默；exhausted 后不再 fetch）」

**其余相关行**：L2（:121）搜索＝前端过滤零请求；L3（:122）「选中行→拉该链轮次…渲染中栏」；L4（:123）一链一行（行＝最早轮问句 18 字截断，副行＝`{最新轮状态} · {链轮数} 轮 · {MM-DD HH:mm}`）；L6（:125）收口刷新重拉全量、limit 回 pageStep；H2（:98）history 投影不补造；E4（:107）无数据源展示位不渲染、不出旧版说明句；E7（:110）徽标不上屏。
**FE-04／UI-14 不是规格行**：FE-04＝票 `tickets/frontend/FE-04-历史列真接与拉链.md`；UI-14＝票 `tickets/phase1-ui/UI-14.md`（「失败≠空库」纪律被 `ThreadList.jsx:21-22` 与 `ThreadList.test.jsx:22` 引作依据）。spec 内无 FE-04／UI-14 编号行（`grep -rn "FE-04\|UI-14" specs/` 仅 :70 一处顺带提及 FE-04）。

### 结论：「零提示」是规格明文，但列举对象不含加载态
「**零按钮零提示**」**逐字出现在 L1:119 与验收 #14:156**，是 Owner 2026-10-17 打磨批⑦ 的规格化。但其**列举对象**＝分页入口（「加载更早」按钮）／到头提示（「已到最早」小字）／计数行（「已载入 N / M」）；**首屏·刷新在途·加载更多在途的「加载中」态从未被列举**。故加加载提示**必须同批改规格**（否则与 :119/:156 的无限定整句字面冲突）：

|---|---|
| `specs/frontend-redesign.md:119` | 在「**零按钮零提示**」后插限定：`（限分页入口与到头提示——首屏/刷新在途的加载态另见下；按钮仍零）` |
| `specs/frontend-redesign.md:156` | 验收 #14 同插限定：`（零按钮零提示＝分页入口与到头提示；加载态提示见 #33）` |

## 四、渲染成本实测（本地只读跑，未写仓内任何文件）

**方法**：node 22.22 内联脚本（`node --input-type=module` 从 stdin，零落盘）——`groupRunsIntoChains` 直 import 计时；`ThreadList` 经 esbuild 内存打包＋jsdom＋`react-dom/client`＋`act` 渲染（React **dev** 档，非 production）。

**A. `groupRunsIntoChains`（`cites.js:90-110`，200 次均值）**

| 输入行数 | 链数 | 平均耗时 |
|---|---|---|
| 20 | 20 | 0.0079ms |
| 100 | 100 | **0.0183ms** |
| 500 | 500 | 0.0551ms |
| 500（单条深链） | 250 | 0.0620ms |

→ 100 行量级 ≈ **0.02ms**：**分组不是瓶颈**，memo 化收益≈0。

**B. `ThreadList` 整件渲染（jsdom dev，7 次中位；DOM 节点含 antd 包裹）**

| 行数 | 首渲 | 稳态重渲 | DOM 节点 |
|---|---|---|---|
| 0 | 93.6ms（冷启） | 1.9ms | 17 |
| 20 | 10.1ms | 2.3ms | 97 |
| 100 | 14.0ms | **3.8ms** | 417 |
| 500 | 31.0ms | 14.9ms | 2017 |

→ 100 行渲染 ≈ **4–14ms**（dev＋jsdom；浏览器 production 更小）：**渲染不是瓶颈**。

**C. 真瓶颈（引姊妹篇真机数＋本次抽样）**：现状 `limit=100` 响应体 **247KB**（2055 行真实样本，均值 **3.3KB/行**；`answer` 全文随行，均值 2895B／最大 100,580B——`列表慢-后端读口调研-20261019.md` §1）；`limit=20` 亦 **31.5KB**。叠加：步进 20→100 共重拉 300 行（§一-2）＋选中链 N 次串行 HTTP（§一-4）。另一样本（27 行／105KB）测得 `answer` 24.5%＋`supplements` 72.3%（`列表慢-票面边界与闸-20261019.md:123`）——占比随样本而异，绝对量级一致。左栏只消费 `question/status/created_at` 三个短字段，**余下载荷对左栏是纯浪费**。
