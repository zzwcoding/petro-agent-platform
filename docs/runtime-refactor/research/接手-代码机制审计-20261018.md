## 一、总览（六面各一段）

**① 角色与承载位——合规，但只做了一半。** H 批「规章＝调用级 system、动态段＝user 入链、链首背景块 system 恰一条」已真落地且有端到端机检（`prompts/task_book.py:183-190`、`prompts/answer_round.py:76-98`、`bookkeeping/closing.py:235-245`、`orchestration/runtime.py:404-408`；`tests/domains/test_v2_four_phase.py::test_system_slot_request_layout_end_to_end`）。偏离在**另一半**：同一条链身兼「决策过程」与「作答输入」两种角色，`state.messages` 里 user 位同时装着「指令性动态段」（任务书数据区／答案题面件／增量条）与「材料」，assistant 位同时装着「动作 JSON」与「终稿」——承载位按**相位**分了，没有按**角色/来源**分（见 M1、M4）。

**② 追加链与 KV 前缀——追加形合规，去重只覆盖 run 级两件。** 只追加有写口与断言（`bookkeeping/ports.py:110-120`、`tests/domains/test_v2_bookkeeping.py::test_messages_append_only`）；run 级共享上下文（§A＋台账常驻块）只注一次有机制有测试（`orchestration/graph.py:478-491`、`tests/domains/test_v2_four_phase.py::test_decision_shared_context_injected_once_per_run`）。偏离三处：**追问 run 整链承接后又重注一遍**（M6）、**恢复选择双写**（M10）、**超窗压缩是死码且判据恒假**（M5）。跨相位首调用前缀必断已在规格里明示接受（`specs/prompts.md:184②`），不算缺陷。

**③ 上下文装配面——渲染层合规，账本层缺失。** 材料段确定性渲染、检索族帽＋披露行、血缘卡瘦身成口径行、材料面 Manifest 四列表皆在位（`context/materials.py:131-184`、`context/manifest.py:35-97`、`tests/domains/test_v2_context.py::test_manifest_material_fields_and_reason`／`::test_truncation_disclosure_line_verbatim`）。偏离：Manifest **只覆盖材料面**，不覆盖「本次请求窗口里的链级注入件」（任务书／共享块／锚行／增量条／规章）——没有一处能回答「这条 19k token 的 prompt 里什么各几份」（M-缺口 G1）；帽只对检索族生效（`context/materials.py:149-151`），链条目无任何上界。

**④ 答案相位——机制层靠提示词补位。** 起草真流式一段一帧、剥离管线四层（围栏／裸 JSON／占位符／程序块）、收口同批落 citation 帧与链尾、交付面分层走增补面，均合规且有测试（`answering/core.py:250-345`、`answering/emission.py:192-201`、`transport/blocks.py:73-113`）。偏离：**回声源没有被隔离**——答案调用把整链（含每次决策的原始动作 JSON）原样送给模型，抑制手段只有 system 合同第⑦条＋事后剥离＋一次输入侧提取热修（M1）；**空稿零重试**（M3）；材料与题面拼成同一条 user（M4）。

**⑤ 路由与澄清——程序分派合规，回炉由头断链。** 路由集中在单表、意图单写口、相位零跳转（`orchestration/graph.py:100-146`、`bookkeeping/ports.py:197-206`）；对象歧义 ask 门程序化且预算受制（`clarification/subject_ask.py:80-145`）；读题只按 `route` 分派、直答结构核验退回（`understanding/interpret.py:156-169`）。偏离集中在「回炉」这一跳：换链回炉轮在链上**没有回炉由头**，三处判据同时失效（M2）；ask 上限两套闸口径不一致（M11）；歧义门的关键输入槽仍以模型输出为第一判据（M8）。

**⑥ 核验与交付——零模型核验合规，回写口径偏窄。** 逐行断言判、无据删句＋计数＋notice、矛盾分源、归属审、行集对账、verifier 抛错 fail-closed，全在位（`verification/core.py:198-325`）。偏离：删句结果只写 `state.draft` 与 step payload，**交付面不出现「删了什么/为什么」**，`AnswerDraft.gaps` 在收口段恒为 `[]`（`answering/core.py:411-423`），缺口只经 notice 帧与步账——「答案少了三句」这件事在链路账本里不可复算（M-缺口 G4）。

## 二、发现清单

### M1（P0）答案相位请求直送全链：前序动作 JSON 与交付文本同链，回声源未隔离
- **现象**：每轮决策的模型原话（含 `{"action":"ask"/"decompose"/…}`）原样作 assistant 条入链；作答相位把 `state.messages` 整链送模型。设计上这是「模型可见自己历史输出」的有意选择（`clarification/core.py:181-182`、`tests/domains/test_v2_multi_turn_context.py:106-112`），但**没有为作答任务构造视图**：回声抑制只靠 system 合同第⑦条（`prompts/constants.py:249-251`）＋事后 `strip_emission_fences`（`answering/emission.py:192-201`）＋一次性输入侧提取热修（`answering/core.py:284-291`）；`echo_flag` 明写「只记不拦」（`answering/degradation.py:162-171`）。
- **证据**：`clarification/core.py:182`（原话入链）｜`tool_matching/matching.py:147`｜`understanding/interpret.py:223`｜`answering/core.py:281-283`（`call_model(..., list(state.messages), system=…)`）｜`answering/core.py:289-291`（finalize 提取热修，真机 `run-9d1c5267`）。
- **最佳实践**：`BP-节点-读题步 §②10`（严格用 chat 角色传信息、禁自行拼接——「把工具结果混进 user 消息等于抹掉模型辨别来源的依据」）＋`§②11`（区分指令与数据）＋`BP-2a §五-1`（静态前缀不动、动态只追加）＋`对照表 C2`。
- **影响**：全部十题；尤其 C-反1／D-诱12 的作答回声与 NQ-C6／NQ-C9 的越相发射。
- **建议修法**：在 `call_model` 之上加一层**视图构造**（不是改链）：作答调用的视图＝链首内规章上下文＋各轮 user 动态段＋本次材料段，assistant 条只保留终稿/非发射段（发射条在视图层按「整条可解为发射 JSON」形态过滤，不改原史、不进 checkpoint）；`echo_flag` 由「只记」升级为视图层闸的机读旁证。
- **优先级**：P0。

### M2（P0）换链回炉的「回炉由头」三处同时断裂（A14）
- **现象**：前置判定触发换链 → 路由回澄清改链，但**回炉轮链上没有「为什么回炉」**，模型只能拿同参重发 → 撞「一次为界」→ 终局拒答/空交付。三处断点：①`rejection_guidance` 的绑定拒段读一个生产中不存在的键；②回炉条只读执行阶段结果，前置阶段的换链提议不在其中；③词面触发表与引擎拒因原文不同族。
- **证据**：`clarification/guidance.py:35`（读 `verdict.get("state") ∈ VERDICT_REFUSAL_STATES`）vs `preconditions/models.py:130-138`（投影键是 `decision`）→ ①段恒缺席｜`preconditions/core.py:243,263`（换链提议只落 `notes`，不入链）｜`prompts/decision_round.py:484-494`（`_rework_block` 只扫 `subtask_results`）＋`clarification/core.py:298-300`（增量条唯一内容＝预算行，`prompts/decision_round.py:512-514`）｜`prompts/decision_round.py:123`（触发词 `("未绑定","不在台账")`）vs `appv2/tools/fake.py:111`（原文「不在指标台账——」）→ 子串校不命中。
- **最佳实践**：`BP-节点-批量执行 §②10/13`（失败先分类再决定重试／换路，换路不得静默）＋`BP-节点-批量执行 §②13`（把拒绝理由当作一次失败写回轨迹、让模型据此改法）＋`对照表 T3`；`docs/runtime-refactor/全链路全景图-Owner判读版.md:114`（A14 已登记，含同样两处判定）。
- **影响**：B-正6（空交付根链）；同族 D-诱9／C-正4。
- **建议修法**：回炉由头改为**结构化装配**——前置判定结论（`decision`＋`hit_rule`＋`notes`）与执行失败档（`bad_args`/`retryable`）合流成「本次回炉由头」增量条一件，由编排按「本腿是否新落换链计点」下传；`rejection_guidance` 的 ① 段改读结构化判据（禁文案子串判定）。
- **优先级**：P0。

### M3（P0）起草空稿零重试：V1 的「同相位重试一次」在 V2 未迁移
- **现象**：起草调用后无论是否剥成空稿，都先落「已起草」标记；空稿分支直接 `set_intent(END)`，只产缺口，不做第二次起草。真实病历（模型只回一枚发射 JSON／围栏全被剥空）在 V2 直接零交付。
- **证据**：`answering/core.py:302`（无条件落起草标记）＋`answering/core.py:335-338`（空稿→END，无重试）；对照 V1 `appv2/runtime/graph.py:3904-3911`（「零余量→同相位重试一次→交付重试草稿」，钉在 `tests/domains/test_v2_v248_draft_face_isolation.py:173-199`，该用例**只覆盖 V1**）。
- **最佳实践**：`BP-节点-批量执行 §②10/13`（可重试档 vs 修参档；重试封顶）＋`对照表 T3、G1`（失败题冻成回归项）；工程常识（V2 迁移须做机制对等表）。
- **影响**：数-闸2 形／NQ-C6／NQ-C9（发射形整段被剥空即零交付）。
- **建议修法**：起草段收口前判「剥后零余量」→ 同相位重试恰一次（重试事实落 payload／notice），仍空才走缺口收口；同时补 V2 侧的对等回归钉。
- **优先级**：P0。

### M4（P1）指令与数据拼成同一条 user 消息（题面件＋材料段＋引擎注记）
- **现象**：作答轮的 user 条＝答案装配动态段＋材料段＋引擎注记段，三件混为一条；材料（模型外部不可信输入）与「本步要你写答案」的指令同层。材料帽披露行是**同一层内**的一句，不是结构边界。
- **证据**：`answering/core.py:272-280`（`assemble_answer_prompt(...) + materials_text + engine_notes_block(...)` 一条 `append_message`）。
- **最佳实践**：`BP-节点-读题步 §②10/§②11`（来源标记＋结构化角色；外部内容包裹并标注来源，不得自动升级为系统指令）＋`对照表 C2`。
- **影响**：全部十题的引用精度与「跨源冒充题眼」面（B-正6／D-诱12）。
- **建议修法**：材料段与引擎注记段各自成条（或单条内以定界包裹＋来源帽包裹），使「指令 vs 数据」在消息层可分；帽与披露行的位置由装配面固定，不改文本。
- **优先级**：P1。

### M5（P1）超窗 compaction 未接线，且识别面判据恒假（链只增不减）
- **现象**：`compact_messages` 无生产调用点；其「对话轮」判定读条目的 `origin` 键，而 `append_message` 落地的条目恰两键（无 `origin`）——即使接上调用点也永不压缩。规格明确「压缩唯一调用点＝编排面」。
- **证据**：`context/compaction.py:48-50`（`entry.get("origin") ∈ DIALOGUE_ORIGINS`）＋`bookkeeping/ports.py:120`（`{"role","content"}` 恰两键）→ 判据恒假｜全仓仅 `context/__init__.py` 导出与 `tests/domains/test_v2_context.py:563-650` 单测，无编排调用｜`specs/context.md:117`（唯一调用点＝编排面、触发参数注入制）、`:143-144`（挂点测试）。
- **最佳实践**：`BP-2a §4.1-5`（压缩是 Commit→Compact→Rebuild→Validate 状态迁移，不是纯摘要）＋`BP-2a §五-2`＋`对照表 C6`；规格 `specs/context.md:168`（风险 6 自陈）。
- **影响**：追问链与长 run（`specs/prompts.md:184②` 已计缓存代价；真机 19359 token 面）；非十题直击。
- **建议修法**：二选一并登记——(a) 写口侧给 messages 条目加 `origin` 标记 ＋ 编排接调用点 ＋ 压缩账目合成进 Manifest；(b) 裁定 V2 不做 compaction，把该公开面降级为「未接线」并从契约面摘除，避免死码长期冒充机制。
- **优先级**：P1。

### M6（P1）追问 run 把已在前链的信息再注一遍（任务书＋run 级共享上下文）
- **现象**：追问 run 整链承接前轮终链（含前轮任务书、§A、台账常驻块），但本轮「是否已注」的判据是**本 run** 的 `contracts_appended`／`process_notes` 标记（新 run 恒为空）→ 再装配一份任务书、再注一份 §A＋台账全量块。窗口内同文本出现两份，且前一份带着前轮的题干与水位。
- **证据**：`orchestration/runtime.py:392-396`（整链承接，只拷 role/content）｜`understanding/assembly.py:88-115`（判据＝本 run `process_notes` 标记）｜`orchestration/graph.py:478-491`（判据＝`PHASE_CLARIFY not in contracts_appended`）｜`prompts/decision_round.py:224-249`（常驻块渲染）。
- **最佳实践**：`BP-2a §4.1-1`（上下文是有限资源/上下文腐化）＋`对照表 C1、C4`（同一信息只注一次）＋`BP-节点-读题步 §②8`（关键信息放首尾）。
- **影响**：追问链（跨会话连续性）；非十题直击但同属「重复注入」病灶族。
- **建议修法**：把「run 级已注清单」持久化并随播种继承（或按「前链是否已含同文本」判定），使注入判据跨 run 有效；任务书同理——追问 run 只追加「本轮题干段」，不重发数据区。
- **优先级**：P1。

### M7（P1）回炉轮看不到本次取回的材料（观察只在作答相位进窗，「已做段」死线）
- **现象**：观察材料只有一个渲染消费点＝作答起草段；执行完的批次若回炉改参，决策轮链上没有任何材料面（只有拒因/状态行）。`context.render_process_notes`（有界「已做段」）在 runtimev2 **零调用点**，`clarify` 也不接 `done_text`。
- **证据**：`context/materials.py:131`（`render_materials` 唯一调用点＝`answering/core.py:261`）｜`execution/core.py`（全文件无 `append_message`/材料注入，仅 :48 注释）｜`prompts/decision_round.py:497-531`（增量条五件无材料件）｜`context/process_notes.py:24`（无调用点；`clarification/core.py:284-285` 自陈「不传」）。
- **最佳实践**：`BP-节点-批量执行 §⑥警惕3`（执行成功≠业务完成，0 行/未命中须落缺口并被后续看见）＋`BP-2a §4.1-10`（状态栏由代码维护、把算好的结论加进上下文）＋`对照表 T2、C6`。
- **影响**：D-诱12／数-降2（取回后重复取/改参无依据）。
- **建议修法**：把「已取得观察摘要段」（有界、带 `[n]` 序号）作为回炉轮增量条一件，或在执行收口处落一条 user 观察条；同时把 `render_process_notes` 接进决策增量条（现为死线，需先裁其与「过程档案不进对话轮」的边界）。
- **优先级**：P1。

### M8（P1）对象歧义门的第一判据是模型输出槽，而输出契约模板未列该键
- **现象**：门的判定序＝「模型 `subjects` 非空→不问｜空则程序候选回填→不问｜双空走门」。关键输入 `subjects` 属 additive 宽松解析（缺省＝空），而 system 输出契约的 full 形模板只列 `route/text/metric_candidates`，`subjects/terms` 仅以正文条款要求——模板与条款不同源，模型漏键即触发回填/误门。
- **证据**：`clarification/subject_ask.py:108-114`（判定序）｜`prompts/constants.py:94-103`（正文列两键，模板 `{"route":"full","text":…,"metric_candidates":[…]}` 未含）｜`understanding/interpret.py:317-319`（槽写入）｜`clarification/subject_ask.py:110-114`（程序回填＝事后补救）。
- **最佳实践**：`BP-节点-读题步 §③14/15`（模型产候选、Harness 校验；输出格式用最窄可用契约）＋`对照表 P5`（输出契约按消费面冻结：消费面读了哪些键，契约就必须列哪些键）。
- **影响**：B-正6／NQ-C9（ask 误触与漏触各一次真机）。
- **建议修法**：契约模板与「消费字段清单」同源生成（模板由字段清单渲染，禁两处手写）；门的权威输入优先取程序确定性候选（现已是回填，但序在模型槽之后），模型槽降为补充面。
- **优先级**：P1。

### M9（P1）读题 system 规章段内部自相矛盾（两行式 vs 单 JSON），且无仲裁机制
- **现象**：同一份 system 里，【你的输出与它的消费方式】要求「输出固定两行」、红线要求「只输出上述两行」，而【输出契约】要求「只输出一个 JSON 对象」「缺 route 一律作废」。代码侧登记为「待主窗裁决」（`task_book.py:16-19`），规格侧已裁为单 JSON。运行时以两份冲突文本同时在场运行。
- **证据**：`prompts/constants.py:31-48`（两行式＋红线）vs `prompts/constants.py:94-103`（单 JSON）｜`prompts/task_book.py:16-19`（登记张力）｜`specs/understanding.md:76`（「输出契约＝单个 JSON 对象；不使用两行式」）。
- **最佳实践**：`BP-节点-读题步 §②2`（指令层与数据层分节分责任，冲突不可在同一层并存）＋`BP-3a §主题4.5`（条款数↑则遵循率乘性衰减）＋`对照表 P1、P5`；规格条款优先（工程常识＋AGENTS.md 1）。
- **影响**：所有题的读题入口（含 NQ-C6／NQ-C9 的读题稳定性）。
- **建议修法**：机制级收敛为**单一权威契约**：由规格裁定的契约文本单点出（模板＋字段清单同源），旧两行式常量随票退场或降级为「历史样例」明确标注非契约；不以「待裁」长期双轨在制。
- **优先级**：P1（属**规格—实现冲突**，非业务语义判断）。

### M10（P2）重复注入配额缺失：恢复选择双写、台账信息三份、题面锚行多地
- **现象**：①挂起恢复时用户所选原话既入链又作「用户已补充」增量条；②台账信息在环境数据区（名字级）、决策常驻块（全量行）、材料面台账卡观察（被 discover 时）三处各出现一次，无「同文本出现次数」上界或机器对账；③题面/题意锚在三处各自的「首行位」（任务书题干段、澄清锚行、匹配锚行、作答题面件）。
- **证据**：`clarification/core.py:213-215`（用户原话入链）＋`prompts/decision_round.py:124,518-519`（同内容 hint 行）｜`prompts/task_book.py:167-171`（环境名录）＋`prompts/decision_round.py:224-249`（常驻块）＋`context/materials.py:46-57`（台账族观察）｜`prompts/decision_round.py:179-187`（锚行）＋`prompts/answer_round.py:66-73`（题面件）。
- **最佳实践**：`对照表 C4`（任何信息只在被需要的最早环节注入一次）＋`BP-2a §4.1-1`；②③的重复属「位置偏好」合理代价（`BP-节点-读题步 §②8`），但需要**明示配额**而非默认合理（工程常识）。
- **影响**：澄清恢复类（D-诱9／C-反1）token 与注意力；台账三份影响引用归属判断（C-正4 类「台账卡拼答案」）。
- **建议修法**：①二选一（原话入链 或 增量条），不留双写；②③登记「计划内重复配额表」（哪件、几份、为何），由装配清单机检，超出即红。
- **优先级**：P2。

### M11（P2）ask 上限两套闸、口径差一
- **现象**：澄清相位的到顶判据是「**将要发的**计数 `+1 >= cap`」（第 6 次不发），入口轮闸判据是「**已用** `>= cap`」（第 6 次已用才收敛）。同一 cap 两处语义，等效上限 5 vs 6；连续反问计数两个实现（`clarification._ask_count` 与 `graph._consecutive_asks`）共用「步 payload 带 ask 帧标记」这一隐式契约。
- **证据**：`clarification/core.py:783`（`_ask_count+1 >= ask_cap`）＋`clarification/core.py:831-845`（计数实现）｜`orchestration/graph.py:410-425`（第二份计数实现）｜`state/limits.py:125,147`（`used >= cap`）。
- **最佳实践**：工程常识（同族判据单点；计数与上限不得双实现）＋`BP-节点-澄清 §②2.4`（封顶口径要可预期）。
- **影响**：澄清/反问类（D-诱9／C-反1）——预算少一次或多一次直接改行为。
- **建议修法**：把「已发 ask 数」抽成 `state` 侧唯一读取面（或计数随写口维护），两闸引同一判据；到顶语义统一为「已用 ≥ cap」。
- **优先级**：P2。

### M12（P2）承载位声明漂移：背景块挂点在三个文件里三种说法
- **现象**：`interpret` 模块注称链首背景块「在 `assembly.ensure_task_book` 内、链为空时挂」；`assembly` 明写「本函数不挂（会重复）」；实际挂点在编排建链面。规格与实现一致（编排面），**代码内声明**与实现不一致。
- **证据**：`understanding/interpret.py:10-11` vs `understanding/assembly.py:107-109` vs `orchestration/runtime.py:404-408`；规格 `specs/prompts.md:26,61`。
- **最佳实践**：工程常识（承载位单点声明；本轮审计即因该漂移多绕两跳）。
- **影响**：维护/回归面；非十题直击。
- **建议修法**：删/改块内声明，或把「背景块构造」收成单点函数（`prompts.SYSTEM_BACKGROUND` 的包装件）由编排调用，机检「背景块只能在一处构造」。
- **优先级**：P2。

### M13（P2）材料 Manifest 的零材料文案与 `step` 槽脱钩
- **现象**：零材料时 `selected_reason` 恒写「理解步零材料渲染」，但调用方在作答轮也用它（`step=answer`）；规格也写「零材料步仅生于理解步」——即文案与真实相位不一致，账本失真。
- **证据**：`context/manifest.py:74-75`（固定字面）＋`answering/core.py:258-260`（作答轮调用）＋`specs/context.md:114`（「零材料步仅生于理解步」）。
- **最佳实践**：`BP-节点-作答 §②10`（Context Manifest 要能解释「为何遗漏某信息」）＋工程常识（账本文案与实际槽位同源）。
- **影响**：可解释性/审计面（不直击十题答案面）。
- **建议修法**：文案槽与 `step` 绑定（或限该形只在理解步产生）；改动属规格文案面，须带逐字稿回设计仓。
- **优先级**：P2。

## 三、机制缺口（代码里没有、最佳实践应有）

- **G1 上下文装配清单（call-level view manifest）**：`Manifest` 只覆盖材料面（`context/manifest.py:35-97`），无「本次请求含哪些链级注入件、各几次、各多少 token」。范式＝`BP-节点-作答 §②10`（source_type/selected_reason/transform/token_count）＋`BP-节点-读题步 §②4`。影响：任何「同一信息重复注入」只能靠人肉 grep（本轮即如此）。
- **G2 材料面与注入面配额**：帽只对检索族（24，`context/materials.py:61,149-151`）；权威/台账族「恒全量」、链条目数、单条材料字符数、注入件份数均无上界，也无「超界披露」的统一口径（`BP-2a §4.1-1`「最小的高信号 token 集」）。
- **G3 回声抑制机制**：只有「检测」（`echo_flag` 只记不拦）与「事后剥离＋输入侧提取」（`answering/core.py:284-291`），没有「视图层隔离」这一档（`BP-节点-读题步 §②10`；`BP-节点-核验 §②12` 的一票否决思想可平移到「发射形不得进交付面」）。两档之外缺第三档＝只能靠提示词压制。
- **G4 核验回写口径**：删句/分列结果只落 `state.draft` 与 step payload；收口段不再携带缺口（`answering/core.py:411-423` 的 `gaps=[]`），链尾只留删后稿——「用户看到的答案被删了哪几句」在账本链上不可复算，追问轮也看不见。范式＝`BP-节点-核验 §②3/§⑤`（Verifier 返回结构化缺口＋可修复性）＋`BP-节点-核验 §②14`（precision/recall 标定；本仓无「已知漏网/误杀」名单）。
- **G5 机制对等表（V1→V2 迁移守门）**：V1 的「零草稿重试」「换链 hint＋换链提议标记」「prompt 回声行剥除」等机制在 V2 无对等物，对应用例仍只跑 V1（`tests/domains/test_v2_v248_draft_face_isolation.py`、`tests/domains/test_v2_p040_chain_switch_refurnace.py` 均 `runtimev2` 命中 0）。缺一道「V1 机制清单 × V2 有/无/否」的机器对账，机制在本轮重写中以「文案改述」形态静默丢失（`对照表 G1`）。
