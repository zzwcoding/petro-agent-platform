## 二、落点对照（应落在哪 / 不该落在哪）

四类落点：**提示词**（调用级 system 规章／链首 system 背景／user 条）｜**上下文装配**（常驻块／动态段／材料面）｜**程序机制**（代码闸）｜**数据面**。

| # | 应落在哪 | 不该落在哪 |
|---|---|---|
| R1 | 程序机制：T2b 只产枚举、代码分派 | user 条里让模型兼判「该不该走完流程 + 结果对不对」 |
| R2 | 程序机制（枚举解析＋回退分支）＋提示词（只出枚举） | 无回退路径的「模型自判」；靠扩枚举名掩盖分类不稳 |
| R3 | 程序机制：直答/轻出口的确定性最小闸（拿不准回落重流程） | 把「模型判无关即直答」当出口条件 |
| R4 | 程序机制：核验器提交完成；venv/证据门 | 提示词写「请确保已经完成」 |
| R5 | 评测：轨迹前缀回归钉住该决策点 | 加词表/加枚举来「收敛症状」 |
| C1 | 上下文装配：常驻块零动态；时间/计数/用户态一律新消息追加 | system/常驻块塞时间戳、水位、run 计数 |
| C2 | 上下文装配：规章（指令）与数据区物理分消息块 | 同段文本内用子句区分「指令/数据」 |
| C3 | 提示词承载位：环节规章走**调用级 system**（不入链） | 把合同/规章文本塞 user 条、与观察材料同角色 |
