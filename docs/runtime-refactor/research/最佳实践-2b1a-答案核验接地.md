## 一、一句话结论

**零 LLM 的确定性核验只能做「结构性接地」，做不了「语义性接地」。** 确定性一侧能可靠做到：引用是否存在、引标序号是否越界、断言里的数字/字符串是否在材料原文中出现、同一来源是否自相矛盾、格式残留（JSON 通道泄漏）是否剥离、血缘/版本号是否回读一致——这些都可以写成断言、可复现、可进 CI（技术书籍/ai-agent-book/ai-agent-book/book/chapter7.md 第 290、302 行：确定性验证不引入模型开销、完全可复现、可像单元测试一样纳入持续集成）。做不到的是：同义改写与原句是否等价、隐含推论是否成立、跨多句综合结论是否有据、反讽/条件句的方向、以及「材料够不够」的充分性判断——这些没有唯一终态可比对，确定性匹配只能退化到**子串命中**，于是同时产生假阳性（`52` 命中 `1520`）与假阴性（同义但不同字）。业界共识的出路是**先穷尽确定性断言，确无可机械化处才上模型评判**（book/chapter7.md 第 300-302 行；handbook/ch4 4.6.2 五级验证强度表），而不是二选一。对本项目（只读问答、答案本质是「复述材料」）：**「数值必须来自材料」这条强约束使确定性核验的适用面远大于一般 Agent 场景**，本仓 `verify_draft` 已落地的方向正确；主要风险不在路线，而在子串匹配的边界、单向检查与「恒过」盲区（见四、六）。

## 二、业界主流做法（每条注出处）

1. **验证强度按风险分级，共五层；模型只能「申请完成」，Harness 才能「提交完成」，Verifier 返回结构化缺口。** 五级：结构验证（Schema/必填字段/格式/文件存在）→ 环境验证（查真实系统/文件差异/执行结果）→ 确定性验证（测试/规则/静态检查/业务校验）→ 独立模型验证（独立上下文查质量与遗漏）→ 人工验收（责任人签署）。失败不是终点，而是新的 Observation，由 Harness 决定继续修复/重规划/转交/失败。来源：技术书籍/ai-agent-handbook/06_第 4 章 任务：编排、长程推进与协作流转.md（下文简称 handbook/ch4）4.6.2 节（第 376-388 行）。

2. **「完成」的最终形态不是一句话，而是一组带证据引用的事实（结构化 evidence 字段 + remaining_actions）。** 案例给出的产出形：`state: COMPLETED, outcome:…, evidence: {各检查项 → artifacts 路径}, remaining_actions: [...]`。来源：handbook/ch4 4.6.3 节（第 407-425 行）。

3. **答案溯源的两个粒度：回答可回溯到具体文档、段落与版本；并配版本快照/回滚/时效检测/引用分析。** 权限过滤覆盖「检索到生成」全链路，防止推理成为受限信息的旁路。来源：技术书籍/ai-agent-handbook/11_第 8 章 Agent 状态存储与语义资产.md（下文简称 handbook/ch8）8.5.6 节（第 307-311 行）。

4. **引用质量用「蕴含判定」机检，不靠 LLM 自评：citation recall = 每条陈述至少一个引标、且被引段落蕴含该陈述（NLI 模型判定）；citation precision = 引标是否「无关」（去掉它陈述仍被其余引标蕴含）。** 该基准的自动引用质量用 TRUE NLI 蕴含模型算，不是 LLM judge；correctness 用数据集特定的 exact-match 子串/列表比对（如 ASQA 的短答案子串精确匹配）。来源：https://arxiv.org/html/2305.14627 （ALCE，arXiv 2305.14627）。**要点：这是「用一个小分类模型 + 子串匹配」而不是「用一个大 LLM」做引用的机制化验证，与本仓子串匹配同侧。**

5. **接地（Attribution）有独立定义与标注流程：AIS（Attributable to Identified Sources）——「输出是否被所给来源支持」可作为一个可操作的外部世界判断，用两阶段人工标注流水线执行，并在多类数据集上做人评验证。** 该框架明确是**人工判断**，不是自动 entailment。来源：https://arxiv.org/abs/2112.12870 （Rashkin et al., arXiv 2112.12870）。

6. **验证方式是一条谱系，横轴是「任务的可机械验证程度」；向右移动不等于放弃左侧——能写成程序化断言的继续用断言，LLM 评判只用确实无法机械判定的维度，因为确定性检查更便宜、更稳定、更适合长期回归。** 来源：book/chapter7.md 第 290-302 行（第 300 行「RAG/LLM-as-a-Judge 是谱系右侧两件工具」；第 302 行「向右移动并不意味着放弃左侧」）。

7. **三层轨迹验证器：结果层读环境真值、过程层用程序规则（业务规则/隐私/事实依据/承诺—行动一致性）、质量层才用 LLM/Rubric；且下两层坚持用环境真值与代码规则，LLM 质量评判永不替代前两层代码闸。** 示例默认用确定性 `HeuristicQualityJudge`，无需 API Key 即可跑。来源：技术书籍/ai-agent-book/ai-agent-book/chapter9/trajectory-verifier/README.md（第 3-16 行）。

8. **幻觉设为一票否决（Veto）维度：无论其他维度多优，出现编造虚假信息即判零分。** 来源：book/chapter7.md 第 320、355-366 行（Rubric 四准则第 3 条与用户记忆 Rubric 示例）。

9. **失败归因定位「首个导致偏离的错误」，且可用确定性手段先筛：把 Agent 的陈述与工具返回值逐步对齐（事实锚点比对）取首次背离；比对「完成声明」与「实际执行命令」的交叉核对。规则先筛、LLM 再定位，比全量喂 LLM 更便宜也更准。** 注意：失败归因**不能完全依赖 LLM**，因为往往反映产品问题而非纯技术问题。来源：book/chapter7.md 第 434-476 行（第 458 行「至少三类可先用规则筛出嫌疑轨迹」；第 476 行「事实锚点比对 + 轨迹前缀二分，不能用搜索报错关键字代替」）。

10. **事实锚定（Grounding）要求写进评测约束：对设备状态的任何回答都必须以工具返回结果为依据**；缺此约束时评估会退化为两个模型互相确认。来源：book/chapter7.md 第 89 行。

11. **Provenance 硬约束 + 证据链 DAG：没有来源不许入库（×）；来源类型映射初始置信度（human_input 1.0 / document 0.8 / merge_result 0.7 / agent_inference 0.6 / trace_extraction 0.5 / dream 0.3-0.4）；关系类型含 derived_from / refuted_by（冲突检测）/ supersedes / merged_from，综合置信度用 Noisy-OR，并提供 `chain.conflicts` 检测矛盾。** 来源：资料/data - AI - 演讲/已完成/《Agent 数据底座的进化论：从存储系统到认知系统》.知识.md 6.1-6.2 节（第 125-160 行）。

12. **「回读权威源」作为检索瀑布的固定一站：按固定 Commit、校验 ID / Hash / Status 再回读，防止用到旧版本或已被推翻的结论。** 来源：资料/data - AI - 演讲/已完成/从业务本体到持续进化.知识.md「运行时 S0–S8」表 S7 行（第 292 行）。

13. **强类型中间态让每一步可检查、可回放，末段是 EvidencePack（结果、口径、版本、血缘、验证状态）；分工是「模型负责理解与提出计划，语义编译器 + Harness 负责验证、授权、执行、审计与失败关闭」。** 来源：同上「从用户问题到证据答案：强类型中间态」五段式（第 295-313 行）。

14. **零资源（不依赖外部知识库）的幻觉检测路线：SelfCheckGPT 通过多次采样同一模型、检查输出间是否互相矛盾来判定幻觉（知识存在则输出相似、编造则分歧），是黑盒、无外部库的方法。** 来源：https://arxiv.org/abs/2303.08896 （arXiv 2303.08896）。**注意它测的是「自洽性」不是「正确性」，且需多次生成。**

15. **语义熵路线：用一组生成的语义含义不确定性估幻觉；原版需多次采样（成本 5-10×），改进版 SEP 直接从单次生成隐状态近似、几乎零额外开销；不需要外部知识库。** 来源：https://arxiv.org/abs/2406.15927 （arXiv 2406.15927）。

16. **原子事实分解 + 逐条验证：FActScore 把长文本拆成 atomic facts，算「被可靠来源支持的比例」，需要可靠知识源 + 检索 + 一个强语言模型（自动化版本误差 <2%）。** 来源：https://arxiv.org/abs/2305.14251 （arXiv 2305.14251）。

17. **「先校验，再执行」：把权限校验（policy check）、新鲜度（freshness）、血缘（lineage）、审计（audit log）插入「编译 → 执行」之间；可信取数要把校验做进执行路径。SQL 可执行 ≠ 业务可信。** 来源：资料/data - AI - 演讲/已完成/《从元数据到 Data Agent：企业如何从"能问数"走向"可信取数"》刘镔辉｜Datastrato 解决方案架构师.知识.md 第 182-189、95-97 行。

18. **实测基线（防幻觉的工程口径）：提示词层「所有回答必须来源于知识库」，评测口径为「忠诚度（不胡编，来源知识库）+ 点题」；并指出「上下文接近阈值 → 压缩 → 细节丢失 → 幻觉」这条因果链。** 来源：资料/录音 面试考点速查.md Q43（第 579-584 行）、第 267-271 行。

## 三、分歧取舍

**取舍一：确定性断言 vs 模型评审。** 不是二选一，而是分层混用、风险驱动。
- 确定性一侧：便宜、可复现、可进 CI、可跨模型排名；**代价是只能判最终结果对不对，不能说明错在哪**——τ²-bench 那条失败任务最终得 0 分，但这个 0 分不说明是线路选择错还是漏了充值步骤（book/chapter7.md 第 292 行）。
- 模型评审一侧：能拆维度、给原因；**代价是评判模型有偏见、同输入多次评判有波动，最典型是长度偏差**（更长的回复更易得高分），需显式惩罚冗长、控制长度、定期审计评分与长度的相关性（book/chapter7.md 第 310 行）。
- 主流收敛点：**凡能写成程序化断言的继续用断言，LLM 只用于确实无法机械判定的维度**（book/chapter7.md 第 302 行）。

**取舍二：引用的机检用「NLI 小模型」还是「LLM judge」。** ALCE 选了前者（TRUE NLI 蕴含模型，可复现、便宜，见 https://arxiv.org/html/2305.14627 ）；AIS 选了人工标注（https://arxiv.org/abs/2112.12870 ）。生产落地通常 NLI 打底、LLM/人工兜开放维度。**这是本项目最值得讨论的中间选项**：若子串匹配不够，引入一个中文 NLI 蕴含小模型是「比子串强、比 LLM 判便宜可复现」的第三档。

**取舍三：溯源粒度——出处级 vs 段落级 vs 引标级。** handbook 要求「文档 + 段落 + 版本」（handbook/ch8 8.5.6）；ALCE 到 citation 级（每条陈述对每个引标）；本仓落在地**行内 `[n]` 引标 → observation index**（runtime-refactor/recon/A2-核验规则与归属审.md `_assertion_chunks`，第 78-90 行）。粒度越细越可核，但切分与对齐成本越高。

**取舍四：来源矛盾——自动裁决 vs 暴露给用户。** 本仓做法是**「分源列明，禁止无出处调和」**（A2 第 178-195 行 `verify_draft` 尾部 `_contradiction_members` → 追加「多来源不一致——分源列明」块，R-A2-23/INV-4）；ContextSeek 则用 Noisy-OR 加权 + refuted_by 表达冲突（ContextSeek 6.2）。**主流倾向是不让模型自己选一个**：要么如实分列，要么按可信度/版本分列，把判断留给用户。

**取舍五：自洽检测（多次采样）vs 外部材料核验。** SelfCheckGPT/语义熵不需要知识库，但需要多次生成、且只测「一致性」不测「正确性」；FActScore 需要知识源 + 强模型。**本项目有权威材料库**，所以「对材料核验」比「多次采样求自洽」更直接、更省。

## 四、反例踩坑

1. **「全程无报错」被当成「正确」——静默失败。** AndroidWorld T3A：32 步完成任务、无任何一步报错、Agent 自行宣告完成，验收却发现记录的 `expenses.jpg` 数据根本不存在；第 8 步思考里模型自己写着「我看不到图像内容」，却既没停也没报告，第 11 步四条数据凭空出现。**教训：错误信号缺失 ≠ 事实正确；核验不能只看「有没有报错」。** 且该例根因是 Harness 观察通道缺失、不是模型能力——**若误记为模型能力问题，就会去换模型或训练 OCR，方向全错**。来源：book/chapter7.md 第 468 行。

2. **二元/终态奖励漏掉过程违规。** τ²-bench 满分轨迹里，Agent 一次发出两个 tool call，违反政策「一次只调一个工具」，验证器因 `reward_basis` 只看最终状态而漏判。**这是二元奖励的固有代价：以过程颗粒度换取跨模型可比的单一数字。** 来源：book/chapter7.md 第 123 行。

3. **上下文学习是「检索而非推理」，模型会把上下文里相近但不正确的内容当答案。** 这是「模型为何会记错」的理论支点。来源：book/chapter2.md 第 861、999-1014 行。

4. **压缩丢细节 → 幻觉：** 上下文接近阈值触发压缩，细节被压掉后模型开始编。来源：资料/录音 面试考点速查.md Q43（第 582 行）。

5. **子串匹配是确定性核验最常见的坑（本仓已自陈）。**
   - 假阳性：数值匹配为**子串包含**，`"52"` 会命中 `"1520"`、`"52.3"`（A2 D-A2-10/D-A2-15）。
   - 假阴性（漏判矛盾）：矛盾分组以**全角「：」**切 subject 且按原文精确分组——半角冒号、或同一对象名写法差异（空格）会被拆成不同组，真矛盾漏判（A2 D-A2-20/D-A2-31）；值比较取「：」后原文字符串，格式差异（空格/换行）即算不同值，可能**误判**矛盾（D-A2-32）。
   - 支撑方向单向：`_supported` 只查「被引观察的数值是否在断言里复述」，**不查断言里多出的、观察没有的数字**——「有据行内编造额外数字」不被拦（A2 D-A2-11）。
   - 「恒过」盲区：零数值 token 的观察/断言恒判支撑（纯文本卡），**语义充分性完全不查**（A2 R-A2-12/D-A2-12）；无引标但有数字的行可经「窗内对齐」放行，答案面会**出现无出处序号的数字行**（D-A2-21）。

6. **只溯源不校验会「自证」。** 本仓修一（R-A2-19）明确「引标序号自身不作数，防自证」——即不能因为「它自己带了引标」就认定有据，必须用整行文本对引标逐一重判。这是个好习惯：**引用存在 ≠ 引用正确。**

7. **LLM judge 的两类作弊。** 长度偏差（见三、取舍一）；奖励作弊——Agent 找到拿高分的捷径却没真正完成任务，需显式惩罚幻觉、讨好用户、关键词堆砌、回避棘手问题。来源：book/chapter7.md 第 310、324 行。

8. **只输出一个总分无法归因。** τ²-bench 成功率下降时，单分数不告诉你「是没检索到、还是把关系想错了、还是补了没依据的内容」；必须把笼统失败率拆成逐维诊断再配合失败归因。来源：book/chapter7.md 第 368 行；trajectory-verifier README 第 7 行（单总分 vs 带证据多维诊断的对比）。

## 五、对本项目适用性（只读问答、单租户）

**已落地且高度适用（本仓纯确定性核验族，全部零 LLM、纯函数）：** 见 runtime-refactor/recon/A2-核验规则与归属审.md（锚定 commit e4b75f1，覆盖 `appv2/runtime/graph.py` L668-L1047）：
- `strip_emission_fences`——确定性剥离答案面 JSON 通道残留（发射令牌/围栏 JSON），零误伤域外 JSON（R-A2-03…07）。
- `_assertion_chunks` / `_supported` / `_scope_usable` / `_window_aligned`——逐行断言级「观察→行」支撑判定：被引观察的数值须在断言文本复述；空壳辖域重判、窗内对齐放行两条修补线（R-A2-08…15、17…21）。
- `_contradiction_members` + `_attribution_block` + `_observation_aligns`——两个来源矛盾时**分源列明、禁止无出处调和**；跨源材料不冒充题眼证据（R-A2-23…28）。
- `verify_draft` 统一入口：无据断言改写为「未找到（材料未披露）：…」并计数，返回 `(文本, 改写数, 被引序号, 是否分源)`（R-A2-16…24）。**这正是「业界：模型申请完成、Harness 依据事实提交完成」在单点上的落地。**

**为什么只读问答特别适合确定性核验：** 答案只能是材料的复述，于是「数值/字符串必须能在材料里找到」是一条**可机检的硬约束**，本仓 `_supported`/`_window_aligned` 就是它；一般 Agent（写代码、发消息、改数据）没有这条约束，只能靠模型评审。

**可借鉴、建议补齐（标「适用」）：**
- **把核验强度显式分层**（结构 / 确定性 / 模型 / 人工），现在是一个 `verify_draft` 混装；分层便于按风险决定要不要上模型（handbook/ch4 4.6.2）。
- **Verifier 返回结构化缺口**（缺什么、失败证据、可否修复），而不是只回「改写了几行」（handbook/ch4 4.6.2）。
- **EvidencePack（结果 + 口径 + 版本 + 血缘 + 验证状态）** 作为答案的固定产物（DataBuddy 强类型中间态）。
- **回读权威源校验 ID / Hash / Status**，防止引用旧版本结论（S7 回读权威源）。
- **一票否决项**：出现无出处断言/编造数值即判不合格，不被其他好项抵消（book/chapter7 Rubric Veto）。
- **失败归因的「事实锚点比对」**：把模型陈述与工具返回值逐步对齐取首次背离，可用纯规则先筛（book/chapter7 第 476 行）——与本仓 `_supported` 同思路，可扩到「改写行」的归因。

**不适用（标「不适用」）：**
- SelfCheckGPT / 语义熵的**多次采样自洽**路线：本项目有权威材料库，直接对材料核验更准更省；多次采样 = 多次 LLM 成本，且只测一致性不测正确性。
- 多模态 LLM-as-a-Judge、GraphRAG 长程归因、多租户权限过滤（单租户）。
- FActScore 的「原子事实分解 + 强模型逐条验证」：适用于长报告，本项目问答粒度更细、且强调零 LLM。

**待裁：**
- 是否引入**中文 NLI 蕴含小模型**做「语义蕴含」第三档（比子串强、比 LLM judge 便宜可复现）；本仓 docstring 已自陈「细化批可换更强实现」（A2 D-A2-12）。
- 溯源粒度是否从「行内 `[n]` 引标 → observation index」细化到「文档 + 段落 + 版本」（handbook/ch8 8.5.6）。

## 六、值得抄三条 / 要警惕三条

**值得抄三条：**
1. **验证强度分级 + 「模型申请完成、Harness 提交完成」+ Verifier 返回结构化缺口。** 把单点 `verify_draft` 显式分层，并让 Verifier 说清「缺什么、证据是什么、能否修」（handbook/ch4 4.6.2、4.6.3）。
2. **引用质量用可复现的蕴含判定（citation recall/precision），而不是让模型自评「我有没有依据」。** 「每句有没有材料撑着」落成「引标 → 材料蕴含」的机检（ALCE，https://arxiv.org/html/2305.14627 ）；本仓子串匹配是它的最简形态，缺口就是缺蕴含判定这一档。
3. **矛盾不调和、分源列明，并给答案配证据链/版本。** 本仓已落地「分源列明、禁止无出处调和」；再补 EvidencePack 的版本/血缘/验证状态与「回读权威源」（handbook/ch8 8.5.6；ContextSeek Provenance；S7）。

**要警惕三条：**
1. **子串匹配的假阳/假阴。** 数值先做**边界 token 化**（区分 `52` 与 `1520`/`52.3`）；中文标点/全角半角先归一化再分组切分（本仓 D-A2-10/D-A2-20/D-A2-31/D-A2-32 是现成反例清单）。
2. **把「无报错」当「正确」，把根因误记为模型能力。** 静默失败（AndroidWorld T3A）与过程违规漏判（τ²-bench）都说明：核验要独立于「有没有报错」，归因要靠事实锚点比对取首次背离（book/chapter7 第 123、468、476 行）。
3. **确定性核验的「单向 / 恒过」盲区。** 只查「材料有的被复述」不查「断言多出的编造数字」（D-A2-11）；零数值观察/断言恒过、语义充分性不查（D-A2-12）；放出无出处数字行（D-A2-21）。**应把已知漏网类型名单化，作为回归用例固定下来。**

## 七、疑点与不确定

1. **本地资料没有一篇专讲「零 LLM 确定性核验」的完整方法论。** handbook/ch4 4.6.2 的五级验证强度表是最接近的框架，其余条目（ALCE/AIS/SelfCheckGPT/语义熵/FActScore/ContextSeek）是我按主题拼合，且多数是「模型一侧」的做法——**「纯确定性核验」的正面方法论在本地素材里偏薄（诚实标注：本文第二节是拼合汇编，非某章原文）。**
2. **中文/石油领域下 NLI 蕴含判定的表现未知。** ALCE 用 TRUE 模型、AIS 用人工，都是英文基准，能否直接迁移到中文 + 表格数值断言未验证（推断，无本地证据）。
3. **SelfCheckGPT 是否适用于「有权威材料」的场景存疑。** 其优势恰是「无外部知识库」，而本项目有库——推断「不划算」，但未见直接对比实验。
4. **本仓 recon 锚定 commit e4b75f1（`graph.py` L668-L1047）。** 若代码已变，行号与函数清单须重核；A2 的疑点（D-A2-01…34）是该版本的自陈，不代表当前实现。
5. **「grounding/attribution」与「faithfulness」两个词在资料里混用**（handbook 8.5.6 叫「答案溯源」，ALCE 叫 citation quality，AIS 叫 attribution，面试速查叫「忠诚度」）——本文按「答案被所给材料支持」统一理解，具体定义以各自原文为准。
6. **本仓「分源列明」的召回去向未在 A2 覆盖范围内**（A2 只覆盖 graph.py L668-L1047 纯函数段），两个来源矛盾时的 UI/接口呈现须另查 `_finalize`（L3746-3762）与 citation 帧（A2 D-A2-19 提及「cited 集合/引用块/citation 帧三处语义不同」）。
