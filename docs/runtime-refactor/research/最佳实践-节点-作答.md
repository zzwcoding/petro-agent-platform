## ① 一句话结论

业界一致把「写答案」拆成**四件互不等价的事**——**选材料（哪些进上下文、怎么标来源）**、**写正文（句句带引标）**、**核验与合并（无据就改写/不写，矛盾就分源）**、**交付与流式（一段段推、可续传、不把内部推理暴露）**；核心纪律是**「模型只申请、Harness 依据事实提交」**（`技术书籍/ai-agent-handbook/06_第 4 章 任务：编排、长程推进与协作流转.md` §4.6.2，第 376–388 行）。对本项目（**只读问答**）：答案本质是「复述材料」，所以「句句有据」可落成**硬约束**（数值/字符串必须来自材料），矛盾应**如实分源列明**而非调和，被拒/未覆盖/未核验应**写进答案正文**而非静默丢掉。本仓 ⑦ 已落地其中大部分；**最大缺口在「流式」**——当前答案面是 `text` 帧**一次性全量**推送，不是「一段段推」（见 ⑤、⑥）。

## ② 业界主流做法（逐条注出处）

### A. 怎么让答案句句有据（引用/溯源：引标怎么标、和材料怎么对齐）

1. **答案溯源要能回溯到「具体文档、段落与版本」，且是用户验证与审计的基础。** 出处：`技术书籍/ai-agent-handbook/11_第 8 章 Agent 状态存储与语义资产.md`（下文简称 hand ch8）§8.5.6（第 307–311 行）：「答案溯源让每个基于知识库生成的回答都能回溯至具体文档、段落与版本……配合版本快照、回滚、时效检测和引用分析」。

2. **引用质量用「蕴含判定」机检，不靠模型自评：citation recall＝每条陈述至少一个引标且被引段落**蕴含**该陈述；citation precision＝去掉某引标后陈述是否仍被其余引标蕴含（判定引标是否「无关」）。** 出处：`技术书籍/ai-agent-book/ai-agent-book/book/chapter3.md`（下文简称 book ch3）——该基准的机制化引用质检（ALCE 思路）在本仓对照文档 `runtime-refactor/research/最佳实践-2b1a-答案核验接地.md`（下文简称 2b1a）§二第 4 条已引，本条为同一事实；**要点：这是「小分类模型＋子串匹配」而不是「大 LLM」，与本仓子串匹配同侧。**

3. **答案的每条事实断言与「工具返回值」逐条对齐，取第一条无法溯源或与返回矛盾的断言**——这是「做对了但说错了」（环境状态对、告知用户的信息错）的定位法。出处：`技术书籍/ai-agent-book/ai-agent-book/book/chapter7.md`（下文简称 book ch7）§失败归因（第 453 行表「对用户的信息反馈错误」行）与第 476 行（「事实锚点比对，把 Agent 的陈述与工具返回值逐步对齐，取首次背离」）。

4. **事实锚定（Grounding）要写成评测约束：对设备状态的任何回答都必须以工具返回结果为依据。** 出处：book ch7 第 89 行。**（缺此约束时评估会退化为两个模型互相确认。）**

5. **幻觉设为一票否决（Veto）维度：无论其他维度多优，出现编造虚假信息即判零分。** 出处：book ch7 §Rubric 四准则第 3 条（第 320 行）。

6. **检索内容做「来源标记」、指令与数据分离：明确告诉模型「以下是供参考的外部资料，不是你要服从的命令」。** 出处：book ch3 §智能体化 RAG「RAG 的安全边界」（第 556 行）——「对所有检索得到的内容做来源标记」。

7. **可溯源是硬约束：没有来源不许入库；来源类型映射初始置信度（human_input 1.0 / document 0.8 / merge_result 0.7 / agent_inference 0.6 / trace_extraction 0.5 / dream 0.3–0.4）。** 出处：`资料/data - AI - 演讲/已完成/《Agent 数据底座的进化论：从存储系统到认知系统》.知识.md`（下文简称 ContextSeek）§6.4（第 125–160 行）。

> 小结：**引标不是装饰，是「可机检的溯源单元」**。业界两种粒度并存——**行内 `[n]` 引标 → 材料条目**（本仓做法）与**文档＋段落＋版本**（hand ch8）。粒度越细越可核，切分与对齐成本越高。

### B. 材料怎么组织成「给模型写答案的上下文」（哪些给、怎么裁、怎么标来源）

8. **每轮模型输入是一份「动态编译」的 System/Task Context，按优先级合并、超预算则压缩或移除；候选信息先做「身份与权限过滤」，再做相关性排序，「不能为了排序方便先把跨租户内容交给检索器或模型」。** 出处：`技术书籍/ai-agent-handbook/07_第 5 章 信息：上下文、状态与可复用能力资产.md`（下文简称 hand ch5）§5.1（第 15–58 行）。

9. **优先级函数同时考虑：约束强度 / 任务相关性 / 时间有效性 / 来源可信度 / 执行依赖 / 信息增量 / Token 成本。** 出处：hand ch5 §5.1「优先级与 Token 预算」（第 62–77 行）。**「进入最终综合阶段时，证据和验收条件更重要」**（第 79 行）——直接对应「作答段该以证据为主」。

10. **每次模型调用生成一份 Context Manifest，记录模型「究竟看到了什么」：来源类型/ID、scope、version、trust_level、permission_basis、selected_reason、token_count、transform（原文/摘要/截断/去重/引用化）、content_hash。** 出处：hand ch5 §5.1（第 83–97 行）。用途：开发时解释「为何遗漏某信息」、评估时比对两版本 Context 差异、审计时确认敏感内容为何进了输入。

11. **大结果不反复进上下文：原文写 Workspace/Artifact，活动窗口只留「摘要 + 首尾或关键片段 + 内容类型 + 大小 + 生成工具 + 权限范围 + 可继续读取的稳定引用」；引用必须稳定且带读取版本/时间。** 出处：hand ch5 §5.2（第 163–165、212–230 行）。压缩是四步有纪律的状态迁移：`Commit→Compact→Rebuild→Validate`（第 169–177 行）。

12. **工具结果截断必须显式标示，禁止静默截断；搜索类返回「结构化候选列表」，读取类支持 offset/limit。** 出处：`技术书籍/ai-agent-book/ai-agent-book/book/chapter4.md`（下文简称 book ch4）§感知工具（第 224–226 行）：「已显示第 1-200 行，共 5000 行，可用 offset 参数继续读取……静默截断是危险的——Agent 会误以为自己看到了全部」。

13. **只读工具的结果可安全缓存（相同查询直接复用），且只读调用可放心并行。** 出处：book ch4 第 228 行——直接适用于本项目「查数据表/搜报告」全只读。

14. **结论性事实应先「确定性进入权威状态」再允许退出活动上下文；高风险事实不能只由模型自由归纳。** 出处：hand ch5 §5.2（第 161、167 行）：「高风险事实不能只由模型自由归纳，最好从 Task State、工具结果和审批记录中确定性提取，再让模型压缩叙述性内容」。

> 小结：**「哪些给」的分界＝「这条材料是不是当前要答的那几句的支撑」**；「怎么标来源」业界要求**来源类型 + 信任等级 + 版本 + 可寻址 ID** 随材料一起给（本仓观察的 `source/source_id/trust` 与之一致，见 ⑤）。

### C. 被拒 / 缺失 / 未核验怎么在答案里如实交代（不编造、不隐瞒）

15. **「模型只能提出完成申请，Harness 才能提交完成状态」；最终结果不是一句「已完成」，而是一组带证据引用的事实（结构化 `evidence` 字段 + `remaining_actions`）。** 出处：hand ch4 §4.6.2（第 376–388 行）与 §4.6.3（第 407–425 行）——`state: COMPLETED / outcome:… / evidence:{各检查项→artifacts 路径} / remaining_actions:[…]`。

16. **缺信息就进入「明确缺口」而非硬答：业务条件不满足要明确缺口，而不是盲目重试或编造。** 出处：hand ch4 §4.6.1（第 368–370 行）；Verifier 应返回**结构化缺口**、失败证据、可修复性（§4.6.2，第 388 行）。

17. **防幻觉的工程口径：提示词层「所有回答必须来源于知识库」；评测口径为「忠诚度（不胡编，来源知识库）＋ 点题（不跑题）」；并指出「上下文接近阈值 → 压缩 → 细节丢失 → 幻觉」这条因果链。** 出处：`资料/录音 面试考点速查.md` Q43（第 579–584 行）、Q20（第 264–274 行）。

18. **坦诚做不到 > 硬编答案：业务边界、框架边界都是合理限制，如实解释为什么。** 出处：`资料/录音 面试考点速查.md` Q44（第 586–594 行）：「坦诚做不到并解释为什么，比硬编答案好得多」。

19. **「未完成/不一致」不能静默丢：行业把「先解决能不能信」放在「能做什么」之前；未命中的候选须经编译校验/冲突检测/人工审核才发布。** 出处：`资料/data - AI - 演讲/已完成/《从元数据到 Data Agent：企业如何从"能问数"走向"可信取数"》刘镔辉｜Datastrato 解决方案架构师.知识.md`（下文简称 Datastrato）§四（第 38 行）、§八第 4 轮（第 180 行）。

> 小结：**「如实交代」不是加一句免责声明，而是把「哪句没找到依据、哪个子问题被拒、哪些材料未及核验」结构化成答案的一部分**，并保留 `remaining_actions`/缺口清单（hand ch4）。

### D. 多来源结果怎么合并（一致就合、矛盾怎么摆）

20. **矛盾无法自动裁决时，如实暴露而不是硬选一个：ContextSeek 用 `refuted_by`（冲突检测）表达冲突，并对外提供 `chain.conflicts` 查矛盾；综合置信度用 Noisy-OR。** 出处：ContextSeek §6.4（第 144–159 行）。

21. **孤立分块的历史会「各自独立但相互矛盾」，系统若强答会呈现混乱或错误信息；根源是分块丢上下文，解法是「上下文感知检索」（索引期给文本块补前缀/背景，把块锚回原语义环境）。** 出处：book ch3 §智能体化 RAG（第 590 行矛盾记忆例）与 §上下文感知检索（第 594–608 行）。**注意：本节讲的是索引期补上下文（做加法），与运行期压缩（做减法）时机不同（第 604 行）。**

22. **压缩/摘要的「矛盾率」要作为质量指标：摘要是否与工具事实、Task State 或最新指令冲突。** 出处：hand ch5 §5.2（第 197–208 行）——衡量压缩质量至少含事实保留率、继续成功率、矛盾率、引用可用率、成本收益。

23. **同一指标每次问出来不一样要「收敛自由度」：把已验证的 SQL/口径固化成 verified metric，未命中的候选经校验/冲突检测/人工审核才回写；生产指标不应在运行时反复临时解释。** 出处：Datastrato §八第 4 轮（第 176–180 行）。

> 小结：**主流倾向是不让模型自己「调和」矛盾**——要么如实分列（按来源/版本/可信度），要么把判断留给用户；一致的多来源可合并，矛盾的必须暴露。

### E. 流式输出（一段段推）的注意点

24. **流式事件要「面向任务语义」，分 Text / Progress / Tool / State / Approval / Artifact / Error / Usage 八类；「模型内部的隐藏推理不需要通过 Streaming 暴露」。** 出处：`技术书籍/ai-agent-handbook/08_第 6 章 行动：受控执行、验证反馈与交付准备.md`（下文简称 hand ch6）§6.5.1（第 397–414 行）。

25. **事件流必须假定「网络会断开、客户端会重复连接、消费者速度不同」：每个事件要有单调序号或可恢复游标；重连从最后确认位置续传，服务端支持去重；慢消费者可先读状态快照再补关键事件。** 出处：hand ch6 §6.5.4（第 458–464 行）。

26. **背压取舍：高频文本 Token 或细粒度工具日志可合并/采样/仅调试模式发送；但「状态、审批、Artifact 和终态事件则不能因背压被丢弃」。** 出处：hand ch6 §6.5.4（第 462 行）。

27. **取消要区分「已收到取消」和「底层动作已安全停止」；同一 Task 在不同 Channel 显示内容可不同，事件发布前按接收者身份与能力生成视图，「不能把内部 Trace 原样广播」。** 出处：hand ch6 §6.5.4（第 462–464 行）。

28. **「只在结束时返回一段文本」是反模式：长任务若只在结束返回，用户不知道 Agent 在做什么、是否等待审批、是否阻塞。** 出处：hand ch6 §6.5.1（第 401 行）——这正是「一段段推」的动机。

> 小结：**流式的语义契约优先于传输协议**（hand ch6 第 466 行）：先定 Task/Event/Approval/Artifact 模型，再选 SSE/WebSocket。**引标与最终答案同源**（本仓 `citation` 帧与 `text` 帧同出 `_finalize`，见 ⑤）。

## ③ 分歧取舍

1. **引用的机检用「子串匹配/小 NLI 模型」还是「LLM judge」。** 走「便宜可复现」一侧（ALCE 用 NLI 蕴含模型，book ch7 第 300–302 行「能写成程序化断言的继续用断言」）；LLM judge 只在确实无法机械判定时用，且要防**长度偏差**（book ch7 第 310 行）。本仓当前是**纯子串匹配**（最简形态）；2b1a §三取舍二把「中文 NLI 小模型」列为「比子串强、比 LLM 判便宜可复现」的第三档（**待裁**）。

2. **溯源粒度：出处级 vs 段落级 vs 引标级。** hand ch8 要求「文档＋段落＋版本」；本仓落在**行内 `[n]` 引标 → 观察条目**（`runtime-refactor/recon/A2-核验规则与归属审.md`）。粒度越细越可核，成本越高。

3. **材料组织：全塞 vs 摘要＋稳定引用＋按需取回。** hand ch5 §5.2 选后者（大结果退出窗口）；book ch4 第 224 行选「结构化候选＋分页让 Agent 自主翻页」。两者可叠加：窗口留行数＋摘要，明细按 offset/limit 取。

4. **矛盾：自动裁决 vs 暴露给用户。** 本仓与主流都选**暴露/分源列明**（本仓 `verify_draft` 尾部 `_contradiction_members`「分源列明」；ContextSeek `refuted_by/conflicts`）；「让模型自己选一个」是反面做法。

5. **流式：token 级增量 vs 事件级语义段。** hand ch6 明确事件要**面向任务语义**、内部推理不外露；token 级文本增量只是 Text 一类，不能替代 Progress/State/Approval。**对本项目**：答案面「一段段推」应是**语义段/子问题段**的推，而不是把隐藏推理也推出去。

## ④ 反例踩坑

1. **「全程无报错」被当成「正确」——静默失败。** AndroidWorld T3A：32 步无一步报错、Agent 自行宣告完成，验收却发现数据根本不存在；根因是**观察通道缺失**，不是模型能力。教训：**错误信号缺失 ≠ 事实正确**；若误记为模型能力问题，就会换模型/训练 OCR，方向全错。出处：book ch7 第 468 行。

2. **「做对了但说错了」被整体成功率掩盖。** τ²-bench 带信息告知要求的 704 次运行失败 240 次，其中 162 次是信息告知出错，80 次（占失败 1/3）环境状态正确但告知错误。出处：book ch7 第 466 行。教训：**答案面的「告知内容」必须与工具返回逐条对齐**，不能只看环境状态。

3. **上下文学习是「检索而非推理」，模型会把上下文里相近但不正确的内容当答案；长上下文还会「上下文腐化」（装得下但找不到）。** 出处：`技术书籍/ai-agent-book/ai-agent-book/book/chapter2.md`（下文简称 book ch2）第 999–1014 行。这是「模型为何会记错/被无关材料带偏」的理论支点。

4. **压缩丢细节 → 幻觉**：上下文接近阈值触发压缩，细节被压掉后模型开始编。出处：`资料/录音 面试考点速查.md` Q43（第 582 行）。

5. **静默截断工具结果**：Agent 误以为看到全部，基于不完整信息判断。出处：book ch4 第 226 行。

6. **把「执行跑完」当「业务完成」**：执行状态 ≠ 证据 ≠ Outcome 是三层；「查表返回 0 行 ≠ 该问题无答案」。出处：`技术书籍/ai-agent-handbook/13_第 10 章 Agent 异步任务与自动化流程.md` §10.1.2（第 28–42 行）。

7. **只溯源不校验会「自证」：引用存在 ≠ 引用正确。** 本仓 `verify_draft` 明确「引标序号自身不作数，防自证」（2b1a §四第 6 条，R-A2-19）。业界对应：citation precision 要判「去掉该引标后陈述是否仍被其余引标蕴含」。

8. **多来源矛盾时强答一个**：孤立分块的历史会呈现「三个各自独立但相互矛盾的指令」，系统强答会给用户混乱或错误信息。出处：book ch3 第 590 行。

9. **LLM judge 的长度偏差与奖励作弊**：更长回复更易得高分；Agent 找捷径拿高分却没完成任务；需显式惩罚幻觉、讨好用户、关键词堆砌、回避棘手问题。出处：book ch7 第 310、324 行。

## ⑤ 对本项目适用性（只读问答、单租户、答案＝复述材料）

**已落地且高度适用（本仓 ⑦ 作答链路，锚定 commit e4b75f1，覆盖 `appv2/runtime/graph.py` 与 `orientation.py`）：** 见 `runtime-refactor/recon/H-观察核验作答与图装配.md`（下文简称 H）与 `runtime-refactor/recon/L2b-作答装配与回声.md`（下文简称 L2b）：
- **答案要求逐字稿 7 条**（L2b R-L2b-02）：①逐条事实断言带 `[n]` 引标；②材料未覆盖部分不得断言、须如实说明未覆盖；③材料含多来源时**逐个来源分别作答**（不冲突也分别列出）；④作答后仍有未覆盖来源/指代不明处**如实点名**；⑤引擎的降级/未绑定/拦停注记**如实转述**、不得静默丢弃；⑥引用观察**摘录必要短语并带引标、禁整段照搬原文**；⑦「理解：／指标候选：」及任何动作 JSON 出现即废品。**这正是「句句有据＋如实交代＋禁整段照搬」三条的落地。**
- **核验段零 LLM**（H R-H-07…H-19）：`verify_node` 用 `verify_draft` 把**无据断言改写为「未找到（材料未披露）：…」**、矛盾时**分源列明**（INV-4「禁止无出处调和」）、跨源引用按出处区分；零实质材料**不烧模型、不冒充出数**（三分支人话壳）。
- **收口出帧**（H `_finalize`）：引用块只列**核验支撑集**（`[n] source · source_id（trust）`）＋逐号 `citation` 帧＋**答案全文 `text` 帧**＋`verdict final` 帧；事件序恒为 `step→citation→text→verdict`（H R-H-25）。
- **观察条目标来源**：`observation` 帧载荷 `{index, source, content, trust}`（`runtime-refactor/synth/S6-事件与帧目录.md` 第一节），`index` 从 1 起（H R-H-03）——与 hand ch5「来源可信度」/hand ch8「可寻址」一致。
- **截断必披露**：材料渲染截断 → `material_truncated` notice（H R-H-33）——对应 book ch4「禁止静默截断」。

**为什么只读问答特别适合这些做法：** 答案只能是材料复述，于是「数值/字符串必须能在材料里找到」是一条**可机检的硬约束**（2b1a §五）——这正是本仓 `_supported`/`_window_aligned` 的立足点；一般 Agent（写代码/改数据）没有这条约束，只能靠模型评审。

## ⑥ 值得抄三条 / 要警惕三条

**值得抄三条：**
1. **「模型申请完成、Harness 依据事实提交完成」＋答案配结构化证据与 remaining_actions**（hand ch4 §4.6.2/4.6.3）。本仓 `verify_draft`＋`_finalize` 已是它的单点落地（H R-H-19/R-H-25）；可再补「结构化缺口 + 未完成项清单」。
2. **矛盾不调和、分源列明/`refuted_by`，并给答案配证据链/版本**（ContextSeek §6.4；本仓 INV-4 已落地）。再多来源合并时**按来源分别作答**，一致可合、矛盾必须摆开。
3. **大结果退出窗口、引用带版本/信任等级、截断必披露**（hand ch5 §5.2；book ch4 第 224–226 行；本仓 `material_truncated` 已落地）。材料进上下文要带 `source/source_id/trust`。

**要警惕三条：**
1. **答案面「一段段推」目前没做到**：本仓 `text` 帧在 `_finalize` **一次性推全量答案**（H R-H-25、「emit text（answer 全文）」；S6 第 17 行标 `text` 为「流式文本段」但发射点是收口单点）——**这是「流式」需求的最大缺口**。若 ⑦ 要求「流式一段段推」，现在的实现与需求不符（**待裁**：是否改为随起草/分段产出增量 `text` 帧）。
2. **别把「无报错」当「正确」、别把根因误记为模型能力**（book ch7 AndroidWorld T3A 第 468 行；「做对了但说错了」第 466 行）。核验要独立于「有没有报错」，且要覆盖**答案面的告知内容**。
3. **别静默截断、别静默丢未核验/被拒项**（book ch4 第 226 行；hand ch4 §4.6.1）。被拒小问题、未覆盖来源、未及核验材料都应**写进汇总答案正文**（本仓 R-L2b-02 第②④⑤条已要求，须逐票守住）。
