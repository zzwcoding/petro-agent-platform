## 与石油问答平台的对照点（最值得借鉴的 7 条）

1. **把「完成」与「事实」的决定权从模型挪到 Harness**（ch4 4.6.2 / ch16）：模型只能提出完成申请，Harness 才能提交完成状态；验证强度按风险分级（结构→环境→确定性→独立模型→人工）。直接对应本仓第 ⑧ 段「核验」——可把现有逐句核对升级为「分级验证 + 结构化缺口返回」。
2. **压缩不是摘要，是四步有纪律的状态迁移**（ch5 5.2）：Commit（结构化事实先进权威状态）→ Compact（带来源与覆盖范围的摘要）→ Rebuild → Validate。并给出「压缩必须保留的 8 类事实」清单。本仓 K 分片（上下文/事件/指南/预算）可直接拿这份清单做自检表。
3. **大结果退出窗口、但不退出任务**（ch5 5.2 / ch8 8.3）：原始结果落 Workspace/Artifact，窗口只留摘要 + 稳定可寻址引用（带权限与读取版本）。对应本仓第 ⑥ 段批量查数/搜报告——报告全文不该反复进上下文。
4. **路由层只判「该用哪个入口」，不判「结果对不对」**（ch9 9.4.3）：路由与结果判定分权。对应本仓第 ② 段「定路由」与第 ⑧ 段「核验」应保持不互相污染。
5. **「执行结果 ≠ 业务完成」，恢复与幂等要划清责任**（ch10 10.1.2/10.1.3）：工具调用成功只等于执行成功，业务完成需另判。直接对应本仓 D 分片挂起恢复与 G 分片批量执行。
6. **Checkpoint 不是上下文拷贝，要含恢复所需关键状态**（ch8 8.2.3）：当前阶段、已完成/未完成步骤、工具结果引用、工作区版本、等待条件、状态版本；并明确关键边界（外部调用前后、人工确认前后）。本仓 RunState 53 字段可对照此清单查漏。
7. **入口防线是「区分指令与数据」**（ch6 6.4.4）：网页/工具结果/远程 Agent 返回一律视为不可信输入，不得改变政策、授权范围与当前工具集；Guardrail 只作为额外信号，确定性权限用 Policy+Sandbox 兜。对应本仓第 ② 段安全闸与只读不变量——只读约束应落成确定性策略，而非只靠提示词。
