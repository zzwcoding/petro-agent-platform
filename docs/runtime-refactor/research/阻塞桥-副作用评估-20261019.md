## 0. 结论速览

- **A 案不是「小改」**：要真正解开主环阻塞，offload 点只能是**最外层 async 调用点**（`orchestration/graph.py:547,617` 的 `execute`、`call_model` 的相位调用方）。一旦如此，`execute`/`call_model` 的**全部同步副作用**被搬进工作线程——首当其冲是环亲和的 `EventBus._wake`（`transport/bus.py:101-105`）与 `SecurityAuditSink.__call__`（`api/app.py:100-101`）。只 offload 内层 handler（姊妹件 A 案边界所写）**不解决主环阻塞**。

## 4. 并发语义风险

### 4.1 线程池上限与排队

- 现状：`ThreadPoolExecutor(max_workers=1)` **逐调用新建**（`execution/core.py:473-474`、`closing.py:277-279`、`pg_*` 同款）⇒ 每次 = 1 OS 线程＋1 新事件环＋（DB 桥）一套 `create_async_engine` 引擎池（`pg_executor.py:141-147`、`pg_store.py:162-164`、`pg_waterline.py:97-99`）。成本已在册（`docs/runtime-refactor/design/统筹方案-会话历史持久化.md:136,206`）。
- `anyio.to_thread` 默认容量＝**40**（anyio 4.15.1，`current_default_thread_limiter().total_tokens`，本机实测）；`asyncio.to_thread` 走 loop 默认 executor（`min(32, cpu+4)`）。anyio limiter 是 per-async-context RunVar ⇒ 桥内 `asyncio.run` 的嵌套环各拿新 limiter（不共享）。
- A 案每 offload 占 1 线程**整段**（LLM 秒级）。若 offload 粒度落到单工具 handler（`tools/handlers.py:837,840,1296`），一次 `_gather` 的 N 个工具 ⇒ N 线程同时占额 ⇒ 40 可被并发 run 耗尽，其它 `to_thread` 用户排队（换了个队列的 head-of-line）。
- A 案 offload 最外层时，桥的「有环分支」不再命中（工作线程无运行环）⇒ 省掉 `ThreadPoolExecutor` 那根线程，但 `asyncio.run`＋新引擎照旧**逐调用新建**（成本未减，只是不再占主环）。

### 4.2 asyncpg 环绑定（`infra/db.py:172-260`）

约束：`_LoopResources`／`_resources()`（`db.py:242-252`）按**当前环**懒建一套引擎，`_drop_closed` 剔除已关环桶；`asyncpg` 连接不可跨环（`db.py:186-196` 记录了 2026-10-16 真机缺陷）。钉测＝`tests/infra/test_v2_db_loop_scope.py:40-70`。

- **A 案（工作线程内 `asyncio.run`）：安全。** 线程内无运行环 ⇒ 走直跑分支 ⇒ 当次新环 ⇒ `_resources` 按该环新建引擎；DB 桥每次新建 `ConnectionManager` 并 `finally dispose`（`pg_executor.py:141-147`／`pg_store.py:162-164`／`pg_waterline.py:97-99`）⇒ 池连接与当次环同源，不跨环复用。`test_v2_db_loop_scope.py` 不破。
  - 危险形（A 案须禁）：把 offload 点放在 `_gather` 内的 handler ⇒ `to_thread` 线程内再 `asyncio.run`（第三层环），环/引擎数量翻倍——不炸，但成本与 4.1 叠加。
- **B 案（主环直 await）：安全且是收益。** 引擎归主环桶 ⇒ **连接池首次真实复用**（现状每桥调用都新环新池，池零复用）。风险转为容量面：主环桶首次承担全部 DB 流量，须核 `DatabaseSpec.pool_size/max_overflow`（`config/database.yaml`）是否够。
  - 危险形（B 案须禁）：把模块级 `ConnectionManager` 缓存后又被 `asyncio.run` 工作环取用 ⇒ 回到真机缺陷。B 案若只改部分桥（如只改 LLM/execution，DB 桥仍留），两态必须共存于 `db.py` 的按环分置之下。
- 共同红线：**不得跨环复用同一 `ConnectionManager` 实例**；现状无，A/B 均不得引入。

### 4.3 全局 LLM 门 `_DynamicGate`（`infra/gateway/service.py:69-141`）

门是 `GatewayService` 实例级单例（`:163,196-202`），`_in_flight:int`＋`_waiters: deque[asyncio.Future]` 是**无锁、环亲和**状态；类注释自述「并发正确性建立在事件循环单线程模型上」（`:80-88`），waiter future 由 `asyncio.get_running_loop().create_future()` 在**调用方所在环**创建（`:108`）。生产装配是跨环共享的同一实例：`q12_v2_launcher.py:17`／`q12_v2_eval_launcher.py:22` `GatewayBridge(egress=GatewayService(...))`。

- **现状即有的雷**：`call_model` 在**工作环**里 await `complete`（`closing.py:221→272-279`）⇒ 门的 acquire/release 发生在工作环。并发 ≥3（`llm_max_concurrency=2`）时，A 环 waiter 被 B 环 `release()` 经 `_wake` `set_result`（`service.py:135-141`）⇒ `Future.set_result` → `loop.call_soon` 落到 A 环，**跨线程**。CPython 仅在 `loop._debug=True` 时 `_check_thread` 抛 `RuntimeError`；生产 debug=False ⇒ 不抛，但**不写 self-pipe**，A 环可能睡在 `select()` 里**丢失/延迟唤醒**；同时 `_in_flight += 1/-= 1`（`:105,132`）跨线程读改写有丢更新 ⇒ 门超额或额度泄漏。
- **死锁形（题面「门被线程占用而主环等待」）**：
  - 形①（A 案，唤醒丢失）：主环 waiter 与工作环 releaser 交错 ⇒ 主环 future 永不 `set_result` ⇒ 主环任务挂死；若该主环任务正是驱动 `to_thread` 的 await，则工作线程完成后主环仍不醒 ⇒ **整 run 挂死**（比 4–11s 阻塞更坏）。触发＝≥3 个 `call_model` 并发。
  - 形②（A 案，`release()` 抛错）：某环 `_debug=True`（或 Python 未来收紧）⇒ 跨线程 `set_result` 抛 `RuntimeError` ⇒ 异常从 `gate.__aexit__`（`:139-141`）冒出，`_in_flight` 已减、waiter 未唤醒 ⇒ 门状态腐化。
  - 形③（A 案的伪解）：offload 粒度放内层 handler ⇒ `execute` 仍在主环 `.result()` 死等；「等门的线程」占满 40 额度 ⇒ 新 offload 排队 ⇒ 主环等更久。**A 案不解决主环阻塞，除非 offload 最外层。**
  - B 案：`call_model`/`execute` 变 async、主环直 await ⇒ acquire/release/`_wake` 全在主环 ⇒ 形①②消失，门**零改动**即自洽。前提＝所有 `complete` 调用方都在主环（生产＝uvicorn 单环；评测 launcher 独立进程/独立实例）。
- **若走 A 案**：门须同批线程安全化（`_in_flight` 加 `threading.Lock`；waiter 唤醒改 `loop.call_soon_threadsafe`）——否则是把「未爆的雷」引爆。

### 4.4 A 案独有：线程亲和副作用（姊妹件未列，本次取证）

- **`EventBus` 环亲和**：`_wait_new`（`transport/bus.py:96-98`）在**消费方（SSE，主环）**建 future，`_wake`（`:101-105`）`future.set_result(None)`。`execute` 路径内 `bus.emit(EVENT_TOOL)`（`execution/core.py:1211`）、`bus.emit(EVENT_OBSERVATION)`（`:1237`）、`bus.emit(EVENT_ASK)`（`:1343`）。A 案若 offload 整个 `execute` ⇒ `_wake` 在工作线程 `set_result` 主环 future ⇒ 同 4.3 的跨线程唤醒问题（帧延迟/丢失，`stream()` 消费方挂起）。B 案 `bus.emit` 仍在主环 ⇒ 安全。
- **`SecurityAuditSink` 硬依赖运行环**：`api/app.py:100-101` `asyncio.get_running_loop()`，无环即 `RuntimeError`（docstring 明写「无运行环＝`RuntimeError` 上抛」）；挂 `persistence.configure_audit_sink`，由 `orchestration/audit.py:254` 调用（`audit_run_created` 在 `runtime.py:269`，属驱动段）。当前 `execute` 路径不直调 audit，但**边界不清**——A 案须显式划线「留痕点不入线程」。
- **`RunState` 数据竞争**：`execute` 在 `record_step`/`note` 原地改 `state`；A 案下改发生在工作线程，主环同时可能经 `get_run`（`api/chat.py:340-365`）读同一 run ⇒ 跨线程读改写。B 案全在主环。
- **`anyio` 未声明为直接依赖**（见 §3 末）。
