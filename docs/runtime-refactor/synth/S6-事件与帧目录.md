## 二、wire 帧（api 接缝 3 帧）

真源：`appv2/api/wire.py:47`＝`EVENT_KINDS ∪ {session, done, error}`。

| 帧 | 语义 | 载荷 | 出现时机 |

## 三、帧信封与编号（重写不可漂移）

- **信封字节形**：`id: <int>\nevent: <str>\ndata: <json>\n\n`（恒三行＋空行）；`ensure_ascii=False`（T-P9a1-03）。
- **帧号 `id`**＝**单响应内**自增计数器（非全局、非 runtime seq）（T-P9a1-09）：
  - 新段（提问/resume 段）：session 帧＝0，后续 +1；
  - 重放流：session＝断点+1 → 重放帧号与原流**不对齐（+1）**（T-P9a1-17）；
  - resume 段：帧号**重新从 0 起**（T-P9a1-21）。
- **runtime `seq` ≠ 帧 `id`**：`seq` 只作 `step`/`tool` 帧载荷内键（T-P9a1-10）。
- **载荷透传**：帧 `data`＝`RunEvent.data` 原样，api 层零裁剪零改名（T-P9a1-04）；唯一改造＝verdict 注入 `subtype`。
- **两个面字段不同源**：流内 `step` 帧＝`{step,seq,title}`（3 键）；E4 `steps[]`＝`{seq,step,status,title,manifest,payload}`（6 键）——消费方不得互推（T-P9a1-29）。

## 五、错误码目录（7 值，`errors.py:26-32`）

| HTTP | code | 触发 |
| --- | --- | --- |
| 400 | `chat_param_invalid` | 问句空/仅 Last-Event-ID/appeal 缺参 |
| 400 | `chat_last_event_id_invalid` | Last-Event-ID 非整数 |

| 401 | `security_unauthenticated` | 非五角色键 |
| 404 | `chat_run_not_found` | run 不存在/不在本进程缓冲/前轮不存在 |
| 409 | `chat_run_state` | 互斥入参/前轮未 completed/run 非 waiting_ask |

错误包形状恒 `{code, message[, detail]}`；错误只在**开流前**出 HTTP 状态，开流后一律出帧（T-P9a1-25）。

## 六、本目录暴露的边界与疑点（重写输入）

- `【边界-1】` **挂起铁律**：`ask` 帧之后**照发 done**——挂起看 ask 帧、不看 done（T-P9a1-26）；重写须保留。
- `【边界-2】` **失败腿**：引擎/网关异常→`notice{type:"run_failed"}`＋正常 done（**不触发 error 帧**）（T-P9a1-27）。
- `【边界-3】` **buffer 在进程内**：无淘汰/无上限/无 TTL（D-P9a1-05）——重写接缝须守 ADR-0003（队列消费者形态）。
- `【疑点-1】` `EVENT_BLACKBOX` **未进 `runtime/__init__.py` 公开面**（D-P9a1-09 = S3 C-10）：若重写改显式白名单，blackbox 帧会静默丢。
- `【疑点-2】` **重放帧号位移（+1）**致二次重连可能漏事件（D-P9a1-01）；resume 段帧号从 0 重启致跨段断点失效（D-P9a1-02）。
- `【疑点-3】` **E1/E4 无身份过滤**（D-P9a1-06）：任意身份可读任意 run 全文——是否按 actor 过滤属业务裁决。
- `【疑点-4】` **appv2 路由不在合同覆盖率闸扫描面**（D-P9a1-07）：`GET /runs` 连清单条目也无——重写后端点增删无机器闸对账。
- `【疑点-5】` **error 帧直出 `str(exc)`**（D-P9a1-11）；**E4 触发图重建读态**（D-P9a1-10，异常成裸 500）。
