## 一、现状（这一段现在从头到尾怎么做）

**位次**：理解段入口，**先于一切解析**（零 LLM）。

**数据源**：台账 `ledger_dump` 里的**禁用词行**（`status_key=禁用词`）；取序＝状态优先、`deps.ledger_dump()` 兜底、**双缺则闸静默**（不判）。

**匹配**：问句包含某个禁用词（子串）即命中；**按台账序，首个命中即处置**。

**两分**（`is_ban_exempt` 判）：
- **豁免形**（放行，非直出）＝①**元问形**：元问词（以前叫什么/旧称…）与命中词**同句共现**；②**引用形**：该词每次出现都在**引号对内**。命中 → 先落豁免 notice＋步，**原问句照常进完整管线**；审计 `agent_v2.ban_exempt`。
- **非豁免形**（拒答）＝拿旧叫法要数 → 硬终止，话术：`禁用词「{term}」已废弃——如实拒答，不代答废弃口径（替代：X／见台账）`；替代词取台账「替代：X」注记，**缺映射回落「见台账」**。

**收口**：与词面安全阀同形（notice type=refused ＋ decision 步 ＋ 过程档案 ＋ 直答收口）。

**保留不变**：豁免＝放行非直出；拒答带替代词；豁免/拒答都留痕（审计）。

## 三、最佳实践对照（`research/最佳实践-节点-禁用词闸.md`，本地材料）

- **旧词不是「禁用词黑名单」，而是术语表（Glossary）的一个字段**：旧词先**映射到受治理的语义对象**，命中现行定义才执行。（资料/本体篇、handbook ch8 §8.5-8.6）
- **「提及/询问」与「按旧口径执行」的分界靠「动作类型」**（是否拿它去算数），**不靠词面**；收口两法＝列候选让用户确认，或拒答并给结构化原因＋替代项。
- 台账建成 **Glossary 条**（现行词／状态／替代／Owner）；豁免写成「作用域＋动作＋例外＋验证」并配**保留集验收**。
- 要警惕：**只测拦截不测误放**；把「提及旧名」当「按旧口径执行」**一刀切拦**；**词面命中替代状态判断**。
- 本地缺口：「元问形/引用形→放行」无直接业界条目（只能类推）；判不准时「拒 vs 问」的量化基线没有。

## 五、我的建议 ＋ 重写规划（草案）

1. **判据**：保留**零 LLM 词面豁免**（元问/引用形）——但**把它当「启发式」而非「判据」**；台账里每条禁用词同时标**状态**与**替代**，判不准时倾向「放行进后续」而不是「一刀切拦」。
2. **多条命中**：改为**逐条判、全部非豁免项都处置**（不再是「首个豁免即整句放行」）——治 Q1 漏拦。
3. **台账升级 Glossary 条**：每条术语含 现行词／状态（现行/禁用/别名）／替代／归属。
4. **收口单点**：与词面安全阀共用同一收口（一并消除 Q4 两处平行）。
5. 词典层取读**一次 + 异常兜底**（治 Q2）。
6. 保留不变：豁免＝放行非直出、拒答带替代词、豁免与拒答都留痕。
