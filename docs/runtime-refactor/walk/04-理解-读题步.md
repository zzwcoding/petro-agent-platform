## 一、现状（这一段现在从头到尾怎么做）

**1. 装配任务书**（把一段话发给模型）：
- **静态骨架**四常量：场景（第一环＋走向＋不答题不选工具）／任务（两行输出定义）／**三则样例**（多部分题／口语映射题／判断纠错题）／红线（只输出两行、候选不得出现名录外名字）；
- **动态活体数据**五渲染器：指标名录／术语表／本体对象／本体关系／库族＋水位（**现从活体数据渲染**，台账变它跟着变）；
- 顺序：场景 → 任务 → 样例 → 环境（库族/水位/名录/术语/本体）→ 红线 → 【题干】→「（现在输出两行。）」。
- **指令与数据挤在同一段**：名录/术语/本体（约 1500 字活体数据）嵌在任务书正文中段，未分节（P6a A-P6a-06 病灶 P6/P7）。

**2. 模型读题**：把整条对话链发给模型（一次调用）；模型回「理解：…／指标候选：…」。

**3. 解析**：`parse_understanding` 两级宽容——①优先认两行式（行首「理解」「指标候选」，冒号后取值）；②两行全缺 → 从应答里抠第一个 `{...}` 当 JSON 降级提取；③两级全空 → 返回空值如实上报、**不拦停**。另一路 `parse_direct_reply` 抽「直接回答：」行。

**4. 产物**：`understanding`（理解文本，另发 text 事件灰条）＋`metric_candidates`（候选指标）；理解摘要落过程档案（**截 200 字**）。模型原话**不进对话层**。

**保留不变**：任务书每 run 追加一次；模型原话不入对话层；候选须出自名录（红线）。

## 三、最佳实践对照（`research/最佳实践-节点-读题步.md`，本地材料）

- **三层分离**：静态指令前缀 ／ **动态数据分节注入、追加末尾** ／ 输出契约独立冻结；**来源标记**（标明哪段是数据）。（handbook ch5；ai-agent-book ch2）
- 用 **Context Manifest** 记录「这次模型看到了什么」。（handbook ch5）
- **指令与数据分离是核心防线**：分节＋来源标记＋结构化角色三层；消融实证——打乱规则组织成功率降 >30%、删工具描述错误率 +45%。（handbook 6.4.4；ai-agent-book ch2）
- **输出**：模型出候选、程序校验放行；**宽容解析层正被「结构化输出」内化淘汰**；强 schema 表达不了隐式约定时，靠 **1–5 个真例**补。（ai-agent-book ch1/ch4）
- **few-shot**：只在规则说不清时给 2–3 个边界例，固定示例集（缓存友好），**忌逐请求挑**。（ai-agent-book ch2）
- 判据：**严格契约 vs 宽容降级，看「消费面是否按字面解析」**——消费面按字面依赖，就必须逐字冻结。
- 本地缺口：纯读题步「该给什么/不该给什么」无专章；自定义文本契约的解析宽容度覆盖不到。

## 五、我的建议 ＋ 重写规划（草案）

1. **任务书分三区**：**指令区**（场景/任务/红线，纯指令）→ **数据区**（名录/术语/本体/水位，**程序渲染、标来源、追加末尾**）→ **输出契约区**（末尾、短）。
2. **输出契约**：**短期保持两行式逐字冻结**（下游三消费面按字面解析）；统一 JSON 作为**中期迁移目标**（P6a 建议③缓行项，这次不做）。
3. **解析改严格**：去掉「冒号回退取整行」；同类行多次出现**报错或取最后一条并标注**，不静默覆盖。
4. **单出口**：直答/理解**强制二选一**（新契约下由字段天然互斥）。
5. **样例**：保留格式样例（教格式不教判断）；**不再加边界对照例**（沿 Owner 已定）。
6. 保留不变：任务书每 run 一次、模型原话不入对话层、候选出自名录。
