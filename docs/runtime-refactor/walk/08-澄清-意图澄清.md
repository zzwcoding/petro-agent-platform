## 一、现状（这一段现在从头到尾怎么做）

澄清段（相位①）＝**模型的第一个决策相位**，只有**四个动作**（闭世界）：
1. **查资料**（discover）：先探清楚名词/对象（限额每轮 ≤2、全 run ≤10）；
2. **把大问题拆成小问题**（decompose）：≤4 个子问题，每个带台账逐字注释、标路线（数据链/文档链）；
3. **向用户反问**（ask）：问题/口径确实有歧义 → 发「反问卡」（问题＋选项）**挂起等用户选**；
4. **定案**（finalize）：进下一相位。

**时机规则**：时间范围能从问句确定＝**不许反问**；时间词能解析＝直接定范围；**没有时间词＝默认「近 30 天」并注明**。

**上下文**：台账全量（含别名、结构卡）**每轮完整放进模型上下文**（ADR-0005 拍板「注入胜检索」——词典层小）。

**解析**：模型出**结构化发射**（`ClarifyEmission`），程序做**闭合世界 schema 对账**（四动作、子问题数、注释必带）；非法产＝拒因回喂自环（不做自动修补）。

**反问封顶**：连续 ask **≥6** → 截断＋带材料如实直答（不环，S3 C-04 已核）。

## 三、最佳实践对照（`research/最佳实践-节点-澄清.md`，本地材料）

- **反问不是默认兜底**：只在「歧义**实质改变**交付内容/责任/执行边界」时才付反问的成本。（handbook ch11／ch6）
- **主流形态＝先探后问**：先在指标库/知识里探出 2–3 个候选，**再让用户确认**。（Datastrato／DataBuddy 检索瀑布）
- **澄清前置**是正面范式（执行前先把意图、数据源、指标问清）。（ai-agent-book ch1）
- **分解要封顶**：只在「独立交付/不同责任/明确依赖」时才拆；**子问题数、分解深度、返工轮次都要封顶**。（handbook ch11）
- **默认值按风险分级**：低风险读取可给默认（**带记录**）；口径由参数决定、**不交模型猜**。（handbook ch6）
- 缺口：本地**无**「反问封顶/追问次数上限」专论；**无**「默认时间窗」直接论述（部分为推断）。
