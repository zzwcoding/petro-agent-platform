## 一、现状（这一段现在从头到尾怎么做）

澄清相位里模型可选的一个动作：**把大问题拆成 ≤4 个小问题**。
- 每个小问题必须带**从台账逐字抄来的注释**（ledger_notes）——不能自造；
- 每个小问题标**路线**：`data`（查数表出数字）／`knowledge`（搜报告出答案）；

- **程序对账**：闭合世界 schema——四动作、子问题数、注释必带；非法产＝拒因回喂自环。
- 模型也可以选 **finalize**（不拆，直接进下一相位）——**拆与不拆由模型定**。

## 三、最佳实践对照（`research/最佳实践-节点-分解问题.md`，本地材料）

- **分解是「有条件动作」，不是默认**：存在「独立交付／不同责任／明确依赖」才拆。（handbook ch14）
- **封顶要开始前一次性约定**（最大深度、派生任务数、返工轮次）。（handbook ch14）
- 子任务带**可机读契约**（目标边界／已知上下文／能力权限／预算／输出证据／失败语义／验收）；**共同约束引用父级、只补特有字段**——正合「注释逐字抄台账」。（handbook ch06/ch14）
- **拆完要校验覆盖**：子结果**共同覆盖原目标**；需求↔实做**集合差**取遗漏项；必要时**交叉验证**。（handbook ch14；ai-agent-book ch7）
- **失败模式**：太碎/太粗、**依赖没显式声明**、**覆盖不全**。
- 缺口：无「≤4」数字论述、无「拆完即刻机检覆盖」工序、无「路线由谁定」专论。

## 五、我的建议 ＋ 重写规划（草案）

1. **拆与不拆交模型**（现状已符合）；**路线标注交模型**（现状已符合）；**程序只对账**（数/注释/路线闭世界）——保留。
2. **补一道「覆盖校验」**：拆完后确认「子问题合起来是否覆盖原题」——**这是语义判断，交模型**（可让模型在 JSON 里附「覆盖自证」，或加一步轻校验）；**程序不拿词表去猜覆盖**。
3. **子问题不引入依赖**（只读问答、子问题独立并行）；若将来出现依赖场景，再按最佳实践加显式依赖字段。
4. **「≤4」进统一预算表**（值可调，注明自定来源）。
5. 保留不变：注释逐字抄台账、路线闭世界（data/knowledge）、非法产拒因回喂（不自动修补）。
