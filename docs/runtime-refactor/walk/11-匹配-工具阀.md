## 三、最佳实践对照（`research/最佳实践-节点-工具匹配.md`，本地材料）

- **模型只「提议」配哪个工具＋参数；工具清单是闭世界白名单**，程序放行。（ai-agent-book ch4；handbook ch6/ch9）
- **参数走结构化 schema 强校验**（必填、闭世界枚举）。（ai-agent-book ch4；handbook ch6）
- **失败处置**：把**结构化原因回喂重选**（**不自动修补**）、**重试封顶＋熔断**。
- **选错工具的首因是「描述没写边界」**，不是模型弱——工具描述要写「**何时用／不能做什么／参数示例**」。
- **工具集小（<10）→ 不该上检索式/主动发现那套重设施**。
- 缺口：本地**无**「子问题恰好配一条」的闭合对账范式（**本项目自定**）、无失败反馈措辞模板、无「查询计划」字段定义。

## 五、我的建议 ＋ 重写规划（草案）

1. **保持**：模型提议 → **程序闭世界对账（恰配一条）**、拒因回喂**不自动修补**、参数强校验、工具集小**不做主动发现**。
2. **补强工具描述**：每个工具写全「**何时用 / 不能做什么 / 参数示例**」——这是**选得准的第一因**（不是加更多规则）。
3. **重试封顶**：拒因回喂的自环**保持靠轮数闸兜底**；若实测仍有空转，再加**熔断**（同一子问题连拒 N 次即停）。
4. **参数枚举收紧**：把能枚举的参数（task_type／direction／chain）都落成闭世界。
5. 保留不变：名归一闸、聚合下推。
