# 回答全链路全景图（Owner 判读版）

> 2026-10-17 · 目的：一份文档看懂"一个提问变成答案"的全程——每个节点**什么条件下**加什么提示词（附**真实原文实例**）、病例是哪个节点的输入造成的、修改方案改哪里。

## 一、七个节点总览

用户提问 → 依次过七个节点，每个节点要么**调一次大模型**（提示词=发给它的全部内容），要么**纯程序**（不调模型，只做检查/改写）：

| # | 节点 | 干什么 | 谁干活 |
|---|---|---|---|
| 0 | **读题** | 把问题读懂：复述题意＋列出涉及指标 | LLM |
| 1 | **澄清/分解** | 信息不够就反问；够就拆成子问题、决定每问走"查数链"还是"报告检索链" | LLM（每轮） |
| 2 | **工具匹配** | 为每个子问题填具体参数（哪口井、哪个指标、什么时间窗、是否排名） | LLM（每轮） |
| 3 | **前置检查** | 程序闸门：时间窗合法吗？指标绑定了吗？有没有禁用词？ | 纯程序 |
| 4 | **执行** | 真去查：数据库取数 / 报告库检索；产出"观察材料"（数据行、报告片段） | 工具＋程序 |
| 5 | **作答** | 看着观察材料写答案正文（Markdown） | LLM（一次） |
| 6 | **核验** | 逐行检查：每句断言有没有材料支撑、数值对不对、油田归对没有 | 纯程序 |
| 7 | **交付** | 把核验后的正文＋引用清单＋血缘卡发给前端 | 纯程序 |

**先记住两条铁律**：
1. **模型最省力的策略是"转述它在提示词里最后读到的原文"**——哪段话放在末尾、是程序写死的，模型就会照抄。这是后面一大批病例的总根源。
2. **角色全景**：实测多 run 全量消息统计——**程序加入的一切信息都是 user 角色，链路里不存在 system 角色**（233 条消息＝user 154／assistant 79／system 0）。合同指令与观察材料**同角色平级**：指令优先级天然矮一级，模型区分"命令"与"资料"只能靠文本形态。结构改法候选（未动工）：合同指令族挪一条 system 消息放链首（只换承载位不换文本）。

## 二、逐节点解剖（条件 → 加入什么 → 真实实例 → LLM 要输出）

### 节点 0 · 读题（understand）

- **条件**：每个提问必进，一次。
- **加入的提示词**（全部 user 角色，`appv2/runtimev2/understanding/`）：
  1. 读题合同约 1500 字（角色＋输出格式＋样例）
  2. 环境装配约 2100 字（20 指标名册＋11 术语表＋本体速览，静态，每问必带）
  3. 用户原题
- **真实实例**（发给 LLM 的格式指令，逐字）：
```
【你的输出与它的消费方式】输出固定两行，格式强制：
第一行「理解：〈一句话〉」——它是后续所有环节的题意锚：澄清按它拆子问题，
核验按它判断是否答全，交付按它对题。要求：忠实复述题干要求；题干分①②③的照数保留…
第二行「指标候选：〈逗号分隔〉」——它是后续取数的指标白名单：定案环节填报的
指标名必须逐字出自本行
```
- **LLM 要输出**：严格 JSON（理解句＋指标候选名单）。
- **已知问题**：教的是"两行式"样例、收的是 JSON——教与考不同形，约 13% 首读不合规被拒（后有重试/引号自修兜底）。

### 节点 1 · 澄清/分解（clarify）

- **条件**：读题通过后进入；每轮决策都调 LLM；可能在此反问用户（挂起）或拆子问题。
- **加入的提示词**（user 角色，`clarification/core.py` 装配）：
  1. 相位①合同约 2400 字（四动作＋样板行）
  2. §A 指南段约 2400 字（首轮带一次）
  3. 台账常驻注入约 5000 字（**首轮带一次**：全量指标名册，标了每个指标"已绑定/未绑定"）
  4. 动态条（每轮变）：轮数、探查预算
- **真实实例 1**（合同中的分解指令，逐字摘自 `CLARIFY_EMISSION_CONTRACT`）：
```
- 分解：{"action": "decompose", "question_group": {"subtasks": [{"id": "s1",
  "question": "子问题原文", "ledger_notes": "〈精确指标 slot 名〉〈绑定态〉〈锚定窗〉",
  "chain": "data"|"knowledge", "tool": "data_query"|"doc_retrieve"}]}}
  ——子问题 ≤{max_subtasks} 个；…ledger_notes 必带——从下方台账全量块逐字转抄，不改写不杜撰。
- 钻取：{"action": "discover", …}——1~2 支。开局已给全台账，禁猜词敲门…
```
- **真实实例 2**（真机产出的 ledger_notes 行——D-诱9 病例里把路锁死的就是这一行）：
```
L04-07 run： "日产油量｜已绑定｜2026-09-08~2026-10-08","chain":"data"
D-诱9 run：  "检泵周期｜未绑定｜2026-08-01~2026-08-31","chain":"data"  ← chain 写死，后面就是它堵死的路
```
- **LLM 要输出**：JSON 动作（分解/探查/反问/定稿）。
- **关键程序闸门（提示词之外的硬规则，用户不可见但决定走向）**：
  - `clarification/core.py:463`：只要"问题组已生成"就**禁止再探查**（`_rediscover_blocked`）——D-诱9 的堵点之一
  - 换链回炉"一次为界，坚持同参即终局拒答"

### 节点 2 · 工具匹配（match）

- **条件**：有子问题组后每轮调 LLM。
- **加入**：相位②合同约 1560 字（填参契约：井号槽/指标槽/窗槽/排名槽/限量槽＋禁则）＋台账常驻（同节点 1，首轮一次）＋问题组清单＋检索锚注入。全 user 角色。
- **LLM 要输出**：每子问题的工具参数 JSON。
- **已知问题**：题面含已注册指标词（如"台账口径"）时，报告检索类正题可能被带进查数链（D-诱9 族）。

### 节点 3 · 前置检查（precondition）—— 纯程序，零 LLM

- **条件**：每轮子问题执行前必过。
- **干什么**（全部程序判定）：时间窗闸（模糊词必须窗槽 null）／绑定闸（指标未绑定→拒或换链）／**禁 discover 闸**（问题组在场即拒探查）／词面门／互斥闸（排名∧合计同真拒）／**换链回炉一次为界**。
- **真实实例**（程序写死、**用户可见**的话术，逐字）：
```
反问卡（ask 帧 prompt，前端反问卡正文）：
「这个问题没说清要看哪段时间——请先选一个时间范围
 （含糊的说法我不会自己猜，也不会默认取最近一段时间）」

换链回炉终局话术（EB4b 改前原文，D-诱9 用户看到的就是这句）：
「换链回炉已用尽（一次为界）：坚持 data 链同参（指纹 ……在簿）——未绑定口径如实拒答，不代答」
```

### 节点 4 · 执行（execute）

- **条件**：前置放行后逐子问题执行；产出**观察材料**（observation，节点 5 的输入）。
- **观察材料装配规则**（`context/materials.py`——多数病例的根在这）：
  1. **权威族**（数据库行集、台账卡）**全量进窗**，不占帽
  2. **检索族**（报告片段）**最多 24 支**（24 帽）
  3. 选支规则（`retrieval/domain.py:564`）：同一份报告至多选一半片段＋来源多样性配额
  4. 血缘卡五要素不进窗，浓缩成一行「【口径】…｜来源：…」
- **真实实例 1**（数据链"口径行"渲染，逐字自测试实测）：
```
[2]（authoritative｜agg.fct_daily_metering）【口径】日产油量（单位：吨）——指标台账注册
声明：日产计量的日产油量（吨），口径随答案标注｜来源：agg.fct_daily_metering（agg 星型读模型 ⋈ 井维度 ⋈ 日期维度）
```
- **真实实例 2**（引擎注记——生成代码与真机产出，这就是被照抄 221/291 次的那段）：
```python
# retrieval/domain.py 生成单点（逐字）
note = f"召回 {recalled} 支/送窗 {sent} 支"
if recalled > sent: note += f"；已召回未送窗 {recalled - sent} 支"
if len(sources) >= 2: note += "；矛盾来源同窗并立（各留代表支）：" + …
if missing: note += "；缺位来源（预算未及）：" + …
```
真机拼接后追加在节点 5 提示词**最末尾**：
```
引擎注记（引擎降级／拦停／未绑定注记——如实转述，不得静默丢弃）：
召回 46 支/送窗 11 支；已召回未送窗 35 支；缺位来源（预算未及）：《渤中34-8…月报-202701》
```

### 节点 5 · 作答（answer）—— 病例最集中的节点

- **条件**：执行完、有材料后，调一次 LLM。
- **加入的提示词**（全 user 角色，顺序固定，`prompts/answer_round.py:106-116`）：
  1. 三件套（用户问题＋"现在：写最终答案"＋【答案要求】头）
  2. **JARGON_PLAIN_GLOSSARY 术语白话表**约 300 字——位置在**前 12%**
  3. SUMMARY_CONTRACT（逐子问题一行结论）
  4. ANSWER_REQUIREMENTS **10 条**（引标纪律/分源/未覆盖处理/引擎注记转述/白话要求⑨⑩…）
  5. 子问题结果清单
  6. **观察材料渲染段**（几百到上万字，带 [n] 序号，24 帽已生效）
  7. **引擎注记段**（230–890 字，**最末尾**——见节点 4 实例 2）
- **真实实例**（白话表＋⑨条＋⑩条，逐字）：
```
【术语白话表】口径＝这个数是按什么规则算的；台账＝平台里登记指标和术语的名册；
水位＝数据目前更新到哪一天；窗＝统计的时间段；绑定＝登记关联；召回＝检索到的材料；送窗＝用进答案的材料。
```
```
⑨：「…不要把内部说法整句甩给用户（『召回 51 支/送窗 12 支』应写成
    『检索到 51 条材料，其中 12 条用进了答案』）。」
⑩：「材料未覆盖所问时：先从已给材料中答出可能与问题相关的内容，
     再给用户一句更容易查到结果的提问建议（如补充井号、时间范围或报告名称）。」
```
- **对照要点**：白话表在前 12%、禁则⑨条配了正反例——但**最末尾**是"召回 46 支/送窗 11 支"原文。落笔前最后读到的是后者（铁律 1）。
- **LLM 要输出**：答案正文 Markdown。

### 节点 6 · 核验（verify）—— 纯程序，"看病的医生"

- **条件**：草稿产出后必过；逐行处理。
- **干什么**：引标可解析？数值在不在被引材料里？（**只查"有没有据"，不查"配得对不对"**）油田归属对不对？没据的行**删**（残尾护栏补一句诚实收口）；坏引标剥除；分源/血缘块移到增补面。
- **真实实例**（三个判定，逐字形态）：
```
保留：「断点 1650 米 [7]」      → 引标7的值域含 1650 → 保留
删（F1修前）：「W-22 井教训侧重定向井段…」 → 无引标且含数字串 22 → 整行删
           （F1修后：井号不算数值断言 → 保留）
拒收（F1件四）：NQ-M4 整行材料全属渤中34-5而题眼是 34-8 → 拒收
```

### 节点 7 · 交付 —— 纯程序

- **干什么**：正文（核验后稿）＋ supplement 增补面帧＋ notice 帧＋ citation 帧。
- **真实实例**（帧载荷）：
```
supplement: {block:"lineage", text:"血缘卡五要素全文"}
supplement: {block:"citations", text:"\n\n引用：\n[1] agg…·N-01@2025-09-01（authoritative）…"}
notice:     {type:"material_truncated", text:"这次回答只用到检索到的 24/88 条材料——没用上的部分不作答。"}（EB4b 白话化后）
```

## 三、病例归因：哪个节点、哪段输入、造成什么

> 排序按危害。根因分类：④输入材料 / ①提示词诱导 / ②提示词缺失 / ③模型行为。

### 病例 1 · 满篇"本报告"却不知道是哪份报告（run-15754d25）
- **断点节点**：5（作答）→ 输入里**没有"先报名字"的任何诱导**（②缺失）；材料段里每份报告以检索窗注记形出现，不带《报告全名》。
- **影响**：答案 3 次"本报告"、9 次裸"报告"、0 次全称——用户无法知道依据是什么。

### 病例 2 · "话没说完"三连（C-反1 断在冒号 / NQ-D5 表头悬空 / D-诱12 断在裸标题）
- **断点节点**：6（核验删句）＋ 5（草稿漏行级引标）。
- **机制**：草稿里综述段是**重组上文已引事实**、没挂引标；旧删句判据把"W-22"的 22 当数值→整段删；无数字的引导句（"："、表头、标题）幸存 → 用户看到话没说完。
- **状态**：F1 已修（判据收窄＋跨行支撑＋残尾护栏），真机重放 rewritten 5→0。

### 病例 3 · D-诱9 路由翻转（EB3 能答四数 → EB4 整题拒答）
- **断点节点**：1（澄清）→ 3（禁 discover 闸＋换链一次为界）。
- **机制**：题面含"台账口径"→合同教它"台账命中＋窗已定＝直发分解"→chain:data 写死→想回头探查时被 `core.py:463` 拒→换链"一次为界"拒→终局拒答零数值（节点 3 的终局话术原文见上）。
- **根因**：①提示词诱导（"禁再 discover"条款）＋程序判据过死。

### 病例 4 · 谎称无据族五题（B-反2/B-正6/C-正4/NQ-D4/D-诱12）
- **断点节点**：4（送窗规则）× 6（未送窗不得断言）。
- **机制**：选支配额＋24 帽把含答案的片段切走（实测多处 0 命中）→ 材料窗里真没有 → 答案如实说"未覆盖" → 用户读到"库里没有"（库里明明有）。
- **根因**：④输入材料——两个各自正确的规则相乘的系统性后果。

### 病例 5 · 428 当杆断平均（B-正2，应为 443）
- **断点节点**：4（24 帽把含 512/521 的明细表切出窗外）→ 5（拿看得见的全员均 428 答）。
- **根因**：④＋③——窗外无据可算，窗内的值口径不对。

### 病例 6 · 压力配对错（NQ-C6，4 处配对错误）
- **断点节点**：4（16.5/12.5 MPa 整 run 79 条观察一条都没有——根本没召回）→ 5（两井的值并列混配）。
- **根因**：④（题眼数值没进检索锚）＋③（核验只判"有没据"判不出"配对错"）。

### 病例 7 · 白话化三层失效（7 题甩"召回 N 条/送窗 M 条"）
- **断点节点**：5 的提示词**尾段**（引擎注记原文）vs **前 12%**（白话表＋⑨条）。
- **机制解剖**：①⑨条前半命令"如实转述引擎注记"、④条命令"点名未覆盖来源"——而"计数＋缺位名单"是同一行不可分的原子文本，转述必然连计数带行话一起抄；②白话表是"映射不是禁令"；③反例『召回 51 支/送窗 12 支』与输入同模板只差数字——示例反噬；④位置：白话表在前 12%、注记在末尾。
- **数据**：291 次答案调用 221 次照抄计数；白话化合规 0 题。
- **结论**：输出侧再加任何层都会同样失效——**只能改输入侧**。

### 病例 8 · 报告口径值不标"非权威"（L04-10/11/19/20、数-降2）
- **断点节点**：5（无此诱导）→ 7（交付装配不补标注）。报告检索链的值直接当数据库权威值交。

### 病例 9 · A-正6 零检索断言"报告库未检索到 W-111"
- **断点节点**：1（澄清 ask 文案）——条款"主体未命中→反问并给相近候选"**邀请模型对根本没检索过的库下断言**（库实：《A-W11 报告》1.1 载 W-111 为观察井）。

### 病例 10 · L04-07"采得最狠"自选指标直取数
- **断点节点**：1——三个指标候选并列、题面含义含糊，合同样例没有这一形（②缺失），模型自选"日产油量"直发查数链。

### 已自然收敛的（不修）
- 数-反1/L04-17 弹不弹澄清分叉：**EB4 最近窗已稳定合规**——D 项专批可降级观察。
- 模型漏行级引标：随病例 2 修法消除诱因后观察。

## 四、修改方案：哪个节点、什么条件下、改什么

| 方案 | 节点 | 改什么（条件→动作） | 治哪些病例 | 风险 |
