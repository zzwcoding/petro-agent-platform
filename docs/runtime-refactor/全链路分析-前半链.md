## §2 逐环节分析与修复方向

### 2.1 理解（understand）

- **它加载什么**：任务书一条（§1.1），段序＝指令区→数据区→输出契约区→题干段；**题干在链首、指令在链尾**。
- **实测表现**：理解环基本不失分。EB4 目标题中，理解输出全部合理（数-反1 `理解：问最近各井日产油量。`／L04-07 三候选并列／A-正6 `指标候选：[]`／D-诱9 `指标候选：检泵周期`）。
- **本环具体问题（两条）**：
  1. **多候选并列无裁决**（L04-07）：`metric_candidates: ["日产油量","日产液量","综合含水率"]` 三个并列，且对「采得最狠」未做含义澄清——但这个裁决**不该**由理解环做（合同明写理解「不回答问题、不选工具」），所以它是**传递面**问题，不是理解环缺陷。真正的空档在下环（见 2.2 L04-07）。
  2. **两行式文本回流 JSON 字段（本环唯一实测往复）**：三处形态——①EB4G-L04-17（`run-224ce49b`）`{"route":"full","text":"理解：问最近各井的日产油量。\n指标候选：日产油量","metric_candidates":["日产油量"]}`——`text` 里混入旧两行式的第二行；②EB3-数-反1（`run-b0c12369`）与 EB3G-L04-17（`run-ff786dcf`）**首读即被 schema 拒**（回喂条逐字：「【拒因】缺必填字段 `metric_candidates`……」，见 `understanding/interpret.py:225/236`），模型第一次回的正是两行式、第二次才落 JSON——**每 run 白烧一次模型调用**；③EB4-数-反1（`run-cde08ace`）才一次落 JSON。`task_book.py:11-13` 自己已登记这条张力（指令区字面仍是 V1 两行式，而 `TASK_BOOK_OUTPUT_CONTRACT` 要 JSON）。
- **修复方向（不加条例）**：①**文本面收口**（不是新增条例而是删余）：指令区的「第二行『指标候选：...』」措辞与样例里的「指标候选：X」行改为与输出契约同形的示例（样例三则本来就有「输出：理解：…／指标候选：…」行，改成 JSON 形即可）——属**位置调整＋few-shot 示例替换**，不加新条款；②多候选并列时**不**在理解环加判据（守「理解不选工具」），把并列如实传下去。
- 理由：两处都是**教据与闸不同形**的同款病灶（教两行式、收 JSON），修教据最省且零新规则。

### 2.2 澄清（clarify）

**（a）窗槽裁决**（数-反1／L04-17）

- 链路：理解不给窗 → 澄清模型在 `ledger_notes` 窗段与（下环）`plan.window_*` 自选 → 程序只做**形态**对账（`specs/clarification.md:87` 三段槽位对账）与**双 null 机械分派**（`preconditions/core.py` 位 2）。
- **裁决者结论：澄清相位的模型**。理解环无窗字段；前置条件机只在「载荷窗槽双 null」这一结构事实上反问，不判断「最近」该不该锚。EB4 两跑同走合规形（`null~null`）→ 该对题在最近窗**已不分叉**；EB3 的分叉（数-反1 自锚 `2026-09-08~2026-10-08`、L04-17 写 `null~null`）是模型侧不确定性。
- **修复方向**：**程序接管**——把「已定窗」这一事实改为可机检：模型在窗段给出锚定窗时，程序照 §A 窗词锚定表回校（表中「最近／近期」= 双 null 是闭世界词面，`ontology/petro/skill-guides/instructions.md §A` 逐字在窗），不一致＝走既有**拒因回喂**（不是新增条款，是把既有对账从「形」扩到「表」）。理由：同类病灶（错锚窗→新鲜度拦停→零交付）复发面大（EB3 数-反1、EB4G-L04-07、EB2/EB3 一批），合同措辞已足够、救不了，唯程序回校能止。**不动合同一条字**。

**（b）chain 选择**（D-诱9）

- 病灶链：`台账口径` 句式 → 理解 `指标候选：检泵周期`（台账内、`未绑定`）→ 澄清**先 decompose**（三子问题全 `chain=data`）→ 程序 `_rediscover_blocked`（`clarification/core.py:463`）冻死后续 discover → 工具匹配维持 data → 前置条件机闸 4 `unbound_binding`（`appv2/tools/precondition.py:543-547`）触发 `chain_switch` → 一次回炉后同参 → `refuse`（终局）→ 零数值。
- 与 EB3 的差异**只在一步**：EB3 的模型**先**发了 5 次 discover（`semantic_query`/`table_schema`），拿到口径卡后写成 `chain=knowledge`（单子问题），一次成功交付四数。EB4 先 decompose 即被锁死探索路径。
- **修复方向**：
  1. **程序接管（首选）**：`_rediscover_blocked` 的机械前提「`ledger_projection` 非空 ＋ `question_group` 已在场」过宽——台账常驻注入几乎恒非空，导致「先分解」＝永久放弃探查。收窄为「**问题组内的 chain 已全部为可执行形**」时才冻结（即只有「分解已可执行」才叫『分解完毕』），可让 D-诱9 这类「先分解但 chain 选错」的题仍有 discover 修正窗。零合同改动。
  2. **材料面修补（次选）**：台账常驻块的 `LEDGER_DICT_NOTE`（`decision_round.py:95`）与 `_ledger_rows`（`decision_round.py:179`）在「未绑定」行后**紧跟**该指标的可检索来源（族/报告名），把「未绑定→knowledge」从「样例里的一条」变成「行内的事实」。
  - 理由：合同字面（含样例）已教过「未绑定→knowledge」，再加条款只会加重「指令诅咒」；真正的缺口是**程序把修正路封了**，以及**台账行不自带去向**。

**（c）ask 文案的库态断言**（A-正6）

- 病灶：§A「主体未命中」条款邀请模型直接 ask 并给相近候选；模型据此写出「台账与报告库中均未检索到命中」——**全程零检索**（`run-ef5fa4bb` 只有 understand→decision 两次调用），库实有（A-W11 完井报告 1.1 井位与井别）。
- **修复方向**：**结构化输出＋程序接管**：`ask` 帧内容拆件（`reason`／候选／来源），要求「库态断言」类句子只能由**程序**在既有 discover 结果上生成（无 discover 记录＝程序不生成该句）——模型只给候选与问题。理由：库态是事实面、不是模型可推的面；同族（§A 主体未命中）已被写进合同，缺的是**供给侧结构性约束**，属程序接管而非新条例。

**（d）快慢路裁决／含义未澄清**（L04-07）

- 病灶：`采得最狠`＝含义歧义（采油强度？产液强度？），golden 期望 `metric=None`（慢路·不编数）；实际自选 `日产油量` 直发 data 链（且窗晚于水位必被拦停）。
- **修复方向**：**few-shot 示例（首选）**——在既有 `TASK_BOOK_EXAMPLES`／分解样例的位置补一条**「题面含义含糊、指标候选多个并列」**形的整样例行（示范「发 `ask` 或先点名所选口径再取数」），位置放在现有三则之后；**不新增条款句**。理由：本轮同类成功案例全来自样例面（EB3 D-诱9 的 discover 形、L3-06 的三段位行），抽象条款一轮轮加都无效（`docs/runtime-refactor/research/最佳实践-3a-白话化与受众适配.md`：示例>抽象规则）。

### 2.3 工具匹配（toolmatch）

- 本环在目标题里**未见独立断点**：D-诱9 的 `malformed_matches`（模型发 `waiting_hold=false` 裸文本）经既有拒因回喂一次即修；其余题 `matches` 与问题组一一对应、`metric_slot` 逐字合规。

- **修复方向**：无（守「每子问题恰一条、id 闭合」现状）。若采纳 2.2(b) 的「问题组 chain 可执行才冻结」，本环自然受益（能收到修正后的 chain）。

### 2.4 执行（检索腿）——「材料在库答未覆盖」家族

- 机制（实测）：`supply_window`（族配额＋来源多样 3/4 与 1/4 分池）＋ `render_materials` 的 **24 支检索族帽** —— 两个上限叠加，再叠加答案面的转述规则「未渲染片段不在本轮视野，不得对其断言」（`materials.py:170-178`）与 `ANSWER_REQUIREMENTS`「材料未覆盖的部分不得断言、如实说明未覆盖」，把**上游选址失误**翻译成用户可读的「**库里没有**」。

- **另有一条族级环境面（非全批系统性）**：钟 2026-10-08 与水 2026-08-31 差 38 天 → 「无时间词默认近 30 天」窗（`2026-09-08~2026-10-08`）与「本月／今年」类窗**必**晚于水位 → 新鲜度闸必拦停。EB4/EB4G 全批 121 帧中 **8 帧命中「新鲜度闸拦停」**（`EB4-数-察1`「各井日产油量是多少？」、`EB4-数-闸1`「本月各井日产油量」、`EB4-数-闸2`「近 7 天各井日产液量」、`EB4-数-闸3`、`EB4G-L04-13`（排名）、`EB4G-L04-07/14/24`——即**全部为无时间词／本月／近 N 天类**），且这 8 帧的作答面材料块数全部 ≤3（0/0/0/0/1/0/0/0）——即「窗选择＋钟水差」在这一族题上必然产出零交付（L04-07＋EB3 数-反1 为同因；带时间词的题不受影响，如 EB4-数-明1 窗 2025 全年 → `s1=allow`、支撑 51）。口径本身已被挂账：流水 72（`c423170`）记「冻结钟=水位日致闸族结构性不触发……全量评测钟口径待 Owner 裁」。
- **修复方向**（材料面修补，不加条例）：
  1. **送窗选支加「题眼章节保底」**：`supply_window` 的题眼锚保底（现仅按井号/报告名锚）扩到**章节级锚**（问句里出现「1.2 折算表」「4.1 节」「断点」等题面词时，命中该词的 section 整支保底）——与既有「表类整行集」同族，属程序接管。

## §3 横向结论：前半链共性病灶 top3

**病灶 1｜「限制条款写死、修正路被程序封」——前置条件机的换链回炉形同虚设（D-诱9 形，危害最大）**
合同里「台账命中＋窗已定＝禁再 discover（直发分解）」（`constants.py:129`）与程序 `_rediscover_blocked`（`clarification/core.py:463`：台账投影非空＋问题组已在场即拒 discover）**同款同向**，把「先分解」变成不可逆选择；`chain_switch` 回炉「一次为界、坚持同参即终局」（`preconditions/core.py:242-250`）再补一刀。结果是 EB3 能交付的题（靠先 discover 拿到 `chain=knowledge`）在 EB4 翻转成零数值。**证据**：`run-de7dc1c1` 全链 24 步、`s1/s3=refuse（chain_switch）`、答案仅两条改问建议；对照 `run-17b48ed0` 同题 7 支撑交付四数。**方向**：把「分解完毕」的机械前提从「问题组已在场」改为「问题组内 chain 全部可执行」，让换链有一次真实的修正机会（程序接管，零合同改动）。

**病灶 2｜「未送窗＝不得断言」× 上游选址上限 ＝ 系统性「谎称无据」（B-反2／B-正6／C-正4／NQ-D4／D-诱12 五题同形）**
送窗受**族配额＋来源多样性（同报告至多半额）**（`retrieval/domain.py:564`）与**24 支检索族帽**（`context/materials.py:61`）双重限制；答案面又被合规要求「未渲染片段不得断言、如实说明未覆盖」。两个正确行为的乘积＝**用户读到「库里没有」，而库里明明有**（34-8 次月目标、34-5 近三年表、C-34-5 的 W-33 酸化效果、34-8 1.2 折算表、W-22 断点 1980）。EB4 全批 108 次作答调用中 **44 次（41%）命中 24 帽**、**15 次材料 ≤3 块**。**证据**：六题的「答案句 ↔ 原文出处 ↔ 送窗实测命中数」三点对照（§0 附）。**方向**：供给侧加题眼**章节级**保底座位、原文支优先于摘要支、帽值例外口径；不在答案面加措辞（那是把病灶藏起来）。

**病灶 3｜「教据与闸不同形」＋「含义歧义无处裁决」——批量制造慢路/快路错判（L04-07／A-正6／L04-17 形）**
同一类病在三个相位各有形态：理解环**教两行式、收 JSON**（`task_book.py:11-13` 自陈的张力，EB4G-L04-17 已实证 `text` 里混入「指标候选：」行）；澄清环 **ask 白场两例不覆盖「题面含义含糊／候选并列」**（L04-07 自选 `日产油量` 直发 data，golden 期望慢路 `metric=None`）；§A「主体未命中」条款**邀请对未检索的库态下断言**（A-正6 写出「台账与报告库均未检索到命中」，零检索、库实有）。共同点：**抽象条款加得越多，模型越按最近邻样例行事**——而样例面恰好缺这几形。**方向**：只在**样例面**补三条整样例行（JSON 形输出／含义含糊→ask 或先点名口径／主体未命中→先 discover 再答），并把「库态断言」这类事实句划归程序生成；同时把「钟≠水位」的评测环境对齐（否则无时间词/本月类 8 帧的零交付会持续被误读成提示词问题）。
