## 三、全链路运行流程（含再探环）

```mermaid
flowchart TB
  Q[提问] --> U[读题 understand]
  U --> C{① 澄清 clarify<br/>discover 探索（≤10，只读）| decompose | ask}
  C -->|decompose| TM{② 工具匹配 toolmatch}
  TM --> PC{③ 前置条件机}
  PC -->|pass/note| EX[④ 批量执行<br/>每子问题：L0 召回 → L1 供给窗]
  PC -->|blocked| C
  EX --> M[L2 并集池<br/>去重·稳定序]
  M --> A[⑤ 作答 answer<br/>L3 渲染窗 + 引擎注记]
  A -->|出答案正文| V[⑥ 核验 verify]
  A -->|出 explore 意图| X{再探校验<br/>工具闭世界·指纹·预算}
  X -->|通过| XR[执行只读检索<br/>doc_retrieve→L0/L1<br/>fetch_section/report→KB]
  XR --> M2[新观察并入 L2] --> A
  X -->|不通过/预算尽| A2[强制作答<br/>如实缺口]
  A2 --> V
  V --> O[⑦ 交付<br/>正文+增补面+notice]
```

### 步骤明细

1. **读题/澄清**：不变。澄清相位 `discover` 仍是「看到材料前」的探索（≤10 次，只读，不占轮）。
2. **执行**：每子问题走 L0→L1；L1 产出的窗口合并成 L2。
3. **作答（L3+L4）**：L3 按第四节选席渲染；模型两种出口：
   - `answer`：正常草稿（现有行为）；
   - `explore`：材料不足时出意图（第四节·合同）。
4. **再探环（≤2 轮）**：校验→执行→追加→回作答；第 2 轮仍 `explore` → 强制作答（附「已试过什么/仍缺什么」）。
5. **核验/交付**：按 D6 与既有行为。

## 四、L3 选席规则（V2-93 定稿）

**输入**：L2 观察集（含 `locator.node_kind`＝`slice`/`section_summary`、`locator.report/section/fragment_id`、`table_bearing` 标记——由 L1/引擎侧打）、`anchors`＝`[(kind,text)]`（subject/term/number/章节）、帽＝`SEND_BUDGET_CAP`。

**输出**：渲染文本＋元数据（`material_truncated/rendered/total`）＋**`window_materials`**（入选序号＋来源＋选席理由）。

**选席顺序（确定性，零语义）**：
```
1) 权威/台账族（信任级≠report）：全量入选，不占检索族帽（现有行为）
2) 声明类观察：不进检索族候选（D4），走 note 通道
3) 检索族候选分池：
   a. 题眼表/节保底席：锚（含章节号/表名/题面数值清单）命中的**原文切片**优先；
      同一锚命中多支时，取「表格承载优先 → 锚命中类型数降序 → 片段长度升序 → index」
   b. 同源原文保底席：每个来源保 1 席给 `node_kind=slice` 的**原文**（摘要不得顶替）
   c. 表格保底席：每个来源若有 `table_bearing` 片段，保 1 席
   d. 锚共现补席：高分锚片段（≤ANCHOR_SEATS），题眼来源不吃单源上限
   e. 来源保底席：每来源 1 席
   f. 来源轮转补席：按来源轮转填满
4) 每来源常规席 ≤ MAX_REPORT_SEATS_PER_SOURCE=6（锚/题眼/表格保底席不计）
5) 总席 ≤ SEND_BUDGET_CAP；截断时披露行逐字不变
```

**`window_materials` 形状（答案步 payload，additive）**：
```json
{"selected":[{"index":7,"source":"《B-…月报-202608》","reason":"题眼表保底"}],
 "dropped_sources":["《…》"],"cap":24,"rendered":24,"total":97}
```

## 五、作答侧再探（V2-96 定稿）

### 5.1 合同（作答相位第二个出口）

```json
{"action":"explore",
 "reason":"s1 缺 W-24 断点米数；s2 缺三、检泵作业明细表",
 "requests":[
   {"tool":"doc_retrieve","query":"W-24 井 断点 米 第几根 抽油杆","anchors":["W-24"]},
   {"tool":"fetch_section","report_id":"《B-渤中34-5油田躺井治理与检泵作业月报-202608》","section":"三、检泵作业明细"}
 ]}
```

- **闭世界**：`tool ∈ {doc_retrieve, fetch_section, fetch_report}`；每轮 `requests` 1..2；`reason` 必填（非空）。
- `doc_retrieve`：`query` 非空；`anchors` 可空。
- `fetch_section`／`fetch_report`：`report_id` **必须是 L2/L3 窗口里出现过的来源**（模型只许对见过的东西要更多）；`section` 可空（空＝整篇）。
- 重复指纹（`tool`＋`query` 或 `report_id+section`）→ 拒，回喂拒因。
- 解析失败／越界 → 回喂拒因恰一次；仍不合 → 强制作答（不判 run failed）。

### 5.2 执行与回链

```
校验通过
 → doc_retrieve：走 L0→L1（合成一个「再探子问题」窗口，budget 同常规）
 → fetch_section/report：KB 只读取片段（按 report_id[+section]；整篇必截断+披露）
 → 新观察并入 L2（按 fragment_id 去重，序号续排）
 → 追加一条 user 消息：
     「补充检索（第 k/2 次，还剩 m 次）」
     ＋模型上一轮 requests 原文（照抄）
     ＋新入选材料（[n] 格式，经 L3 选席规则）
 → 重入作答
```

### 5.3 预算、防转圈、硬停止

| 项 | 值 |
|---|---|
| 再探轮数 | ≤2（独立计数 `explore_rounds`，不占澄清 3 轮、不动 discover ≤10） |
| 每轮请求 | ≤2 |
| 指纹 | `state.explore_fingerprints`（拒重） |
| 硬停止 | 第 2 轮仍 `explore` → 强制作答；正文须含「已试 N 次检索（列出）、仍缺 X」 |
| 留痕 | 每轮 step payload `explore`（requests 原文/执行/命中/追加/token）＋`retrieval_calls` 行 |
| 总时长 | 仍受单段 300s 约束；触界按既有预算收敛 |

### 5.4 工具（新增，只读）

| 工具 | 参数 | 行为 |
|---|---|---|
| `doc_retrieve` | `question`,`anchors?`,`family_hints?` | 现有 |
| `fetch_section` | `report_id`,`section?` | 取该报告该节片段（section 空＝按 `_is_table_bearing`/原序取该报告代表节）；受 `fetch_cap` 与截断披露 |
| `fetch_report` | `report_id`,`max_chars?` | 取母报告全篇（`kb_report.doc` 或片段有序拼接）；**必须截断+披露**，且作为最后手段 |

- 权限谓词沿用 INV-3（`report_id` 必须落在当前 actor 可见库内；越权＝拒，不静默）。
- 三个工具全只读；工具返回结构复用现有 Observation 形（带 `report/section/fragment_id`）。
