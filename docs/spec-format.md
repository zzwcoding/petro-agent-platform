# 规格版式（本仓规格写作纪律）

> 本文件＝本仓 `specs/<功能名>.md` 的**写作硬要求**。它是 sdd-flow 通用模板
> （`.agents/skills/sdd-flow/references/module-spec-format.md`）在本仓的**加固版**：
> 通用七节**全部保留**，另加三节、升级五节——加固点全部来自本仓自己的事故证据。
> 出处：`docs/runtime-refactor/eng/02-规格防漂移要求.md`（独立评审＋逐条处置）。

## 一、为什么加固（三句话）

1. **本仓的通用模板里，防漂移最吃劲的三节（不做什么／行为约定／依赖与风险）全是散文**，没有任何闸或人审工序把它们当作"验收对象"。
2. **本仓吃过"框架被静默替代"的亏**（soc-demo 教训：LangGraph.js／llm-guard／MCP SDK 被"手写同构件＋记票出入"顶掉，每张票局部合规、全局偏离承诺）。
3. **本仓有真实复发史**：静默截断（装配器写死上限、模型面零告知）、同一件事多种数字（闸数 5/6/8 三说、事件类数 8/9 两说）、挂账悬空（81 条挂账未逐条回写终态）。这些都必须由规格**提前立成可判的条目**。

## 二、十节结构（硬要求）

| # | 节 | 硬要求 |
|---|---|---|
| 1 | **目标** | 一句话，术语全部来自 `CONTEXT.md`，不自造同义词 |
| 2 | **范围围栏**（＝通用模板的「不做什么」） | 每条排除必须带**替代落点锚点**：「不做 X → 由 <模块> 承担 → 锚点 `文件#节`」。只写"不做 X"而无落点＝静默缺失的温床 |
| 3 | **触及的模块** | 首列模块名 ∈ `specs/modules.md` 已声明；注明改动类型；**要改别的模块接口就先回阶段 2** |
| 4 | **接口契约**（＝「接口定义」） | 逐字字段名／类型／必填性／**枚举闭世界（列全合法值＋越界行为）**／**错误契约（返回什么、抛什么）**。真源在模块卡，本处引用不复述 |
| 5 | **框架与依赖红线**（新增） | 逐条列点名框架／唯一出口，写「验收写法（lockfile 出现 X ＋ 行为测试绿）」＋「**对应闸名**」。无点名框架则写「无点名框架」 |
| 6 | **行为约定** | 每条**必须能直接写成一个 `assert`**；出现「尽量／合理／必要时／视情况」即不合格。**数字、上限、口径只许引真源**（`文件#节`），**禁写裸字面值** |
| 7 | **不降级与静默禁令**（新增） | 声明**合法降级路径**（或写「无」，指向 ADR）；任何截断／缺位／降级必须产生**机读信号**，且验收里有一条断言"该信号在场" |
| 8 | **验收测试** | 每行绑一个可执行测试标识；**另补「边界集」与「保留集」两栏**（应当改变的样本 ＋ 不应受影响的样本） |
| 9 | **依赖、风险与对策** | 依赖带真源指针；**每条风险必须带检测手段**（闸名／测试标识／明确写"人审"并给原因） |
| 10 | **与闸的挂钩表**（新增） | **关键红线与闸相关项**逐条挂（闸名／测试标识／人审）——**不要求把每条行为约定都挂上**（十条全挂成本高、收益低）。**接不上闸的，写明为什么接不上** |

## 二之二、节标题必须逐字（机检约束）

spec gate 按**标题名逐字匹配**（`line.strip() == "## 触及的模块"`）。所以：

- 通用模板原有的七节，**标题名一字不改**：`## 目标`｜`## 不做什么`｜`## 触及的模块`｜`## 接口定义`｜`## 行为约定`｜`## 验收测试`｜`## 依赖与风险`（上表的「范围围栏／接口契约」只是**这一节的职责**，标题仍用原名）。
- 新增三节用这三个名字：`## 框架与依赖红线`｜`## 不降级与静默禁令`｜`## 与闸的挂钩表`。

## 三、必须守的三条判据

1. **可判真伪**：一句话能不能直接写成 `assert`？不能就重写。
2. **数字单点**：规格里出现的每个数字都能指到一处真源；横切事实（事件类数、端点清单、模块名）**只引用、不复述**。
3. **闸在前面**：每条硬要求要么有闸、要么有测试、要么明确写"人审＋原因"。**"文档里写着却没有闸的禁令等于不存在"**——所以第十节不是可选项。

## 四、交稿前自查清单（逐条勾）

1. 目标一句话，术语全来自 `CONTEXT.md`，无自造同义词。
2. 范围围栏每条排除都写了「由谁承担 ＋ 锚点」。
3. 涉及的模块都在 `specs/modules.md` 声明过；没顺手改别的模块接口（有就回阶段 2）。
4. 接口契约：字段名逐字、类型齐、**枚举列全**、错误契约齐；与模块卡不一致时**以卡为准并改卡**。
5. 框架红线：点名的都写了「验收写法 ＋ 对应闸名」；无则写「无点名框架」。
6. 行为约定逐条读一遍：**能不能写成 `assert`**？有含糊词就重写。
7. 规格里每个数字都能指到真源；没有裸字面值。
8. 事件类数／端点清单／模块名等横切事实只引用、不复述。
9. 验收测试每行绑一个测试标识；补了「边界集／保留集」两行。
10. 每条"如实上报／不许静默"都配了一条**断言机读信号在场**的验收行。
11. 依赖与风险每条风险都有检测手段（闸／测试／人审＋原因）。
12. 填了「与闸的挂钩表」；接不上的写清了原因。
13. 本地跑过 `uv run python tools/check_specs.py` 且无 FAIL（**该闸已接进 CI**，但仍须本地先绿）。
14. 不变量只写 `INV-x`，未复述原文。

## 五、机检的边界（诚实声明）

- **能机检**：模块名已声明（spec gate）、验收测试行有标识（spec gate）、import 方向与框架红线（`tools/importlinter_v2.toml` 边界闸）、端点覆盖（覆盖率闸）、债务短语（债务标记闸）。
- **接不上机检、只能进票面＋人审**：像"不做澄清、不查数"这类**纯范围排除**——没有形状／存在性／退出码判据。
  能做的是**降维**：① 能翻成 import 方向禁令的 → 转边界闸；② 能翻成端点／路由禁令的 → 转覆盖率闸；③ "不许出现某符号" → 自写 AST／grep 断言测试。剩下的才写"人审＋原因"。
