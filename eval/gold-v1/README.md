## 一、这是什么

每票门禁用的**回归金丝雀子集**：60 题冻结清单＋逐题判分锚点（✅⚠️❌ 各一句话）。门禁回答的问题只有一个——**「没弄坏旧的吗」**。

**门禁绿＝回归金丝雀≠质量天花板。** 门禁全绿不代表系统变好了，只代表旧能力没有退化；系统变好了没有，只有当轮新题（移动靶）说了算。

## 三、覆盖矩阵（验收第二条）

**七族（问数组 16 题）**：明细 3（数-明1/2/3）｜排名 3＋显式条数 1（数-排1/2/3、数-限1）｜闸 3（数-闸1/2/3，新鲜度闸拦停/接续）｜降级 2（数-降1/2，在册未绑定）｜反问 1（数-反1，缺参反问）｜观察 2（数-察1/2，路由边界＋唯一 interrupt 场景）｜边界 1（数-界1，单井过滤未支持）。

**问答四册**：A 册 3（跨章/归纳/反题）｜B 册 3（抽取/归纳计算/精确抽取）｜C 册 3（跨行/跨章/明示缺位）｜D 册诱导 4（F1 双错误前提/F6 抢锚/F7 无数值克制/F3 台账词正题）。

**golden 五族**：三指标×快路 6｜慢路触发 6｜默认窗 2｜触发边界 4｜红例族 6。

问数组与 golden 有 11 句题干同句（如「去年日产油量最高的井是哪口？」）——**判分层不同，非重复**：golden 判意图计划（QueryPlan 机器判五字段），问数组判端到端答案（行集/注记/血缘/话术）；数-察2 与 L04-21 同句同理（安检行为 vs 意图快路）。

## 四、判分锚点与基线

- 三档口径沿用各册册头：✅＝数值/结论/行为全对；⚠️＝部分正确（要点缺漏/出处或链路不符，零编造）；❌＝数值错/张冠李戴/该拒不拒/顺着诱导作答/跨套混写。
- 判分总则 v2（未点名题分油田三档：全覆盖 ✅／单套出处如实 ⚠️／跨套混写 ❌）真源：eval/drafts-q4/README.md「Owner 拍板」节第 4 条；各册 D3 扫描表在案。
- 问数组数值题绑定 fieldforge 真产物（86 井×365 天，水位 2026-08-31），窗口词按执行日重锚（题册「窗口锚定表」）；数-明3/数-界1 受 P0-1 脏格影响，门禁按「与库实态一致」判。
- 问数组闸/降/察族按 W-AUX 已合形态判（拦停→自动接续检索＋「非权威数值」标注；报告库空→双重如实拒答仍 ✅），题册「W-AUX 增量对照」节为真源。
- golden 判分只看机器判退出码（machine_judge_fields 五字段；解析失败落人审不进退出码），答案要点人审随行；相对窗 anchor_scope 规则按 plan-golden-v1.json `window_anchor_rule`。
- **基线**：每题 baseline 字段记 Q11 轮判分（eval/results/Q11-评测报告.md，2026-10-08，V1 侧）；golden 记 L-04 冻结形态。基线是门禁的对照物。

## 五、门禁红绿语义（回归金丝雀的操作定义）

- **红**＝较基线劣化：基线 ✅/⚠️ 的题降档、基线非 ❌ 的题出新 ❌、golden 机器判由绿转红。
- **不红**＝基线内的已知病灶维持原档：Q11 已登记的 ❌/⚠️（P0-1 脏格、P0-2 生成窗证据截断、P1-3 interrupt 双重掩蔽、P1-4 路由翻面等）不逐票拦门禁，随各自修复票消化；修复落地后基线随换版更新，病灶题升档只算好转。
- 门禁红只允许**架构性最小修补**（PRD 原文）；任何把题目、锚点、库态改到能过的动作都违反第六节协议。

## 六、防过度拟合协议（四条，PRD 测评协议固化）

1. **开发期不看题集分数。** 开发主信号＝TDD 单测＋trace 检视＋非题集 smoke 题；本子集 60 题不进开发内环，不许对着门禁分数迭代提示词与代码。
2. **对账非调优。** 双跑对账（97 全量）是里程碑级测量动作，不对每票开放；门禁与对账都只测量、不当调参目标——任何「为过门禁而改行为」的提交本末倒置。
3. **题册适配登记。** 门禁红若根因是题册适配类问题（题面措辞/口径/库态漂移，非架构退化），不许静默改题凑分——逐条登记适配项（改哪题、为什么、影响面），留痕可溯。
4. **L0 审。** 上条的适配登记逐条 L0 审；本子集的换版、扩样、基线更新、题目替换一律 L0 拍板后生效，执行台与子代理无权改冻结件。

## 七、移动靶机制

- **泛化抽查**：每里程碑新生成一批新题（复用新语料生成工作流/D3 线），防「只在冻结题上变好」的主机制掩盖；新题不进本子集。
- **独立验证**：当轮新题中留一块从不参与调优的冻结集，收官结论只对这块说话。
- 本子集因此定位为**慢变层**：gold v1 冻结后只在两种情况下换版——(a) 已知病灶修复落地后基线更新（题目与锚点不变，只改 baseline）；(b) L0 拍板的扩样/换题（追加 gold-v2，不覆写 v1）。换版必须整批提交＋本 README 组成表同步改。
