## 伪代码（施工基准——L0 亲研，照抄实现，偏离即停报）

**1. `newTurnV2` 新增键**（既有键不动）：
```
events: []            // 按帧到达序追加的 typed 事件
verdictFinal: null     // verdict final 形
errorFrame: null       // error 帧载荷 {code,message}
ignoredCount: 0        // 未知事件计数（机读信号）
phase 不入 state——渲染期由 phaseOf(turn) 派生（纯函数，见下）
```

**2. `reduceV2Frame` 分支改动**（每个 case 只列增量）：
```
case 'supplement':
  block = data.block
  若 block ∈ {'split','attribution','citations','lineage'}：
    t.supplements = { ...t.supplements, [block]: String(data.text ?? '').strip() }
    // strip＝前后空白去（JS 无 strip 用 trim），内文不动（块头行属内文，保留）
  否则：t.ignoredCount += 1            // 未知 block——忽略+计数，不炸流
case 'observation':
  t.materials = _upsertBy(t.materials, 'index', {
    index, source, trust, content,
    payload: data.payload ?? undefined   // 血缘五要素+limit 透传；无键＝undefined
  })
case 'tool':
  t.tools = [...t.tools, { tool, status, message, seq: data.seq ?? null }]  // seq 保留
case 'step':
  t.steps = upsert 同现状
  t.events = [...t.events, { type:'step', seq:data.seq, phase:data.step ?? '', title:data.title ?? '' }]
case 'tool'（events 部分）:
  t.events = [...t.events, { type:'tool', seq:data.seq ?? null, tool, status, message }]
case 'text':
  理解旁白分流同现状（t.understanding 拼接）
  且 kind==='understanding' 时：t.events=[...t.events,{type:'understanding',text:content}]
  正文帧不产生事件（answerText 独立面）
case 'observation'（events 部分）:
  // 聚合行：上一条事件是 materials 就计数+1，否则新开一行
  last = t.events[t.events.length-1]
  若 last?.type === 'materials'：t.events = [...events.slice(0,-1), {...last, count:last.count+1}]
  否则：t.events = [...t.events, {type:'materials', count:1}]
case 'notice':
  t.notices 追加同现状
  t.events = [...t.events, {type:'notice', notice:{type,gates,content}}]   // level 由 NoticeRow 自算（noticeLevel 已在 events.js）——reducer 不重复分级
case 'verdict':
  若 data.status 存在（final 形）：t.verdictFinal = data
  否则：t.verdicts = [...t.verdicts, data]
  且非 final 形时：t.events=[...t.events,{type:'verify', verdict:data}]
case 'citation':
  t.citations upsert 同现状
  t.events = [...t.events, {type:'citation', cite:{index,source,source_id,trust}}]
case 'error':
  t.closed='error'; t.runStatus='failed'; t.errorFrame = {code:data.code, message:data.message}
default:
  t.ignoredCount += 1; // 其余键照旧不动
```

**3. 新增导出（纯函数）**：
```
export function phaseOf(t) {
  if (t.closed) return 'done'                      // done/error/transport 皆收口
  if (t.answerText) return 'answering'             // 首字已到＝流水线让位
  return 'running'
}
```
（挂起腿 done 后 closed='done' → phase 'done'，askFrame 在场驱动续答 UI——与现状语义一致。）

**4. 测试草稿**（6 用例，输入＝真机帧转录）：
- `supplement_four_slots`：EB4-数-明2 的 4 类块帧序列 → supplements 四槽各为 strip 后原文；掺一个 `{block:'bogus'}` → ignoredCount=1 且四槽不变。
- `observation_payload_pass_through`：带 payload 帧 → materials[0].payload.lineage 五键在场、limit={hit,rows}；无 payload 帧 → payload===undefined。
- `tool_seq_kept`：`{tool:'doc_retrieve',status:'ok',seq:7}` → tools[0].seq===7。
- `events_arrival_order`：EB4-A-正1 信封 id≤25 前缀真机序 → events 前 N 条快照钉死：understanding→notice→step1..6→tool(seq7)→materials(count 逐帧 +1 至 16)→step(seq7)——「tool 先于承载 step」原样保留。
- `run_status_three_way`：done+askFrame→waiting_ask；done+run_failed notice→failed；done 干净→completed（三分用例各一）。
- `unknown_event_counted`：`{event:'mystery',data:{}}` → ignoredCount=1、其余字段与输入 turn 深等。

## 施工要点

- G4 到达序：reducer 按 reduceV2Frame 被调顺序追加 events（调用序＝信封 id 升序，chatV2 客户端保序——底座现状已保序，本票在测试里用「乱义真机序」钉死，不新做排序逻辑）。
- supplement `strip()`：前后空白去、内文不动（块头行属内文，保留——渲染分层归展示件）。
- 忽略计数字段名 `ignoredCount`（reducer 返回形状新增键，规格 TurnShape 未列——本票落码时回写规格「接口定义」节，随票收尾提交）。
- verdict 帧按 `subtype` 分区：verify 形→`verdicts`、final 形→`verdictFinal`（对账 D-6；RunMetaLine 消费 verdictFinal 不再靠帧序）。
- error 帧载荷落 `errorFrame`（对账 D-2）。
