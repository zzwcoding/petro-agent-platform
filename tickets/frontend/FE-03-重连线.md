## 伪代码（施工基准——L0 亲研，照抄实现，偏离即停报）

**1. 持久化（R1）**——放新页 A1V2R 内（hooks 文件 `useRunningRun.js` 或页内，子代理定名但键名照下）：
```
const KEY = 'a1v2r:runningRun'   // 与 A1V2 的 rootId/followup 键隔离
ask 受理（session 帧到达、拿到 run_id）：
  sessionStorage.setItem(KEY, JSON.stringify({ runId, question, at: Date.now() }))
run 收口（closed 为非空：done/error/transport）：
  sessionStorage.removeItem(KEY)
```

**2. 刷新发现与重连（R2/R3）**——页面 mount 一次：
```
async function restoreRunning() {
  raw = sessionStorage.getItem(KEY);  无 → return
  { runId, question } = JSON.parse(raw)
  try {
    rows = await listRunsV2(100)                    // 行集确认（本进程注册表语义）
    row = rows.find(r => r.run_id === runId)
    if (!row || row.status !== 'running') { sessionStorage.removeItem(KEY); return }  // 已收口，交历史列
    turn = newTurnV2('replay', question); turn.runId = runId; turn.resumed = true
    推入会话数组 → postAskV2({ resumeRunId: runId }, 同一套 handlers, { lastEventId: '' })
      // 不带头＝从头全量重放（chat.py:58-87 语义）；handlers.onFrame 逐帧 reduceV2Frame
      // 重放帧序与 live 完全一致（transport.md 行为 13）→ 归一出含 events 的完整形状
  } catch (e) {
    if (e instanceof ApiError && e.status === 404) {
      // R3：run 不在服务端缓冲——终态灰条，不悬挂不重试
      sessionStorage.removeItem(KEY)
      push 合成 turn：{ ...newTurnV2('replay', question), runId,
                       errorFrame: { code:'run_unreachable', message:'本轮已结束或不可达' },
                       runStatus:'failed', closed:'error' }
      // 页面渲染：errorFrame 在场 → 回答块出灰条（文案＝message 原串）；流水线块无事件不渲染
    } else { throw }   // 其他错误走页面既有错误出口，不在本 hook 吞
  }
}
```
- 重放与提问**同一条 dispatch 管道**：handlers 直进 reducer，不分两路（真流时 R2 的重放尾巴与新帧天然衔接，无拼接逻辑）。
- 重连后清键时机＝该 turn closed 时（同一收口清除逻辑覆盖提问与重连两种来源）。

**3. 挂起还原（R4）**：
```
restoreRunning 中 row.status === 'waiting_ask' 分支（替代 running 重连）：
  view = await getRunV2(runId)                     // RunView.pending_ask 投影（chat.py:350-353）
  turn = adaptHistoryTurn(row, view)               // FE-02 适配器——pending_ask 落 askFrame
  push 该 turn；sessionStorage 保留该 runId（等用户续答后再清）
续答：postResumeV2(runId, resumeBodyFromAskFrame(askFrame, chosen), handlers)
  → 本腿新帧直进同一 reducer（run 已存在 turn 上 upsert）；done 收口清键
```

**4. 页面接线点（A1V2R.jsx）**：
- mount 调 `restoreRunning()` 一次（useEffect 空依赖）；会话数组从「固定 MOCK_TURNS」改 useState 数组（本票仍允许 mock 数据并存：restore 推入的 turn 排在 mock 轮之后，FE-05 去 mock）。
- errorFrame 渲染位：回答块顶部 `turn.errorFrame && <Alert type="error" message={turn.errorFrame.message} />`（A 级 notice Alert 之前）。
- 输入区「发送」本票仍禁用（真提问接线归 FE-05）；**但 resume 挂起卡的选项点击接线本票做**（R4 的续答通路必须真通，否则挂起还原测不了）。

**5. 测试草稿**（4 用例，全部零真实网络——listRunsV2/getRunV2/postAskV2/postResumeV2 以 vi.stubGlobal 或注入桩替换）：
- `persist_running_run_id`：session 帧 → KEY 在场且含 runId；done 帧 → KEY 清除。
- `reconnect_replays_full_stream`：预置 KEY + listRunsV2 桩返回 status='running' → postAskV2 桩收到 `{resumeRunId}` 且 handlers 被喂 EB4-A-正1 全帧 → 会话数组该 turn 的 answerText/citations/events 与 live 归约逐键相等。
- `reconnect_404_terminal`：postAskV2 桩抛 ApiError(404) → 合成 turn 在场、灰条文案断言「本轮已结束或不可达」、无重试（postAskV2 调用计数===1）、KEY 已清。
- `pending_ask_restore`：listRunsV2 桩返回 waiting_ask 行 + getRunV2 桩返回 pending_ask → 挂起卡渲染；选选项 → postResumeV2 桩断言 body.kind 正确；done 帧 → KEY 清除。

## 施工要点

- 重放后尾随：reconnectRun 返回的流与提问流同管道（chatV2 事件回调直进同一 reducer dispatch——一处接线，不分两路）。
- R3 的 404 判定：开流前 HTTP 404（chat.py 语义）→ 终态；流中途 transport 断开≠404（既有 closed='transport' 分支不动）。
- 持久化键名与现 A1V2 的 sessionStorage 键不冲突（现键：`rootId`/`followup`——新键如 `a1v2r:runningRunId`，namespaced）。
