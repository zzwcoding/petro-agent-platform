## 二、排障手册（症状 → 检查 → 修法）

### 症状 1：`/api/wells` 等 midplatform 路由端点 500「password authentication failed」
- 检查（**必须从宿主机用真驱动探——教训 L1：容器内 psql 是 trust 认证，验不了口令**）：
```bash
cd /Users/divh/Downloads/petro-agent-platform && uv run python - <<'EOF'
import asyncio, asyncpg
async def main():
    try:
        c = await asyncpg.connect(host="localhost", port=5433, user="midplatform",
                                  password="midplatform", database="petro")
        print("OK", await c.fetchval("SELECT count(*) FROM raw.well_info")); await c.close()
    except Exception as e:
        print("FAIL", type(e).__name__, str(e)[:80])
asyncio.run(main())
EOF
```
- 口令错 → 修：`ALTER ROLE midplatform PASSWORD 'midplatform';`（docker exec psql -U petro）→ 重启后端（清连接池）。

### 症状 2：登录成功但「permission denied for schema raw」
- 修：补授权（症状 1 检查通过后仍 404/403/拒绝时）：
```bash
docker exec -i petro-agent-platform-pg-1 psql -U petro -d petro <<'SQL'
GRANT USAGE ON SCHEMA raw TO midplatform;
GRANT SELECT ON raw.well_info, raw.oil_production_daily, raw.water_injection_daily,
               raw.well_overhaul, raw.well_measures, raw.fluid_test,
               raw.equip_status, raw.monthly_settlement TO midplatform;
SQL
```
- ⚠️ 本期该授权**丢了两次**（并行窗口重跑建号脚本 DROP+CREATE 所致，无 PG 日志不可考）——教训 L2。

### 症状 3：端口 8000 无响应但有进程
- 检查僵尸实例：`lsof -nP -i :8000`（LISTEN 者为准）；`pkill -f "uvicorn app.main:app"` 后重启。
- 教训 L4：多实例并存时 vite 代理会打到**僵死实例**——启动前先查端口。

### 症状 4：alembic 报「Can't locate revision 'XXX'」
- 原因：迁移文件改号后 DB 版本表指向旧号——修：`UPDATE alembic_version SET version_num='<新号>';`（docker exec psql）。

## 三、教训登记（L1~L5）

| # | 教训 | 固化方式 |
|---|---|---|
| L1 | **容器内 psql 是 trust 认证——验口令必须从宿主机用真驱动（asyncpg/psycopg）** | 本手册排障症状 1 |
| L2 | **多个执行体重跑建号脚本会互相丢授权（DROP+CREATE 或重建）**——建号/授权只有一个执行入口（部署批 runbook） | 部署批 runbook＋建议 PG 角色变更日志 |
| L3 | **后台启动命令必须带绝对 `cd` 前缀**（cwd 漂移两次致启动失败） | 本手册启动节（全部命令带前缀） |
| L4 | **启动前先查端口（lsof LISTEN）——僵尸实例抢答** | 本手册排障症状 3 |
| L5 | **commit 前必须 `git branch --show-current` 核对**（本期两次提交落错分支：L0 落册＋执行台收口） | 已登记 journal（两次事故复盘） |
