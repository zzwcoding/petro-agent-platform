# G-01 网关出站流式化＋空闲超时（2026-10-05 Owner 会话内授权追加票）

## 背景（现场事故驱动）

B1 建库图谱/百科两条支路连续两轮静默失败（`task-2309cac5`/`task-52c6020b`，后端日志
`wiki 生成失败 report=rpt-1c9819bc`）。排查结论：

- **不是并发打爆**——单发探针三连成功（1~3.5s）、图谱抽取提示词复现 2.1s 成功、上游（MiniMax/GLM）
  裸探测可达；
- **真因＝出站调用为非流式，读超时（request_timeout=30s）是唯一死活判据**：百科支路一次调用
  「整篇报告进→整页百科出」，生成时间必然超 30s；非流式线上静默，客户端无法区分"在慢慢写"与
  "对面死了"，`SocketTimeoutError: Timeout on reading data from socket` 后网关重试 8 次
  （petro-main×4＋petro-lite×4），每次从头生成、每次必超时——确定性全灭；
- 图谱支路小块调用能过但被重试拖慢（一次失败逻辑调用最长 4 分钟），呈现"假死"。

## 目标

出站 LLM 调用改**真流式消费**：逐帧接收、以「空闲超时」（连续无新帧）替代「总时长」作为死活判据。
调用方（gateway.complete 及全部业务面）签名与应答形状零改动。

## 方案（三层各一刀）

1. **infra.llm_client.complete**：`litellm.acompletion(..., stream=True, stream_options=
   {"include_usage": True})`；逐帧 `asyncio.wait_for(迭代, idle_timeout)`——空闲超时抛
   `UpstreamUnavailable`（可切备，复用既有 fallback/重试/熔断面）；总时长护栏
   `stream_max_seconds` 防失控；usage 从末帧取（include_usage），缺失走既有 chars/4 估算兜底；
   流结束/异常路径均关闭流释放连接。
2. **infra.config**：新增顶层 `stream:` 配置段（`idle_timeout`/`max_seconds`，带默认值）——
   **刻意不放 gateway 段**：D1 配置面按固定四键整块重写 gateway 段，新键放那里会被下次保存抹掉
   （`upsert_gateway_params` 块替换策略实证）；独立顶层段且带默认，旧 yaml（无此段）照常校验。
3. **config/models.yaml**：加 `stream:` 段两键（注释注明 G-01 与建议域）。

## 边界（红线）

- gateway 域（路由/fallback/重试/熔断/记账/Completion 形状）零改动——LlmCompletion 五字段不变；
- A1 SSE 帧合同、计费记账口径（prices.default 单价真源）不变；usage 记账保持「上游给就用、
  没给才估算」的既有优先级；
- 不碰 B6 边界：litellm 唯一 import 点仍在 infra.llm_client；
- `request_timeout` 语义收窄为「连接＋首帧（TTFT）超时」，键名与值域不动（D1 四键合同面不动）。

## 验收

1. 单测：流式拼接/末帧 usage/空闲超时→UpstreamUnavailable/总时长护栏/流关闭 五类用例绿；
   既有 llm_client/gateway/config 套件回归绿；
2. 两闸（contract_coverage/debt_markers）不红；
3. 复测（真环境）：后端重启加载新实现后——B1 端点 10 触发百科重跑 → 百科页生成成功；
   图谱支路出节点推进（或重传报告触发全量支路）→ `graph/net` 节点边数 > 0；
4. 单提交，显式路径 git add。

## 审查

派独立审查（diff 全量）：流关闭泄漏/异常分类正确性（自抛 UpstreamUnavailable 不得被
classify_upstream_failure 二次改判）/wait_for 对 async 迭代器的取消语义/计费兜底分支保留。
