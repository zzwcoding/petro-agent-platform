# G-02 支路进度可见（百科/图谱状态进任务卡——2026-10-06 开票）

## 背景（Q3 评测现场反复踩坑）

入库五步（parse/chunk/embed/index/enrich）走完即任务 done，但图谱/百科是完成后事件触发的
后台支路——进度、成败、拦下边数页面上全不可见。Q3 期间三次「为什么没生成」排查全靠翻
后端日志；支路静默失败（设计使然）＋无进度面＝用户不可知。

## 方案（最小闭环——后端全做，前端一行）

1. **存储**：`kb_ingest_task` 新列 `branch_status jsonb`（迁移 0020）——形状
   `{"wiki": {"state": "running|done|failed", "detail": 一句话}, "graph": {"state": ..., "chunks_done": n, "chunks_total": n, "edges": n, "blocked": n}}`。
2. **回写缝（B9 边界不破）**：derivatives 支路不 import kb——组合根在装配时注入
   `branch_reporter(task_id, branch, state, detail)` callable（kb 服务提供写口，update
   kb_ingest_task.branch_status jsonb 合并键）；wiki/graph 支路在 启动/完成/失败 三点回写。
3. **DTO additive**：`TaskProgressResponse` 增 `branches` 键（additive——B1 合同按
   「实现先行登记」先例，teach 侧随后补登记）；五步 nodes 形状不动。
4. **前端**：B1 任务卡五步之下加一行「支路：图谱 进行中(12/30) · 百科 完成」——只读文本，
   零交互。

## 边界

- 五步 nodes jsonb 键序与状态机不动；支路状态不参与任务 state（done 不回退——支路失败
  只标支路态）；
- 支路重跑入口（图谱缺）另登记（本票不含——重跑触发现有 wiki 路由与图谱待补，归 G-06）。

## 验收

1. 单测：reporter 合并写/三态流转/DTO additive 键；
2. 真环境：重传 A 报告——任务轮询期间 branches.graph.state=running（chunks 递增）、
   完成后 done；B1 页面任务卡可见支路行。
