# G-08 mixed 模式父块截断丢内容（入库内容丢失——2026-10-06 开票即修）

## 背景（Q4 评测排查实证）

C 报告（动态分析类库，mode=mixed）入库后检索持续 miss（C-正4/5：W-33 酸化/W-57 吸水
剖面"材料未披露"）。排查发现**根因不是检索排序，是入库内容丢失**：

- C 报告 4542 字，章节标题「一、」「1.1」双样式均未被结构识别命中 → 单父块「正文」；
- mixed 分支 `parent_body[:MIXED_PARENT_MAX_CHARS]`（2048）截断后，**子块从截断后的
  文本生成** → 2048 字之后的内容（第四~八章：W-33 酸化、递减率、分层测试表、环比表）
  静默丢失，索引只覆盖前 44%；
- 铁证：KB-02 无损自检 dump `/tmp/chunk_validate_task-352204a8.md` 列出原文 72~122 行
  全部「未被任何片段覆盖」（自检器工作正常、告警不阻塞设计——但 dump 无人在看）；
- DB 实证：`kb_fragment_version` 全表 0 行含"增油"；C 报告仅 7 片段且 section 恒"正文"。

## 修复

`chunk_text` mixed 分支：**子块源＝未截断全文**——父块行截断只影响父块自身表示
（概览位，is_parent_only 不索引），子块改从 full_body 切。二字组 BM25（G-07）与
编号保送负责找回后的可检索性。

## 登记不实施

- 结构识别对「一、」「1.1」双样式标题的覆盖增强（命中章节则父块分章、截断自然
  规避）——归结构提取增强批；
- 自检 dump 落 /tmp 无人消费——告警面进 G-02 branches（后续）。

## 验收

1. 单测：mixed 模式无章节标题 4500 字文本 → 子块并集覆盖全文（validate_chunks 零
   违规）＋父块行 ≤2048；
