## 一、定位记录（票面第一步——先行完成后才进入消除）

### 实验设置

同一 fixture（`tests/fixtures/report_C_heading双样式裁剪.txt`，DE-04 考题），三组实验，全部跨进程实跑（独立 Python 进程＋独立 sqlite 库文件）：

- **实验 A（纯规则链双跑）**：`rule_structure_map → chunk_text`（生产链同构），两次独立进程，`PYTHONHASHSEED=0` 与 `=12345` 分别注入；
- **实验 B（服务全流程双跑·同应答）**：完整 `KbService` 入库管线（建库→上传→确认→五步→片段落库），stub LLM 两次给**同一**完整合法结构图；

### 嫌疑面逐一排查结论（票面四嫌疑）

| 嫌疑面 | 结论 | 证据 |
|---|---|---|
| LLM 辅助结构路径 | **真凶（唯一非确定源）** | 实验 C：两翼双合法仍 5 片 vs 3 片分歧；实验 B 排除其余环节 |
| 集合/字典迭代序 | 排除 | 实验 A：不同 `PYTHONHASHSEED` 跨进程全等；代码面复核——`heading_at` 字典只做键查、`seen` 集合只做成员判断、`spans` 为 finditer 有序列表，无迭代序泄入输出 |
| 并发写序 | 排除 | 实验 B 双跑全等；`_persist_chunks` 串行落库，分支进度写（E2 已知项）不触片段行 |
| 浮点/时间戳混入切分键 | 排除 | 片段 id＝`f{seq}` 纯序号（domain.py `new_fragment_id`）；切片文本/路径不含时钟；overlap 截断为确定性浮点算术（实验 A 全等佐证） |

### 云实证（13 片/589 字 vs 10 片/443 字）的环境差异归因

机制同构推定（**非历史现场复现**——云上两次入库的具体应答无法回放，如实注明）：本地与云上是两个独立环境、各自首次入库，版本级缓存（旧 :1748，键绑定正文 sha 但**只扫同报告既往任务**）双双未命中→各自走 LLM 提取（或一方不可用走回退）→两次**各自合法但不相同**的结构图→切片序列不同（片数/均长/章节路径全变）。实验 C 在当前基线上复现了同一机制（5/103.0 vs 3/171.7）。

## 二、消除：LLM 辅助结构路径退役，边界供给改纯规则（票面授权选项二）

**理论依据（子集恒等式，消除零丢失的形式化证明）**：旧管线的 LLM 定稿图须过 `refine_structure_map`——每标题须过 `is_heading_line`（内含 `_HEADING_RE` 命中＝纯规则判据）＋层级与 `_section_of` 推导一致；`chunk_text` 再对两来源统一施加 `¬_table_like`。因此 **LLM 定稿图在 chunk_text 消费面的有效标题集，恒为纯规则图有效标题集的子集**——LLM 路径对切分边界的全部影响＝从规则集中随机删边（实验 C 的 3 片正是 5 片删边产物）。改纯规则＝取确定化超集：边界零丢失、零 LLM 成本、零抽签。

改动面（白名单内：kb 切块管线＋测试位）：

- `app/domains/kb/service.py`：chunk 步改 `structure = d.rule_structure_map(text) if mode != "fixed" else None`（铁律注记随行）；删 `_structure_map_for`/`_cached_structure`/`_llm_structure_headings`/`_save_structure_snapshot` 与 `STRUCTURE_CALLER` 常量、`hashlib` import；头部管线注记更新。
- `app/domains/kb/domain.py`：删 LLM 图专用件（`STRUCTURE_PROMPT_TEMPLATE`/`STRUCTURE_TIMEOUT_SECONDS`/`STRUCTURE_PROMPT_MAX_CHARS`/`parse_structure_json`/`validate_structure_map`/`_level_consistent`/`level_mismatch_rows`/`refine_structure_map`/`StructureMap.to_snapshot`/`from_snapshot`）；结构图节首落演进注记；**`chunk_text` docstring 落「同文同切」铁律一句话**（交付物④，测试引用见新测试 `test_chunk_entry_docstring_carries_iron_law`）。
- `app/domains/kb/__init__.py`：随删三导出。
- `store.py` 的 `structure_snapshot` 列与既有迁移**零触碰**（列保留、恒 NULL、不再读写；迁移不在本票白名单）。

## 六、偏差与疑点

1. **f26 边际行已知取舍**：corpus A「12 mm 油嘴工作制度」（标题形/13 字/无句读/无表格特征）按纯规则成章——原 LLM 图可随机剔除它（这正是抽签面），退役后该行**确定地**成章（「章节 03 12 mm 油嘴工作制度」，第八章顺延「章节 04」）。内容覆盖不变（无损自检恒过），仅章节路径命名受影；若未来要摘除此类边际行，须以**确定性规则**收紧（如行首带单位数字形的专项断言），归后续规则增强票，不许回 LLM。
2. **P1F-05 方案 A 整体退役**：LLM 结构图（含逐字校验/层级守门/版本缓存三道被测闸）随本票删除——票面授权「缓存键控或改纯规则」取后者，理由：缓存键控只闭合同库重入，闭不住跨环境首灌（正是云实证的分歧类），纯规则才满足「不留每次跑结果不同的缝」。若未来恢复 LLM 参与结构理解，只许走**不进切分边界**的消费面（对照告警/建议落盘），铁律不破。
3. **`structure_snapshot` 存量列**：不再写读，列与既有迁移保留（迁移不在本票白名单）；`TaskStore` 模型零触碰。
4. **铁律域口径**：「切片序列」指原文块（type=原文块，含父块行）的 text＋section＋顺序；enrich 摘要/问题块为 LLM 派生内容、不在铁律域（两次跑的派生块文本可不同）——票面「切分全流程」口径如实按此落。
5. **对外契约零变化**：`chunk_text` 签名（含 `structure` 可选参）与 `validate_chunks` 语义未动；零新依赖；eval/ 只读未动；web/、migrations/、tools/、config/ 零触碰。
