## 二、登记方式定案（票内记录）

**等价 SQL（0015 种子机制同款）**：`INSERT INTO quality_rule (...) VALUES (...) ON CONFLICT (no) DO NOTHING`。
不走 E2 管理面端点——端点 2（`PATCH /api/quality/rules/{no}`）只承载**存量规则启停**，无新增规则端点
（app/api/quality.py 全量核对在案）；迁移 0015 种子即同机制先例（幂等重放不翻倍，已实测重放两次 31→31、33→33）。
不新造写口：登记语句与种子同机制、不经应用代码。

**行形定案**（照 QT-20261006-03 先例 12 条的列形 no/kind/rule/crit/enabled/action/autofix）：

| 列 | 取值口径 |
|---|---|
| no | 21 起顺延（1-20 被种子占用；PK 是普通整数列无域约束） |
| kind | transform.py 族内 dimension 逐字照抄（票面「检查类型」）＝唯一性/完整性/值域/枚举合法 |
| rule | 族内规则名逐字照抄＋表域前缀（表展示名照 quality_store._TABLE_LABEL；措施台账照挂账 §C1 用词） |
| crit | 执行体锚 `data-plane transform.py RULES_<族> · rule-<N>（进料闸执行体）`——SSOT 对账键 |
| enabled | **false**——照 13-20「仅登记不实施」先例。理由：本批规则执行体在**进料闸代码绑定**（scheduler.py Ingest rules dict，常开），无整队 RULES_FULL 执行位；置 true 会造「已启用但 QT 任务只跑 1-12」静默矛盾（E2 端点 2 守卫 rev F1 点名的同款矛盾），且 QT 报告 rules_count 会虚涨到 23/25 与 rules_run=12 打架。置 false 后 enabled 集仍 12，QT 报告口径零扰动；进料闸不读此表，本位不影响 DE-09 进料 |
| action | `整批拒收`——进料闸行为如实（ingest._load：任一违例 BatchRejected 整批不入湖，ingest.py:119-121）；CHECK 约束合法值 |
| autofix | false |

**范围外延（声明）**：票面交付物 1 写「五族」（5 张被拦表），交付物 3 对账写「**六族**」；云上进料面
`DP_PIPELINE_TABLES` 实含 8 表（第 6 族表 well_measures 在列，run-local-book 有其 CSV 59 行）。若只登记五族，
对账表必现第 6 族缺行＝验收二「零差」不成立。故将 RULES_MEASURES 族 2 条一并登记（no=32,33），
登记面与执行面六族全等。同机制同形态，非新写口。
