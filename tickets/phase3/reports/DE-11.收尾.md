# DE-11 收尾报告 · reextract 防重入覆盖入库路径（E3 报告级统一）

- 票号：DE-11（分支 `debt/e3-ingest-reentry-guard`，基点 master cf1ba1f；与 DE-12/DE-13 同分支顺序续提交）。
- 票面：`tickets/phase3/DE-11-reextract防重入覆盖入库路径.md`（来源：挂账清单-20261006 §E3）。
- 结论一句话：**防重入从「reextract-vs-reextract」升级为「报告级」——登记统一收进图谱支路唯一启动器 `_spawn_graph_extract`（入库触发与手动重抽两路共用），启动即登记、支路收尾即解除（asyncio done 语义含异常路径）；reextract 入口查登记拒双跑，文案「入库支路在跑/重抽在跑」两态可辨；三态测试新立全绿。**

## 一、问题定位（改前形态）

- `app/domains/derivatives/service.py` `reextract_graph`（原 :516-536）：防重入登记 `self._graph_running: set[str]` **只在 reextract_graph 内自登记自清理**；入库触发的图谱支路走 `on_ingest_completed → _spawn_graph_extract`（原 :153、:477-514），**完全不经该登记**——入库支路运行中调 reextract 不拦，双跑同报告图谱 upsert（幂等未证，blocked-edges 可能双记）。
- 登记点核实：kb 域（app/domains/kb/service.py）只发 IngestCompleted 事件＋装载 extract_snapshot（B9——kb 不跑图谱支路），图谱支路启动点**唯一**在 `_spawn_graph_extract`——登记收进此处即天然覆盖两路，无第二登记点。

## 二、实现（边界红线内：derivatives 防重入段＋测试位）

`app/domains/derivatives/service.py` 两段：

1. **`_spawn_graph_extract`（两路共用启动器＝统一登记点）**：
   - 启动即登记：`self._graph_running[report_id] = task_no`——登记从 `set[str]` 改 `dict[str, str]`，值存 task_no 兼作来源标记（`"reextract"`＝手动重抽、其余＝入库任务号）；
   - 收尾即解除：`task.add_done_callback(...pop(report_id, None))`——asyncio done 语义：正常/失败/取消均触发回调，**异常路径清理由此保证**（支路体 `_run` 本就全捕获异常，task 必然正常完成触发回调；即使取消/异常完成回调亦跑）；
   - 登记→create_task→回调三行连续同步段，进程内事件循环无交错窗口。
2. **`reextract_graph`（入口查登记）**：
   - 查 `self._graph_running.get(report_id)`，在跑→抛 `GraphParamError`（**400 语义保持**——归一归 DE-12），文案按登记值分两态：`"该报告图谱支路已在运行中——入库支路在跑，防重入拒"` / `"……——重抽在跑，防重入拒"`；
   - 原 spawn 后手工 add_done_callback 段删除（清理已统一收进启动器）；
   - 404 早抛（`report_detail`）保持在查登记之前不变。

框架红线遵守：零新依赖；图谱 upsert 本体语义零触碰——幂等未证的事实照旧，防护只加在登记面（docstring 如实注记）。

## 三、测试（新立——改前 reextract 无既有测试位）

`tests/domains/derivatives/test_graph_service_unit.py` 新增 `TestReentryGuard`（3 用例）＋`GatedCompleter`/`BoomCompleter` 桩＋`_graph_quiesced` 等待面：

| 用例 | 覆盖态 | 断言 |
|---|---|---|
| `test_ingest_branch_running_reextract_rejected` | 入库支路在跑（替身占登记：登记值＝任务号） | reextract 拒且 `match="入库支路在跑"` |
| `test_reextract_running_second_call_rejected` | 重抽在跑（真跑——GatedCompleter 挂闸） | 第二次拒且 `match="重抽在跑"`；放行后支路收尾 |
| `test_failed_branch_releases_guard` | 异常中断（BoomCompleter 抛） | 等待「任务完成且登记清」→ `assert _graph_running == {}`（无泄漏断言）→ 可再入受理成功 |

三测试库配置统一 `graph=False`（防重入登记只由测试主动驱动——completion 模板默认图谱开，make_report 的入库支路与测试并发登记同一 report_id 会造成时序偶发）。等待面用 `_graph_quiesced`（任务全 done **且**登记空）：done 回调经 `call_soon` 调度，单等 `task.done()` 为真的瞬间回调可能尚未执行，有竞态窗口。

- 「既有 reextract 测试零跌」核实：改前 tests/ 全目录 grep `reextract` 零命中——**现实现无既有 reextract 测试**（防重入行为票面交付物 2 既有、无测试位），零跌自然成立；全量 pytest 零失败佐证（含图谱支路既有回归 `TestExtractionPipeline` 全过）。

## 六、偏差与疑点

1. **TDD 过程中修掉两处自写测试缺陷（如实登记）**：①初版 predicate 以 `_sync(coroutine)` 包裹导致 coroutine 未 await（RuntimeWarning，改直传 async 调用）；②组合等待条件误写为 `lambda: A and B`（A 为 coroutine 恒真值→表达式短路返回 bool→`await bool` 抛 TypeError→超时），改为 `_graph_quiesced` async 函数内组合。实现代码本身无返工。
2. **图谱 upsert 幂等未证照旧**：本票只加登记面防护，未宣称双跑安全；若未来要证幂等（upsert 语义审计/blocked-edges 去重），归独立票。
3. **登记为进程内内存态**：单进程语义（与既有 `_graph_tasks` 任务族同域）；多进程/多实例部署的跨进程防重入不在本票范围（现部署形态为单进程演示级）。
4. **api 层零触碰**：409 归一归 DE-12（下一票），本票 400 语义保持；`app/api/graph.py`、`app/api/errors.py` 未动。
