## 一、实现（按交付物）

1. **`app/domains/chat/domain.py` 新增「问数入口精解析影子观测件」节**（与 QueryPlan/MEASURE_COLUMNS 同文件同节区，B1 纯语义零 IO）：
   - **交付物① QueryPlanDraft**：frozen＋slots dataclass，五源槽位 `metric_slot/window/limit_requested/ranking/direction`；window 用 `TimeWindow`（半开区间 [start, end) 同形）。构造唯一入口 `QueryPlanDraft.from_payload(payload)`：
     - 六禁区键（actor/metric_name/measure_column/unit/limit_effective/external_tables）**出现即拒**——`DRAFT_FORBIDDEN_REASONS` 逐键携禁因文案，报错串「禁区键（出现即拒）＋逐键禁因」（与值是否为空无关——键不在准产白名单，红例③的非空 external_tables 是其攻击态特例）；
     - 白名单外未知键同样拒（闭世界——只收五源槽位）；window 载荷只收 start/end/label/is_default，ISO 日期解析、**start≥end 即拒（红例⑤）**；limit_requested **非 [1,200] 整数即拒（红例⑥——0/负/超 200/浮点/字符串/布尔全拒，收口是服务端的事）**；direction 二值白名单、ranking 布尔、metric_slot 非空串。
   - **交付物② validator**：`validate_query_plan_draft(draft, *, question, actor)`——以 metric_slot 为唯一锚重推导：measure_column/unit←`resolve_measure`（MEASURE_COLUMNS 单源封装，**无第二份映射表**）；metric_name←注册名（MEASURE_COLUMNS 键即注册名——票面规定字面执行）；limit_effective←`effective_limit`（50/200 现行收口纯函数）；external_tables←`detect_external_tables(问句)`；actor←函数参数注入（生产调用点恒传 ctx.actor_who，影子期恒为测试替身值）。metric_slot 不在 MEASURE_COLUMNS 即拒（红例④——不在目录不代答）。
   - **交付物③ 比对算子**：`compare_query_plans(draft_plan, deterministic_plan)`——执行语义字段集 `PLAN_COMPARE_FIELDS`（metric_slot/window.start/window.end/limit_effective/ranking/direction 六字段单源枚举驱动逐字段等值）；三态常量 `PLAN_COMPARE_MATCH/DIVERGE/INCOMPARABLE`（一致/分歧/不可比）；分歧态 `divergent_fields` 列明差异字段；window.label/is_default 差异进 `notes` 记日志**不判分歧**；任一侧 None＝不可比（注记指明缺哪侧）。
   - **交付物④ 触发谓词**：`should_trigger_plan_parse(*, verdict_chain, question, metric_slot)`——verdict 判「状态机六站链」∧（词面不齐 ∨ 解析缺件）；核心 `plan_parse_trigger_reasons` 产出原因集（词面不齐＝DATA_QUESTION_RE 不命中经 `is_data_question` 单源复用；解析缺件＝metric 锚缺或未绑定计量列）；另抽 `data_route_signal(question, candidates)`＝service 兜底路由的「指标台账命中＋DATA_QUESTION_RE 词面」组合单源。
2. **`app/domains/chat/chains.py` 影子接线**：
   - ChainDeps 增 `plan_drafter: d.PlanDrafter | None = None`（`PlanDrafter = Callable[[str], Awaitable[QueryPlanDraft | None]]`——照 WaterlineLoader 注入缝同款形状，缺省 None＝生产组合根现状）；
   - 影子观测点＝query_chain N7.1 `declared` 求值之后、三要素分支之前（守卫 `deps.plan_drafter is not None`——未装配恒静默）：触发谓词不命中即静默；命中则调替身/生产 drafter→`validate_query_plan_draft`→与确定性解析（`_shadow_deterministic_plan`——`build_query_plan` 单源重建，vague 窗＝None 不可比、无显式时间走链体同款默认窗）比对→`LOGGER.info` 一行结构化；
   - **影子路异常全吞并**（drafter 抛错/validator 拒都只进日志注记，主链零受扰）；观测点不产任何 SSE 帧（影子零生效）。
3. **`app/domains/chat/service.py` 一行回接**（偏差，见五.1）：`_verdict_signals` 的「指标命中＋词面」两行内联改为 `d.data_route_signal(question, assembly.candidates)` 单源调用——票面「抽纯函数复用，不复制粘贴第二份」的字面落实；逻辑恒等，既有测试零改动全绿。

## 五、偏差与疑点

**偏差（现象→原因→处置）**：

1. **service.py 被改动（协调指令 add 清单列「domain.py/chains.py＋tests＋票面＋回报」未含 service.py）**。现象：本票对 `app/domains/chat/service.py` 有一处两行→一行的恒等改写（`_verdict_signals` 数据问句信号改调 `d.data_route_signal`）。原因：票面交付物④明文「确定性信号（service.py:1295-1301）从既有实现抽纯函数复用，**不复制粘贴第二份**」——若只抽不回接，「指标命中＋词面」组合逻辑即存在两份（service 内联＋domain 抽取），恰是票面禁止态；且票面边界红线明示「只许触碰 app/domains/chat/」并预留「信号函数从 service 抽出时……回 service」的路径。处置：按票面执行最小恒等回接（行为零变化——既有 1046 测试零改动全绿），在此如实登记超出协调 add 清单一行；如 Owner 判不宜，回退该一行即可（domain 抽取件保留，第二份问题转 L-02 入口层接线时再收）。
2. **影子观测消费点落链内（query_chain N7.1）而非入口裁决层**。原因：入口层消费需动 service._decide 接线（L-02 交付范围）；且降级路（指标未绑定＝解析缺件的主覆盖缺口）在链内才可观测——入口层观测反而漏掉它。处置：链内守卫式消费（缝未装配恒静默）；带 verdict 项的完整谓词 `should_trigger_plan_parse` 为入口层契约件（本票测试覆盖），L-02 接线时消费。
3. **红例③「携非空 external_tables」实现为「携键即拒（含空表）」**。原因：票面交付物①明文六禁区键「**出现即拒**」、键不在准产白名单；「非空」是红例攻击态描述。处置：从严执行并加空表仍拒的边界测试；如 Owner 要「空表放行」语义再放宽（单点改动）。
4. **TDD 红证据以 stash 方式补全**。原因：实现落笔时①-④一次成块写入 domain.py，②③④测试后写，丧失自然红态。处置：以 git stash 在实现缺席状态下实跑取得红态记录（37 failed/1 passed、7 failed）再恢复转绿——红绿均为实跑，非事后追认；已按逐交付物分节留痕。

**疑点（L0 不动手，列待 Owner/L-02 裁决）**：

1. **模糊时间窗（「最近/近期」类）不计入解析缺件**——本实现读法：模糊窗走缺参反问是既定确定性出路（缺的是用户事实，LLM#plan 不代猜），故不触发；若影子数据（L-03）显示该档有触发价值，改 `plan_parse_trigger_reasons` 单点即可。
2. **validator 产 metric_name＝注册名（MEASURE_COLUMNS 键），与确定性路的台账原名（含 ★ 前缀）字面可不同**——票面「metric_name←MEASURE_COLUMNS 注册名」字面执行；比对算子不比 metric_name（执行语义字段集之外）故影子期无影响；**L-05 生效路钉 plan 前需拍板** metric_name 取台账原名还是注册名（牵血缘卡①照抄语义）。
3. **「verdict 判六站链但路由落别链」的过窄桶场景不在本观测点覆盖内**——链内观测点只见进了六站链的问句；该桶归 L-02 入口层接线/L-03 报告双分桶口径处理。
4. **Draft window 载荷放行 label/is_default（展示注记非禁区键）**——比对算子按「记日志不判分歧」消费；若 Owner 要求窗口载荷闭世界只收 start/end，`_draft_window_from_payload` 单点收紧即可。
