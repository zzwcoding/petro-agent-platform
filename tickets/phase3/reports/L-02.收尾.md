## 一、实现（按交付物）

1. **交付物①提示词构建器**（`app/domains/chat/service.py`，与 INTENT_VERDICT_SYSTEM_PROMPT
   同址）：`build_plan_messages(question, projection, golden_samples=(), *, today=None)`
   纯函数→`[system, user]` 两条消息；system（PLAN_SYSTEM_PROMPT）钉五源槽位闭世界＋六禁
   区键明示＋ISO 半开窗＋方向二值；user 携今天日期（窗口推算基准，缺省 infra.clock 真值
   ——测试显式注入定日）＋台账投影三源＋少样本。台账投影三源（票内定案）全在
   `app/domains/chat/domain.py` 单源：
   - 可出数指标＝`MEASURE_COLUMNS` 键集（`PlanPromptProjection.metrics` 经
     default_factory 现取注册目录——零第二份可出数清单）；
   - 时间/条数词表＝`PLAN_TIME_WORDS`/`PLAN_COUNT_WORDS` 常量**拼装出** DATA_QUESTION_RE
     （词表即正则的本体来源，不是第二份）＋`PLAN_TIME_WORDS_DISPLAY`/`PLAN_COUNT_WORDS_
     DISPLAY` 展示形（模式形以样例展开；「近3天」取无空格形与正则 `近[0-9…]` 字面一致）；
   - 同源回归测试：展示词表逐词回查 DATA_QUESTION_RE 命中＋正则 pattern 文本冻结（改一
     词两处不同步即红）。
   golden 少样本：构建器参数缺省空（L-04 交付后接入）；首批未就绪时生产装配喂内置常量
   `PLAN_FEWSHOT_FALLBACK`（两条格式示范样例——票内定案记录在案：L-04 产出后装配点换喂
   golden 列表，构建器与 drafter 零改动）。
2. **交付物②gateway 接线**（`service.py`＋`domain.py`＋`chains.py`）：
   - `CALLER_INTENT_PLAN = "chat.intent.plan"`（domain.py，与 CALLER_INTENT_VERDICT 并排）；
     `INTENT_PLAN_TIMEOUT_SECONDS = 8.0`（与 verdict 同值——票内定案）。
   - `ShadowPlanDrafter`（service.py）：提示词构建→`asyncio.wait_for(completer.complete
     (MAIN_ALIAS, messages, caller=chat.intent.plan), 8.0)`→`_strip_json_object` 宽容剥离
     →`QueryPlanDraft.from_payload`＋`validate_query_plan_draft`（越界即拒）→返回 Draft
     或 None。三重兜底照 _verdict_llm 模式：超时/调用失败/解析坏/越界→LOGGER.warning＋
     None→确定性快路，不许问挂。token 计量从 completer 返回对象属性读取
     （`getattr(completion, "prompt_tokens", None)`——缺属性记 null 不断流），单次调用
     遥测落 `last_telemetry`（PlanCallTelemetry：latency_ms/prompt_tokens/completion_
     tokens/breaker_tripped），链内观测点消费（裸替身无此属性→全 null）。
   - 生产装配：ChatService.__init__ 在 ChainDeps 构造点域内接线
     `plan_drafter=ShadowPlanDrafter(completer, breaker=plan_breaker_from_settings())`
     （completer 缺席的极简单测形状＝缝保持 None 恒静默）——组合根 app/main.py 零改动。
     端到端测试实证：make_service 形状提问「上个月产量完成率排名前三」，替身 completer
     收到 caller=chat.intent.plan（归因记账经 B6 统一出口）。
   - 顺带单源化：`_parse_intent_json` 的宽容剥离段抽 `_strip_json_object`，verdict 与
     plan 共用（行为恒等——既有 verdict 测试全绿零改动）。
3. **交付物③跨问熔断**（service.py `PlanBreaker`＋`app/infra/config.py` 两键）：
   - 规则：连续 N 次失败，或固定窗口（PLAN_BREAKER_WINDOW_SIZE＝20，机制参数非阈值）
     计满后失败率严格超阈→熔断位单向置位＋LOGGER.warning 告警；此后 LLM#plan 直接短路
     返回 None（＝快路-only，替身不再被调的测试在案）。恢复＝重启进程（管理面接口不在
     本票范围——如实写明；测试断言成功/失败均不解除＋新实例＝干净旗标）。
   - 阈值不预设：`plan_breaker_consecutive_failures`/`plan_breaker_failure_rate_threshold`
     两可选键挂 InfraSettings（环境变量 PLAN_BREAKER_CONSECUTIVE_FAILURES/
     PLAN_BREAKER_FAILURE_RATE_THRESHOLD），缺省 None＝熔断不启用——**L-03 影子出数后
     Owner 拍板回填（方案开放问题 4，呈 Owner）**。生产装配经 plan_breaker_from_settings()
     读 Settings 面；影子期熔断即使触发也只影响影子日志产量（测试断言用户面零影响）。
   - 数据源（方案 D6）：caller=chat.intent.plan 归因记账经 gateway 落列（观测面）＋
     drafter 本地调用成败计数（熔断判据面）——两者并存。
4. **交付物④影子日志增强**（chains.py 观测点＋service.py ShadowLogSink＋domain.py 记录件）：
   - L-01 影子行扩为字段超集（只增不删向后兼容）：原六字段（run_id/trigger/draft_state/
     elapsed_ms/divergent/note）保留原序，附尾 latency_ms/prompt_tokens/completion_tokens/
     bucket/breaker（缺值渲染 "-"）；JSONL 另携 question/ts（ts 由落盘侧经 infra.clock
     注入）。elapsed_ms＝观测总耗时，latency_ms＝LLM 调用本身延迟——两字段分工在记录件
     注释钉死。
   - `ShadowLogSink`（chat 域内小类，service.py）：LOGGER.info 结构化行＋JSONL 追加写
     双写；默认路径 `logs/shadow-plan.jsonl`，构造参数可注入路径（测试全走 tmp_path）；
     零新依赖（标准库 json/Path）；落盘失败只告警不断流（OSError 吞并——测试：路径被
     文件占位仍不抛）。
   - 触发双分桶（L-03 报告直接消费）：
     - 过宽桶 `PLAN_BUCKET_OVERWIDE＝"过宽：触发但快路可解"`＝触发谓词 True 且比对三态
       「一致」——判例：「哪几口井采得最狠」＋一致草案→bucket 过宽；反例：分歧态不进桶。
     - 过窄桶 `PLAN_BUCKET_OVERNARROW＝"过窄：该触发未触发"`＝触发谓词 False 且本问最终
       落降级解释链或缺参澄清——判例：「日产油量最近怎么样」（词面齐＋锚在册但落模糊窗
       askback）→过窄行（无 drafter 调用）；防双记：钩子先自查触发原因集（非空即静默——
       降级解释链路指标未绑定＝解析缺件恒已触发，N7.1 观测点已落行）。
   - 链内消费：观测活跃判据从「plan_drafter 在位」放宽为「plan_drafter/shadow_log_sink
     两缝任一在位」；落盘缝缺席＝只走 LOGGER 行（L-01 形状不变——L-01 全部 46 例零改动
     全绿）。

## 五、偏差与疑点

**偏差（现象→原因→处置）**：

1. **「既有测试无断言改动」的唯一例外＝FX-09 守护
   `test_production_composition_root_never_wires_plan_drafter` 改写为断言装配**。现象：
   L-01 测试文件该守护从「断言 `_deps.plan_drafter is None`」改为「断言非 None 且
   isinstance ShadowPlanDrafter」。原因：协调指令与守护注释本身明示的 L-02 改写义务
   （「本票把生产装配点接上真实影子 drafter，该守护必须同步改写为断言装配」）。处置：
   原位改写＋docstring 留痕改写依据；改写后测试语义＝断言生产装配的 plan_drafter 非
   None 且指向影子实现。
2. **`logs/` 不在 .gitignore，pytest 运行会因生产默认落盘路径产生未追踪文件**。原因：
   影子日志默认路径 logs/shadow-plan.jsonl 的生产接线在 ChatService.__init__（组合根
   零改动约束下的唯一装配点），测试经 make_service 走真实装配即落盘。处置：本票提交前
   删除 logs/ 保持工作树干净；.gitignore 不在票面边界红线许可清单内故未动——如 Owner
   认可长期共存，建议后续把 `logs/` 入 .gitignore（一行，归下一票或 Owner 直改）。
3. **熔断滑动窗口大小为机制常量（PLAN_BREAKER_WINDOW_SIZE＝20）而非配置键**。原因：票
   面配置两键＝「连续失败次数 N／滑动失败率阈值」，窗口大小属机制参数非阈值；固定窗口
   且计满才判（防小样本误跳闸）。处置：常量集中可调＋注释钉死「机制参数非阈值」；如
   Owner 要窗口可配，单点改 InfraSettings＋plan_breaker_from_settings 即可。
4. **词表展示形「近3天」取无空格形**。原因：DATA_QUESTION_RE 的近 N 模式
   `近[0-9一二两三四五六七八九十]` 不容空白（与 askback 选项「近 3 天」的有空格形不同
   ——既有正则行为零改动红线），词表展示词必须逐词过正则（同源回归断言）。处置：展示
   形随正则字面；提示词语义不受影响（LLM 从词表理解词族，不逐字匹配问句）。
5. **service.py 超出协调 add 清单所列「提示词构建器与接线与熔断」的一个小改**：
   `_parse_intent_json` 的宽容剥离段抽 `_strip_json_object` 供 verdict/plan 共用（约 12
   行恒等重构）。原因：JSON 剥离逻辑若复制第二份即违反零第二真源纪律。处置：行为恒等
   （既有 verdict 测试零改动全绿），在此如实登记。

**疑点（L0 不动手，列待 Owner/L-03 裁决）**：

1. **过窄桶现达场景仅「模糊时间窗缺参澄清」一档**——降级解释链路（指标未绑定）触发谓
   词恒已触发（解析缺件），钩子自查静默防双记，故该桶目前只在「词面齐＋锚在册＋落
   askback」时落行（例：「日产油量最近怎么样」）。若 L-03 实跑显示该桶产量过低，扩口
   单点在 `_shadow_miss_observation` 的原因集自查条件（或 L-01 疑点 1 的模糊窗触发化）。
2. **熔断只读进程内旗标、无管理面接口**——恢复＝重启进程（票面明示范围外）；影子期影
   响面＝影子日志产量。L-05 生效路若启用熔断，需补管理面（置位/复位/只读查询）与告警
   通道（现仅 LOGGER.warning）。
3. **golden 内置少样本的日期为格式示意（2026-09-01 等）**——与「今天」推算规则并存可
   能诱导模型照抄样例日期；影子期产物只落日志无影响，L-04 golden 首批替换时消解（装配
   点换喂即可）。
