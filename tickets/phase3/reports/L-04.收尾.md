## 三、交付物②：跑批脚本用法

```bash
# 全量实跑（服务地址照 rerun.py 惯例走 RERUN_BASE——L-03 可直接复用）：
RERUN_BASE=http://localhost:8000 uv run python eval/results/tools/plan_rerun.py --tag L04G3 --sleep 2
# 离线自检（不起服：golden schema 闸＋提取/判定/锚内置判例）：
uv run python eval/results/tools/plan_rerun.py --tag SMOKE --dry-run
# 冒烟（只跑前 N 题）：--limit 3
```

- 纪律同 rerun.py：题干原句、每题一遍零重试、SSE 帧全量存档 frames/{tag}-{qid}.json、题间
  --sleep；判定表＝eval/results/{tag}-plan判定.jsonl（rerun.py {tag}-跑批结果.jsonl 同款惯例）。
- 机器判：N7.1 finish 行解析为主（指标/时间标签/条数）＋N7.3 模板 SQL 行取窗端点/排名/方向/
  LIMIT＋verdict slots 佐证（矛盾即红）；解析失败落人审列不进退出码。
- 退出码＝机器判（全绿 0／有红 1）；答案数值只在判定表（answer_essentials × answer_head
  并排——人审件），不进退出码，两不相混。
- 窗口锚新鲜度：golden 锚定 anchor_date，去年窗年内有效、今年/本月/默认窗当日有效；过期落
  人审并提示重锚（不误红——L04G 轮跨零点实证，见偏差 4）。

## 八、偏差逐条（现象→原因→处置）

1. **判定表落点 eval/results/{tag}-plan判定.jsonl 在边界红线清单字面之外**。现象：边界红线
   只列「golden（新）／plan_rerun.py（新）／frames（跑批存档）／tests」。原因：票面验收要求
   「判分辅助表在案」，边界清单未给辅助表落点。处置：按 rerun.py 的 {tag}-跑批结果.jsonl
   同款惯例落 eval/results/ 根并随票提交（该目录既有跑批结果全部在 git 追踪——惯例一致）；
   如 Owner 判不宜，移入 frames/ 即可（单点改 FRAMES_DIR.parent）。
2. **问数组册 v2 明细首行数值与现行库不符**。现象：册记 N-01 2025-09-01＝21.16 吨/28.43 方/
   7.56 MPa，实查＝21.00/27.13/7.50。原因：b-8c8cd81fea34 增量批（28 行）覆 N-01/N-02/Z-01/
   Z-02 的 2025-09-01～07 七日值（复合 PK upsert）；排名合计仅舍入差（X-25 5708.15：PG
   round=5708.2／册记 5708.1；N-09 1851.55 同）。处置：golden 按「数值实查为准」记现行值并
   注记漂移来源；**题册零改动**（纪律）——册面数值族按其自己的「换新数据重算」条款由 Owner
   裁量是否换版。
3. **数-察1（各井日产油量是多少？）实测形态与题册 G 族预期不一致**。现象：册预期「无词面不
   入六站链、verdict 落检索问答链」，实测（Q3W 轮帧＋本票探针 P2＋L04G2 三轮一致）LLM 裁决
   判入六站链走默认窗。原因：入口裁决是 LLM（petro-main）——词面正则只是兜底路由信号，裁决
   LLM 天然覆盖了册面「W-AUX 后判型恢复」的预期。处置：golden 按实测形态钉（族 3·快路·默认
   窗），并在答案要点注记「过宽桶实证」；题册 G 族是否换版注记呈 Owner（L0 不动手）。
4. **首轮跑批跨零点导致 5 道 day 级窗题落人审**。现象：L04G 轮开跑时 today 由 2026-10-07 翻
