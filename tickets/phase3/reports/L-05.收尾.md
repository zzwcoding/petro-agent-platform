## 六、偏差逐条（现象→原因→处置）

1. **L05G 轮 24 题 error 帧（`chat_stream_failed 流内异常`）**。现象：首轮 golden 全量
   error 帧收场（绿 4 系未触 chat_run 写路 题）。原因：本地 dev PG 尚在 0020——ORM 已
   映射 `plan_pinned` 列，任何 SELECT chat_run 即 `UndefinedColumnError: column
   chat_run.plan_pinned does not exist`。处置：`uv run alembic upgrade head` 推进共享
   dev 基础设施至 0021（性质同 L-03 的 midplatform 口令修复——环境状态修复非本票代码
   改动）；重跑 L05G2。**教训：迁移批的 golden 实跑前必须先对执行库跑 alembic current**。
2. **L05G2 轮 L04-14 机器判红（真回归——闸 B 红例转修红证据）**。现象：「各井日产油量
   是多少？」（默认窗族·快路可解·词面缺件）提取窗 2026-10-08→2026-10-09（1 天），
   与 golden 期望默认窗（2026-09-08→2026-10-08）分歧——影子期同句比对必现此分歧但零
   生效，生效路开通即成真实行为回归。原因（三层）：①触发谓词按设计命中（词面不齐）；
   ②L-02 提示词未定义「问句无时间词」语义（window 必填且未教缺省语义），LLM 编造
   1 天窗；③validator 只做形状/台账校验，不校窗与问句词面的落定关系。处置（TDD 先红
   后绿 6 例）：新增纯函数 `domain.ground_pinned_window`（零模型——问句零时间词
   （`parse_time_window` missing 契约同源判据）→窗强制默认窗，照快路同语义；有显式
   时间词含模糊「最近」照钉入窗不动），生效钉入（`service._effective_plan_pin`）与恢复
   复验（`domain.revalidate_pinned_plan`）同源消费——重放确定性（同问句同落定）；持久化
   载荷发生在落定后（恢复重放不复活编造窗，篡改窗例在案）。L05G3 该题绿（窗＝默认窗
   全字段一致）。
3. **PG 集成测试两处缺陷由真库实跑抓出**。现象：首跑 `ModuleNotFoundError: No module
   named 'psycopg'`→修驱动后 `AttributeError: module ... has no attribute 'up'`。原因：
   ①票面跑法惯例的 `postgresql://` URL 形让 SQLAlchemy 异步引擎落到未装的 psycopg 驱动
   （先例测试同gate未在本机实跑过此形态）；②测试 `_apply` 直调 `module.up/down`，而
   alembic 版本文件函数名＝`upgrade()/downgrade()`。处置：实跑命令显式
   `postgresql+asyncpg://` 驱动形；`_apply` 方向名映射修正——真库跑绿（1 passed，
   up/down 可逆＋jsonb 列型实证）。
4. **血缘①尾缀文案与 teach 注记不一致（实现照票面定案）**。现象：teach 册 T-01 注记
   （specs/api/A1-问一问.md:199）文案＝「——意图来源：LLM 起草·已过确定性校验」；票面

   各自成文（票面约束条款只钉键名 `intent_source` 以 teach 为准——键名一致无缺陷）。
   处置：实现照票面（本仓不改合同语义）；文案两选一呈 Owner 裁决后统一（疑点 4）。
