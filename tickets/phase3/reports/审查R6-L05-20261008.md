## 发现清单

### R6-01（high）指标替换通道：未注册指标问句被 LLM 换成在册指标并执行出数——golden 终轮两例实锤，比对层零拦截

- **现象**：生效 on 态下，问句问及的指标不在注册目录时，LLM#plan 起草一个「在册但非所问」的 metric_slot，validator 放行、钉入、执行、出数。
  - L05G3-L04-08：问「去年各井含水率是多少？」（含水率未注册）→ 钉入 `metric_slot=油压` → N7.3 装配 `agg.oil_pressure` → answer 返回 50 行油压数据表（帧 `eval/results/frames/L05G3-L04-08.json`：N7.1 行「三要素齐：指标＝油压…——意图来源：LLM 精解析（已复验）」，answer kind=table 列头「油压（MPa）」）。
  - L05G3-L04-09：问「去年各井配产量是多少？」（配产量在册未绑定）→ 钉入 `metric_slot=日产油量` → 执行出 50 行日产油量表。
  - 收尾报告疑点 1 只列了 L04-09 一例；**L04-08 是同通道第二实例**，收尾报告把它归入「期望缺件人审」未按替换通道点名，实际 3 例 llm_plan 钉入中 2 例是错指标执行。
- **根因（三层全部确认）**：
  1. validator 只守注册目录闭世界：`validate_query_plan_draft` 仅查 `resolve_measure(metric_slot) is not None`（domain.py:1726-1731），**不校验 metric_slot 与问句指标候选集的一致性**——「不在目录不代答」防不住「在目录但换了指标」。
  2. 触发谓词在解析缺件形（anchor=None）仍放行钉入：`_effective_plan_pin` 对 `should_trigger_plan_parse` 命中即调 LLM，无 anchor 时 LLM 可自由挑注册目录任意槽位（service.py:1913-1921）。
  3. 钉入后无一监控层能拦：N7.1 复验跑同一个有洞的 validator（同源即同盲）；比对算子 `_shadow_plan_observation` 在 declared=None 形恒「不可比」（chains.py:1449 对 None 侧直落 INCOMPARABLE），影子行照记但不判分歧不阻断。
- **披露面症状（同屏自相矛盾）**：verdict 帧 slots＝「指标＝配产量」，血缘①口径行＝「日产油量…——意图来源：LLM 精解析（经校验）」——同一屏两个指标名，用户可见冲突但答案表已按错指标出数。与「宁可查不到，不给差不多」纪律相悖（收尾报告自认）。
- **建议修法（供 Owner 拍板，三选一或组合）**：
  1. 最小修法（推荐）：`_effective_plan_pin` 钉入前加一致性闸——`draft.metric_slot` 必须 ∈ 问句指标候选集（`assembly.candidates` 中 kind=metric 的槽位名集），不在集合按兜底路分派（澄清额度在→candidates 澄清；否则现状降级）。装配物当场在手，纯增量判定零新缝。
  2. 解析缺件形（anchor=None）禁钉只走兜底——最保守，代价是词面齐但锚缺的题永远澄清/降级。
  3. 提示词加「清单外指标不得换近似指标」——只降概率不封通道，不建议单用。
  - 修复后须补测：L04-08/09 同形红例（替换形→兜底）＋替换形在恢复重放面（plan_pinned 载荷携在册槽位但问句候选集不含）的复验拒例。
- **证据**：app/domains/chat/domain.py:1726-1731（validator 只查注册目录）、app/domains/chat/domain.py:1970-1971（解析缺件触发）、app/domains/chat/service.py:1913-1921（无 anchor 仍调 LLM）、app/domains/chat/chains.py:1446-1466（影子观测消费钉入计划、None 恒不可比）、eval/results/frames/L05G3-L04-08.json / L05G3-L04-09.json（执行出数帧）。

### R6-02（medium）恢复重放防篡改只防「注册集外」篡改；DB 直写把槽位换成另一个在册指标或任意改窗，复验照过执行

- **现象**：`revalidate_pinned_plan` 五源槽位照抄重投 validator，故持久化载荷被改时：
  - 篡改成**未注册**槽位（测试例「完井数」）→ 拒，兜底（test_resume_tampered_slot_rejected_falls_back）✓；
  - 篡改成**另一个在册**指标（如 日产油量→日产液量/油压）→ **复验通过并按新指标执行**——无测试覆盖、无机制防护（注册集仅 3 项，枚举完全可行）；
  - window 槽位改成任意 ISO 区间 → validator 不校窗界（见 R6-03），**显式时间词问句的篡改窗直接生效**（零时间词问句有 ground_pinned_window 兜住，test_resume_tampered_window_grounded 已证该子集安全）。
- **威胁模型如实评估（不夸大）**：利用前提是对 chat_run 表的 DB 直写权限（DBA/越权运维面），高于普通 API 用户；主链路「挂起载荷/API 面」篡改已有测试防住。但本仓把 plan_pinned 定位为「持久化意图的确定性重放」权威源（机制 11），而该权威源无任何完整性封签（HMAC/签名）——载荷在库内可被无声改写且复验放行。
- **建议**：Owner 二选一拍板——①plan_pinned 载荷加服务端 HMAC 列（或并入 payload 带签字段），恢复复验先验签；②明示「DB 直写不在威胁模型内」并记录在案（A2 权限边界文档/票面注记）。至少补一例「在册内换槽」测试把现状行为钉死为已知接受态。
- **证据**：app/domains/chat/domain.py:1852-1871（revalidate 五源槽位照抄重投）、tests/domains/chat/test_chat_plan_effective.py:600-621（篡改测试仅未注册槽位形）。

### R6-03（medium）钉入窗无窗界校验：未来窗、无上界窗长均过 validator

- **现象**：validator/ground_pinned_window 均不校 window 端点与「今天」的关系、不校窗长。三面后果：
  - L05G2 修红轮红例即证：零时间词问句 LLM 编造 `2026-10-08→2026-10-09`（end＝明天）过了 validator 被钉入执行（收尾报告偏差 2 自认）——该形已被 ground_pinned_window 修掉，但**有显式/模糊时间词的问句仍无任何窗界防线**；
  - 模糊词「最近」照钉入窗不动（设计内——LLM 具体化），窗长无上界：LLM 可把「最近」具体化为任意大区间，快路同问是缺参反问（不猜），生效路直接执行 LLM 猜的窗——「模糊时间窗不代猜」纪律在生效路被设计性豁免，豁免范围无边界校验兜底；
  - 未来端点窗静默返空数据（用户看到空表无解释）。
- **建议**：validator（或钉入收口处）加窗界纯函数校验：`end ≤ today＋ε`、窗长上限（如 ≤ 366 天，与 golden 锚新鲜度口径对齐）、超界按 validator 拒走兜底。与 R6-01 同票处置成本最低。
- **证据**：app/domains/chat/domain.py:1683-1711（_draft_window_from_payload 只查半开区间形状）、domain.py:1840-1858（ground_pinned_window 只管 missing 形）、eval/results/frames/L05G2-L04-14.json（end=2026-10-09 过闸实据，见收尾偏差 2）。

### R6-04（medium）转正开闸时熔断仍缺省不启用，且拒形同问两调使失败计数按调用而非按问
