## 任务：

补回**收口刷新**：问一问V2 的 run 收口后，左栏「对话」列表重拉一次——让刚问的那条立刻出现在左栏。

今天左栏只在 mount 拉一次（`web/src/landing/redesign/ThreadList.jsx:103-107` 逐字 `  useEffect(() => {` / `    inFlightRef.current = true` / `    load(pageStep, 0)` / `  }, [])`，且页面没给它任何刷新触发），而 FE-05 重写时把 V2-73 原页的「onDone 自动刷新」丢了。后果：用户刚问完的轮次**要等浏览器刷新才进左栏**——叠加 :8001 重启（V2-135／136 面）时，观感就是「问了一堆，一刷新全没了」。

三处改动：`ThreadList` 收一个刷新键；页面在**收口回调**里递增它；hook 的续答腿把收口回调透出来（今天提问腿有、续答腿没有）。

### 偏离点（逐条带由头——请 Owner 复核）

1. **受理刷新（超出票面「收口刷新」）**：票面只在收口刷新；Owner 报障口径是「**开始运行中后**历史对话没有更新」——只收口刷新则整段作答期间（数十秒）左栏仍不见新对话，与报障现象同形。故提问腿 `onFrame` 里 **session 帧**（run 行受理即落库，真源 `appv2/runtimev2/orchestration/runtime.py:264`）额外 `refreshThreads()` 一次——新对话「运行中」当场进列。代价＝每轮多一次列表读口（进程内读口，O(全表) 已登记为方案 §七.3 增长项）。
2. **`legHandlers` 收口幂等护栏**：票面验收第 2 条要求「同一 run 的收口只递增一次」。原 `onClosed?.()` 无护栏，重复 `onDone()` 会重复递增——补 `closedFired` 每腿至多一次（脏流/双收口幂等），落在 `legHandlers` 内。
3. **新增测试落点**：票面只列「新用例（ThreadList）」与「新用例（页面）」各一；实施后为 2＋3 例（ThreadList 收口刷新 2 例；页面受理/收口/挂起续答 3 例）——受理刷新与幂等护栏各需钉测。
