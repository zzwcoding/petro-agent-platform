## 0. 本票一句话

`RunState.dialogue`（只装自然对话）升级为 **`RunState.messages`（对话链——只追加的消息列表）**：每个 LLM 调用＝发送整条链（＝上次链＋尾段），模型应答与过程记录以**类型正确的消息**追加链尾。任意相邻调用互为前缀延伸——缓存命中率随链增长逼近全量。compile 退役降级为「追加内容渲染器」。

## 1. 目标形态（abc → abcdef → abcdefg）

```
调用 1  [system][user:任务书]                              → ab
调用 2  [system][user:任务书][assistant:理解两行式]           → abc（全命中，只算新尾）
调用 3  …[user:澄清合同][assistant:决策JSON]                 → abcd…
调用 N  ＝ 调用 N-1 ＋ 尾段                                  → 每次只算尾段
追问 run ＝ 前链 ＋ [user:新问]                              → 跨 run 仍是前缀延伸
```

## 4. 各相位追加伪代码

### 4.1 理解（understand_node）

```python

if not state.messages:
    state-appends: [user 任务书(build_understand_instruction 渲染——内容零变化)]
# N0/N1 闸在模型调用前（命中→链尾追加 assistant 话术——§4.6）
context_messages = state.messages            # 整链发送

append [assistant content]                   # 理解原文（两行式/直接回答——原样）
# 解析照旧：parse_understanding/parse_direct_reply 零变化
```

### 4.2 澄清（clarify_node——首入一次性合同＋每轮增量）

```python
# 相位一次性：合同＋样例＋§A＋常驻块只在首次进入澄清时追加
if "clarify" not in state.contracts_appended:
    append [user 澄清相位包 = 相位头＋CLARIFY_CONTRACT{max_subtasks}
            ＋分解样例＋§A 指南＋finalize 边界句＋台账常驻块]
    contracts_appended += ["clarify"]

增量 = [decision_error 回喂行] + [failed 回炉行] + [user_hint 行] + [本 run 已做段]
if 增量: append [user 增量]

# 挂起反问：append 语义由回收侧承接（§4.6）——模型 JSON 已在链
```

## 5. 追问播种（跨 run 前缀延伸）

```python
# executor._seed_dialogue → _seed_messages：
def _seed_messages(followup_of):
    前链 = 前轮 run 的 messages（检查点终态整链——含全部相位合同/台账/答案）
    return 前链 + [user 新问]        # 跨 run 前缀延伸——追问命中前链全部缓存
# 兼容：前轮 schema_version≤2（dialogue 形）→ 抽取 [问, 答, 回收…] 为链种子
#（79a 同源降级——完整度随前轮形态如实）
```

## 6. compile 退役与 compaction

```python
- ContextBuilder.compile 退役 → 保留两个渲染器（纯函数）：
    render_task_book(...)      # 理解任务书（内容零变化）
    render_materials(obs)      # 材料段（[n] 渲染——answer 用）
- 常驻块/合同/指南＝相位包的组成段（文本常量与渲染函数零变化——只换承载位）
- compaction（80d 机制保留）：messages 超 dialogue_view_tokens → 最旧的
  「对话轮对」（user+assistant，非合同/非相位包）摘要化；合同与相位包永不摘除；
  触发即断缓存（可接受——超长对话才触发）
- calllog/blackbox：留痕原样（messages 即链）；blackbox distill 键
  dialogue→messages；前端零变化（SSE/runs 表不变）
```

## 7. 钉测（三条红线＋回归）

1. **只追加性**：同 run 任意相邻两次调用的 messages 满足 `后[:-len(尾段)] ＝ 前`
   （留痕 JSONL 自动断言——批跑驱动加钉）；
2. **类型正确性**：assistant 消息内容禁含伪标注词面（「上轮答案：」「用户已补充：」「用户原题：」）；
3. **相位一次性**：同相位合同消息在链中恰一条；
回归：六闸＋23 场景对照＋cached_tokens 前后对比（改造后多轮链命中率应≫0——
前提上游支持；MiniMax 未证实则如实记录零）。
