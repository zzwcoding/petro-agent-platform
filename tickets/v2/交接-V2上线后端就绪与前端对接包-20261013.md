## 二、API 面（appv2/api/chat.py——合同挂账登记 V2 册，仓内真源 specs/agent-loop.md）

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/v2/chat/asks` | POST | 问一问主链，`text/event-stream`（首帧 session 携 run_id）。头：`Content-Type: application/json`＋`X-Dev-User: <角色键>`（开发期身份桩，生产 OAuth 换 `security.resolve_actor` 单点） |
| `/api/v2/chat/runs/{id}/resume` | POST | 挂起段续跑：clarify＝`{"kind": "clarify", "choice": "<选项原串>"}`；approval＝`{"kind": "approval", "decision": "approve"|"reject", "approval_id": "<透传>"}`（⚠️ kind 判别字段必填——实测缺失 400 request_invalid）（值映射 AskFrame 选项闭世界） |
| `/api/v2/chat/runs/{id}` | GET | `{status, steps, manifest_digest}` |

错误分两段：**流开前**＝同步状态码（400 参数非法／401 未认证／404 run 不存在／409 状态冲突，JSON `{"code","message"}`）；**流开后**＝`error` 帧收场（不走 HTTP 错误包，00 §6.1）。断线重连：asks 携 `resume_run_id`（＋`Last-Event-ID` 头）＝重放断点后事件，不重新执行。

## 四、V2 事件词表（Q17 实测字段——11 种）

| event | data 字段 | 消费建议 |
|---|---|---|
| `session` | run_id, resume | 开场——建会话 |
| `step` | seq, step, title, emission | 思考树节点（step∈decision/execute/observe/answer/verify…） |
| `tool` | tool, seq, status, message | 工具调用卡（doc_retrieve/graph_query/data_query/faq_lookup…） |
| `observation` | index, source, trust, content | 材料堆（**出处三件：报告名＋信任级＋V2-64 本体标签**；V2-64 起渲染形 `[n]（trust｜报告名｜标签）`） |
| `citation` | index, source, source_id, trust | 引用清单面板（cN 对照） |
| `notice` | type, gates, content | 注记（**type=refused 拦停／window_note 窗口声明／渲染截断披露**——前端必须透出，不许吞） |
| `ask` | frame{kind: clarify\|approval, prompt, options[], detail}, run_id | **挂起帧**——流会停在这里，等 resume |
| `text` | content | 答案正文增量 |
| `verdict` | subtype, status, run_id, split, rewritten, cited[], attribution, manifest_digest | 核验摘要（supported/rewritten 计数） |
| `blackbox` | run_id, question, status, stored, bytes, counts, error | 会话落库回执 |
| `done` | run_id | 收场 |

收场三帧 `done`/`error` 与 V1 `RESERVED_FRAMES` 语义对齐；keep-alive 注释行解析器已兼容。

## 六、V1→V2 适配要点（A1.jsx 改造清单）

1. **基座不动**：信封解析、RESERVED_FRAMES 收场、断线重连（Last-Event-ID）全复用。
2. **事件 case 增补**：保留 session/citation/notice/text 处理；新增 `step`（思考树）、`tool`（工具卡）、`observation`（材料堆——按 index 去重展示）、`verdict`（核验摘要）、`blackbox`（落库回执）、`ask`（挂起帧→选项 UI→调 resume）。
3. **端点换 V2**：`/api/chat/*` → `/api/v2/chat/*`；resume 入参按第二节形状（clarify 用 `choice`，approval 用 `decision`+`approval_id`）。
4. **必须透出的三类 notice**：refused（拦停——新鲜度闸/安检）、window_note（缺位来源＋截断披露——判分轴 #7 的诚实面，产品面即"材料只看到 N/M 支"的用户告知）、降级转述。
5. **行集/表格答案**：V2-61 行集交付规矩（逐行带 [n]）已在答案正文，前端按 markdown 表格渲染即可。
6. 判分轴/考试基线不进前端——Q17 已冻结（✅76/⚠️19/❌2），残余病因（渲染帽 24、召回未及）已知不修，注记会随流到达。
