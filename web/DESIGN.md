> 真源：`web/src/theme.js`（令牌）＋ 本文件（用法）。
> 配套：`web/design-tokens.json`（机读令牌）· `web/preview.html`（色板预览）。

## 一、这份系统为什么存在

改造前的实测（18 个页面、1280 与 375 两档、真实渲染的 computed style）：

| 症状 | 数字 |
|---|---|
| 内联 `style={{}}` | 1421 处，散在 49 个文件 |
| 手写 hex 色值 | 526 处，去重约 60 个 |
| 字号档位 | 8 档（10/11/12/13/14/16/18/24），10–14 之间挤了 5 档 |
| line-height | 19 个不同值 |
| padding / margin / gap | 13 / 15 / 10 档（含 7px、11px、15px 等手调值，含负边距） |
| 控件高度 | 31 档 |
| 页面 h1 数量 | **18/18 页为 0** |
| 375px 横向溢出 | **18/18 页** |

根因不是「忘了加变量」，而是**源码作者写的是 antd 亮色主题的色值，而 antd 的
`darkAlgorithm` 会把每个语义色重新派生一遍**：

```
种子 #4a9dff  →  渲染 #4288dc     源码 26 处写前者，渲染出来是后者
源码 #52c41a  →  渲染 #49aa19
源码 #faad14  →  渲染 #d89614
源码 #ff4d4f  →  渲染 #dc4446
```

于是每个语义色都分裂成「源码值」和「渲染值」两套，分属两个系统。
**解法不是逐个改 526 处源码，而是在算法层把整套令牌钉死**，让 antd 的渲染值
=== 项目源码里已经写了 287 次的那套值。一处改动，全站收敛。

## 二、性格（§1.4）

| 轴 | 取向 | 产出 |
|---|---|---|
| serious ↔ playful | **serious** | 企业内部生产管理工具，不做拟物、不做圆润亲和 |
| classic ↔ modern | **modern** | 中性无衬线（`-apple-system`），无衬线字重分两级 |
| dense ↔ spacious | **dense** | 管理台是看数据的不是读故事的，工作默认取 8px 档 |

**暗色是唯一模式**（平台运维场景，夜间值守是真实工况）。不预留亮色主题——
但令牌的语义分层按「换肤是重映射而非重写」设计（§5.2.3）。

## 三、文字层级（§2.2）—— 三级 + 禁用级

| 级 | 值 | 对卡片底 `#161b22` | 用途 |
|---|---|---|---|
| 一级 `text.primary` | `rgba(255,255,255,0.85)` | **12.61:1** | 正文、标题、表格主字段 |
| 二级 `text.secondary` | `rgba(255,255,255,0.65)` | **7.71:1** | 次要说明、表头、标签 |
| 三级 `text.tertiary` | `#8a94a3` | **5.64:1** | 辅助元信息、时间戳、? 图标 |
| 禁用 `text.quaternary` | `rgba(255,255,255,0.25)` | 2.25:1 | **仅限禁用态**（WCAG 对禁用控件豁免） |

**三级是硬上限。** 不要再写第四种灰。
`#8a94a3` 是项目既成值（全站 287 处），本次只是把它**从散落的手写 hex 收进令牌**，
值本身没动——它 5.64:1 的对比度本来就好于 antd 默认的三级（`rgba(255,255,255,0.45)`，4.54:1）。

**字重只有两档**：`400`（正文）与 `600`（标题/强调）。不要用 500，不要用 700。
改造前实测全局只有 400/600/700 三档，这一项本来就合格，保持。

## 四、动作金字塔（§2.8）

**一页一个主操作。**

| 档 | 用法 | 例子 |
|---|---|---|
| 主 | 页面级唯一推进动作 | 「发送」「提交」 |
| 次 | 2 个左右 | 「导出」「查看详情」 |
| 三级 | 若干 | 行尾图标按钮、页签、「?」 |

主按钮 = `colorPrimary` 底 + `colorTextLightSolid` 字。

> **翻转对比（§5.6.1）**：白字 on `#4a9dff` 只有 **2.78:1**，不达标；
> 深字 `#0d1117` on `#4a9dff` 有 **6.81:1**。故主按钮用深色字。
> 副作用是**主按钮与选中菜单项同一套语言**（`#4a9dff` 底 + `#0d1117` 字），
> 「这里是当前所在」在全局只有一种视觉表达。

## 五、表面与深度（§6.1、§8.5.2）

暗色下投影几乎不可见，**抬升靠表面明度差表达，不靠阴影**。三层表面：

| 层 | 值 | 用途 |
|---|---|---|
| `surface.page` | `#0d1117` | 页面底 |
| `surface.card` | `#161b22` | 卡片 / 容器底 |
| `surface.raised` | `#212830` | 浮层、弹层、表头 |
| `border` | `#30363d` | 分隔线 / 描边（软边是对的，§2.7.2） |

改造前 body 是 `#0d1117` 而 antd 卡片是 `#141414`——两者之间有可见接缝。
现在同源。

> **控件边框的例外**：WCAG 1.4.11 要求可交互控件边界达到 3:1。
> `#30363d` 对 `#161b22` 只有 1.42:1，**输入框/下拉框边界需要单独一档更实的描边**。
> 详见 `theme.js` 的 `components.Input` / `Select` 等覆盖。

## 六、间距（§3.2.2、§3.6）

刻度：`0 4 8 12 16 24 32 48 64`（4 基准）。改造前有 13 档 padding、10 档 gap、15 档 margin。

**组外间距必须大于组内间距**（§3.6）——这一条修掉大部分「看着乱」的问题：
分组之间用 24/32，分组内部的项之间用 4/8。

改造前实测存在 **负边距**（`-16px` / `-17px` / `-6px`）与 `-0.1px`——
负边距是跟布局较劲，改为改用正确的 gap / flex。

---

## 七、字号（§4.1.1d）

刻度：`12 14 16 18 20 24`。改造前 8 档，含 10px（342 处）、11px、13px（142 处）。

- `12` 小标签、辅助说明、表格次要字段
- `14` 正文、表格主字段（antd 默认）
- `16` 页标题、卡片标题
- `18` / `20` / `24` 区块标题、统计数字

**不再使用 10px 与 13px。** 10px 低于可读下限；13px 不在刻度上。

---

## 八、行宽（§4.3）

正文每行 **45–75 个拉丁字符 ≈ 22–37 个汉字**。

改造前实测 `proto/C1` 正文块宽 948px @12px = **每行约 79 个汉字**，
`proto/D3` 1024px @13px 同。表格与正文区应限宽 20–35em。

## 九、颜色的三条硬规矩

1. **不许灰字压彩底**（§5.7）。侧栏是品牌蓝 `#0b2e59`，其上的次要文字用**带蓝相的浅色**
   `#8fa8c8`（5.55:1），不是灰。若要在彩底上降对比度，手挑同色相的值，不要用「白 + 降透明度」。
2. **不许只靠颜色传递信息**（Law 12）。状态标签既有文字也有颜色，颜色是加强不是唯一编码。
3. **改已有色阶可以，加新色阶不行**（§5.3.5）。要新颜色先加令牌，不许在调用点临时造。

## 十、系统里没有什么 —— 以及缺了怎么办

**没有**：动效体系、浅色主题、插画/图标资产、栅格断点体系（只有 `lg` 992px 一档）。

**缺了怎么办**：**加令牌，不写临时值。**
在 `theme.js` 的 `palette` 里加一个语义名 → 同步 `design-tokens.json` → 需要的话在 `DESIGN.md` 补一行说明。
**不要**在调用点写一个 `#xxxxxx` 了事——那正是这次要消灭的东西。

## 十一、三条已知的系统边界（别再踩）

### ① antd 的预设色板钉不住

`Tag color="blue"/"green"/"orange"` 这类**预设色关键字**走的是 antd 从种子派生的
预设色板，**不是** `colorInfo`/`colorPrimary` 令牌，ConfigProvider 的公开令牌 API 覆盖不了。

实测：主色 `#4a9dff`（动作面：按钮/链接/选中菜单）与 antd 预设 Tag 蓝 `#3c89e8`
（标签面）亮度比 **1.27:1**；两者对卡片底分别是 6.23:1 与 4.89:1，都达标。

**这是 antd 自己的组件契约（既有系统优先），不改。** 但要知道：
页面里同时出现蓝按钮和蓝 Tag 时，两者色相**不完全一致**——这不是我们漏了。

### ② 喂给 G6/canvas 的颜色必须是字面 hex

G6 v5 默认 **canvas** 渲染器。`fill` / `stroke` / `labelFill` / `iconFill` /
`background` 走 canvas 2D 上下文或 SVG 属性，**CSS 变量在那里不解析**。

实测踩坑：把画布底与节点文字改成 `var(--pa-*)` 后——

- 画布变**纯黑**（不再是卡片底色）
- 节点主文字**整段消失**（`iconText` 的填充色失效）
- 边标签不显

页面看起来像「图没了」，但代码 review 看不出问题。

**规则**：进 G6 配置的颜色，一律取 `theme.js` 的 `palette.viz`（字面 hex）；
DOM 侧（tooltip 浮层、图例色点、行内样式）仍走 CSS 变量。
`tools/check_design_tokens.py` 的第 ④ 条检查专守这个：按**槽位名**判定
（`*Fill` / `stroke` / `haloStroke` / Graph 根层 `background`），
不会误报 tooltip 那套 DOM 样式。

### ③ 数据可视化分类色是独立一套

图谱按节点类型着色（井/区块/平台/油田/措施 + 未知类型轮转），
这一套的职责是**互相区分**——若都映射到 `--pa-primary`/`--pa-success`，
图上不同类型会撞成同一色，图谱失去可读性。故独立放在 `palette.viz`，
经令牌文件统一看守，但不经 CSS 变量（理由同 ②）。

## 十二、改这套系统的正确姿势

| 想改什么 | 改哪里 | 不要改哪里 |
|---|---|---|
| 主色 / 语义色 | `theme.js` 的 `palette` | 各页面里的内联 hex |
| 表面 / 文字层级 | `theme.js` 的 `palette.surface` / `palette.text` | 各页面里的内联 hex |
| 某个组件的特例 | `theme.js` 的 `antdTheme.components.<组件>` | 页面里 `style={{}}` 硬塞 |
| 间距 / 字号刻度 | `theme.js` 的 `spacing` / `fontSizes` | 调用点随手写的 `margin: 15` |

`antdTheme.components` 是 antd 自己的令牌契约，**优先用它**，别在 `className` 里覆盖组件已定的值——
否则同一个组件会同时受两套颜色控制，且改令牌时页面不跟着变。

## 十三、与本仓既有纪律的关系

- 本次只动**落地树**（`web/src/landing/**`）与**壳层**（`web/src/shell/**`、`main.jsx`、`index.css`）。
- **原型树**（`web/src/pages/**`）是 teach 仓原型真源的同步快照，**受
  `tools/prototype_guard.py` 保护，本次不碰**（AGENTS.md 硬纪律 0）。
  令牌层对原型树同样生效——因为 `ConfigProvider` 与 `index.css` 是两树共用的。
- 页面功能定义见 `teach-petro-agent/specs/frontend-foundation.md` 与 `V2-page-spec.md`，
  本文件只管**呈现形态**，不改功能定义。
