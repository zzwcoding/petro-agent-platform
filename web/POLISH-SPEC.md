# 页面整理规范（POLISH-SPEC v1）

> 来源：Owner 2026-09-27/28 逐页整理 A1/A2/A3/C1/C2/E1 的拍板沉淀，经调研总结成文。
> 适用：其余页面（B1–B5/C3/C4/D1–D6/E2/E3/F1/INDEX）的管理化重构；也是审查代理的验收标准。
> 先例页面（照着抄感觉）：`A3.jsx`（状态页签+筛选+按面组织详情）、`C1.jsx`（四本账+登记卡+台账同源）、`C2.jsx`（列头 ? 悬浮+结构化改写）、`E1.jsx`（三页签+工具栏筛选行+Drawer 回看）、`A2.jsx`（档案+关系链页签）。

## 一、页面定位（管理系统三问，Owner 原话："内容要有管理方式、组织方式，而不是全部摊开在页面中"）

1. 每页是**提供给企业用户用的管理系统页面**：有明确的业务定位（管什么、给谁用），不是功能演示堆叠，不是拼凑内容。
2. 内容要有**组织方式**：状态/分类页签（Tabs，页签名带计数）→ 筛选行 → 列表表格 → 行操作 → 详情弹窗分层组织。**禁止把所有内容平铺摊开**。
3. 页面正文只放**业务内容**；一切说明性/解释性/规则性文字收敛到 **? icon 悬浮**（见三-3）。

## 二、文案纪律（Owner 原话："提示文案要面向用户的普通计算机用户描述，不要显得像是教学"）

1. **界面正文零教学痕迹**：不出现 教学/演示/样张/讲解/教学演绎/设定书 §/W-/m-/票N 等字样。契约溯源只走 `window.__traces` + TraceBar（`?dev=1` 才显示）。
2. **用户语言**：面向懂业务、不懂 AI 的普通计算机用户。技术黑话必须翻译：
   - 闭世界 → "只许从清单里选"；听懂问题 → 意图识别；问句进来 → 发起对话；剧本 → 工作流；打分/置信度 → 把握度；召回 → 找出候选。
   - 禁"捎上邻居/信心高"式含混口语；用简单计算机语言，不 low 不玄。
3. **说明收敛到 ? 悬浮**（helpIcon 模式，照 C2.jsx）：
   ```jsx
   const helpIcon = content => (
     <Tooltip title={<div style={{ fontSize: 12, lineHeight: 1.8 }}>{content}</div>} placement="topLeft">
       <QuestionCircleOutlined style={{ marginLeft: 4, color: '#8a94a3', cursor: 'help' }} />
     </Tooltip>
   )
   ```
   挂点：表格列头、卡片标题、按钮旁、页签。原独立说明卡/说明区块**删除**，文案原样搬进对应 ?。
4. 每页导览 `window.__guides` 保留并随重构更新（导览是操作指引，允许步骤口吻，但也不写教学腔）。

## 三、布局模式（照已整理页面的先例逐条落实）

1. **页头**：全局规则/治理链一行灰字放 Card 顶部或 `extra`（如 A3 "低风险自动执行 · 高风险必须人工终审 · 批准后只写变更记录区…"；C1 "先提案 → 过五道检查 → 负责人批准才发布，且可回滚"）。
2. **组织**：Card title 嵌 Tabs（状态/分类，带实时计数）→ Space wrap 筛选行（Select 下拉 + Input 搜索 allowClear + 灰字"筛选结果 n / m 条"）→ Table（size="small"）→ 行操作（"详情"按钮 / 双击行 / 行尾图标）。
3. **详情**：Modal 或 Drawer，用"项/内容"两列表组织、**全状态可见**（状态只占底部一行处理信息，不按状态拆视图——A3 先例）；宽 520–720。
4. **控件细节**：控件统一 `size="small"`；操作按钮白色居中；页签在左；统计数字并入页签括号（如"待审批（3）"），**不设独立统计卡；右栏装饰卡一律去掉**（C1 先例）。
5. **表格**：内容撑满余下空间、默认窗口内滚动（A2 先例）；行尾操作列窄、图标化并带 Tooltip；选中行背景色（非标签式）。
6. **数据**：条目要丰富到能展示不同情况的差异（各状态都有样本）；**仿真不造假**——全部数据取自设定书/页面既有事实，禁止编造数值；台账类选项与 C1 命名导出**同源**（票 93 纪律：TERMS/METRICS/ENTITY_GROUPS/WORKFLOWS/ACTIONS import 使用，禁止本地拷贝）。

## 四、红线（违一条即 FAIL）

1. **不丢既有功能**：重构前后功能逐项对账（票 96/90 同款"页面即规格"反向约束——现有交互点全保留，可新增不可删减）。
2. **业务事实零新增**：数据/规则/枚举全部有源（设定书/PRD 版本 7/C1 台账/页面既有）。
3. **合同数字不动**：50/200 限量、0.05 元熔断、±0.5% 容差、0.4 阈值等合同值原样保留。
4. **`npm run build` 必须通过**（prototype/app 下执行）。
5. **不改共享件**：`shell/`、`roles.js`、`flows/`、`data/changeTickets.jsx`、C1 命名导出的**签名**不动（其他页面只读引用它们）。
6. **不动 DESIGN.md §1 / V2-page-spec.md**：功能定义照旧，本规范只管页面呈现形态（文档同步另票）。

## 五、审查验收（审查代理照此逐条出证据）

对施工结果逐条检查一~四，每条给**行号证据**；输出：
- 逐条判定表（规范条款 → 达标/不达标 + 证据行号）
- 功能对账表（重构前交互点 → 重构后落点）
- 结论：**PASS** 或 **FAIL + 修改清单**（清单要具体到行为与文案，可直接照单施工）
